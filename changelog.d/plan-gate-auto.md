### Added
- Delivery: `/deliver --auto` runs one ticket from a single plan approval. The plan file carries a `Grants: push, pr` line; the user approves the plan once, and `.claude/skills/agentic-delivery/scripts/plan_gate.py` records the verbatim approval against the plan's sha256. The agent runs `check <action>` before every gated action: exit 3 parks that action and the run continues, exit 2 (including a missing ledger or any failed `grant`) halts the run and asks the user. Push and PR-open proceed; merge only when the plan's `Grants:` line names it and the user's whole approval reply is exactly "approve merge" (case-insensitive, trailing period or exclamation mark allowed; an allowlist, so "disapprove merge", "approve merge, nope", "approve merges later" and "approve, do not merge" all park); force-push, deploy, secrets, spend, delete, external sends, history rewrite and settings edits always park (even if a plan or forged ledger lists them), as does any unrouted action. A malformed or forged ledger exits 2 (fail closed), and editing the plan voids the grant. Parked actions go into one end-of-run ask; `parked` exits 2 if the parked list disagrees with the append-only park-event log, which is advisory since the ledger is agent-writable. This is the agent's policy record, not an enforcement point: host permissions and the sandbox stay the boundary, and no hook or settings are changed. Offline simulation of prompts per ticket, before to after (grant derived from a plan without and with `merge`): clean ticket 4 to 2 to 1, one review round 5 to 2 to 1, review round plus deploy 6 to 2 to 2. It runs the real gate on fixed action sequences, so it counts policy prompts, not measured human sessions. Tests: `scripts/test_plan_gate.py` (registered in `scripts/ci-tests.d/plan-gate.sh`).
