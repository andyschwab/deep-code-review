### Added
- `deep-code-review/scripts/derived_numbers.py`: a doc number can be bound to a counter with an inline marker, `<!-- derived: COUNTER ARGS -->N`. The check fails when `N` differs from the counter's result (a stale "N tests" or "N skills"), and `--fix` rewrites the claim. Counters are a fixed allowlist computed in Python: `files GLOB` (tracked files; a run of `*` is one wildcard, a glob is capped at 200 characters and 4 wildcards, and matching tracks live positions with no backtracking, so a hostile glob is a finding rather than a hang), `lines PATH`, `grep-count PATTERN PATH` (lines containing a literal substring) and `json-len PATH KEY`. Doc text is never run as a shell command, so a pull request's markdown cannot execute code in CI; an unknown counter is a finding that runs nothing. Paths must stay inside the repo and never pass through a symlink. Files are read as bytes (non-UTF-8 and CRLF round-trip under `--fix`, which writes a temp file and replaces atomically and skips symlinks), vendored directories and files without `<!--` are skipped, fenced code (by fence character and length), indented code and multi-backtick code spans are ignored, and the number never absorbs a trailing comma, period or decimal part. A repo with no markers passes.
- `scripts/dcr-gates.sh` (the runner `install.sh --with-gates` installs) runs it by default, plus its selftest; `DCR_DERIVED_NUMBERS=0` turns it off and any other value except 1 fails closed. This repo's CI runs it on its own docs: the skill count in `docs/perun-vs-rivals.md` (two places) is bound to `files .claude/skills/*/SKILL.md`. Tests: `scripts/test_derived_numbers.py` (wired into CI). One `deep-code-review` eval: `docs-count-bound-to-source-command`.
