### Changed
- Token optimization: `landing_watchdog.py` now emits its stall or WIP line to a prompt once per session and again when the line changes or after an hour (so a compaction that dropped it re-shows it), always to an Agent/Task spawn, with stale stamps pruned after a week (a per-session stamp beside the repo cache, the same pattern as `context_nudge.py`'s work-kind stamp), instead of on every prompt while the condition holds. Measured: the stall line is 103 bytes (167 with the WIP line), so a session with N prompts under a standing stall sends 103 bytes about once an hour instead of 103 x N. A payload without `session_id` is not deduped, and a stamp I/O error still returns the line. `SubagentStart` still injects `HOST_RULES`: a subagent does not see the parent's SessionStart context, so cutting it there would drop the rules from every lane (`multi-session-coordination.md`, "A standing house default must live where every subagent reads it").
