### Added
- New `agentic-delivery/scripts/sandbox_preflight.py`, a read-only autonomy advisor (stdlib only, never writes settings). It scans a repo's package scripts, Makefile, git hooks and local scripts for what the Claude Code sandbox breaks (tsx Unix-socket IPC, local port binds, Chromium/Playwright, database clients, `gh` TLS, docker, git over SSH on macOS, writes outside the repo) and prints "To run autonomously, add:": a settings JSON snippet with only what the existing settings lack (exact `permissions.allow` patterns for the repo's test, lint, build and `git push <remote> HEAD`; `sandbox.excludedCommands` written as the command the agent types; allowed domains, `allowLocalBinding`, `allowWrite`; `permissions.deny` for destructive git and `rm -rf`), what stays blocked or asks you on purpose, and the per-host mechanism the docs confirm (Claude Code, Codex). Every allow rule is checked against `destructive_guard.py`. `perun_doctor.py` and `install.sh` print the section; sources and dates are in `docs/standards-index.md` (2026-10-16).
- `lane_guard.py` now copies the gitignored `.banlist.local.txt` from the main checkout into a new lane worktree when it is missing (plain copy, never a symlink, never an overwrite, only when git ignores the path, only after an OK result).

### Changed
- `terse_reply_check.py` now prevents instead of forcing a rewrite: on `SessionStart` it injects the reply budget (3 lines / 500 chars by default; code blocks and `! ` lines excluded), a violation on `Stop` no longer blocks but is recorded, and the next `UserPromptSubmit` gets a one-line reminder, so the user never sees a reply and its shortened copy. `TERSE_MODE=block` keeps the old rewrite. The opt-in template `terse-replies.settings.json` registers all three events.
- `handback_cap.py` no longer counts fenced code blocks or lines starting with `! ` toward its 800-char / 10-line cap, so copy-paste commands never force a rewrite; the whole message may still not pass 5 times the char cap, so a deliverable cannot hide in a fence.
