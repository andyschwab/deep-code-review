- agentic-delivery: `destructive_guard.py`, a PreToolUse(Bash) hook wired by the operating layer. It never runs the command; it unwraps `bash -c`, `env`, `sudo`, `xargs` and `/bin/rm`, then denies `rm -r` on a variable, glob, root or home path, `git reset --hard`, `git clean -f`, force-push, `git checkout .`, `find -delete`, `dd` to a device, `mkfs`, `chmod -R /`, `curl | sh` and kill-by-pattern, each with a safe alternative. Shell keywords and braces, `bash -lc`, `timeout`/`setsid`/`stdbuf`/`ionice`/`nice`, `$(...)` and backtick bodies, `curl | python`, process-substitution fetches, near-root and `.`/glob `rm -r` targets, git global options with values and interpreter one-liners that delete are covered. A parse failure falls back to a regex scan (block on a hit). The escape hatch is a `destructive-guard-allow: <exact command>` line in `CLAUDE.md` that `git blame` shows was committed by an owner (no Co-authored-by trailer). On the 32-command bench corpus it blocks 30 (was 11) with 0 of 30 false positives. Tests: `scripts/test-destructive-guard.sh`.
