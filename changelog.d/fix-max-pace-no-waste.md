### Changed
- Maximum pace no longer reads as a licence to spend. It lifts the lane and heavy-slot caps, the `HOLD`/`FULL` retry waits and approval pauses inside the granted budget, and spends more only where that buys speed or quality: parallel lanes up to the load gate, a stronger model or deeper verification on hard steps. A waste filter holds in both modes: no duplicate run of the same gate on the same tree, no idle polling, no courtesy messages, no restating, and the cheapest model that keeps quality for mechanical work. Spend is still reported. The old wording that max pace "outranks the model-tier economy" is gone.
- One source of truth: the rule, its triggers and the `perun_policy.py set tokens maximize` / `set local_cpu maximize` knobs now live once in `templates/lane-preamble.md` **Drive to the goal**; `references/operating-discipline.md`, `templates/loops/coordinator.md`, `commands/perun-run.md` and `docs/for-fleets.md` point to it. The preamble also names the way back (`set tokens efficient`, `set local_cpu efficient`), and the trigger list reads "push at max" instead of a bare "push" so a git push grant does not switch the spend mode.
- New eval `max-pace-mechanical-rename-stays-cheap` (a max-pace rename lane stays on the cheapest tier while a security re-review gets the stronger one) and new test `scripts/test_max_pace_no_waste.py`, which pins the wording, the single source, and that the documented knobs match `perun_policy.py`.
