### Added
- `token_report.py` now measures tool-result size, the lever peer tools target: `tool_results` in `--json` counts main and lane tool results over 10000 chars (length only, never the text), split by tool (`by_tool`: Bash/PowerShell, Read, other such as MCP), and estimates their carry as chars/4 tokens times the turns resent until the next observed compaction (or the end) times the 0.1 cache-read weight. It is an estimate, clamped to the scope's input-eq (`clamped` says when). At 5% of session input-eq or more from Bash/PowerShell output past the 10000-char cap, it ranks a `cap Bash output with bashOutputMaxChars` row marked `estimate: true` and prints a `Lever:` line pointing at `docs/token-cost-tips.md`; a set `bashOutputMaxChars` or `BASH_MAX_OUTPUT_LENGTH` mutes it. Large Read and MCP results get info lines (read with offset/limit, check MCP output size), never a ranked row. Tests: `scripts/test_token_tool_results.py`.
