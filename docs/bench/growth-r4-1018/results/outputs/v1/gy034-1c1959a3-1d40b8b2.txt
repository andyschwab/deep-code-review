### Diagnostic Framework: DataVista Dashboard Update (Oct 3–6)

**Objective:** Determine if the 12% DAU drop is a navigation friction issue (fixable) or a fundamental workflow breakage (requires rollback) by Friday EOD.

**1. Immediate Triage Metrics (Monitor Daily)**
*   **Core Action Completion Rate:** Define the single "value" action (e.g., "Report Generated" or "Dashboard Viewed"). Compare the rate of users completing this action *per session* pre- and post-launch.
    *   *Signal:* If sessions are stable but completion drops >15%, the workflow is broken. If sessions dropped but completion per session is stable, users cannot find the entry point (navigation friction).
*   **Time-to-First-Value (TTFV):** Measure time from login to core action completion.
    *   *Signal:* A spike in TTFV confirms navigation confusion. A flat TTFV with low volume suggests users are abandoning before even trying.
*   **Support Ticket Tagging:** Categorize the 40% ticket surge into "Navigation/Findability" vs. "Functionality/Error."
    *   *Signal:* >60% "Findability" supports a UI fix; >40% "Broken/Error" supports immediate rollback.

**2. Cohort Segmentation (The "Power User" Test)**
*   **Segment A (Power Users):** Top 20% of users by historical frequency.
*   **Segment B (Casual Users):** Remaining 80%.
*   *Analysis:* Is the 12% drop uniform, or concentrated in Segment A?
    *   *Decision Rule:* If Power User retention drops >20% while Casual remains stable, the new workflow fundamentally breaks expert efficiency → **Recommend Rollback**. If both drop equally, it is likely a general discoverability issue → **Recommend Fix**.

**3. Funnel Leakage Analysis**
Map the specific path: `Login` → `New Nav Interaction` → `Report Selection` → `Report Load`.
*   Identify the exact step with the highest drop-off increase compared to last week's baseline.
*   *Action:* If the drop occurs at `New Nav Interaction`, the menu is invisible. If it occurs at `Report Load`, the backend or query builder is broken.

**4. Experiment/Canary Validation**
*   If feasible, route 10% of traffic back to the old interface (or a simplified version of the new nav) immediately.
*   Compare DAU and Core Action rates between the 90% (new) and 10% (old/control).
*   *Signal:* If the control group maintains historical norms while the 90% dips, the change is the sole cause.

**Decision Matrix for CTO (By Friday)**
| Scenario | Metric Signal | Recommended Action |
| :--- | :--- | :--- |
| **Critical Failure** | Power user core action completion drops >20%; High "Broken" ticket volume. | **Immediate Rollback.** Do not wait for learning curve. |
| **Navigation Friction** | Sessions down, but completion rate per session stable; High "Findability" tickets. | **Hold & Fix.** Deploy targeted tooltips, search bar prominence, or "classic view" toggle. |
| **Transient Shock** | Drop stabilizes by Day 4; TTFV improving daily. | **Hold & Monitor.** Communicate expected stabilization timeline to stakeholders. |
