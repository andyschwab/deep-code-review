**Subject: Data Remediation Strategy for Series B Due Diligence**

**Objective:** Standardize event taxonomy and reconstruct a continuous, auditable historical dataset by October 15 to support the November 30 funding close.

**1. Immediate Governance: The Canonical Taxonomy**
Define a single canonical event name immediately (e.g., `add_to_cart`). Declare `addToCart` and `item_added` as deprecated aliases. No new instrumentation proceeds until this definition is locked in the analytics platform. This stops the bleeding before fixing the past.

**2. Historical Reconstruction: The Union Strategy**
Do not attempt to "clean" raw logs in place, which risks audit trails. Instead, create a new computed dataset (a view or materialized table) for the reporting layer:
*   **Logic:** Construct a query that unions the three variant events over the past six months, mapping all three to the single canonical `add_to_cart` event ID.
*   **Continuity:** Because this logic applies retroactively to the entire six-month window, the resulting time-series will show a continuous trend. There will be no artificial spikes on the day of implementation because the historical data is being re-aggregated under the new rule, not appended to it.
*   **Audit Trail:** Document the exact SQL or transformation logic used. This script *is* the audit evidence. It proves to investors that the growth curve is derived from a consistent rule applied uniformly across time.

**3. The Transition Gap: Dual-Tagging & Annotation**
While the engineering team deploys the fix (estimated 3 weeks):
*   **Forward-Looking:** Update all client-side and server-side code to fire *only* the canonical `add_to_cart` event.
*   **The "Gap" Narrative:** If the remediation script cannot be run in real-time during the 3-week build, annotate the dashboard for this specific period as "Transitional Data – Pending Final Aggregation."
*   **Investor Communication:** Do not hide the gap. Present the "Raw/Fragmented" view alongside the "Reconstructed/Unified" view for the historical period. Explicitly state: "Pre-October data is reconstructed via union logic; post-October data is native canonical." Investors prefer a disclosed methodology over hidden inconsistencies.

**4. Validation Protocol (Pre-October 15)**
Before the CFO signs off:
*   **Spot Check:** Manually verify 50 random sessions across platforms to ensure the union logic captures 100% of the variant events.
*   **Sanity Check:** Compare the reconstructed total conversion volume against a rough aggregate of the three separate streams. The numbers must reconcile within a <1% margin of error (accounting only for timezone edge cases).
*   **Sign-off Artifact:** Deliver a one-page "Data Integrity Memo" to the CFO containing: the canonical definition, the reconstruction logic summary, the validation results, and the explicit statement that YoY growth figures are now based on the unified dataset.

**5. Risk Mitigation**
If the 3-week timeline slips, prioritize the **last 12 months** of data first. Investors care most about the recent trend. Older data can be marked as "Legacy/Unreconciled" if necessary, though the union approach should cover the full six months easily.

**Decision Required:** Approve the engineering budget to build the transformation layer by October 1. Delaying beyond this date risks the due diligence start.
