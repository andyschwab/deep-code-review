**The Measurement Gap & Event Taxonomy**
Your assumption that "Quick Start" readers convert is currently `UNVERIFIED` because "successful" is undefined beyond HTTP 200. A 200 OK on a malformed query is a silent failure. To measure adoption depth and justify the $200k investment, instrument only these three events that answer specific questions:

1.  **Event:** `integration.validated_success`
    *   **Question:** Did the developer's code actually work, or just return a status code?
    *   **Properties:** `endpoint_complexity_score` (weighted by schema depth), `payload_size`, `latency_p95`, `is_production_env` (derived from API key scope).

2.  **Event:** `integration.stuck_point`

    *   **Why:** High retry counts with 200 OKs but empty payloads indicate logic errors the docs didn't solve. This captures the "silent failures" you fear.

3.  **Event:** `docs.actionable_engagement`
    *   **Question:** Does documentation usage correlate to success?
    *   **Properties:** `snippet_copied` (boolean), `time_on_page` (capped at 5m to avoid noise), `search_query_used`.
    *   **Why:** Rejects "time spent" as a standalone vanity metric. Only count engagement tied to a subsequent `integration.validated_success` within 24 hours.
