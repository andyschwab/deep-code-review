# User Path Analysis Framework: Custom Dashboard Adoption

**Objective:** Diagnose friction points in the custom dashboard creation workflow to increase adoption from the current 12% baseline among active users.

## 1. Event Taxonomy: Answering Named Questions
Do not instrument "everything." Track only the events that answer specific hypotheses about where users abandon the multi-step workflow. Each event must include a `session_id`, `user_id` (pseudonymous), and `step_sequence_number` to handle non-linear behavior.

| Event Name | Question It Answers | Required Properties |
| :--- | :--- | :--- |
| `dashboard_creation_started` | How many users attempt the flow vs. view the entry point? | `entry_point` (menu, banner, shortcut), `user_segment` (power vs. casual) |
| `data_source_selected` | Do users drop off before choosing data? | `source_type` (SQL, API, CSV), `time_to_select` (ms) |
| `widget_added` | Is the core value being realized? | `widget_type`, `canvas_count` (current number of widgets) |
| `configuration_panel_opened` | Where does complexity cause hesitation? | `widget_id`, `property_group` (filters, styling, data mapping) |
| `step_revisited` | **Critical for non-linear flows:** Are users looping due to confusion? | `from_step`, `to_step`, `loop_count` |
| `dashboard_saved` | What is the final conversion rate? | `total_time_spent`, `widget_count_final` |
| `dashboard_creation_abandoned` | Explicit abandonment or session timeout during flow. | `last_completed_step`, `error_message` (if any) |

## 2. Segmentation Strategy
Aggregate data hides the signal. Segment analysis by:
*   **Proficiency Cohort:** Compare "Power Users" (top 20% by weekly active days) vs. "Regular Users." If power users struggle, the UI is likely flawed; if only regular users struggle, the feature may require too much domain knowledge.
*   **Entry Context:** Users entering via a "blank canvas" vs. those using a "template." Templates may reduce cognitive load.
*   **Data Source Complexity:** Segment by `source_type`. SQL users might drop off at widget placement, while CSV users might drop off at source selection.

## 3. Handling Non-Linear Behavior
Standard funnels fail when users jump back and forth. Use **Path Analysis** rather than strict funnel conversion:
*   **Loop Detection:** Calculate the percentage of sessions where `step_revisited` > 2. High looping between `widget_added` and `configuration_panel_opened` indicates unclear configuration options.
*   **Drop-off Heatmap:** Map abandonment rates to the *last successful step*. If 40% abandon after `data_source_selected` but before `widget_added`, the gap is in the transition logic or empty state design.
*   **Time-in-Step:** Outlier detection on `time_to_select` or time between events. Long pauses often precede abandonment.

## 4. Implementation Plan (Start Date: Next Monday)
*   **Engineering:** Deploy the six events above with strict schema validation. Ensure `user_id` is stable across sessions for cohort tracking.
*   **UX Research:** Prepare to correlate quantitative drop-offs with qualitative session recordings for the top 3 friction paths identified after 7 days of data.
*   **Success Metric:** Increase `dashboard_creation_started` → `dashboard_saved` conversion from 12% to 18% within 6 weeks.

**Note:** Current 12% adoption is a baseline, not a benchmark against external tools. Do not compare to industry averages without verified sources.
