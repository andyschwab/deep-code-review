**Measurement Framework for NairaWallet Investor Check-in (July 5)**

**North Star Metric:** Weekly Active Users completing a **First Successful Transfer** within 3 days of signup.
*Rationale:* This directly measures value delivery (money moved) rather than vanity (signups). It aligns with your unit economics hypothesis.

**Prioritized Event Taxonomy (Top 5)**
These five events answer the specific question: "Do users verify, fund, and transfer successfully despite network volatility?"

1.  `signup_completed`
    *   **Properties:** `timestamp`, `device_type`, `network_type` (4G/3G/2G).
    *   **Question Answered:** What is our top-of-funnel volume and device mix?
2.  `verification_attempted` (Critical for volatility analysis)
    *   **Properties:** `timestamp`, `document_type`, `failure_reason` (e.g., timeout, image_reject).
    *   **Question Answered:** Is network latency causing drop-off before funding? (Distinguishes user intent from technical failure).
3.  `first_deposit_made`
    *   **Properties:** `timestamp`, `amount`, `currency`, `funding_source`.
    *   **Question Answered:** Does deposit size correlate with transfer completion? (Tests your "leading indicator" hypothesis).
4.  `transfer_initiated`
    *   **Properties:** `timestamp`, `recipient_type`, `amount`.
    *   **Question Answered:** Are users attempting the core action after funding?
5.  `transfer_completed` (The North Star Event)
    *   **Properties:** `timestamp`, `duration_from_signup`, `success_bool`.
    *   **Question Answered:** Did the user achieve the "aha" moment within the 3-day window?

**Rationale for Exclusions**
*   **Profile Completion:** Excluded. This is a vanity metric; a user can have a 100% complete profile and never move money. It does not predict retention if the transfer fails.
*   **Social Sharing:** Excluded. At seed stage, referral is secondary to validating the core loop. Instrumenting this distracts from the primary leakage point: network-induced failure during verification or transfer.

**Addressing Data Loss & Volatility**
To mitigate mobile network data loss without overburdening your engineer:
*   **Strategy:** Implement local queuing for events 2, 4, and 5. If the network drops during `verification_attempted` or `transfer_initiated`, the app must retry sending the event once connectivity returns.
*   **Measurement Gap:** If `transfer_initiated` exists without a matching `transfer_completed` and no retry occurs, flag this cohort as "Potential Network Data Loss" vs. "Actual Failure." Do not invent a recovery rate; report the gap as `UNVERIFIED` until the queue logic is confirmed.

**Investor Read-Out Plan (July 5)**
Do not report raw signups. Present the **Activation Rate**: (% of `signup_completed` who hit `transfer_completed` within 72 hours).
*   **Retention First:** Before discussing acquisition spend, show the retention of users who completed Event 5. If this is low, acquisition is wasted.
*   **Leading Indicator Test:** Compare the retention curve of users with `first_deposit_made` > ₦5,000 vs. < ₦5,000. If the higher deposit group retains significantly better, you have validated your leading indicator. If not, pivot the onboarding flow to encourage smaller, faster first transfers.
