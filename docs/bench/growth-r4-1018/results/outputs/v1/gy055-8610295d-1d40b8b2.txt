### Diagnostic Plan: Date-Selection Friction Isolation

**Objective:** Isolate the specific cause of the 58% drop-off between "Date Selection" and "Room View" to prioritize fixes for the June peak.

**1. Event Taxonomy (Instrument Only These)**
Track these three events to answer specific questions. Do not instrument generic clicks.
*   `date_search_submitted`: Triggered when the user clicks "Check Availability."
    *   *Properties:* `device_type` (mobile/desktop), `load_time_ms` (time to next screen), `search_params` (dates, guest count).
    *   *Question:* Does friction correlate with device or query complexity?
*   `room_list_loaded`: Triggered when the room options successfully render.
    *   *Properties:* `load_time_ms`, `error_code` (if any), `room_count_returned`.
    *   *Question:* Is the drop-off due to technical failure (timeout) or empty results?
*   `filter_interaction`: Triggered if filter UI appears and is touched.
    *   *Properties:* `filter_type`, `time_to_first_interaction`.
    *   *Question:* Are users abandoning because they cannot refine results immediately?

**2. Segmentation Strategy (The "Cut")**
Slice the funnel drop-off by these dimensions to isolate the variable:
*   **Device Type:** Compare mobile vs. desktop drop-off rates. If mobile drop-off is >70% while desktop is <40%, the issue is likely **mobile load times** or layout, not price transparency.
*   **Performance Quartiles:** Group users by `load_time_ms`. If drop-off spikes in the slowest 25% of loads, engineering must prioritize performance over UX copy.
*   **Result Set Size:** Compare users who see 0 rooms vs. 10+ rooms. If users with 0 results drop off at 90%, the issue is **inventory availability**, not trust or filters.

**3. Hypothesis Testing Matrix**
| If Data Shows... | Then The Friction Is... | Next Action (Sprint Priority) |
| :--- | :--- | :--- |
| Mobile drop-off >> Desktop | **Mobile Load/Layout** | Optimize images/scripts; simplify date picker for touch. |
| High drop-off when `room_count` = 0 | **Inventory/Expectation** | Add "no rooms" educational copy or alternative date suggestions. |
| Uniform drop-off across all segments | **Trust/Price Perception** | A/B test trust badges or breakdown of fees *before* the submit click. |
| High drop-off + Fast Load + Rooms Available | **Filter/Sort Needs** | Move critical filters (price, amenities) to the date selection screen. |

**4. This-Week Steps**
1.  **Engineering:** Implement the three events above with `device_type` and `load_time_ms` properties by Wednesday. Verify data flow in the analytics tool.
2.  **UX/Analytics:** Run the segmentation query once data accumulates (minimum 500 `date_search_submitted` events per segment). Identify the highest variance segment.
3.  **Decision Gate:** By Friday, select *one* primary hypothesis based on the data cut above to build an A/B test for next sprint. Do not proceed to design solutions until the segment is identified.

*Note: All metrics must be compared to your internal baseline from May 5–20; no external benchmarks are applied. If `load_time_ms` data is missing, the performance hypothesis remains UNVERIFIED.*
