### Analysis Plan: Mobile Filter Friction vs. Intent Segmentation

**Objective:** Distinguish whether the mobile conversion drop (1.5% vs. 4.2% desktop) post-Jan 20th is caused by interface friction (usability) or inherent user intent (browsing behavior).

**1. Isolate the "Intent" Variable (Behavioral Cohorting)**
Before blaming the UI, verify if mobile users who *avoid* filters also convert poorly.
*   **Action:** Segment mobile traffic into two cohorts: "Filter Users" and "Non-Filter Users."
*   **Metric:** Compare conversion rates of Mobile Non-Filter Users against their pre-Jan 20th baseline.
*   **Interpretation:**
    *   If Mobile Non-Filter conversion is stable (~pre-launch levels) while Filter Users dropped: The issue is **Interface Friction**.
    *   If Mobile Non-Filter conversion also dropped significantly: The issue is likely **External/Intent** (e.g., traffic source quality, seasonality, or a broader mobile site regression unrelated to filters).

**2. Funnel Step Drop-off Analysis (The "Where")**
Pinpoint the exact interaction causing abandonment for mobile filter users.
*   **Action:** Map the funnel specifically for the "Mobile + Filter Engaged" cohort:
    1.  View Product List
    2.  Open Filter Modal
    3.  Apply ≥1 Filter
    4.  View Filtered Results
    5.  Add to Cart
    6.  Checkout Start
*   **Metric:** Calculate step-to-step drop-off % compared to Desktop Filter Users.
*   **Interpretation:** A spike in drop-off immediately after "Apply Filter" or "View Filtered Results" on mobile (but not desktop) confirms **Cognitive Load/UI Complexity**. If the drop occurs later (e.g., Checkout), the filter is likely working, and the issue lies elsewhere (e.g., payment UX).

**3. Temporal & Device Granularity (The "When" and "What")**
Test the "Browsing vs. Buying" intent hypothesis.
*   **Action:** Break down mobile conversion by:
    *   **Time of Day:** Do evening/weekend users (typically browsers) have lower intent than weekday commuters?
    *   **Device Screen Size:** Segment mobile into "Small (<375px)" vs. "Large/Phablet."
*   **Interpretation:**
    *   If small screens show drastically higher drop-off than phablets *only* when filtering: This is **Usability** (touch target size, modal overlap).
    *   If conversion is uniformly low across all mobile sizes and times, but high on desktop: This suggests a **Platform Intent** gap (mobile users are indeed just browsing), though the 20% penalty for *using* filters still points to a specific feature failure.

**4. Qualitative Correlation (The "Why")**
*   **Action:** Cross-reference quantitative drop-off points with session replay tools (e.g., Hotjar, FullStory) for the "Mobile + Filter + Abandon" cohort.
*   **Look for:** "Rage clicks" on filter apply buttons, rapid closing of the filter modal, or scrolling loops within the filter menu.
*   **Outcome:** Visual proof of frustration validates the "cognitive overload" hypothesis.

**Decision Matrix for Q2 Roadmap:**
*   **Scenario A (Friction Confirmed):** Drop-off spikes at filter application on small screens; non-filter users are stable.
    *   *Action:* Redesign mobile filter as a bottom-sheet or simplified toggle; remove complex multi-select options.
*   **Scenario B (Intent Confirmed):** Drop-off is uniform across all mobile behaviors; non-filter users also converted poorly historically.
    *   *Action:* Optimize mobile for "browse-to-save" (wishlist) flows rather than forcing immediate checkout; adjust marketing expectations for mobile ROI.
*   **Scenario C (Mixed):** Non-filter users are stable, but drop-off occurs *after* filtering during checkout.
    *   *Action:* The filter works, but the resulting product list or checkout flow on mobile is broken. Investigate page load speeds or form factors post-filter.

**Required Data Queries:**
1.  `conversion_rate` GROUP BY `device_type`, `filter_used`, `date` (Pre/Post Jan 20).
2.  `drop_off_rate` per funnel step FOR `device_type = mobile` AND `filter_used = true`.
3.  `conversion_rate` GROUP BY `mobile_screen_width_bucket`.

**Note:** Do not assume the 20% penalty is purely usability until Non-Filter mobile baselines are verified. If the baseline mobile conversion is naturally low, the "penalty" might be relative to an already weak cohort.
