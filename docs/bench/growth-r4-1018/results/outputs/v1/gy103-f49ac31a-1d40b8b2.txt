# WriteWise Adoption & Habit Formation Measurement Plan

**Audience:** Founding Team
**Objective:** Isolate value drivers (Local Language vs. Core Editing) to inform monetization pivot decisions.

### 1. North Star Metric: "Weekly Value Sessions"
Reject "Downloads" (15k) and "Daily Logins" as vanity metrics; they rise regardless of product health.
**Definition:** A user who completes **three distinct editing sessions** in a 7-day window where at least one suggestion (grammar or tone) is **accepted**.
**Rationale:** This measures repeated value realization, not just curiosity. If this metric stagnates while downloads grow, the leak is in activation or retention, not acquisition.

### 2. Defining "Value Realized" for the Philippines Market
For students and professionals, "value" is not opening the app; it is **trust in the suggestion**.
*   **Core Action:** `suggestion_accepted` (Property: `suggestion_type`: [grammar, tone, clarity]).
*   **Habit Signal:** `document_exported` or `text_copied` within 2 minutes of an acceptance. This confirms the output was usable.
*   **Local Language Specific:** `tagalog_code_switch_detected` → `suggestion_accepted`. If users switch to Taglish but reject suggestions, the local model is failing.

### 3. Event Taxonomy (Instrument Only These)
Do not instrument "everything." Track only events that answer specific funnel questions.

| Event Name | Question Answered | Critical Properties |
| :--- | :--- | :--- |
| `onboarding_step_completed` | Where do users drop before the first edit? | `step_name`, `time_spent_sec` |
| `suggestion_viewed` | Are users seeing the premium value? | `suggestion_type`, `is_premium_locked` |
| `suggestion_accepted` | **Core Value:** Did they trust the AI? | `suggestion_type`, `language_context` (EN/Taglish) |
| `paywall_viewed` | Is the pricing model the barrier? | `days_since_install`, `session_count` |
| `trial_converted` | Did they pay? | `plan_type`, `source_campaign` |

**Identifier Seam:** Ensure a stable, pseudonymous `user_id` persists across sessions to track cohorts. Do not use device IDs alone if users switch phones. Route PII handling to privacy compliance protocols.

### 4. Isolating Local Language vs. Core Tools
To decide whether to pivot monetization or fix onboarding, segment the North Star by **Feature Cohort**:
*   **Cohort A (Core Only):** Users whose first 3 sessions contain *only* English grammar suggestions.
*   **Cohort B (Local Feature):** Users whose first 3 sessions include *at least one* Taglish/Local context interaction.

**Analysis Rule:** Compare the **Day-7 Retention** and **Trial Conversion Rate** of Cohort A vs. Cohort B.
*   If Cohort B retains 2x higher but converts poorly → The **value** is there (local language works), but the **paywall timing** or price point is wrong. *Action: Adjust monetization.*
*   If both cohorts churn before Day 3 → The **onboarding** fails to demonstrate value before the trial ends. *Action: Fix product flow, do not pivot pricing yet.*

### 5. Immediate Next Steps (This Week)
1.  **Verify Instrumentation:** Confirm `suggestion_accepted` fires with `language_context`. If this data is missing, current retention figures are `UNVERIFIED`.
2.  **Run Cohort Split:** Query Day-7 retention for users who accepted a Taglish suggestion vs. those who did not.
3.  **Decision Trigger:** If Local Feature users show >15% higher retention but <2% conversion, delay the monetization pivot and instead test moving the paywall from Day 7 to Day 14 for this specific segment.

*Note: No external benchmarks for "good retention" are applied; success is defined strictly by the delta between your local-feature users and core-only users.*
*All metrics must be read from your analytics platform; no values are fabricated here.*
