### Community Health Dashboard: Q3 Framework for AyudaTech

**North Star Metric:** Weekly Active Users (WAU) completing a "Resolved Value Loop" (a user posts a question AND receives an accepted answer or a reply marked "helpful" by the poster within 24 hours).
*Why:* Raw thread volume is vanity; it rises with noise. This metric only increases when real value is exchanged.

**The Funnel (Read Bottom-Up):**
Do not optimize for new threads (Acquisition) until the core loop holds. Diagnose in this order:
1.  **Retention of Value:** Do users who got help last month return to help others this month? (If this drops, the community is decaying regardless of thread count).
2.  **Activation:** Of new posters, what % receive a quality response within 24h?
3.  **Acquisition:** New registered users.

**Event Taxonomy (Instrument Only These):**
Every event below answers a specific question. Do not instrument "everything."
*   `question_posted` (Properties: `user_tenure`, `tags`) → *Question: Is noise coming from new or veteran users?*
*   `reply_posted` (Properties: `is_power_user`, `time_to_reply`) → *Question: Are our experts engaging or fleeing?*
*   `solution_accepted` OR `reply_marked_helpful` (Properties: `time_to_solution`) → *Question: Is the core value being delivered?*
*   `post_flagged` OR `post_deleted` (Properties: `reason_code`) → *Question: Is toxicity rising? (Automated proxy for quality)*
*   `user_session_end` (Properties: `did_not_return_days_7`) → *Question: Are users churning after bad experiences?*

**Automated Quality & Toxicity Proxies:**
Since manual reading is impossible at scale, use these leading indicators:
*   **The "Noise Ratio":** `(Total Replies) / (Solutions Accepted)`. If this rises while solutions stay flat, discussion is becoming circular noise.
*   **Power User Retention:** Cohort track your top 10% contributors. If their activity drops >10% MoM, the community is at immediate risk before general churn appears.
*   **Flag Velocity:** Track `posts_flagged_per_100_threads`. A sudden spike is an earlier signal of decay than user departure.

**Decision Rules for the CEO (The "At Risk" Thresholds):**
Do not hire 10 moderators based on activity growth alone. Use these tripwires:
*   **Green:** Noise Ratio < 5:1 AND Power User Retention > 80% → *Action: Maintain current team.*
*   **Yellow:** Noise Ratio rises 20% MoM OR Power User Retention dips 5-10% → *Action: Run a targeted experiment (e.g., stricter tagging rules) before hiring.*
*   **Red:** Noise Ratio > 10:1 OR Power User Retention drops >10% OR Flag Velocity spikes 2x → *Action: Community is "At Risk." Justify immediate headcount investment.*

**This Week's Steps:**
1.  **Define the "Resolved Value Loop"** in your database query today using existing `accepted_answer` or `upvote` data; calculate the baseline for the last 3 months.
2.  **Implement the `post_flagged` event** with reason codes if not already present; this is the only automated proxy for toxicity you need immediately.
3.  **Run a cohort analysis** on your top 50 power users: did their reply count drop last month despite the 20% thread increase? If yes, present this divergence to the CEO as the primary risk signal.

*Note: All benchmarks above are derived from your own historical baseline; no external industry averages are used. If `post_flagged` data is missing, that metric is UNVERIFIED until instrumented.*
