# TaskFlow Lean Analytics Plan

## Core Metrics (The "Vital 4")

Track these four metrics only. They directly answer: "What keeps users subscribed?"

| Metric | Definition | Why It Matters |
|--------|------------|----------------|
| **Weekly Active Users (WAU)** | Users who performed ≥1 core action in 7 days | Measures actual engagement, not just signups |
| **Feature Adoption Rate** | % of WAU who used a specific feature that week | Identifies which features drive retention |
| **Retention Cohort Rate** | % of users from signup week still active in week 4, 8, 12 | Shows if new features improve long-term stickiness |
| **Revenue Per Active User** | Monthly revenue ÷ monthly active users | Connects feature usage to actual paying behavior |

## Implementation Approach (20 hours/week dev capacity)

### Week 1-2: Minimal Setup
1. **Install PostHog** (free tier covers 5K users) - 4 hours
   - Auto-captures pageviews and basic clicks
   - No custom code needed for initial metrics

2. **Define 3-5 Core Events Only** - 8 hours
   ```
   - feature_used (property: feature_name)
   - subscription_started (property: plan_type)
   - subscription_renewed (property: plan_type)
   ```

3. **Create Simple Dashboard** - 4 hours
   - One page showing the 4 metrics above
   - Filter by feature_name property

### Week 3-4: Validation
- Verify events firing correctly
- Train founders to read the dashboard
- Document what each metric means for decisions

## Decision Framework for Quarterly Planning

Use this simple rule for each feature:

**Keep & Improve:** Feature adoption >30% among WAU AND used by 50%+ of renewing subscribers

**Investigate:** Feature adoption 10-30% but low correlation with renewal

**Deprecate:** Feature adoption <10% among WAU AND no correlation with renewal after 8 weeks of data

## Expected Outcomes by March 5

You will know:
- Which 1-2 features drive 80% of renewals
- Which features consume dev time but add no retention value
- Whether new users who adopt key features early are more likely to stay

## Maintenance Requirements

- **Weekly:** 15 minutes to review dashboard before team sync
- **Monthly:** 1 hour to check data quality (event counts match expectations)
- **Quarterly:** 2 hours to add/remove events based on new features

## Critical Success Factors

1. **Resist adding more events.** Every new event increases maintenance burden.
2. **Focus on adoption, not usage frequency.** One meaningful use per week signals value better than 100 trivial clicks.
3. **Tie everything to renewal.** If a feature doesn't correlate with subscription_renewed within 90 days, question its priority.

This approach gives you actionable insights within 3 weeks while requiring less than 5 hours/month ongoing maintenance. The constraint of tracking only 3-5 events forces discipline in identifying what truly matters for TaskFlow's growth.

*Note: PostHog's free tier includes session replay, which can supplement these metrics when you need qualitative context on why a feature isn't adopted.*
