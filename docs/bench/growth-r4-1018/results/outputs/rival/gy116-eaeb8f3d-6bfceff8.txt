# Data Remediation & Standardization Strategy for Series B Due Diligence

**Objective:** Standardize event naming to reconstruct a six-month historical dataset with auditor-grade integrity, ensuring continuous trend lines for the November 30 funding target.

### Phase 1: Mapping & Schema Definition (Days 1–3)
Establish a single source of truth before touching data.
*   **Standard Name:** Adopt `add_to_cart` (lowercase, underscore) as the canonical event name across all platforms (GA4, Mixpanel, Data Warehouse).
*   **Mapping Logic:** Create a definitive lookup table mapping legacy variants (`addToCart`, `item_added`) to the standard name.
*   **Documentation:** Record this mapping in a version-controlled schema registry. Auditors require evidence of the transformation logic, not just the result.

### Phase 2: Historical Reconstruction (Days 4–14)
Rebuild the dataset in your data warehouse (e.g., BigQuery, Snowflake) rather than overwriting raw logs.
*   **Backfill Script:** Execute a SQL transformation that unions raw data streams, applying the mapping logic to normalize event names retroactively.
*   **Continuity Check:** Validate that the sum of normalized events equals the sum of original variant events for every day in the six-month window. This proves no data was lost, only renamed.
*   **Trend Verification:** Plot the reconstructed series against the original fragmented data. The aggregate trend line must remain smooth; any artificial spikes indicate a mapping error (e.g., double-counting).
*   **Output:** Generate a new table, `fct_events_normalized`, covering the full six-month period. Do not alter the raw ingestion tables; keep them as the "audit trail."

### Phase 3: Forward-Looking Implementation (Days 15–18)
Prevent recurrence immediately.
*   **Tag Management:** Update Google Tag Manager (or equivalent) to fire only `add_to_cart`. Remove legacy tags.
*   **Validation:** Use DebugView and data layer inspectors to confirm the new convention fires correctly on all devices.
*   **Governance:** Implement a pre-deployment check requiring all new events to match the naming convention.

### Phase 4: Auditor Handoff & Transition Narrative (Days 19–21)
Prepare the defense for due diligence starting October 15.
*   **The "Data Integrity Memo":** Draft a one-page document for the CFO and auditors explaining:
    1.  **The Issue:** Inconsistent naming previously fragmented the funnel.
    2.  **The Fix:** A deterministic mapping was applied to unify the data.
    3.  **The Proof:** Reconciliation totals (Pre-fix sum = Post-fix sum) confirm accuracy.
*   **Handling the Gap:** Explicitly state that historical data has been *restated* for consistency. Present two views in your dashboard:
    *   *Reported View:* The normalized, continuous trend line for investor decks.
    *   *Technical View:* A footnote linking to the raw, unmodified logs for verification.
*   **Narrative Control:** Frame this not as "corrupted data" but as "data maturation." Proactively disclosing the remediation demonstrates rigorous financial hygiene, which increases investor confidence rather than diminishing it.

### Deliverable Timeline
*   **Oct 1–10:** Execution of Phases 1–3.
*   **Oct 11–14:** Final validation and memo preparation.
*   **Oct 15:** Ready for due diligence with a clean, defensible dataset.

**Note:** Do not attempt to merge data inside GA4's interface; perform the normalization in your warehouse to preserve raw granularity. Ensure the CFO signs off on the mapping logic before the backfill script runs.
