# LearnHub Pilot Tracking Plan (August 20 Launch)

**Objective:** Validate the "lesson completion" conversion hypothesis with 50 schools while minimizing engineering load.
**Strategy:** Track only events that directly measure the primary business risk (do completions drive sales?) and operational health. Defer "learning quality" metrics until the core funnel is proven.

### 🚨 Non-Negotiable: Day One (August 20)
*Implement these three events immediately. They form the minimum viable dataset to calculate your core conversion rate and answer the Series A question.*

| Priority | Event Name | Trigger Point | Critical Properties | Why This Matters |
| :--- | :--- | :--- | :--- :--- |
| **1** | `school_onboarded` | Admin successfully creates first class/roster | `school_id`, `student_count`, `onboarding_method` | **Activation.** Without a school actually setting up, no learning happens. This is your top-of-funnel health metric. |
| **2** | `lesson_completed` | Student marks a lesson as "Done" or passes final quiz | `lesson_id`, `course_id`, `time_spent_seconds`, `attempt_count` | **The Hypothesis.** This is your assumed north star. You must capture this cleanly to correlate with future payments. *Note: Include `time_spent` as a property here to satisfy the content team without building a separate complex event.* |
| **3** | `subscription_purchased` | School admin completes payment/contract signing | `school_id`, `plan_type`, `contract_value`, `lessons_completed_prior` | **The Outcome.** You cannot measure conversion rates without the denominator (purchases). Capturing `lessons_completed_prior` allows immediate cohort analysis. |

### ⏳ Deferred: Phase Two (September 1)
*Once the pilot proves users are completing lessons and buying, implement these to optimize content quality and engagement depth.*

| Priority | Event Name | Reason for Deferral |
| :--- | :--- | :--- |
| **4** | `video_interaction_detailed` | **Why Wait:** The content team's desire to track "time watching video" is valid for *product improvement*, but secondary to *business validation* in August. If users aren't completing lessons, granular video pause/play data is noise. <br>**Implementation:** In September, track specific video pauses, rewinds, and drop-off points to optimize content, not just completion. |
| **5** | `feature_adoption_granular` | **Why Wait:** Tracking usage of secondary features (discussion boards, note-taking, peer review) distracts from the primary "Complete → Buy" loop. <br>**Implementation:** Once the core loop is stable, track which auxiliary features correlate with higher retention or upsell potential. |

### Implementation Notes for CTO
1.  **Data Layer Strategy:** Do not build custom timers for video yet. Pass the platform's native `time_spent` value as a property on the `lesson_completed` event. This satisfies the need for duration data with zero extra engineering overhead for the August sprint.
2.  **Validation Rule:** The instrumentation sprint is successful only if you can reproduce the exact "Total Lessons Completed" count from the database using only the analytics stream. If these numbers do not match within 2%, the data is untrustworthy for investor reporting.

**Decision Logic:** We are prioritizing *conversion validation* over *pedagogical optimization*. If lesson completion does not correlate to sales by September, no amount of video interaction data will save the business model. Prove the model first; optimize the learning experience second.
