# Developer Experience Leading Indicators for Nexus APIs

To justify the $200k investment and measure true integration health beyond uptime, track these four leading indicator categories. These metrics connect documentation engagement to production success, addressing your hypothesis about the 'Quick Start' guide and silent failures.

## 1. Activation Velocity (Time-to-Hello-World)
*Measures how quickly teams move from reading to doing.*
- **Metric:** Median time from first 'Quick Start' page view to first non-trivial API call (defined below).
- **Why it matters:** Validates your hypothesis that guide readers succeed faster. A decreasing trend proves the new portal reduces friction.
- **Target:** Reduce median time by 20% quarter-over-quarter.

## 2. Integration Depth Score (IDS)
*Replaces simple 200 OK counts with a weighted complexity score.*
- **Definition:** Assign weights to endpoints based on complexity (e.g., `GET /status` = 1pt, `POST /webhooks` = 5pts, `OAuth flow` = 10pts). Sum points per team over a rolling 7-day window.
- **Metric:** Average IDS per active team; % of teams reaching "Activated" threshold (e.g., 50 points) within 48 hours of signup.
- **Why it matters:** Distinguishes between ping-tests and real integration work. Rising IDS indicates deepening product stickiness.

## 3. Silent Failure Detection Rate
*Captures the unknown variable of production issues you don't see.*
- **Metric A:** Client-side error rate (4xx/5xx) normalized by total calls, segmented by SDK version.
- **Metric B:** "Zombie Integration" rate: Teams with successful auth but zero data-transferring calls (>10KB payload) after 7 days.
- **Metric C:** Documentation bounce-back: Users viewing a specific endpoint reference >3 times in 1 hour followed immediately by an error log entry (correlate via timestamp/user-ID).
- **Why it matters:** Identifies where developers are stuck without filing tickets. High zombie rates suggest the guide creates false confidence.

## 4. Self-Service Efficiency
*Quantifies the 15% ticket reduction in behavioral terms.*
- **Metric:** Ratio of documentation searches to support tickets per 1,000 active teams.
- **Metric:** Code snippet copy-to-execution rate: % of users who copy a snippet and successfully execute a call with that pattern within 30 minutes.
- **Why it matters:** Proves the portal is solving problems before they become tickets. Low copy-to-execution rates indicate snippets are outdated or confusing.

## Implementation Notes for Sarah
Do not track "time on page" or raw "snippet copies" as primary metrics; these are vanity numbers easily gamed and poorly correlated with success. Instead, instrument your API gateway to tag calls with a `documentation_referrer` header (passed from your docs site) to directly attribute production calls to specific guide sections. This links the $200k investment directly to revenue-generating integration activity.

**Immediate Action:** Define "non-trivial call" as any request >1KB payload or using write-methods (POST/PUT), excluding health checks. Use this definition for all Activation Velocity reporting.
