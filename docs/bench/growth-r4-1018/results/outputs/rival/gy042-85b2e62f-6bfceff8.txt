# Diagnostic Plan: CloudVault Onboarding Drop-off

**Objective:** Isolate whether the 13% increase in drop-off is driven by mobile latency (technical) or the permission screen friction (behavioral) by Friday.

### 1. Immediate Data Slices to Pull (Analytics/BI Team)
Request these specific segments from your analytics platform (GA4, Mixpanel, etc.) covering Oct 3rd–Present vs. Sept 1st–Oct 2nd:

*   **Device × Step Funnel:** Break down the conversion rate for *every* step of the new flow, segmented by **Mobile vs. Desktop**.
    *   *Hypothesis Check:* If mobile drop-off spikes specifically at the permission screen while desktop remains stable, it suggests a UX friction issue. If mobile drop-off occurs *before* the screen loads or across multiple steps, it points to latency.
*   **Time-on-Step Analysis:** Calculate the median time spent on the permission screen.
    *   *Hypothesis Check:* A sudden increase in time spent followed by a drop-off indicates users are reading/hesitating (UX friction). An immediate exit (time < 2 seconds) suggests a crash, render failure, or perceived performance lag.
*   **Technical Performance Metrics:** Filter for **Page Load Time** and **Time to Interactive (TTI)** on the permission screen, segmented by device and connection type (4G vs. WiFi).
    *   *Hypothesis Check:* If TTI on mobile 4G exceeds 3 seconds and correlates with higher drop-off, latency is the primary driver.
*   **Error Rate by Event:** Query for JavaScript errors or API timeouts specifically triggered on the permission screen for mobile user agents.

### 2. Key Stakeholders to Interview
*   **Lead Mobile Engineer:** Ask for recent deploy logs affecting the permission component. Specifically inquire about new library dependencies or API calls introduced on Oct 3rd that might block rendering on older iOS/Android versions.
*   **Customer Support Lead:** Request a qualitative summary of tickets tagged "onboarding" or "mobile issue" since Oct 3rd. Look for keywords like "stuck," "loading," or "scary request."
*   **Product Designer:** Review the copy and visual hierarchy of the permission request. Did the new flow explain *why* permissions are needed, or did it just present the system dialog immediately?

### 3. Rapid Validation Tactics (No A/B Test Required)
To distinguish technical lag from psychological friction without splitting traffic:

*   **The "Skeleton Screen" Test:** If latency is the suspect, have engineering implement a temporary "skeleton" loading state or progress bar on the permission screen for mobile only. If drop-off decreases despite the underlying logic remaining unchanged, the issue was perceived wait time, not the permission request itself.
*   **Session Replay Sampling:** Use tools like FullStory or Hotjar to watch 20–30 mobile sessions where users dropped off at this step.
    *   *Look for:* "Rage clicks" (indicates unresponsiveness/latency) vs. "Hesitation then close" (indicates friction/fear).
*   **Intercept Survey:** Deploy a one-question exit-intent popup on the permission screen for mobile users attempting to leave: *"What stopped you from continuing? (A) Page is loading slowly, (B) I'm not ready to grant permissions, (C) Other."* Even a 5% response rate (100 users/day) will provide directional validation within 24 hours.

### 4. Decision Framework for Friday
*   **If Mobile Drop-off >> Desktop Drop-off AND High TTI/Errors:** Prioritize the engineering fix for latency. Rollback is unnecessary; optimize performance.
*   **If Mobile Drop-off ≈ Desktop Drop-off AND High Hesitation Time:** The permission copy/design is the culprit. Iterate on the value proposition explanation before the system dialog triggers.
*   **If Drop-off is uniform across devices with no technical errors:** The new flow itself is fundamentally flawed. Prepare a rollback plan or a simplified "guest mode" alternative.

Focus your squad's effort on the **Device × Step Funnel** and **Session Replays** first; these two data sources will likely provide 80% of the answer within 4 hours.

*Note: Ensure your analytics "observation window" matches the exact dates of the launch to avoid skewing baseline comparisons.*
*Do not attempt to fix the copy until you have ruled out the mobile latency hypothesis with the TTI data.*
