# Wanderlust Bookings: Post-Launch Funnel Tracking Specification

**Audience:** Marketing Team & Product Operations
**Effective Date:** April 5 (Launch Day)

## 1. The North Star & Input Metrics
*   **North Star Metric:** Weekly Confirmed Bookings (completed transactions where payment is captured).
    *   *Why:* Pageviews and "started checkouts" are vanity; revenue only exists when the booking is confirmed.
*   **Primary Input Metric:** Checkout Completion Rate (Confirmed Bookings / Checkout Starts).
    *   *Baseline Warning:* Do not use the 2019 "65% drop-off" figure as a target. Market dynamics and travel restrictions have shifted; that benchmark is `UNVERIFIED` for the current context. We will establish a new baseline from Day 1 data.

## 2. Defined Funnel Stages (Event Taxonomy)
Instrument **only** these five events. Each must answer a specific friction question. Do not instrument intermediate clicks unless a specific hypothesis exists.

| Stage | Event Name | Question Answered | Success Criteria (Day 1) |
| :--- | :--- | :--- | : |
| **1. Intent** | `checkout_started` | Did the user commit to buying after seeing the price? | >0% of landing page visitors. |
| **2. Details** | `traveler_info_submitted` | Is the form length or complexity causing abandonment? | >80% of `checkout_started`. |
| **3. Options** | `add_ons_selected` | Are users confused by insurance/seat upsells? | >60% of `traveler_info_submitted`. |
| **4. Payment** | `payment_info_entered` | Is the payment gateway trusted and functional? | >50% of `add_ons_selected`. |
| **5. Conversion** | `booking_confirmed` | Did the transaction finalize? | >40% of `payment_info_entered`. |

*Note: If any stage drops below 50% of the previous stage, that is the primary friction point to investigate.*

## 3. Handling Exits and Returns (Session Logic)
*   **The Problem:** A 30-minute session timeout will artificially inflate drop-off rates if a user steps away to find a passport or credit card.
*   **The Solution:** Implement a **Stable User Identifier** (pseudonymous ID) persisted via cookie/local storage.
    *   **Funnel Attribution:** Attribute the conversion to the original `checkout_started` event even if it occurs days later, provided it happens within a **7-day attribution window**.
    *   **Dashboard View:** Display two metrics:
        1.  *Session-Based Completion:* (Strict 30-min window) – Measures immediate UX friction.
        2.  *User-Based Completion:* (7-day window) – Measures true conversion potential.
    *   *Compliance Note:* Ensure this ID is pseudonymous. Route any PII handling (consent, retention limits) to the privacy compliance protocol; do not store raw names/emails in analytics events.

## 4. External Correlation Factors
Do not build complex real-time feeds for these yet. Instead, tag events with static properties at the time of the session to enable later correlation:
*   `destination_region`: To correlate with specific travel restriction news.
*   `currency_code`: To correlate with FX volatility.
*   `traffic_source`: To distinguish between organic search (high intent) vs. paid social (lower intent).

## 5. This Week's Actions
1.  **Engineering:** Implement the five events above with the pseudonymous user ID before April 5. Verify tags in a staging environment.
2.  **Analytics:** Build the dashboard showing the "User-Based Completion" funnel alongside the "Session-Based" view.
3.  **Decision Rule:** If `payment_info_entered` to `booking_confirmed` drops below 30% in the first 48 hours, trigger an immediate manual test of the payment gateway; do not wait for weekly reports.
