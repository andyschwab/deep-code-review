# WriteWise Adoption & Habit Formation Measurement Plan

**Audience:** Founding Team
**Objective:** Isolate value drivers (Local Language vs. Core Editing) to inform monetization pivot decisions.

### 1. North Star Metric: "Weekly Value Sessions"
Reject "Downloads" (15k) and "Daily Logins" (2.2k) as vanity metrics; they rise regardless of user benefit.
**Definition:** A user who completes **three distinct editing sessions** in a 7-day window where at least one suggestion (grammar or localization) is **accepted**.
**Why:** This measures repeated *value realization*, not just app presence. If this metric stagnates while downloads grow, the product has a retention leak, not an acquisition problem.

### 2. Defining "Value Realized" for this Market
For students and professionals in the Philippines, "value" is not opening the app; it is **trust in the output**.
**Specific Actions Counting as Value:**
*   **Acceptance Rate > 30%:** User accepts at least 30% of suggested edits in a session (indicates relevance).
*   **"Export/Share" Event:** User copies text or exports the document post-edit (indicates the work is finished and usable).
*   **Local Feature Usage:** Specific trigger of "Taglish/Local Context" checks followed by an acceptance.

### 3. Event Taxonomy: Isolating Local vs. Core Impact
Instrument only these events to answer specific questions. Do not track "clicks" without a hypothesis.

| Event Name | Question Answered | Properties to Capture |
| :--- | :--- | :--- |
| `suggestion_viewed` | Did the user see the help? | `suggestion_type` (core_grammar, local_context, tone), `session_id` |
| `suggestion_accepted` | Did the user trust the help? | `suggestion_type`, `time_to_accept` (speed indicates confidence) |
| `document_exported` | Was the work completed? | `suggestions_accepted_count`, `feature_mix_used` |
| `trial_day_7_reached` | Did they survive the window? | `total_value_sessions` (count of North Star events in first 7 days) |

**The Identifier Seam:** To track cohorts across the 7-day trial, you must implement a **stable, pseudonymous user ID** persisted across reinstalls/sessions. Do not use raw emails/phones here; route PII mapping to your privacy compliance protocol.

### 4. Reading the Funnel (Bottom-Up Diagnosis)
Do not pour more ad spend into Manila/Cebu until the leak is fixed. Read in this order:
1.  **Retention:** Of the 2,200 DAU, what % return for a second "Value Session" within 3 days? If <20%, the core value proposition is failing immediately.
2.  **Activation:** Of new downloads, what % reach *one* "Value Session" in the first 24 hours? If low, the onboarding flow hides the "aha" moment.
3.  **Isolation Analysis:** Compare `suggestion_accepted` rates for `local_context` vs. `core_grammar`.
    *   *Hypothesis A:* If `local_context` acceptance is 2x higher than `core_grammar`, the barrier is likely **pricing/perception** of generic tools (users don't see unique value in standard grammar).
    *   *Hypothesis B:* If both are low, the barrier is **onboarding** (users aren't seeing *any* suggestions or don't understand how to use them).

### 5. Decision Framework for the Founders
Use this week's data to trigger one of these actions:
*   **Pivot Monetization:** If `local_context` acceptance is high but conversion is low, the free trial is too short to demonstrate the *unique* local value. **Action:** Extend trial to 14 days *only* for users who trigger local features.
*   **Fix Onboarding:** If `suggestion_viewed` is high but `suggestion_accepted` is low (<10%), users don't trust the AI. **Action:** Redesign the first session to force a high-confidence "quick win" edit.
*   **Stop Acquisition:** If "Weekly Value Sessions" is <5% of downloads, pause social campaigns. Fix the bucket before adding water.

**This Week's Step:**

2.  Run a cohort query: "Of users who accepted a *local* suggestion in Day 1, what % returned on Day 3?" vs. those who only used *core* tools.
3.  If the local cohort retention is >20% higher, present the case to extend the trial specifically for that segment.
