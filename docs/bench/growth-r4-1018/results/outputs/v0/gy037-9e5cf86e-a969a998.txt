# Referral Program Analysis Plan for SwiftRide Finance Director

**Objective:** Define the measurement logic to validate the hypothesis that referred drivers yield higher Lifetime Value (LTV) than organic drivers, ensuring bonus spend is justified by incremental profit.

### 1. North Star Metric
**Incremental Net Revenue per Referred Driver.**
This measures the additional revenue generated by a referred driver compared to an organic driver over the same tenure, minus the cost of the referral bonus. We reject "Total Referrals" or "Bonus Claims" as primary metrics; these are vanity figures that rise regardless of business health. The program succeeds only if the *net* value is positive.

### 2. Attribution Logic: The "First Earned Dollar" Rule
To resolve the open question on timing and prevent fraud, we attribute success based on **verified economic activity**, not account creation.
*   **Trigger Event:** A referral is considered "activated" only when the referred driver completes their **first paid trip** where the fare exceeds a minimum threshold (e.g., $5.00) and passes initial fraud checks (valid device ID, unique payment method).
*   **Rationale:** Attributing at account signup invites fake accounts. Attributing at an arbitrary earnings threshold (e.g., $500) delays signal too long. The first valid trip proves the user is real and capable of generating value. The bonus is released only after this trigger.

### 3. Core Funnel & Event Taxonomy
We will instrument only the events required to answer specific business questions. Every event includes a stable, pseudonymous driver ID to track cohorts without exposing PII.

| Event Name | Question Answered | Properties Recorded |
| :--- | :--- | :--- |
| `referral_invite_sent` | How many existing drivers are participating? | Inviter ID, channel (SMS/App), date. |
| `referral_link_clicked` | Is the invite reaching potential drivers? | Invitee device fingerprint (hashed), date. |
| `referral_signup_completed` | Are clicks converting to registrations? | Invitee ID, source campaign. |
| `referral_first_trip_completed` | **The Activation Point.** Did the new driver generate value? | Driver ID, fare amount, trip distance, time since signup. |
| `referral_bonus_paid` | What is the immediate cash outflow? | Driver ID, bonus amount, fraud check status. |

### 4. Measuring Incremental Value (The Comparison)
We cannot assert a benchmark for "good" LTV. We must compare referred drivers against our own baseline.
*   **Cohort A (Referred):** Drivers who activated via the referral loop starting Dec 1.
*   **Cohort B (Organic Control):** Drivers who signed up in the same geographic zones during the same period but *without* a referral code.
*   **The Calculation:** Track both cohorts weekly for 12 weeks.
    *   *Metric:* Average Gross Bookings per Driver per Week.
    *   *Incremental Lift:* (Avg Bookings Cohort A) − (Avg Bookings Cohort B).
    *   *ROI:* (Incremental Lift × Commission Rate) − (Referral Bonus Cost).
*   **Decision Rule:** If the cumulative incremental commission exceeds the bonus cost by Week 8, the program scales. If not, we pause to adjust the bonus amount or targeting.

### 5. Fraud Detection & Guardrails
Fraud manifests as high signup velocity with zero retention. We will monitor these guardrail metrics weekly:
*   **Fake Account Ratio:** Percentage of referred signups that never complete a first trip within 7 days. If this exceeds the organic no-show rate by >20%, we suspect bot activity.
*   **Self-Referral Cluster:** Count of unique payment methods or device IDs linked to multiple driver accounts. Any cluster >2 triggers a manual audit before bonus payout.
*   **Churn Spike:** If referred drivers churn (stop driving) faster than organic drivers after receiving the bonus, the incentive is attracting low-quality supply.

### This Week's Steps

2.  **Establish Baseline:** Run a query on the last 90 days of organic driver data to calculate the current average Week 1-4 retention and earnings; this is the only valid benchmark for success.
3.  **Set the Tripwire:** Agree on a specific "Fake Account Ratio" threshold (e.g., 15%) that automatically pauses the bonus payout pending review.

*Note: All user identifiers used for cohort tracking must be pseudonymized; raw PII handling follows existing privacy compliance protocols. No external industry benchmarks are used; success is defined strictly by outperforming SwiftRide's own organic baseline.*
