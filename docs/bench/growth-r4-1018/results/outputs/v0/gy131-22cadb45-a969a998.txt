**Recommendation: Halt Global Rollout; Prioritize "Successful Resolution" Over Click-Through Rate**

Do not proceed with the global rollout based on current data. The divergence between rising Click-Through Rate (CTR) and plummeting dwell time (4m → 90s) is a classic signal of **misleading relevance** (clickbait titles) rather than efficiency. While your hypothesis suggests users find answers faster, a 62% drop in time-on-page is too severe to attribute solely to speed without verifying that the user's intent was actually satisfied. CTR is a vanity metric in this context; it measures attraction, not value.

To determine true impact, shift your North Star from "Search Engagement" to **"Search Resolution."** Implement the following three specific measurements immediately:

1.  **Zero-Result & Quick-Back Rate (The Bounce Signal)**
    *   **What to measure:** The percentage of users who click a result and return to the search results page (SERP) within 10 seconds, or who immediately initiate a new search query.
    *   **Interpretation:** If this rate has increased post-launch, the new algorithm is surfacing misleading titles. Users click, realize the content is irrelevant, and bounce. This confirms the "misleading title" fear.
    *   **Action Threshold:** If quick-back rate > 15%, the ranking logic is broken. Fix title-match relevance before scaling.

2.  **Task Completion Proxy (The Utility Signal)**
    *   **What to measure:** Post-search actions indicating resolution, such as copying text from the destination page, clicking a "was this helpful?" button, or navigating to a related "how-to" guide without returning to search.
    *   **Interpretation:** If dwell time is down but these completion actions are up, your "efficiency" hypothesis is correct: users are getting answers faster. If both dwell time and completion actions are down, utility has degraded.
    *   **Action Threshold:** Only roll out globally if resolution proxies remain flat or improve despite lower dwell time.

3.  **Cohort Retention on Search (The Long-Term Signal)**
    *   **What to measure:** The percentage of users who return to use the search function again within 48 hours of their initial session.
    *   **Interpretation:** If users feel the search failed them (due to misleading clicks), they will stop using the internal tool or revert to asking colleagues. A drop in search retention indicates a loss of trust in the system.

**Decision Framework for Leadership:**
*   **Ship:** Only if "Quick-Back Rate" is stable AND "Task Completion Proxies" are rising. This proves efficiency.
*   **Extend/Iterate:** If "Quick-Back Rate" is high. The algorithm is optimizing for clicks, not answers. Re-weight ranking signals to penalize high-bounce pages.
*   **Stop:** If "Search Retention" drops. The tool is losing user trust.

**This Week's Steps:**
1.  Instrument the "Quick-Back" event (click → return <10s) for the October 15th cohort vs. the prior baseline.
2.  Add a binary "Did this solve your problem?" prompt to 5% of search sessions to gather ground-truth data on resolution.
3.  Recompute the lift using "Resolutions per Search Session" as the primary metric; if this number is flat or negative, the 18% CTR is noise.

*Note: Do not invent a "good" dwell time benchmark; compare these metrics strictly against your pre-October 15th baseline. Ensure any user-level tracking for cohorts uses pseudonymous IDs, routing PII handling to your privacy compliance protocol.*
