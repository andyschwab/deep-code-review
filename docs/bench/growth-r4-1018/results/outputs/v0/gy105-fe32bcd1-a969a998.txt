### Diagnostic Plan: Loan Approval Funnel Drop-off

**1. Quantitative Segmentation Strategy**
To isolate whether the friction stems from the *count* of documents or *file constraints*, segment the abandonment data at the document upload stage by the following dimensions:
*   **Device & Connection:** Mobile vs. Desktop, and estimated connection speed (4G vs. Wi-Fi). If drop-offs correlate strongly with mobile on slower connections, file size limits are the likely culprit.
*   **File Attributes:** Segment by file type (PDF vs. Image) and estimated file size buckets. A spike in abandonment immediately after the first upload attempt for large files indicates size limits; abandonment before the first attempt suggests psychological friction regarding the *number* of required IDs.
*   **Error Logs:** Correlate abandonment timestamps with specific client-side error codes (e.g., "File Too Large," "Unsupported Format," "Timeout").
*   **User Cohort:** Compare new applicants (unfamiliar with the process) vs. returning applicants (if applicable) to see if the friction is novelty-based or universal.

**2. Event Taxonomy & Instrumentation**
Ensure your analytics pipeline captures these specific events to answer named questions:
*   `upload_started`: Did the user open the file picker? (Measures initial hesitation).
*   `upload_failed`: Did the system reject the file? (Captures technical friction).
*   `upload_retry`: Did the user try again after a failure? (Indicates intent vs. frustration).
*   `step_abandoned`: Did the user leave the page after >3 minutes? (Captures "giving up").
*   *Note:* Verify that a stable, pseudonymous user ID links these events across sessions to distinguish between a single user struggling versus many users failing once.

**3. Qualitative Complement**
Quantitative data reveals *where* they stop; qualitative data reveals *why*.
*   **Session Replays:** Watch 20–30 recordings of sessions that abandoned at the upload stage. Look for "rage clicks," repeated failed uploads, or long pauses before selecting files.
*   **Exit Survey:** Trigger a one-question micro-survey on the abandonment page: "What stopped you from finishing?" with options: "File too big," "Don't have ID ready," "Too many steps," or "Other."
*   **Support Ticket Analysis:** Tag and review recent support chats mentioning "upload," "ID," or "error" since November 5th.

**4. Recommended Action Plan for the CLO**
*   **Immediate Hypothesis Test:** If data points to file size, implement a temporary increase in size limits or add client-side compression. If the issue is the *number* of IDs, A/B test a flow allowing "Provisional Approval" with one ID, requesting the second post-approval.
*   **Guardrail Metric:** Monitor fraud rates closely if reducing ID requirements. Any gain in conversion must not compromise risk standards.
*   **North Star Alignment:** Re-align the team's focus from "Application Volume" (vanity) to "Funded Loans per Qualified Applicant" (value). The 30% volume increase is irrelevant if the conversion leak wastes marketing spend.
