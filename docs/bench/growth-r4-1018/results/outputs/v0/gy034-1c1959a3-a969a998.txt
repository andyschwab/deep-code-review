### Diagnostic Framework: DataVista Dashboard Update (Oct 3 Launch)

**Objective:** Determine if the 12% DAU drop is a navigation friction issue (fixable) or a fundamental workflow breakage (requires rollback) by Friday.

**1. Immediate Triage Metrics (Monitor Daily)**
*   **Core Action Completion Rate:** Define the single "value" action (e.g., "Report Generated" or "Dashboard Viewed"). Compare the rate of *Sessions with Core Action* vs. *Total Sessions* for the post-launch cohort against the pre-launch baseline.
    *   *Decision Rule:* If session count is stable but core action completion dropped >15%, the workflow is broken. If both dropped equally, users cannot find the entry point.
*   **Navigation Funnel Drop-off:** Instrument the specific path: `Login` → `New Nav Click` → `Report Selection` → `Report Load`.
    *   *Decision Rule:* Identify the specific step with >40% abandonment compared to historical averages. This isolates whether the confusion is at the menu level or the report-loading level.
*   **Power User Segmentation:** Filter DAU by users with >20 sessions/month historically.
    *   *Decision Rule:* If power user retention of the core action is <80% of their baseline while new users are stable, the update broke advanced workflows. Rollback is likely required. If power users are stable but new users dropped, it is a discoverability issue.

**2. Qualitative & Support Signal Correlation**
*   **Ticket Topic Clustering:** Categorize the 40% increase in support tickets into "Navigation/Findability" vs. "Functionality/Error."
    *   *Decision Rule:* If >60% are "Cannot find X," focus on UI fixes. If >60% are "Feature Y is broken/slow," investigate technical regression immediately.
*   **Session Replay Sampling:** Review 20 random sessions from the dropped cohort where the user logged in but did not complete the core action.
    *   *Observation Goal:* Confirm if users are "rage clicking" the old navigation paths or exiting immediately after landing.

**3. Experimentation & Action Plan**
*   **A/B Test (If traffic allows):** Route 10% of traffic to the legacy dashboard interface.
    *   *Metric:* Compare Core Action Completion between Legacy vs. New.
    *   *Decision:* If Legacy outperforms New by >10% statistically significant margin within 48 hours, prepare rollback.
*   **In-App Interception:** Deploy a one-question micro-survey to users who exit without completing a core action: "Did you find what you were looking for? (Yes/No/Where did you get stuck?)"

**This-Week Steps for the CTO:**
1.  **Today:** Query the `Core Action Completion Rate` segmented by "Power Users" vs. "Casual Users" for Oct 3–5 vs. Sept 26–29. If Power User completion is down >20%, draft the rollback plan immediately.
2.  **Tomorrow:** Tag support tickets from the last 48 hours by "Navigation" vs. "Broken Feature." If "Broken Feature" dominates, halt feature work and assign engineering to bug fixes.
3.  **Thursday:** Review the A/B test results (Legacy vs. New). If the Legacy variant shows significantly higher value delivery, execute rollback by EOD Friday. If the gap is negligible, extend the monitoring period with a guided tooltip fix.

*Note: Do not rely on raw DAU alone; it is a vanity metric in this context. The "Core Action Completion" is the only verified signal of value delivery.*
*All metrics must be compared against your internal baseline; no external benchmarks apply to this specific workflow change.*
