### Barn Buddy Beta Event Taxonomy & Measurement Plan

**North Star Metric:** Weekly Active Collaborators (users who both view a peer's case AND leave a verified comment within 24 hours).
*Rationale:* This matches your definition of "successful interaction." Vanity metrics like total pageviews or raw signups are excluded as they do not prove value delivery.

**Proposed Event Hierarchy (MVP Stage)**
Instrument only these three events to answer specific questions. Do not track "bookmarking" yet; it is an unverified signal that risks inflating engagement data without proving collaboration.

| Event Name | Trigger Condition | Question Answered | Properties to Capture |
| :--- | :--- | :--- | : |
| `case_viewed` | User opens a peer's case file. | Is the content discoverable and relevant enough to click? | `case_category` (exotic/common), `user_segment`, `time_since_post` |
| `comment_submitted` | User posts a comment that passes verification. | Did the user contribute value? | `case_category`, `comment_length`, `time_since_view` |
| `collaboration_completed` | `case_viewed` + `comment_submitted` occur within 24h for the same case. | Did a genuine collaboration loop close? (This is your North Star input) | `case_category`, `user_segment`, `days_since_install` |

**Handling Data Segments & Weighting**
Do not apply arbitrary weights (e.g., "exotic cases count 2x") to your core metrics. This distorts the truth of user behavior. Instead:
1.  **Tag, Don't Weight:** Attach the `case_category` property to every event.
2.  **Analyze Cohorts Separately:** Report retention and collaboration rates for "Exotic Livestock" users vs. "Common Pet" users as distinct lines. If exotic cases drive higher retention, that is a finding to act on, not a factor to bake into the metric calculation.
3.  **Bookmarking Decision:** Exclude `bookmark_clicked` from the beta. If users bookmark but never comment, your current "collaboration" metric correctly identifies this as a failure to convert. Add bookmark tracking only if the beta shows users struggling to return to cases *before* commenting.

**Reading the Funnel (Bottom-Up)**
For the April 2 review, diagnose in this order:
1.  **Retention:** Of the 500 beta users, what % complete a `collaboration_completed` event in Week 2? (Compare this to your existing platform baseline; do not use external benchmarks).
2.  **Activation:** Of those who view a case, what % submit a comment?
3.  **Acquisition:** Are enough users viewing cases to feed the funnel?

**Experiment Rigor Note**
If you A/B test features during beta (e.g., changing the comment button color), pre-commit to a sample size and read the result once at the end. Do not stop early because "p < 0.05" on day 2; this is peeking and creates false wins.

**This Week's Steps**
1.  **Implement:** Instrument the three events above with the specified properties by March 10. Ensure the `user_id` is stable across sessions but pseudonymized for privacy compliance.
2.  **Baseline:** Query your existing database to establish the current weekly retention rate for your core platform action. This is the only valid benchmark for comparing Barn Buddy's success.
3.  **Define Tripwire:** Set a go/no-go criterion for the full launch: If Week 2 retention for the "Exotic" cohort is lower than the "Common" cohort by >15%, pause the exotic content push and investigate content quality before scaling.
