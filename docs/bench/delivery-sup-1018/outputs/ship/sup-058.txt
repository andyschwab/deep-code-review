### Delivery Plan: Adaptive Image Delivery (Aurum Catalog)

**Objective:** Implement network-aware image scaling for connections <500kbps while preserving luxury fidelity on premium devices. Deploy before holiday rush with graceful degradation.

#### 1. Lanes & Parallelism
*   **Lane A (Logic Layer - Builder):** Implement client-side network detection and asset switching logic. Must integrate with existing Helix CDN hooks without modifying the frozen `luxury-zoom` module. Includes graceful fallback to default high-res if detection fails.
    *   *Constraint:* Cannot touch `luxury-zoom`; must handle missing telemetry in staging.
*   **Lane B (Asset Pipeline - Media Engineer):** Configure `media-transform` to generate scaled variants (WebP/AVIF) specifically optimized for <500kbps targets. Define quality thresholds that prevent pixelation on diamond/watch close-ups.
    *   *Constraint:* Limit runs to avoid 40-credit budget alerts; batch processing only.
*   **Lane C (Verification - QA):** Execute functional tests on Staging (mirrored bandwidth) and synthesize "real-user" telemetry scenarios to validate fallback logic.
    *   *Serialization:* Lane C starts only after Lane A commits code and Lane B confirms variant availability.
    *   *Schedule:* Avoid Tuesday mornings to bypass `visual-fidelity` flake.

#### 2. Gates & Checks
*   **G1 Spec (Now):** Define exact bandwidth thresholds, quality presets for "luxury" vs. "low-bandwidth," and the specific fallback behavior. Pin base SHA.
*   **G3 Design (Pre-Code):** Architectural Decision Record (ADR) confirming no impact on `luxury-zoom` and detailing the telemetry synthesis strategy for staging.
*   **G4 Implement:**
    *   Lane A: Unit tests for network detection logic + integration tests with mock CDN responses.
    *   Lane B: Dry-run of pipeline on 5 sample assets; verify credit cost.
*   **G5 Verify (Exact Revision):**
    *   **Revision:** The merged commit of Lane A + Lane B config.
    *   **Checks:** Build/Lint/Type green. `visual-fidelity` regression run (scheduled Wed–Mon). Manual visual inspection of diamond/watch close-ups on emulated low-bandwidth premium devices.
    *   **Success Criteria:** Load time reduction >40% on <500kbps; zero visible compression artifacts on luxury items.
*   **G6 Review:**
    *   **Reviewer 1 (Independent Senior FE):** Reviews Lane A logic; must not be the Builder.
    *   **Reviewer 2 (Media Specialist):** Validates Lane B quality settings.
    *   **Security Lead:** Validates no new data exfiltration risks in network detection.

#### 3. Landing & Human Decisions
*   **Integration (G7):** Merge Lane A and Lane B into a temporary integration branch. Re-run `visual-fidelity` and smoke tests on this exact SHA.
*   **Human Approval (G8):**
    *   **Required Approvers:** Elena Rossi AND Security Lead (Dual approval mandatory).
    *   **Decision Package:** Provide side-by-side visual comparison (high-res vs. adaptive), performance metrics from staging, and the rollback plan.
*   **Deployment:**
    *   Deploy behind a feature flag initially (canary 5% of target region traffic).
    *   Monitor cart abandonment and load times for 24 hours.
    *   Full rollout upon metric confirmation.
*   **Rollback:**
    *   **Trigger:** Increase in cart abandonment >2% or visual fidelity complaints.
    *   **Action:** Instant feature flag flip to disable adaptive logic, reverting to blanket high-res. No code revert required for immediate mitigation.

**Risk Mitigation:**
*   **Budget:** Lane B limited to 3 pipeline runs/day until G5.
*   **Flakiness:** All critical verification gates scheduled outside Tuesday mornings.
*   **Frozen Module:** Explicit test case ensuring `luxury-zoom` remains untouched.
*   **Telemetry Gap:** Lane C includes a synthetic data generator to mimic real-user conditions in staging.

**Timeline:** Execution begins immediately upon spec sign-off. Target G8 approval 48 hours before holiday rush window opens.
