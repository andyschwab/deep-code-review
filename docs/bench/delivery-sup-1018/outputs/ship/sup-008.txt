**Delivery Plan: Nova Quiz Engine with Legacy Parity**

**Scope & Constraints**
Goal: Deploy Nova engine with 100% visual/logic parity for pre-2015 content; new content uses enhanced features.
Constraints: Irreversible DB schema; 40k credit CI cost (partial testing required); "Historical Accuracy" flake (manual override by Jane Smith); dual human approval (Compliance + VP); `global-rules.json` lock (business hours); no rollback >50% traffic.

**Work Lanes**
*Parallel Execution:*
1.  **Lane A (Data & Schema):** Analyze deprecated data structures. Draft irreversible migration script. *Owner: Builder.*
2.  **Lane B (Logic Port):** Implement scoring/layout rendering for pre-2015 modules in Nova. *Owner: Builder.*
3.  **Lane C (Sampling Strategy):** Define statistically significant subset of archive for low-cost CI (target <5% of 40k credits). *Owner: Product Analyst.*
4.  **Lane D (Feature Flagging):** Implement routing logic: `<2015` → Legacy Render, `≥2015` → Nova Enhanced. *Owner: Builder.*

*Serialized Execution (Post-Parallel):*
5.  **Lane E (Targeted Regression):** Run Lane C's sample suite against Lane B's build. *Owner: QA.*
6.  **Lane F (Integration Dry-Run):** Merge A, B, D to integration branch; verify `global-rules.json` write access outside business hours. *Owner: Release.*

**Gates & Checks**
*   **G1 (Spec):** Freeze acceptance criteria: "Zero pixel deviation" defined by screenshot diff tolerance 0.0%. Define sampling math for Lane C.
*   **G2 (Plan):** Confirm DB migration irreversibility mitigation (full backup scheduled). Set lane budget caps.
*   **G3 (Design):** ADR for routing logic and fallback strategy if Nova fails mid-request.
*   **G4 (Implement):** Code complete. Unit tests for scoring logic.
*   **G5 (Verify):**
    *   Run Lane E (Sample Regression) on exact commit SHA.
    *   **Constraint:** If "Historical Accuracy" check fails, flag for Jane Smith (do not auto-retry).
    *   Verify `global-rules.json` lock handling in staging.
*   **G6 (Review):**
    *   **Security:** Independent review of DB migration script (no builder self-review).
    *   **QA:** Sign-off on sample regression results.
    *   **Architect:** Jane Smith manually overrides/validates the flaky check result.
*   **G7 (Integrate):** Merge to release branch. Generate final manifest.

**Review Strategy**
*   **Builder:** Implements Lanes A, B, D.
*   **Independent QA:** Executes Lane E, verifies G5 receipts.
*   **Independent Security:** Reviews DB migration (Lane A) and data divergence risks.
*   **Lead Architect (Jane Smith):** Sole authority on "Historical Accuracy" flake resolution.
*   **Compliance Officer & VP Academics:** Final human gate for production deploy.

**Landing & Rollout**
1.  **Pre-Deploy:** Schedule full DB backup (weekend window). Confirm `global-rules.json` modification window (non-business hours).
2.  **Human Gate 1:** Compliance Officer + VP Academics approve deployment manifest (G8).
3.  **Deployment Phase 1 (0-10%):** Enable flag for internal/staging users only. Monitor logs for silent failures.
4.  **Deployment Phase 2 (10-50%):** Gradual increase. **Hard Stop at 50%**.
5.  **Verification:** Live traffic audit against legacy side-by-side for random sample.
6.  **Human Gate 2:** Final approval to cross 50% threshold (point of no return).
7.  **Rollback Plan:**
    *   **<50% Traffic:** Immediate feature flag toggle to 0%.
    *   **>50% Traffic:** Rollback impossible per constraints. Mitigation requires hotfix in Nova or full weekend DB restore (last resort).

**Risks & Mitigations**
*   **Flaky Check:** Explicitly budget time for Jane Smith's manual intervention; do not block pipeline automatically.
*   **CI Cost:** Strict adherence to Lane C's sampling; full run only on release candidate if budget permits.
*   **Race Condition:** All config changes to `global-rules.json` scheduled strictly outside business hours.
*   **Data Divergence:** Absolute prohibition of crossing 50% without explicit dual-signoff.
