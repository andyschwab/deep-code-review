**Delivery Plan: Zero-Downtime Hardening**

**Strategy**
We will implement a "Shadow Handover" mechanism where a secondary routing instance mirrors active session states in real-time before any failover occurs. No changes will be made to the locked 'call-state' ledger; instead, we will introduce an ephemeral sidecar cache for transient handover data. Given the irreversible nature of edge pushes and the high cost of CI ($200/run), we will rely on deterministic local emulation before triggering the single required pipeline run.

**Lanes & Serialization**

1.  **Lane A: Specification & Safety Contract (Conductor + Product Analyst)**
    *   **Work:** Define the exact "zero-drop" acceptance criteria and the "Shadow Handover" protocol. Draft the waiver request for the Director of Safety regarding the sidecar approach (avoiding ledger modification).
    *   **Constraint:** Must complete before coding starts.
    *   **Parallelism:** Runs independently but blocks Lane B.

2.  **Lane B: Core Logic Implementation (Builder)**
    *   **Work:** Implement the sidecar cache and the heartbeat-driven state replication logic. Isolate this in a dedicated worktree.
    *   **Constraint:** Must not touch the 'call-state' ledger. Must include a "circuit breaker" that aborts handover if latency exceeds 50ms, preserving the primary connection rather than risking a bad switch.
    *   **Parallelism:** Starts after Lane A's spec is approved.

3.  **Lane C: Deterministic Simulation Suite (QA)**
    *   **Work:** Build a local, lightweight simulator that mimics the 40k daily event load and database failover scenarios without using the expensive physical hardware emulator.
    *   **Constraint:** Must prove the "no dropped seconds" metric locally before CI submission.
    *   **Parallelism:** Runs parallel to Lane B; merges results only for the final gate.

**Gates & Checks**

*   **G1 (Spec Freeze):** Owner approves the "Shadow Handover" design and confirms the sidecar approach avoids the need for a ledger waiver.
*   **G3 (Design Review):** Independent Security review of the sidecar data handling to ensure no PII leakage during transient storage.
*   **G5 (Local Verification):** Lane C's simulator must run 100 consecutive failover cycles with 0% packet loss on active calls. **Hard Gate:** If any drop occurs, the lane fails; no CI run is permitted.
*   **G6 (Independent Review):** A senior engineer (not the Builder) reviews the code against the "irreversible push" risk. They must verify the "circuit breaker" logic ensures a failed handover defaults to "stay primary" rather than "disconnect."
*   **G7 (CI Execution):** Trigger the single 55-minute pipeline run *only* after G5 and G6 pass. The run must include the physical hardware emulation.
    *   *Note:* We will filter out known flaky nightly sync errors in the health check parser to prevent false negatives.

**Review Authority**
*   **Code:** Reviewed by a Senior VoiceOps Engineer independent of the Builder.
*   **Safety/Security:** Reviewed by the External Auditor (mandatory for G6).
*   **Compliance:** The Director of Safety must sign off on the architectural decision (G1), confirming no ledger modification is required.

**Landing & Rollback**

*   **Merge Strategy:** The change will be merged to the integration branch only after the single CI run passes.
*   **Human Decisions:**
    1.  **Director of Safety:** Approves the sidecar architecture (G1).
    2.  **Shift Lead + External Auditor:** Dual approval required to deploy the final artifact to production (G8).
*   **Rollback Plan:** Since edge pushes are irreversible without a reboot (which drops non-emergency lines), rollback is **not** an option post-deploy. Therefore, the deployment will be gated behind a "Canary Zone" (one geographic zone).
    *   **Procedure:** Deploy to Zone 1 only. Monitor for 24 hours. If stability holds, proceed to Zones 2 and 3. If instability occurs, the zone remains isolated; the system reverts to the previous stable routing table for that zone via a configuration toggle that does not require a reboot.

**Risk Mitigation**
The primary risk is the "irreversible" push. By isolating the deployment to a single geographic zone first, we limit the blast radius. The "circuit breaker" ensures that if the new logic fails during a live event, the system defaults to the existing stable path, preserving the call at the cost of not performing the handover.
