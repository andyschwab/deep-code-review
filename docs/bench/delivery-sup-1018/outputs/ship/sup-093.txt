**Delivery Plan: Apex-9 Sub-Second Firmware Rollback**

**Objective:** Implement local, automated rollback (<2s trigger) on health check failure, ensuring binary verification and preventing bootloops, adhering to the frozen crypto-library constraint.

### 1. Lanes & Parallelism

*   **Lane A: Bootloader Logic (Serial Prerequisite)**
    *   **Owner:** Senior Embedded Engineer (Builder).
    *   **Scope:** Modify bootloader to include rollback trigger logic and health-check hook. Must execute before OS handoff.
    *   **Constraint:** Must respect read-only partition rules; logic must reside in the writable update partition or pre-boot RAM.
    *   **Parallelism:** Blocked until Lane B defines the verification interface.

*   **Lane B: Verification & Binary Integrity (Parallel Start)**
    *   **Owner:** Security Engineer (Builder).
    *   **Scope:** Implement signature verification using the *currently frozen* crypto-library. Define the "safe previous version" storage mechanism.
    *   **Constraint:** Cannot update crypto-lib; must use existing audit-approved version.
    *   **Parallelism:** Can start immediately. Must finish before Lane A integrates the verification call.

*   **Lane C: Health Check & Trigger Mechanism (Parallel Start)**
    *   **Owner:** Firmware QA Engineer (Builder).
    *   **Scope:** Define the specific health check metrics that trigger rollback. Implement the <2s watchdog timer.
    *   **Parallelism:** Can start immediately. Must align with Lane A on signal propagation.

*   **Lane D: Safety & Loop Prevention (Independent)**
    *   **Owner:** Safety Compliance Officer (Human) + Security Engineer.
    *   **Scope:** Design the "rollback counter" to prevent infinite loops (e.g., if the previous version is also bad). Define the "brick-safe" state.

### 2. Gates & Checks

*   **G0/G1 (Intake/Spec):** Define exact health check failure modes and the cryptographic signature schema. **Gate:** Lead Architect approval on spec.
*   **G2 (Plan):** Acyclic graph confirming Lane B finishes before Lane A integration. Budget: On-prem cluster hours only (no cloud spend).
*   **G3 (Design):** ADR detailing how rollback works with the read-only bootloader constraint. **Gate:** Safety Compliance Officer sign-off.
*   **G4 (Implement):** Code committed to isolated worktrees.

    *   *Check:* Crypto implementation review against frozen library docs.

### 4. Risks & Mitigations

*   **Read-Only Bootloader:** If logic is placed incorrectly, rollback is impossible. **Mitigation:** Lane A must prove via unit test that the rollback vector is accessible pre-boot.
*   **Crypto Library Freeze:** Cannot patch crypto vulnerabilities. **Mitigation:** Strict scope limitation to signature verification only; no new crypto features.
*   **HIL Flakiness:** False negatives in testing. **Mitigation:** Isolated network for G5 verification; require 3x pass confirmation.
