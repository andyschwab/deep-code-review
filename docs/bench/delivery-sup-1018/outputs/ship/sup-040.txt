**Delivery Plan: Customs Declaration Format v4.2**

*   **Lane A (Schema & Parser):** Implement v4.2 XML/JSON schema and the new parser. *Writer: Builder.*
*   **Lane B (Legacy Coexistence):** Refactor the export dispatcher to support region-based toggling (v3.1 vs v4.2) and ensure historical record retrieval remains untouched. *Writer: Builder (Serialized after Lane A starts to ensure interface compatibility).*
*   **Lane C (Fallback Mechanism):** Implement the instant-failover logic if v4.2 validation fails, ensuring zero downtime. *Writer: Builder (Parallel to Lane B).*
*   **Lane D (Sandbox Verification):** Execute integration tests against the Northern Border Authority sandbox using the new format. *Writer: QA (Independent).*
*   **Lane E (Migration Script):** Draft the irreversible database migration script with a dry-run mode. *Writer: DBA/Security (Serialized; requires final schema from Lane A).*

**Parallel Execution:** Lanes A, C, and D can run concurrently once the spec is locked. Lane B must wait for Lane A's interface definition. Lane E waits for Lane A's final schema.

*   **G5 Verify:**
    *   **QA:** Run Lane D against the sandbox. Confirm historical data accessibility in v3.1.
    *   **Resilience Test:** Simulate v4.2 parser failure; verify instant fallback to v3.1 with no dropped shipments.
    *   **CI:** Run full suite on the exact integration SHA, excluding the flaky network check if packet loss is zero.
*   **G6 Review:** Independent review by a senior engineer (not the Builder) focusing on the irreversible migration and fallback logic. Security review for data integrity during the toggle.

*   **Builder:** Implements Lanes A, B, C.

*   **Security/DBA:** Reviews Lane E and the migration plan. Independent of the Builder.
*   **Deep Code Review:** Applied to all diffs, specifically checking for race conditions in the toggle and data loss risks in the migration.

*   **Human Gate (Jane Smith):** Jane must personally approve the production deploy. The request will present:
