### Delivery Plan: Reefer Comms Protocol Upgrade

**1. Lanes & Parallelism**
*   **Lane A (Simulation & Logic):** Develop the dual-stream handover mechanism and fallback logic in isolation. This lane runs the 45-minute CI hardware-in-the-loop simulations. Since reverts are impossible at sea, this lane must validate the "fail-safe" state where the old protocol remains primary if the new handshake stalls.
*   **Lane B (Security & Access):** Coordinate with Jane Smith (Lead Architect) immediately to pre-authorize the network latency flaky check bypass. Simultaneously, schedule access to the read-only vault during the next maintenance window to retrieve current encryption keys for the simulation environment.
*   **Serialization Point:** Lane A cannot finalize validation until Lane B provides the valid encryption keys. The CI pipeline must run with production-grade crypto to be meaningful.

**2. Gates & Checks**
*   **Gate 1 (Code Freeze):** All code for the handover mechanism must be committed to a dedicated release branch by Sunday 23:59. No changes accepted after this point.
*   **Gate 2 (CI Validation):** Execute the full 45-minute CI pipeline on the specific release branch commit.
    *   *Condition:* If the network latency module fails, trigger the pre-authorized bypass approved by Jane Smith.
    *   *Requirement:* Three consecutive successful runs are required to statistically negate the 15% flaky failure rate.
*   **Gate 3 (Dry-Run Verification):** A manual review of the simulation logs confirming that during a forced "mid-ocean" handshake failure, the old telemetry stream maintained 100% continuity with zero data gaps.

**3. Review Process**
*   **Primary Reviewer:** A Senior Engineer *not* involved in writing the handover logic. They must verify the fallback state machine against the regulatory "zero gap" mandate.
*   **Secondary Reviewer (Security):** Verify that the new protocol implementation correctly utilizes the rotated encryption keys without hardcoding or exposing them.
*   **Final Sign-off:** Jane Smith must personally sign off on the CI results, specifically acknowledging the bypassed flaky check and confirming the three consecutive pass requirement was met.

**4. Landing & Merge Strategy**
*   **Deployment Window:** Monday 04:00 – 06:00 (Lowest satellite traffic, maximum ground support availability).
*   **Merge Action:** Merge the release branch to `production` only after Jane Smith's final sign-off.
*   **Rollout Mechanism:** The update is pushed as a configuration flag change. The vessel agents will attempt the new handshake while maintaining the old stream.
    *   *Success:* New protocol confirmed active -> Old stream terminated.
    *   *Failure:* Handshake timeout -> Agent locks to old protocol indefinitely; no retry loop that could cause instability.
*   **Human Decision Point:** If any of the three Atlantic shipments report latency spikes >200ms during the first 10 minutes of the rollout, the Ground Control team must manually abort the fleet-wide push.
*   **Rollback:** There is no technical rollback for vessels at sea. If the update corrupts the agent, the cargo is quarantined. The "rollback" is strictly a preventative abort of the fleet-wide deployment before the vessels exit port range. If a vessel is already mid-ocean and fails, a physical technician visit is the only recovery, scheduled for the next port call.

**Risk Mitigation:** The irreversibility of the deployment dictates that the "Abort" decision threshold is extremely low. It is better to miss the Tuesday batch departure than to quarantine high-value pharmaceutical cargo.
