### Delivery Plan: Signal Logic Tuning for Congestion Relief

#### 1. Work Lanes & Parallelism
*   **Lane A (Algorithm Tuning):** Engineer develops the adaptive timing adjustments within the `core-timing` module logic only. This work isolates vehicle throughput improvements without touching configuration files initially.
*   **Lane B (Test Fixture Repair):** QA Engineer updates test fixtures to inject deterministic wind speed data, eliminating the intermittent flakiness in pedestrian timing validation.
*   **Lane C (Safety Verification Prep):** Public Safety Lead prepares the baseline pedestrian safety metrics report from last month's data for comparison.

**Parallel Execution:** Lanes A, B, and C run simultaneously. Lane A cannot proceed to final integration until Lane B is complete to ensure reliable testing.

#### 2. Gates & Checks
*   **Gate 1 (Unit Validation):** Before any simulation, Lane A's code must pass local unit tests proving no hardcoded values in school zone pedestrian windows are altered.
*   **Gate 2 (Flake-Free Simulation):** Once Lane B is complete, trigger the CI pipeline on the specific feature branch revision.
    *   *Constraint:* Only one simulation run per iteration due to the 55-minute duration and 4-run daily cap.
    *   *Check:* Verify pedestrian crossing windows match the ordinance exactly (0% deviation). Verify vehicle throughput improvement against last month's volume data.
*   **Gate 3 (Joint Sign-off):** Because `core-timing` shares a static config with emergency pre-emption:
    *   Traffic Engineering Lead must sign off on congestion metrics.
    *   Public Safety Lead must sign off on emergency pre-emption non-interference.
    *   *Serialization:* This gate blocks merging until both signatures are recorded.

#### 3. Independent Review
*   **Code Review:** Performed by a Senior Backend Engineer not involved in Lane A. Focus: Logic isolation and adherence to the "no pedestrian window reduction" constraint.
*   **Safety Audit:** Performed by the Public Safety Lead (independent of Traffic Engineering). Focus: Verification of the simulation report showing untouched pedestrian safety metrics.
*   **Conflict Check:** A separate review of the static configuration file to ensure no accidental drift in emergency pre-emption settings.

#### 4. Landing Strategy
*   **Merge Authority:** Only the Senior City Engineer can merge to the production branch.
*   **Pre-Merge Action:** The merge request must include the signed Joint Sign-off document and the passing CI simulation report.
*   **Audit Trigger:** Acknowledge that merging will trigger an irreversible audit log entry regarding school zone intervals. The commit message must explicitly state "No change to school zone pedestrian durations; ordinance compliant."
*   **Rollback Plan:**
    *   If post-deployment monitoring shows pedestrian timing deviations >0s or emergency pre-emption latency increases:
    *   Immediate revert of the production branch to the previous stable revision.
    *   Notification to both Traffic Engineering and Public Safety leads within 15 minutes of detection.
*   **Human Decision Points:**
    *   Approval to consume a CI simulation slot (due to cost caps).
    *   Final Joint Sign-off (requires two distinct humans).
    *   Final Merge approval (Senior City Engineer).

This plan ensures congestion relief is pursued aggressively while treating the school zone mandate as a hard, non-negotiable constraint verified by independent parties before any code reaches production.
