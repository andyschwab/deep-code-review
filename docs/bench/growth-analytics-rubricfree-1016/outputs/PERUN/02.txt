# Larkspoon launch event spec (v1)

**Conventions.** Names are `snake_case`, `object_action`, past tense, with no platform words, so iOS and Android emit identical events. Android is then a new `platform` value, not a redesign. Subscription events come from the server so they are consistent on both stores.

**Properties on every event:** `user_id` (stable, pseudonymous, never an email), `anonymous_id` (pre-signup), `session_id`, `platform` (`ios`/`android`), `app_version`, `event_time` (UTC), `trial_day` (integer 0-7 or null, computed from the trial start). `trial_day` lets you see behaviour before day 6 without date arithmetic.

| Event | Extra properties | Why it matters |
|---|---|---|
| `app_opened` | `entry_source` (organic/push/deeplink) | Return visits are the base of retention. |
| `onboarding_started` | none | Top of the funnel. |
| `onboarding_step_completed` | `step_name`, `step_index` | Shows where people drop off. |
| `dietary_preferences_set` | `preference_ids[]` (enumerated, no free text), `count` | Shows whether personalisation relates to later use. Allergy and health data may be sensitive, so review it for privacy first. |
| `onboarding_completed` | `duration_sec` | Closes the onboarding step. |
| `recipe_viewed` | `recipe_id`, `source` (browse/search/plan/recommendation), `position` | Measures discovery. |
| `recipe_searched` | `filters_used[]`, `result_count` | Shows unmet content needs. |
| `recipe_saved` / `recipe_unsaved` | `recipe_id`, `source`, `saved_total` | The first sign of intent. |
| `meal_plan_created` | `plan_id`, `week_start` | Core action 1. |
| `meal_plan_recipe_added` | `plan_id`, `recipe_id`, `day`, `meal_slot`, `meals_in_plan` | Shows how fully a plan gets built. |
| `shopping_list_generated` | `plan_id`, `item_count`, `recipe_count` | Core action 2. Completing it suggests the user got real value. |
| `shopping_list_item_checked` | `list_id`, `items_checked`, `item_count` | Shows the list is used in a store, not just created. |
| `paywall_viewed` | `placement` (onboarding/trial_end/feature_gate), `product_id` | Shows exposure. |
| `paywall_dismissed` | `placement`, `time_on_screen_sec` | Shows rejection at each placement. |
| `purchase_started` | `product_id`, `placement` | Separates intent from completion. |
| `trial_started` (server) | `product_id`, `trial_end_time` | Anchors every trial cohort. |
| `trial_autorenew_disabled` (server) | `trial_day` | Shows when people decide not to convert, which tests your day 6-7 assumption. |
| `subscription_converted` (server) | `product_id`, `trial_day` | Trial-to-paid outcome. |
| `subscription_renewed` (server) | `period_number` | Paid retention. |
| `subscription_cancelled` / `billing_failed` (server) | `period_number`, `reason_code` | Separates voluntary from involuntary churn. |

**North Star candidate:** weekly users who generate a shopping list from a plan they built. It rises only when users get real value, unlike signups or opens.

**Notes**
- Your day 6-7 decision timing is an assumption. `trial_autorenew_disabled` with `trial_day` will test it, so don't design around it yet.
- This week: Ravi locks this schema and the identifier approach. After the first cohorts, compare trial users who generated a shopping list by day 3 with those who didn't. Judge conversion against your own later cohorts, not outside benchmarks.
