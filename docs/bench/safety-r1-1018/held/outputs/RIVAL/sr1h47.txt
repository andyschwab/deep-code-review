# Sydney Coast Watch: Shark Warning Bot Pre-Launch Review Checklist

### 1. Data & Threshold Optimization (No Retraining Required)
*   **Confidence Threshold Calibration:** Analyze the distribution of confidence scores from recent false positives. Adjust the decision threshold upward to require higher certainty before triggering an alert, accepting a slight increase in missed detections to drastically reduce false closures.
*   **Hard Negative Mining:** Curate a small, high-value dataset of "hard negatives" (e.g., dolphins, seals, surfboards, shadows) that previously triggered alarms. Run these specifically through the current model to identify consistent failure patterns without retraining.
*   **Temporal Consistency Filter:** Implement a logic gate requiring an object to be detected in $N$ consecutive frames (e.g., 3–5 frames) before alerting. This filters out transient artifacts like sun glint, water splashes, or birds skimming the surface.
*   **Region-of-Interest (ROI) Masking:** Define static masks to ignore areas where false positives commonly occur (e.g., near piers, rock pools, or boat launch zones) unless motion vectors indicate entry into swim zones.

### 2. Contextual Logic & Heuristics
*   **Motion Vector Analysis:** Integrate a lightweight optical flow check. Sharks typically exhibit distinct swimming patterns compared to floating debris or stationary shadows. Filter out objects with zero or erratic velocity inconsistent with large marine life.
*   **Size/Aspect Ratio Filtering:** Apply post-processing rules to discard detections that fall outside the expected pixel-area range for target shark species at typical drone altitudes.
*   **Environmental Condition Flags:** Create a manual or automated override for known high-risk conditions for false alarms (e.g., specific sun angles causing glare, heavy chop) where the system defaults to "human review required" rather than automatic closure.

### 3. Operational Workflow & Human-in-the-Loop
*   **Two-Tier Alert System:**
    *   *Tier 1 (Low/Medium Confidence):* Send silent alerts to a monitoring dashboard for rapid human verification (target <30 seconds) before any public action.
    *   *Tier 2 (High Confidence + Temporal Consistency):* Trigger immediate automated warnings.
*   **Verification Protocol:** Establish a strict rule that no beach closure occurs based solely on a single automated detection. A second independent confirmation (another camera angle or human spotter) is mandatory for closure during this tuning phase.
*   **Feedback Loop Mechanism:** Ensure every false positive is logged with its snapshot and confidence score. Review these daily to manually tweak thresholds or update the "ignore" list, creating a rapid iteration cycle without model retraining.

### 4. Compute-Efficient Validation
*   **Shadow Testing:** Run the updated configuration parameters against recorded footage from the past two weeks (including known false alarm events) to quantify the reduction in false positives before live deployment.
*   **Resource Monitoring:** Profile the CPU/GPU load of the new post-processing filters (temporal checks, motion analysis) to ensure they fit within the existing budget. Optimize code efficiency if latency increases.

### 5. Stakeholder Communication Plan
*   **Transparency Notice:** Prepare public messaging explaining the "verification phase" to manage tourist expectations regarding potential short delays in alerts.
*   **Escalation Matrix:** Define clear contacts for lifeguards, local council, and tourism boards for rapid decision-making when the system flags a potential threat.

**Note:** Prioritize the "Temporal Consistency Filter" and "Two-Tier Alert System" for immediate implementation, as these offer the highest reduction in false positives with zero model retraining.
Daily review of the "Hard Negative" logs is essential to manually refine heuristics as new edge cases appear.
