### Risk Mitigation Plan: Pollution Spike Validation Framework

**Objective:** Validate that the SeoulAir filtering algorithm removes sensor noise while preserving genuine, short-term hazardous spikes (e.g., industrial accidents) for government decision-making.

**1. Synthetic Data Injection Strategy**
Since live industrial accidents cannot be waited upon, construct a "Golden Dataset" of synthetic time-series data to feed into the system.
*   **Noise Baseline:** Generate 1,000 hours of data containing typical sensor drift, random Gaussian noise, and transient communication glitches. *Expected Outcome:* All filtered out.
*   **True Positive Spikes:** Inject distinct patterns representing real events:
    *   *Step Change:* Instant jump in PM2.5/NO2 levels (simulating a sudden release).
    *   *Ramp Up:* Rapid, sustained increase over 15–30 minutes.
    *   *Multi-Sensor Correlation:* Simultaneous spikes across adjacent geographic sensors (validating spatial consistency).
*   **Edge Cases:** Create "adversarial" noise that mimics spikes (e.g., a single sensor jumping high while neighbors remain stable) to ensure the filter correctly identifies these as anomalies.

**2. The "Shadow Mode" Testing Protocol**
Do not replace the current algorithm immediately. Run the new validation suite in parallel (shadow mode) against historical data where known events occurred.
*   **Recall Test:** Feed historical dates with confirmed industrial incidents. Verify the system *retains* these peaks in the output. If the trend line flattens during a known event, the filter is too aggressive.
*   **Precision Test:** Feed data from calm periods with known sensor maintenance issues. Verify the system *removes* these artifacts.

**3. Quantitative Success Metrics**
Define pass/fail criteria before running tests:
*   **Spike Retention Rate:** 100% of injected "True Positive" spikes above the hazardous threshold must appear in the final dashboard data with <5% magnitude distortion.
*   **Noise Reduction Rate:** >95% of injected "Noise Baseline" fluctuations must be smoothed.
*   **Latency Check:** Ensure the filtering process does not delay data availability by more than the contractual limit (e.g., <2 minutes), as delayed warnings are useless for acute events.

**4. Human-in-the-Loop Verification**
Automated tests cannot capture all nuances.
*   **Blind Review:** Present a mixed set of filtered vs. raw data plots (including hidden injected spikes) to two senior air quality experts from your team. Ask them to identify potential hazards. If they miss the injected spikes in the filtered view, the visualization or filtering logic requires adjustment.
*   **Threshold Tuning:** If the system fails to retain spikes, implement a "conservative fallback" mode for the launch. This mode lowers the filtering sensitivity specifically when values approach critical health thresholds, prioritizing false alarms over missed detections.

**5. Deployment Safeguard**
For the Friday delivery, include a manual "Override Switch" in the admin dashboard. This allows operators to temporarily bypass the aggressive filter for specific sensor zones if an external report (e.g., fire department call) suggests an incident that the system has smoothed out.
