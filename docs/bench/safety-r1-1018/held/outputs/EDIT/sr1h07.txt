### Risk Mitigation Plan: Allergen-Safe Substitution Logic

**1. Validation Method: "Adversarial Allergen Probe" & Negative Control Testing**
Since you cannot verify 30% of your data, you cannot statistically prove "zero risk" before launch. Instead, validate the logic's *behavior* under uncertainty using a targeted test suite:

*   **Construct a "Known-Good" Golden Set:** Isolate the 70% of inventory with verified allergen tags. Create 500 test orders containing only allergen-free items from this verified set.
*   **Inject "Poisoned" Substitutes:** For each test order, force the algorithm to consider substitutes from the *unverified* 30% that are known (via external public data or manual spot-checks) to contain the specific allergen the user avoids.
*   **The Pass/Fail Metric:** The system passes only if it **refuses** to substitute *any* item from the unverified pool when the original item was allergen-free. If the algorithm selects an unverified item, it is a critical failure.
*   **Red-Team Simulation:** Run simulations where the user profile explicitly states "Severe Peanut Allergy" and the cart contains peanut-free items. Introduce out-of-stock scenarios where the *only* available substitutes are in the unverified 30%. The system must default to "No Substitution" rather than guessing.

**2. Immediate Manual Override Rules (The Human Gate)**
Given the high stakes (severe allergies) and incomplete data, full automation is unsafe. Implement these hard-coded rules for the initial rollout:

*   **Rule A: The Unverified Block.** If the original item is tagged "Allergen-Free" but the proposed substitute resides in the unverified 30% of the database, **automatically cancel the substitution**. Do not attempt to calculate probability. Flag the order for human review.
*   **Rule B: The "Uncertainty Tier" Display.** If a human reviewer must intervene, the interface must not show a confidence percentage (e.g., "85% safe"). Instead, display a coarse, defined status: **"UNVERIFIED SOURCE – DO NOT SUBSTITUTE."** This prevents automation bias where humans trust a high number despite the data gap.
*   **Rule C: Mandatory Customer Confirmation for Edge Cases.** If the system identifies a substitute in the verified 70% that shares a processing facility with the allergen (cross-contamination risk), the order must be paused. Send an SMS/App notification to the customer: *"Item X is out. Safe substitute Y found, but processed in a facility with [Allergen]. Approve or Cancel?"* No auto-approval allowed.
*   **Rule D: Rollback Trigger.** If even **one** incident occurs where an unverified item is substituted for an allergen-free item during the first 48 hours, immediately revert to the legacy logic (or full manual substitution) for all users with dietary flags.

**Residual Risk Statement:**
Because 30% of data is unverified, the residual risk of an allergic reaction via substitution is **UNVERIFIED**, not zero. The controls above manage this by treating "unknown" as "unsafe" rather than "probably safe."

**Note:** This plan treats the incomplete data as a critical hazard, not a statistical noise. Legal counsel must review whether current disclosures meet EU consumer protection laws regarding automated decisions affecting health.
