### Pre-Launch Monitoring Plan & Circuit Breaker Rules

**1. Vulnerable Segment Identification (Monitoring Plan)**
Before the quarterly review, configure your legacy reporting to flag accounts matching these "at-risk of unfair penalty" profiles. Do not alter the core model; instead, create a parallel view that tags these accounts for manual review before any action is taken.

*   **The "Loyal Temporarily Strapped" Segment:** Accounts open >5 years with no prior delinquency, showing a sudden <30% drop in inflows for exactly one billing cycle, but maintaining minimum payments.
*   **The "Essential Spend Spike" Segment:** Accounts where >60% of outflows in the last 30 days are categorized as utilities, healthcare, or groceries, coinciding with a reduced balance.
*   **The "Recovery Phase" Segment:** Accounts that were flagged as "at-risk" in the previous quarter but have made three consecutive on-time minimum payments since.

**2. Temporary Circuit Breaker Rules (Immediate Implementation)**
Given the 10-day constraint and rigid infrastructure, implement these logic gates as a pre-processing filter. If an account triggers *any* of these conditions, the automated reduction is halted and queued for human approval.

*   **Rule A (Tenure Shield):** If `Account_Age` ≥ 7 years AND `Delinquency_Count_Lifetime` = 0 → **Block Auto-Reduction**.
*   **Rule B (Payment Continuity):** If `Last_3_Months_Payment_Status` = "On-Time" (even if minimum) → **Block Auto-Reduction**.
*   **Rule C (Hardship Cap):** If `Proposed_Reduction_%` > 20% of current limit → **Force Human Review** regardless of score.
*   **Rule D (Velocity Check):** If the account had a limit change (up or down) in the last 90 days → **Block Auto-Reduction**.

**3. Execution Workflow**
*   **Step 1:** Run the credit risk model as planned to generate the "recommended action" list.
*   **Step 2:** Apply the Circuit Breaker Rules above to this list.
*   **Step 3:** Split the output:
    *   *Pass-Through:* Accounts not triggering any rule proceed to automatic reduction.
    *   *Hold Queue:* Accounts triggering any rule are exported to a CSV for manual review by your team of eleven.
*   **Step 4:** Manual reviewers have 48 hours to assess the "Hold Queue" using context the model lacks (e.g., known medical leave, temporary contractor gaps).

This approach requires no code changes to the core legacy engine, only a configurable filtering layer or a stored procedure that can be deployed within your 10-day window. It prioritizes preventing irreversible harm to loyal customers while allowing the model to function for clear-cut risk cases.

**Note:** This plan treats the automated decision as a recommendation, not a final action, for high-stakes segments. You must document these rules as a temporary control pending the full quarterly model validation.
