### Testing Plan: Synthetic Stress-Test for Facial Recognition

To address false positives without collecting new biometric data, execute the following synthetic evaluation protocol immediately:

**1. Generate Synthetic Variation Sets (No New User Data)**
Create algorithmic variations of the *existing* enrolled resident images (which you already hold) to simulate common false-positive triggers. Do not capture new photos.
*   **Occlusion Layering:** Programmatically overlay digital assets representing glasses (rimmed, rimless, sunglasses), hats (caps, beanies), scarves, and masks onto existing resident photos.
*   **Environmental Simulation:** Apply noise filters to simulate low-light (night mode), motion blur, and partial obstruction (e.g., holding a grocery bag).
*   **Demographic Slicing:** Ensure these synthetic variations cover all enrolled family members to detect if specific individuals are disproportionately affected by certain accessories.

**2. Define the "Negative Control" Probe Set**
Construct a test batch where the ground truth is known:
*   **Positive Controls:** Original clear images of residents (should match).
*   **Negative Controls:** The synthetic variations described above (should *still* match the resident, not trigger "Intruder").
*   **True Negative Probes:** Images of non-residents (public datasets or team members not enrolled) wearing the same accessories to ensure the system correctly identifies strangers as strangers.

**3. Establish Runnable Test Rows & Metrics**
For each harm scenario (e.g., "Resident wearing hat labeled as Intruder"), define a specific test row:
*   **Input:** Synthetic image set (Resident + Hat).
*   **Metric:** False Rejection Rate (FRR) per accessory type.
*   **Threshold:** Set a zero-tolerance stop condition for "Intruder" classification on any verified resident variation. If the system labels a resident-with-hat as an intruder >0% of the time in this controlled test, the threshold fails.
*   **Stop Condition:** Launch is blocked if FRR for any single accessory category exceeds 1%.

**4. Implement Uncertainty Tiers (Not Precision Numbers)**
Do not display raw confidence scores (e.g., "87% match") to users or rely on them for gating. Instead, map model outputs to defined coarse tiers:
*   **Confirmed:** High match on multiple features.
*   **Unverified:** Match degraded by occlusion (glasses/hat). *Action:* System suppresses the alarm and requests a secondary check (e.g., PIN entry or mobile app confirmation) rather than sounding the siren.
*   **No Match:** Clear non-resident. *Action:* Trigger alarm.

**5. Human-in-the-Loop Gate for High-Stakes Actions**
Since sounding an alarm causes distress and potential police dispatch (high-stakes/irreversible):
*   **Rule:** Any identification falling into the "Unverified" tier must default to a silent notification or a user-confirmation prompt, not an active siren.
*   **Fallback:** If the synthetic stress test reveals that hats cause >5% false intruder alerts, the default behavior for "face + hat" scenarios must be "Assume Resident unless proven otherwise" or require explicit disarm confirmation, rather than "Assume Intruder."

**Deliverable:** A report listing the False Rejection Rate for each synthetic category (glasses, hats, lighting) marked as **UNVERIFIED** until this test suite is run. No claim of "bias-free" or "safe" can be made until these specific probes pass the stop conditions.

**Note:** This plan measures residual risk; it does not certify the system as unbiased.
