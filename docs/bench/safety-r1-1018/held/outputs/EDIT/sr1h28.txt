### Risk Mitigation Plan: Pollution Spike Preservation

**1. Harm Inventory & Worst-Case Definition**
*   **Harm:** False Negative Filtering (suppressing real hazardous events).
*   **Affected:** Government officials, public health responders, and the general public in SeoulAir's jurisdiction.
*   **Worst-Case:** An industrial accident occurs; the system classifies the spike as "noise"; officials receive a "clean" trend line; no emergency response is triggered; public health is compromised.

**2. Testing Framework: "Spike Survival" Eval Suite**
Do not rely on aggregate accuracy. Build a specific evaluation set to test the boundary between noise and signal.

*   **Probe Set A (Known Bad Positives - The Trap):** Inject synthetic data representing genuine industrial accident signatures (sharp rise, sustained high level, specific chemical ratios) into historical quiet periods.
    *   *Pass Condition:* The system **must not** filter these out. They must appear on the dashboard with high visibility.
    *   *Stop Condition:* If >0% of known accident signatures are filtered, the release is blocked.
*   **Probe Set B (Known Negatives - The Noise):** Inject typical sensor glitches (single-point spikes, impossible negative values, flatlines) into active pollution periods.
    *   *Pass Condition:* The system filters these successfully.
*   **Probe Set C (Edge Cases):** Inject "slow burn" events (gradual rise over 2 hours) and "multi-sensor" events (spike in only one sensor vs. correlated spikes in three).
    *   *Metric:* Detection rate by event type.

**3. Human-in-the-Loop Gate (The Floor)**
Given the high stakes (public health) and the known aggressiveness of the current algorithm:
*   **Immediate Control:** Disable fully automatic suppression for any reading exceeding the "Hazardous" threshold.
*   **New Workflow:** Any data point flagged by the filter as "anomaly" but exceeding a safety threshold must be routed to a human reviewer for explicit confirmation before being hidden from the dashboard.
*   **Default State:** In doubt, show the data. It is safer for an official to see a potential false alarm than to miss a real disaster.

**4. Transparency & Uncertainty Artifacts**
*   **Confidence Tiers:** Do not display a raw probability (e.g., "87% likely noise"). Instead, label data points on the dashboard with defined tiers:
    *   *Verified:* Corroborated by multiple sensors.
    *   *Single-Source:* Validated by one sensor, uncorroborated (display with a distinct visual cue, e.g., dashed line or amber border).
    *   *Unverified/Flagged:* Identified as potential anomaly but retained for review.
*   **Data Card:** Publish a versioned artifact detailing the filtering logic, the specific "accident signatures" used in testing, and the known limitations (e.g., "System may retain sensor glitches to ensure spike capture").

**5. Execution Plan (By Next Friday)**
*   **Day 1-2:** Construct Probe Sets A, B, and C using historical accident data and synthetic noise.
*   **Day 3:** Run the "Spike Survival" eval. Tune the algorithm *only* to maximize survival of Set A, accepting higher noise retention if necessary.
*   **Day 4:** Implement the Human-in-the-Loop gate for high-threshold anomalies.
*   **Day 5:** Final validation run. If Set A survival is not 100%, the feature cannot ship in automatic mode; it must ship with the manual gate active.

**Residual Risk:** The system may present more "noise" to officials, requiring them to exercise judgment. This is the required trade-off to prevent missing a catastrophe.

**Note:** This plan treats the risk of missing a spike as zero-tolerance. Do not invent a "safe" error rate for public health failures.
**Note:** Legal requirements for automated decision disclosures in government health contexts must be routed to counsel immediately.
