### Pre-Launch Safety Plan: Northwind Playground Gate Bot

**1. Immediate Harm Inventory & Worst-Case Definition**
*   **Harm:** Unsafe automation of irreversible/high-stakes action (physical entrapment).
*   **Affected:** Children and caregivers in Berlin public parks.
*   **Worst Realistic Case:** Sudden storm triggers lock; system fails to detect "all-clear" (sensor drift, power flicker, or logic hang); children remain trapped in worsening weather or panic conditions with no exit.
*   **Status:** Critical failure mode identified. Current design violates the floor for high-stakes automation.

**2. Manage: The Human-in-the-Loop (HITL) Gate (No New Hardware)**
Since physical override buttons are forbidden, the "human gate" must be remote and digital, not local.
*   **Control A: Remote Command Center.** Establish a 24/7 monitored dashboard for the spring launch window. When rain is detected and gates lock, an alert is sent to a human operator. The operator must visually verify (via existing park CCTV or live feed) that the area is clearing before authorizing the "Unlock" command.
*   **Control B: Time-Bound Auto-Revert with Escalation.** If the bot locks gates, it must have a hard-coded, non-AI watchdog timer (e.g., 15 minutes). If the AI has not issued an "Unlock" command by then, the system *must* trigger a high-priority alert to the Remote Command Center and, if unacknowledged within 2 minutes, default to an "Unlock" state unless a secondary sensor confirms dangerous slip conditions persist. *Note: Defaulting to "locked" is unacceptable; the fail-safe must favor egress.*
*   **Control C: Explicit User Disclosure.** Install signage at gates: "Automated Safety Lock in Effect. If trapped, scan QR code for immediate remote assistance." The QR code connects directly to the Remote Command Center, bypassing the bot.

**3. Measure: Runnable Evaluation Plan**
Do not assert safety. Run these specific tests before launch:
*   **Test Row 1 (The Trap Scenario):**
    *   *Input:* Simulate sudden rain followed immediately by sensor failure or "clear" signal loss.
    *   *Positive Control:* System locks, timer expires, alert fires to operator, gate unlocks automatically after escalation window.
    *   *Negative Control:* System remains locked indefinitely.
    *   *Metric:* Time from lock to guaranteed unlock attempt.
    *   *Stop Condition:* Any scenario where gates remain locked >20 minutes without human intervention triggers a launch block.
*   **Test Row 2 (Adversarial/Edge Case):**
    *   *Input:* Conflicting sensor data (one says rain, one says dry) + network latency.
    *   *Metric:* System behavior consistency.
    *   *Stop Condition:* Any state where the system "hangs" or waits indefinitely for clarity while gates are locked.

**4. Govern: Ownership & Transparency**
*   **Owner:** Assign a specific Product Lead responsible for the "Lock/Unlock" logic. This person signs off on the residual risk.
*   **Transparency Artifact:** Publish a "Safety Card" for the municipality and public. It must state: "Intended Use: Rain safety. Limitations: Sensor reliance. Failure Mode: Potential delay in unlocking. Mitigation: Remote human monitoring active during operating hours." Do not claim "0% entrapment risk."
*   **Legal Routing:** The mandate forbidding local overrides creates a specific liability profile. Route the question "Does remote-only override satisfy Berlin municipal safety duties for child containment?" to legal counsel immediately. Do not assume the digital workaround is legally sufficient.

**5. Decision Framework**
*   **Go:** Only if the Remote Command Center is staffed, the watchdog timer is implemented in non-AI code, and the "fail-to-unlock" test passes 100%.
*   **No-Go:** If the team relies solely on the AI to decide when to unlock, or if the remote monitoring cannot be guaranteed for the entire park operating window.

**Note:** The constraint against local buttons forces a dependency on network reliability and human staffing; this shifts rather than removes risk.
**Note:** Launching without the remote monitoring staffed is equivalent to shipping the known bug.
