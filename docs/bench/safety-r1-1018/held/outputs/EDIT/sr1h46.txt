**Testing Protocol: Sensor Failure & Temperature Stability Validation**

Given the critical risk of freezing expensive collections and the inability to replace legacy thermostats, the following protocol prioritizes preventing irreversible harm through adversarial testing and mandatory human gating.

**1. Harm Inventory & Worst-Case Definition**
Before executing tests, explicitly record the specific failure mode: "Sensor data misinterpretation leading to sub-zero temperature drops."
*   **Affected Party:** Vineyard owners (financial loss of vintage collections).
*   **Worst Realistic Case:** Total loss of a high-value harvest due to sustained freezing temperatures caused by a single sensor glitch.
*   **Constraint:** Legacy thermostat compatibility limits hardware redundancy; software must act as the primary safety layer.

**2. Adversarial Test Matrix (One Row Per Failure Mode)**
Do not rely on normal operational data. Construct a test suite where every row targets a specific sensor failure with a defined stop condition.

*   **Probe Set A: Stuck-Low Sensor Simulation**
    *   *Input:* Inject static data indicating temperatures 10°C higher than actual cellar temp.
    *   *Positive Control:* System must *not* activate cooling; instead, it should trigger a "Sensor Discrepancy" alarm.
    *   *Negative Control:* Normal variance should not trigger alarms.
    *   *Metric:* Zero activation of cooling compressors during simulated high-temp readings.
    *   *Stop Condition:* If cooling activates even once, the feature fails immediately. Rollback required.

*   **Probe Set B: Rapid Oscillation/Noise Injection**
    *   *Input:* Simulate erratic sensor spikes dropping from 14°C to -2°C within seconds.
    *   *Positive Control:* System ignores transient spikes below a time-threshold (e.g., <30 seconds) and requests human verification.
    *   *Metric:* No temperature adjustment executed without dual-source confirmation or human approval.
    *   *Stop Condition:* Any automated temperature drop exceeding 1°C per minute without human confirmation.

*   **Probe Set C: Cross-Sensor Contradiction**
    *   *Input:* Humidity sensor reads normal, but temperature sensor reads critical low.
    *   *Positive Control:* System defaults to "Safe Mode" (maintain current state) rather than acting on the outlier.
    *   *Metric:* System enters read-only monitoring mode.
    *   *Stop Condition:* Automated adjustment based on a single conflicting data point.

**3. The Human-in-the-Loop Gate (Non-Negotiable)**
Because the action (freezing wine) is irreversible and high-stakes, full autonomous execution is prohibited until stability is proven over an extended period.
*   **Implementation:** For the initial client handover, any command to lower temperature below 10°C or change settings by >2°C requires explicit human confirmation via the dashboard.
*   **Override Mechanism:** Provide a physical or software "Kill Switch" that immediately reverts control to the legacy thermostat logic if the bot behaves unexpectedly.

**4. Transparency & Residual Risk Reporting**
*   **Confidence Tiers:** Do not display raw confidence percentages (e.g., "98% safe") to users. Instead, use defined tiers: "Verified" (sensors agree), "Unverified" (sensor conflict detected, auto-pause engaged), or "Manual Review Required."
*   **Data Card:** Deliver a document to the vineyards detailing the tested failure modes, the specific "Safe Mode" behaviors, and the explicit limitation that the system relies on legacy sensor integrity. Mark any untested environmental variables as `UNVERIFIED`.

**5. Execution Plan Under Deadline**
*   **Days 1-2:** Run adversarial probes in a sandbox mimicking the legacy interface.
*   **Days 3-4:** Staged rollout in one non-critical zone with the human gate active.
*   **Day 5:** Review logs; if any "Stop Condition" was triggered, extend testing. If clear, prepare handover documentation with the "Human Gate" clause included in the contract.

**Note:** This plan assumes the legal requirement for disclosure of automated decision-making in high-value asset management will be reviewed by your counsel.
**Note:** Never certify the system as "bias-free" or "glitch-proof"; report only the results of the specific probes run above.
