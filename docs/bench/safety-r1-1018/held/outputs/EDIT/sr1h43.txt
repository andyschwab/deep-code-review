**Immediate Action Plan: Human Gate and Staged Rollout**

Do not enable fully automated broadcasting for evacuation routes by the holiday launch. The incident where passengers were directed toward blocked tunnels confirms a critical failure mode: the system lacks real-time verification against dynamic hazards. Given the incomplete static maps and lack of access to the legacy tunnel database, the system cannot guarantee safety.

Implement a **Human-in-the-Loop (HITL) gate** immediately. All evacuation messages generated by the bot must be reviewed and explicitly approved by a human operator before broadcast. This is non-negotiable for high-stakes, irreversible actions like directing crowds during an emergency.

**Revised Launch Strategy:**
1.  **Staged Rollout:** Limit the bot's scope to non-safety-critical announcements (e.g., minor delays, schedule changes) for the holiday rush. Disable all evacuation routing features until the data gap is resolved.
2.  **Fallback Protocol:** Revert to manual, pre-approved static scripts for any emergency scenario. If a situation requires evacuation, human operators must manually select and broadcast verified routes.
3.  **Data Gap Mitigation:** Prioritize resolving the security clearance for the legacy tunnel database. Without this, any automated routing logic is fundamentally flawed.

**Identified Failure Points in Current Logic:**
*   **Static Data Reliance:** The logic assumes tunnel status is constant. It fails when real-world conditions (blocked tunnels, fire, smoke) contradict the static map.
*   **Lack of Uncertainty Signaling:** The system presents directions as absolute facts. It currently has no mechanism to indicate when its data is incomplete or unverified.
*   **Automation Bias:** Commuters and staff may trust the automated voice over their own judgment or conflicting visual cues, leading to dangerous outcomes if the bot is wrong.

**Required Artifacts Before Any Future Automation:**
*   **Harm Inventory:** Document the specific risks of "Hallucination surfaced as fact" (directing to blocked tunnels) and "Unsafe automation of high-stakes actions." Define the worst-case scenario (mass casualty due to misdirection).
*   **Evaluation Plan:** Create a test suite using adversarial scenarios (e.g., simulate blocked exits) to prove the system fails safely (i.e., refuses to give directions) rather than giving wrong ones. Do not ship until the system passes these tests with a human gate in place.
*   **Transparency Card:** Draft a model card stating the system's limitation: "Routing is based on incomplete static maps and is not verified against real-time tunnel status. Not for use in active emergencies."

**Constraint Acknowledgement:**
The holiday launch date is fixed, but the scope of automation is not. Meeting the deadline with safe operations requires descoping the high-risk evacuation feature. Attempting to launch full automation with known data gaps violates the safety floor for high-stakes decisions.
