### Pre-Launch Review Checklist: Shark Warning Bot (Sydney Coast Watch)

**1. Harm Inventory & Worst-Case Definition**
*   **Identify Specific False Positives:** List the top three benign marine life types (e.g., dolphins, seals, schools of fish) currently triggering alarms.
*   **Define Worst-Case Impact:** Explicitly record the cost of a false alarm (e.g., "4-hour beach closure, $X tourism loss, public trust erosion") versus a missed detection.
*   **Assign Ownership:** Name one team member responsible for reviewing every alarm type before the holiday peak.

**2. Measurement Plan (No Retraining Required)**
*   **Adversarial Probe Set:** Curate a "challenge dataset" of 500 video clips containing only the identified benign marine life in various lighting/weather conditions. Do not use random data; target known failure modes.
*   **Positive/Negative Controls:**
    *   *Positive Control:* 50 clips of confirmed sharks in clear and murky water (must trigger).
    *   *Negative Control:* 50 clips of empty ocean and surfers (must not trigger).
*   **Metric & Threshold:** Define a pass threshold for the false positive rate (FPR) on the benign probe set. Given the high cost of closures, propose a **zero-tolerance** threshold for automated closures on ambiguous detections until verified.
*   **Stop Condition:** If the FPR on the benign probe set exceeds the threshold, the automated closure feature is disabled by default.

**3. Risk Management Controls (Compute-Light)**
*   **Human-in-the-Loop (HITL) Gate:** Implement a mandatory human review step for any detection with confidence below a high bar (e.g., "Confirmed" tier). The bot should *recommend* a check to lifeguards rather than *executing* a beach closure automatically.
*   **Uncertainty Display:** Replace raw confidence percentages (e.g., "87%") with defined coarse tiers for operators:
    *   *Confirmed:* High certainty, multiple frames/features matched.
    *   *Corroborated:* Single clear feature, consistent motion.
    *   *Unverified:* Ambiguous shape or poor lighting (Default to "No Alarm" or "Manual Check Only").
*   **Fallback Rule:** If the system detects a potential threat but cannot assign a "Confirmed" tier within 3 seconds, the default action is **silent logging** for later review, not an active alarm.

**4. Transparency Artifact (Model Card Lite)**
*   **Draft a One-Page Limitation Statement:** Document intended use (daylight drone footage only), known failures (specific marine life confusions), and the fact that false positive rates are **UNVERIFIED** until the probe set above is run.
*   **Distribution:** Ensure lifeguards and beach managers receive this summary so they understand the bot is an assistive tool, not an autonomous authority.

**5. Governance & Launch Decision**
*   **Final Go/No-Go:** The launch decision rests on the owner reviewing the probe set results. If the probe set has not been run, the status is **UNVERIFIED**; do not assert safety.
*   **Rollback Plan:** Define the exact switch to disable automated alerts instantly if false positives spike during the first 48 hours of the holiday period.

**Note:** This checklist optimizes existing weights via threshold tuning and operational gating, requiring no additional model training.
**Reminder:** Never certify the system as "safe" or "unbiased"; rely on the measured results of the probe set to guide the launch decision.
