### Risk Mitigation Plan: Allergen-Safe Substitution Logic

**Critical Finding:** You cannot validate that the new logic "never" substitutes an allergen when 30% of your inventory data is untagged. An algorithm cannot verify safety against missing information. Claiming "zero risk" or "100% safe" with incomplete data is a fabrication that exposes customers to life-threatening harm. The only valid status for untagged items is **UNVERIFIED**.

#### 1. Validation Method: The "Safe-Subset" Constraint
Do not attempt to test the full inventory. Instead, restrict the validation scope to the **70% of items with complete, verified allergen tags**.

*   **Create a "Golden Set" Probe:** Build a test suite using only the fully tagged inventory. Include specific "positive controls" (known allergen-free item → attempted substitution with known allergen item) and "negative controls" (known allergen-free item → safe substitution).
*   **The Hard Gate:** Configure the new logic to **automatically reject** any substitution where either the original item or the potential substitute falls within the 30% untagged category.
*   **Success Metric:** The system passes validation only if it achieves 100% accuracy on the "Golden Set" AND successfully blocks 100% of substitution attempts involving untagged items. If the system attempts to substitute an untagged item, the test fails immediately.

#### 2. Immediate Manual Override Rules (Human-in-the-Loop)
Because the data is incomplete, fully automated substitution for affected orders is unsafe. Implement these mandatory overrides for the rollout:

*   **Rule A: The "Unknown" Block:** If the algorithm identifies a potential substitute but the allergen status is missing for *either* the original or the substitute, the system must **halt automation**. Do not guess. Flag the order for human review.
*   **Rule B: Mandatory Human Confirmation:** For any order flagged with a customer note regarding allergies or dietary restrictions, **no substitution occurs without explicit human verification** against a secondary source (e.g., physical package check or supplier sheet). The engineer or ops staff must manually confirm the safety before the order is finalized.
*   **Rule C: Default to Non-Substitution:** If a human reviewer cannot verify the allergen status within a set time window (e.g., 15 minutes), the default action is to **refund/remove the item** rather than substitute it. It is safer to deliver an incomplete order than a dangerous one.
*   **Rule D: Customer Disclosure:** If an order is modified due to these safety checks, the customer must be notified immediately that the substitution was withheld due to insufficient allergen data, offering them the choice to cancel or accept the partial order.

**Deployment Mandate:** Do not deploy the "improved availability" logic if it bypasses these gates. Higher availability rates are irrelevant if they increase the probability of anaphylaxis. The "human-in-the-loop" gate is not optional; it is the only control preventing irreversible harm given your current data state.

*Note: This plan treats the 30% data gap as a critical safety failure, not a statistical nuance. Legal counsel should be consulted regarding liability for automated decisions involving health risks.*
