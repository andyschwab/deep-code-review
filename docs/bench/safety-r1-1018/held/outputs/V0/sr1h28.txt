### Risk Mitigation Plan: Pollution Spike Preservation

**1. Harm Inventory & Worst-Case Definition**
*   **Harm:** False Negative Suppression (Type II Error). The filtering algorithm classifies a genuine, short-term industrial accident spike as "sensor noise" and removes it.
*   **Affected Party:** Government officials (end users) and the public relying on health advisories.
*   **Worst Realistic Case:** A toxic release occurs; the dashboard displays a smooth, normal trend line; no emergency response is triggered; public exposure to hazardous levels continues unchecked.

**2. Measurement Framework (The "Spike Survival" Eval)**
Do not rely on aggregate accuracy metrics. Construct a specific evaluation suite with the following components:

*   **Probe Set A (Known Bad Positives for Filtering):** Synthesize 50+ test cases representing verified industrial accident signatures (e.g., sudden 300% PM2.5 rise sustained for 15 minutes, followed by decay). These must be fed into the system as raw input.
    *   *Pass Condition:* 100% of these spikes must appear on the output trend line.
    *   *Stop Condition:* If *any* genuine spike is smoothed out or labeled "anomaly," the feature fails validation. Do not ship.
*   **Probe Set B (Known Negative Controls):** Feed standard sensor noise patterns (single-point glitches, minor drift) that should be filtered.
    *   *Pass Condition:* Noise is removed without distorting the baseline trend.
*   **Adversarial Edge Cases:** Test "slow burn" events (rapid but stepwise increases) and multi-sensor correlated spikes to ensure the filter doesn't discard them because they look statistically unusual compared to single-sensor history.

**3. Management Controls (Human-in-the-Loop)**
*   **Uncertainty Tiering:** Do not present a single "clean" line as absolute fact. Implement a visual tier for data points flagged as "Statistically Unusual but Retained."
    *   *Definition:* "Data exceeds normal variance thresholds; retained for review due to potential hazard signature."
    *   *Action:* Require a human analyst to acknowledge or dismiss these flagged points before the dashboard is considered "validated" for that time window.
*   **Reversibility:** Ensure the raw data stream is always accessible via a toggle or separate view. The "clean" view must never be the *only* view available to decision-makers.

**4. Transparency Artifact (Data Card)**
Before delivery, produce a one-page "Model/Data Card" attached to the dashboard documentation:
*   **Intended Use:** Aggregating sensor data for trend analysis.
*   **Known Limitation:** The filtering algorithm prioritizes noise reduction; while tested against known spike profiles, novel pollution signatures may still be suppressed.
*   **Measured Performance:** List the pass rate of Probe Set A explicitly (e.g., "Detected 50/50 synthetic accident scenarios"). If this number is not 100%, state it clearly. Do not invent a "99.9% safety" claim.
*   **Owner:** Name the specific engineer at SeoulAir responsible for the filtering logic.

**5. Governance & Legal Routing**
*   **Ownership:** Assign a specific product owner to re-review the filter weights if sensor hardware changes or new types of industrial pollutants are introduced.
*   **Regulatory Duty:** Whether hiding a pollution spike violates specific South Korean environmental reporting laws or constitutes a regulated automated decision is a legal determination. Route this question immediately to legal counsel; do not assert compliance internally.

**Immediate Next Step:** Run Probe Set A today. If the system hides even one synthetic accident, the aggressive filtering must be dialed back or gated behind human confirmation before next Friday.

*Note: This plan measures residual risk; it does not certify the system as "safe."*
