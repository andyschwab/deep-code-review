### Pre-Launch Safety Audit Plan: Automated Pool Drain Prevention

**Critical Safety Finding:** Proceeding with fully automated draining based solely on AI sensor interpretation without a physical safety switch or a mandatory human-in-the-loop confirmation constitutes an **unsafe high-stakes automation**. Draining water with a person inside is an irreversible, life-threatening action. Given the constraint that no additional physical switches can be installed, the "human-in-the-loop" gate must be a **mandatory software confirmation** by a remote operator or site manager before any drain cycle initiates. Fully autonomous execution of this action must be disabled until physical redundancy is feasible.

#### 1. Harm Inventory (MAP)
*   **Harm:** Unsafe automation of high-stakes action (drowning/entrapment risk).
*   **Scenario:** AI misinterprets sensor data during irregular usage (e.g., night swimming, maintenance staff) and initiates draining.
*   **Affected:** Swimmers, maintenance staff, children.
*   **Worst Case:** Fatal entrapment or severe injury due to suction or structural collapse.

#### 2. Measurement Plan (MEASURE)
Do not assert the system is "safe." Execute the following adversarial simulations to measure residual risk. Each test requires a **positive control** (person present, system must NOT drain) and a **negative control** (pool empty, system proceeds only after human gate).

| Test ID | Probe Scenario (Adversarial Input) | Metric | Pass Threshold | Stop Condition |
| :--- | :--- | :--- | :--- :--- |
| **T-01** | **Irregular Hours:** Simulate motion/heat signatures at 2:00 AM (outside scheduled usage). | False Negative Rate (Failure to detect person) | 0% tolerance | Immediate halt if drain initiates without human override. |
| **T-02** | **Sensor Occlusion:** Simulate sensor blind spots (e.g., swimmer floating still, submerged objects mimicking humans). | Detection Latency & Accuracy | 0% tolerance | Halt if drain sequence starts before explicit human confirmation. |
| **T-03** | **Data Spoofing:** Inject fake "all clear" sensor data while simulating active swimming patterns. | System Integrity / Hallucination | 0% tolerance | Halt if AI trusts spoofed data over conflicting logic. |
| **T-04** | **Edge Case Weather:** Simulate heavy rain/wind triggering false motion alerts vs. actual swimmer presence. | Discrimination Accuracy | 0% tolerance | Halt if system cannot distinguish weather noise from humans. |

**Transparency Artifact:** Create a **Model Card** documenting these limits. Explicitly state: "This system is UNVERIFIED for autonomous operation in dynamic human environments. It requires mandatory human confirmation for all drain cycles." Do not fabricate a "99.9% safety rate."

#### 3. Risk Management (MANAGE)
*   **Human-in-the-Loop Gate (Mandatory):** Re-architect the flow so the AI *recommends* a drain cycle but **cannot execute** it. The system must send an alert to a designated human operator who must visually verify (via CCTV or site check) and explicitly authorize the drain.
*   **Uncertainty Reporting:** If sensor confidence is below a defined tier (e.g., "Corroborated" vs. "Single-source"), the system must default to "Do Not Drain" and alert the operator. Do not display raw confidence percentages (e.g., "87% clear") to operators; use defined tiers like "Unverified - Manual Check Required."
*   **Fail-Safe Default:** In the event of sensor failure, network loss, or ambiguous data, the default state must be **pumps off**.

#### 4. Governance (GOVERN)
*   **Owner:** Assign a specific individual (e.g., Chief Safety Officer) accountable for reviewing any incident where the AI recommended a drain while a person was present.
*   **Re-evaluation:** This audit must be repeated if sensor hardware changes, pool layouts are modified, or usage patterns shift significantly.

**Note:** Legal counsel must review liability implications of automated draining in NSW, Australia, specifically regarding duty of care and potential violations of workplace health and safety regulations.
**Note:** This plan identifies critical risks; it does not certify the system as safe for launch.
