### Pre-Launch Anti-Cheat Review Strategy

**1. Harm Inventory & Risk Mapping**
The primary risk is **unfair exclusion**: legitimate players (especially those with high latency or using accessibility tools) receiving irreversible bans. Given the 10-day tournament window, the worst-case scenario is disqualifying honest competitors, damaging tournament integrity and brand reputation. Since infrastructure is frozen, we cannot add new logging; we must reinterpret existing telemetry.

**2. Correlation Strategy (Using Existing Data)**
Do not treat "glitchy behavior" as an isolated signal. Implement a pre-ban correlation check within your current application logic:
*   **Latency Cross-Reference:** Before finalizing a ban decision, query the existing telemetry for packet loss or latency spikes coinciding with the flagged "glitch." If a movement anomaly occurs during a documented network stutter, downgrade the confidence of the cheat detection.
*   **Accessibility Whitelist Check:** Verify if the flagged input pattern matches known signatures of approved accessibility tools stored in your current configuration files. If a match exists, suppress the ban flag automatically.
*   **Contextual Consistency:** Check if the "unauthorized software" signature persists across multiple sessions or is a one-off event correlated with a specific map load or server restart.

**3. Graduated Response System (The Human Gate)**
Immediate, fully automated bans for behavioral anomalies are too high-risk for a major tournament. Implement this tiered workflow effective immediately:

*   **Tier 1: Silent Flagging (Low Confidence):** If the AI detects an anomaly but network latency is high or the pattern is ambiguous, log the event internally but take **no action** against the player. Mark the account for post-match review.
*   **Tier 2: Warning & Probation (Medium Confidence):** If the signal is stronger but not definitive (e.g., repeated glitches without clear network causes), issue an in-game warning: *"Unusual activity detected. Further violations may result in suspension."* Do **not** ban. Allow play to continue under heightened monitoring.
*   **Tier 3: Temporary Suspension + Human Review (High Confidence):** Only for the most severe, persistent flags. Instead of a permanent ban, issue a **24-hour temporary suspension**. This triggers an immediate ticket for a human moderator to review the replay/telemetry.
    *   *Rule:* No permanent ban is executed by the AI alone before the tournament concludes. All "permanent" decisions require human sign-off.

**4. Measurement & Transparency**
*   **Runnable Test:** Before launch, run a "red team" simulation using historical data of known laggy connections and accessibility tool usage. The pass condition is **zero false positives** on this specific subset. If the system flags these known safe cases, lower the sensitivity threshold until it passes.
*   **Disclosure:** Update the player code of conduct to state: *"Automated systems may flag unusual activity for review. Immediate permanent bans for behavioral anomalies are paused during the tournament; all such cases undergo human verification."*
*   **Ownership:** Assign one product manager as the owner of "False Positive Mitigation" for the tournament duration. They must review all Tier 3 suspensions daily.

**Note:** This plan treats the AI as an advisory tool, not a judge, adhering to the principle that irreversible actions (permanent bans) require human confirmation. Do not invent accuracy metrics; report the results of your red-team simulation as "Verified" or "Unverified" based on actual runs.
