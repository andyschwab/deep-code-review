### Risk Mitigation Plan: Pilot Phase Dispatch Safety

**1. Pre-Dispatch Validation Logic (The "Hard Gate")**
Implement a synchronous, pre-dispatch validation step that blocks assignment rather than correcting it post-hoc. Since real-time government verification is unavailable, treat internal profile data as "unverified" unless recently confirmed.
*   **Staleness Threshold:** Define a strict time-to-live (TTL) for certification data (e.g., 30 days). Any driver profile with certification data older than the TTL is automatically flagged as "Pending Verification" and excluded from receiving orders requiring that specific certification.
*   **Conservative Matching:** If an order requires a specific vehicle type (e.g., refrigerated, heavy cargo), the dispatch algorithm must query the driver's last known valid status. If the status is missing, expired, or flagged by the staleness threshold, the driver is removed from the candidate pool for that order.
*   **Fallback Queue:** Orders that cannot be matched to a "verified-clean" driver within a set time window (e.g., 45 seconds) are routed to a manual dispatch queue rather than forcing a risky automated assignment.

**2. Human-in-the-Loop Intervention Protocol**
Establish a real-time alerting mechanism for the support team to intervene before the driver accepts the job.
*   **Probationary Assignment:** If business pressure requires assigning an order to a driver with borderline data (e.g., certification expires in 48 hours), the system assigns the order in a "Hold" state. The driver's app shows "Order Pending Review," preventing acceptance.
*   **Support Dashboard Alert:** Simultaneously, push a high-priority alert to the support team dashboard containing: Order ID, Driver ID, Specific Certification Gap, and a countdown timer (e.g., 2 minutes).
*   **Resolution Paths:** Support agents must either (A) manually verify credentials via phone/email with the driver and release the hold, or (B) cancel the auto-assignment and re-route to the manual queue. If no action is taken before the timer expires, the assignment is automatically cancelled to prevent accidental acceptance.

**3. Communication & Audit Trail**
*   **Internal Logging:** Every blocked assignment and every "Hold" state alert must be logged with a timestamp, the specific rule triggered (e.g., "Cert TTL Exceeded"), and the final resolution agent. This creates an audit trail for the upcoming regulatory inspection.
*   **Driver Transparency:** If a driver is skipped due to data staleness, send a neutral notification: "You are temporarily ineligible for this order type due to pending profile updates. Please contact support." Avoid implying guilt; frame it as a compliance safeguard.

**4. Pilot-Specific Constraints**
*   **Zero-Tolerance Policy:** For the 10-day pilot, prioritize missed delivery opportunities over compliance violations. It is acceptable to leave an order unassigned temporarily; it is not acceptable to assign it to an potentially uncertified driver.
*   **Daily Data Sweep:** Run a nightly batch job to flag all drivers approaching certification expiry for proactive outreach by the operations team, reducing the load on real-time support during peak hours.

**Note:** This plan relies on a "fail-closed" approach where uncertainty results in no assignment. Ensure your support team is staffed adequately during peak pilot hours to handle the increased volume of "Hold" state alerts.
