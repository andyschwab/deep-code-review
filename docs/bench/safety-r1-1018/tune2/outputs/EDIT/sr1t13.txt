### Risk Mitigation Plan: Pilot Phase Dispatch Safety

**1. Pre-Dispatch Validation Strategy (Deterministic Gate)**
Implement a hard blocking rule in the dispatch logic that treats any driver profile with certification data older than 24 hours as "Unverified." Do not rely on real-time API calls to the government database. Instead:
*   **Static Snapshot:** Require drivers to upload current certification documents 48 hours before their shift. Manual review by your operations team validates these against the internal database before the shift starts.
*   **Logic Rule:** `IF order.requires_cert_X AND driver.profile.cert_X_status != "Verified_Today" THEN exclude_driver_from_pool`.
*   **Fallback:** If no "Verified_Today" driver is available within the proximity window, the order must remain unassigned in the queue rather than risking a mismatch. This creates a deliberate capacity constraint that prioritizes compliance over speed during the pilot.

**2. Human-in-the-Loop Intervention Protocol**
Since full automation of high-stakes regulatory assignments is unsafe without real-time verification, introduce a "Staged Dispatch" for the pilot:
*   **Hold State:** Orders requiring specific certifications enter a "Pending Review" state for 30–60 seconds before being offered to a driver.
*   **Support Dashboard:** Create a simplified view for support agents showing only these pending orders. The view must highlight: Order ID, Required Cert, Assigned Driver, and Driver's Last Verification Date.
*   **Manual Release:** Support agents must explicitly click "Confirm & Release" to push the assignment to the driver's app. If the agent identifies a discrepancy (e.g., uploaded doc looks expired), they cancel the auto-assignment and manually re-route or contact the driver.
*   **Kill Switch:** A global toggle to revert all certified-order dispatching to 100% manual assignment if the error rate exceeds zero during the pilot.

**3. Communication & Escalation**
*   **Internal Alerting:** If the system detects a driver attempting to accept an order where their profile status is "Unverified," trigger an immediate high-priority alert to the support dashboard with the driver's location and order details.
*   **Driver Feedback:** If a driver is blocked due to outdated data, the app must display a clear, non-negotiable message: "Assignment paused: Certification verification required. Please contact support." Do not use ambiguous language that implies a temporary glitch.

**4. Inspection Readiness Artifact**
Prepare a one-page "Safety & Control Card" for the inspectors. This document must list:
*   The specific logic rule preventing uncertified assignments.
*   The definition of "Unverified" (e.g., >24h old).
*   The count of orders held for manual review during the pilot.
*   The name of the Product Owner responsible for the dispatch logic.
*   Explicit statement: "Real-time government API integration is suspended for safety; manual pre-shift verification is the active control."

**Note:** This plan treats the lack of real-time API access as a hard constraint, forcing a slower but safer manual verification loop. Do not claim "zero risk" to inspectors; instead, present the "Unverified = Blocked" rule as your primary control.
