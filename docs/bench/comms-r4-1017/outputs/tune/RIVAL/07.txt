## Add read replica for reporting dashboard queries

This PR routes reporting dashboard queries to a new read replica to reduce load on the primary database. Dashboard queries previously contributed to high primary DB load; they now target the replica exclusively. A dedicated connection pool (size 10) handles replica connections.

**Performance impact**
*   **p95 latency:** Reduced from 320ms to 110ms.
*   **p99 latency:** Reduced from 500ms to 210ms.

**Replica behavior**
The replica typically lags by approximately 2 seconds. Since the dashboard displays hourly aggregated data, this lag does not affect user-facing accuracy.

**Known issues and decisions required**
1.  **Alerting:** Monitoring for replica lag is not yet configured. Please determine if an alert should be added for lag exceeding 30 seconds and define the threshold.
2.  **Flaky test:** One time-series query test fails when replica lag exceeds 5 seconds, causing stale data returns. This occurred in 1 out of 100 test runs. The test is currently marked as flaky. Please confirm if this failure rate is acceptable or if the test logic requires adjustment.
