This PR adds a `deleted_at` column to the `users` table to support soft deletes. The column defaults to `null`.

**Changes**
- Added the migration script (single `ALTER TABLE` statement).
- Updated the user model and data access layer to exclude soft-deleted users from queries.
- Added 3 new tests for the data access layer; all 120 existing tests pass.

**Migration Performance**
We tested the migration on a copy of production (1.2 million rows), where it completed in 4 minutes and 15 seconds. On a smaller table (50,000 rows), it took 20 seconds.

**Open Questions**
1. **Concurrent writes:** We have not tested the case where a user is deleted while another process updates the same row. There may be a race condition. Please advise if this blocks the merge or if we can address it in a follow-up.
2. **Retention policy:** We haven't defined a policy for hard-deleting old soft-deleted rows. Input on this would be appreciated.
