## Search query optimization with multi-column index

This PR adds a multi-column index on the `orders` table `(customer_id, created_at)` and updates the search query to use it. Files changed: migration script (creates the index) and the query file.

**Performance results (staging, 500k rows)**
- Typical customer search: 850 ms → 120 ms (86% reduction)
- Complex search with date range: 1.4 s → 380 ms

All 85 existing tests pass.

**Open items for DBA review**
- **Index size on production:** The production table has ~4.2M rows. We estimate the new index at ~250 MB, but need confirmation of the actual size and whether it fits the storage budget.
- **Large date ranges:** We haven't tested queries spanning very large ranges (e.g., 2 years). The index should still provide benefits, but verification is recommended.

Please review the changes and advise on the index size and storage implications.
