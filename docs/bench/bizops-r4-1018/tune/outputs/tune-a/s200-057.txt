**What Flips It, and The Trigger:**
The deciding factor is not the *function* (analysis vs. transmission) but the *capability* (implementation of 256-bit AES). Under U.S. regulations, software containing cryptographic functionality above a certain threshold is controlled regardless of whether it encrypts data in transit or performs static analysis using encryption libraries.
*   **Trigger:** If the software includes proprietary or non-standard implementation of AES-256, or if it is not eligible for the "publicly available" or "open source" exemptions under specific filing requirements, you cannot export.
*   **Rule of Thumb:** Any custom cryptographic module >56-bit key length generally requires classification before export to non-embargoed countries.
*   **Step this week:** If you have not yet filed an Electronic Encryption Registration (EER) or obtained a Commodity Jurisdiction (CJ) determination, consider halting all outbound sales discussions until counsel confirms your Classification Request (CCAT) status.

**Routing Note:**
This is a Tier 3 binding determination. You must engage a U.S. export control attorney specializing in EAR (Export Administration Regulations) and ITAR. Time sensitivity is critical; exporting before classification can result in permanent debarment.

*Note: The distinction between "analyzing" and "transmitting" rarely exempts software from cryptographic controls if the code itself implements strong encryption.*
