**What Flips It, and the Trigger:**
The single input that changes this call is the **specific license type** and the **linking method** (static vs. dynamic).
*   **Trigger Rule:** If the license is GPL/AGPL and you statically link the proprietary add-ons into the same binary as the core engine, most legal interpretations consider the whole binary a "derivative work," triggering the requirement to release all source code.
*   **Decision Threshold:** If you cannot dynamically separate the modules (e.g., via sidecars, plugins, or separate microservices communicating over a network/API), the risk remains critical.
*   **This Week's Step:** If your build process produces a single monolithic binary containing both core and add-on code, **immediately halt** any public distribution or new customer deployments until counsel reviews the build pipeline. Consider refactoring the architecture to communicate via well-defined network APIs (which generally do not trigger copyleft) as a contingency plan.
