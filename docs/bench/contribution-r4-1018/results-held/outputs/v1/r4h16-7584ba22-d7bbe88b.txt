### Sanitized Crash Summary and Bug Report Draft

**Title:** Query Planner Memory Corruption Leading to Engine Crash on Complex Join Predicates

**Problem Description:**
The database engine crashes with a segmentation fault during the optimization phase of queries containing specific nested join predicates with non-equi conditions. The crash occurs in the query planner's cost estimation routine when handling deeply nested subqueries combined with range filters. This is a reproducible memory corruption issue that affects stability under workloads utilizing complex analytical queries.

**Root Cause Analysis:**
The crash stems from an out-of-bounds memory access in the cost estimation logic. When the planner encounters a specific pattern of nested joins with range predicates, it miscalculates the required buffer size for intermediate statistics, leading to a heap overflow. This corrupts adjacent memory structures, causing a segfault during subsequent access.

**Reproduction Steps (Synthetic):**
1. Initialize a database with three tables: `T1` (1M rows), `T2` (500k rows), `T3` (200k rows).
2. Execute a query joining all three tables with a nested subquery and a range filter on a non-indexed column.
3. Observe immediate crash during the planning phase.

*Example Query:*
```sql
SELECT * FROM T1
JOIN (SELECT * FROM T2 WHERE val BETWEEN 100 AND 500) AS sub
ON T1.id = sub.id
JOIN T3 ON sub.id = T3.id
WHERE T1.timestamp > '2023-01-01';
```

**Proposed Fix:**
The fix involves adding a bounds check in `src/planner/cost_estimator.cc` before allocating the statistics buffer. If the calculated size exceeds the safe limit, the planner now falls back to a conservative estimation strategy instead of proceeding with corrupted data.

**Testing Verification:**
- The provided patch prevents the crash on the synthetic reproduction case.
- Existing regression tests pass without modification.
- No performance degradation observed on standard benchmark suites.
