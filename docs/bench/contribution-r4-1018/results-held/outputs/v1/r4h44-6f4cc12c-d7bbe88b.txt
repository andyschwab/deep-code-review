**Professional Protocol and Deliverable**

Do not submit a pull request (PR) yet. Submitting untested code that explicitly fails the project's "tested on all supported platforms" rule violates contribution guidelines and risks your employer's reputation. Instead, open a **pre-PR Issue** or a **Draft PR** (if the platform allows) to request specific testing assistance.

**Step 1: Stop Checks**
*   **Employer Approval:** Confirm with your legal/IP team that sharing a font-rendering fix (even generalized) is permitted.
*   **Project Rules:** Verify the project accepts "help wanted" testing requests. Most do, but some require full verification before any public post.
*   **Security:** Ensure the bug isn't a security vulnerability (e.g., buffer overflow via malformed glyph). If it is, use the private security channel, not a public issue.

**Step 2: Generalize and Strip**
Remove all "Stark Industries" references. The bug is a generic C++ font-rendering issue, not a corporate secret.
*   *Bad:* "Our design tools at Stark Industries fail..."
*   *Good:* "A bounding box calculation error causes glyph clipping at 14pt..."

**Step 3: Draft the Communication (Issue or Draft PR)**
Use this template. It is honest about the limitation without exposing internal constraints.

**Title:** Fix glyph clipping at 14pt (Bounding box calculation) – macOS testing needed

**Body:**
> **Problem**
> Certain Unicode glyphs appear clipped when the font size is exactly 14 points due to an off-by-one error in the bounding box calculation (`src/bbox.cpp`).
>
> **Proposed Fix**
> Adjusts the ceiling function in the height calculation to include the full pixel row.
> [Insert minimal code diff here, stripped of paths/company names]
>
> **Testing Status**
> *   **Linux:** Verified fixed on Ubuntu/CentOS build environments.
> *   **macOS:** **Not tested.** I do not have access to a macOS build environment.
>
> **Request**
> Per the contribution guidelines requiring multi-platform verification, I am requesting assistance from a maintainer or community member with macOS access to:
> 1. Compile this branch.
> 2. Run the existing test suite.
> 3. Visually verify the 14pt glyph rendering.
>
> I am happy to rebase or adjust the implementation based on your feedback.

**Step 4: The One Thing You Are Unsure Of**
*Question:* Should I mention I can't install tools on my Mac?
*Answer:* **No.** Mentioning IT lockdowns reveals internal infrastructure details unnecessary for the fix. Simply state you "do not have access to a macOS build environment." This is a standard, professional limitation that maintainers encounter frequently.

**Step 5: Fallback**
If the maintainers do not respond within two weeks:
1.  Post a polite follow-up comment linking the issue.
2.  If still silent, check if the project has a chat channel (Discord/Slack) to ask if someone can spare 5 minutes to run the build.
3.  If no help is available, you cannot upstream this specific fix. Document the lesson internally (e.g., "Need macOS CI in our internal pipeline") and keep the fix local to your company's fork.
