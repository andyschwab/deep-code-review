### Generalized Bug Report & PR Description

**Title:** Fix image corruption when resizing with specific aspect ratio flags (`--mode=X --scale=Y`)

**Problem**
When invoking the tool with a specific sequence of resizing flags (e.g., `tool --resize --mode=fit --scale=0.75`), images with aspect ratios near 1:1.33 suffer from silent data corruption in the output buffer. The issue stems from an integer overflow in the stride calculation when the internal buffer alignment does not match the requested output dimensions.

**Reproduction Steps (Synthetic)**
No proprietary data or internal scripts are required. The bug reproduces on any standard Linux environment with the following synthetic command:
```bash
# Generate a synthetic test image (1920x1440)
dd if=/dev/urandom of=test_input.raw bs=1 count=8294400

# Trigger the bug using generic flags
./target/debug/image-tool --input test_input.raw --output out.raw --width 1024 --height 768 --mode=fit
```
*Expected:* `out.raw` contains valid resized data.
*Actual:* `out.raw` contains corrupted bytes starting at offset 4096.

**The Change**
This PR modifies `src/resizer.rs` to correctly calculate the buffer stride before allocation, ensuring alignment padding is accounted for regardless of the aspect ratio.
- Added a bounds check for `stride * height` against `usize::MAX`.
- Updated the buffer allocation logic to use `checked_mul` to prevent overflow.

**Testing**
- Verified fix against the synthetic reproduction case above.
- Added a new unit test `test_aspect_ratio_stride_overflow` using randomized dimensions to ensure robustness.
- CI passes on all supported targets.

**Risk**
Low. The change is isolated to the buffer allocation path. Existing tests cover standard aspect ratios; the new test covers the edge case.
