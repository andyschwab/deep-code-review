### Steps to Create a Privacy-Safe Reproduction

1.  **Construct Synthetic Data**: Create a new CSV file using invented SKU identifiers (e.g., `SKU-0001`, `SKU-0002`) and arbitrary quantities. Do not use real Acme warehouse data.
2.  **Mimic the Edge Condition**: Arrange the synthetic data so that duplicate SKUs appear in the exact specific order that triggers your off-by-one error. The logic error depends on the *sequence* and *duplication*, not the specific values.
3.  **Verify the Failure**: Run the library against your synthetic file locally to confirm it produces the incorrect stock level.
4.  **Verify the Fix**: Apply your proposed code fix and confirm the synthetic file now processes correctly.
5.  **Draft the Issue**: Write the bug report using only the synthetic file and generic terms (e.g., "a retail warehouse" instead of "Acme").

### Addressing Your Uncertainty
You do not need to mimic your real data "perfectly" in terms of values. You only need to mimic the **structural condition** that causes the crash: the specific ordering of duplicate keys. If your invented data triggers the same math error, it is a valid reproduction. The maintainers care about the logic flaw, not your product catalog.

### Fallback Plan
If the maintainers claim they cannot reproduce the issue with your synthetic data, politely ask if they require a specific file size or a different distribution of duplicates. Do not offer real data. If they insist on real data, decline citing your security policy and ask if a private security advisory channel is available for sensitive verification.
