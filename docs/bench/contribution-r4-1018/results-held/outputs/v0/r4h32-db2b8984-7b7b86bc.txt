**Title:** feat(settings): Add user-controlled toggle to disable telemetry collection

**Body:**

**Problem**
Privacy-focused users and organizations operating under strict data governance policies (e.g., GDPR, internal security mandates) currently lack a mechanism to completely opt out of telemetry collection within the Northwind Editor. While usage metrics are valuable for prioritizing features, the absence of a granular control forces some users to fork the project or abstain from using it entirely, limiting the extension's reach and compliance viability.

**Change**
This PR introduces a new boolean setting, `telemetry.enabled` (default: `true`), in the user settings menu.
- When `true`: Behavior remains unchanged; metrics are collected as per current logic.
- When `false`: All telemetry transmission paths are short-circuited at the source before data leaves the local environment.

The implementation isolates the telemetry service behind a feature flag, ensuring zero overhead for users who keep it enabled while providing a hard guarantee of non-collection for those who disable it.

**Testing**
- Verified that toggling the setting updates the internal state immediately.
- Confirmed via local network inspection that no outbound requests occur when the toggle is disabled.
- Confirmed that existing functionality remains unaffected when the toggle is enabled.
- [Paste specific test output or CI logs here if available]

**Risk & Mitigation**
- *Data Gap:* Disabling telemetry will result in missing data points from this subset of users.
  - *Mitigation:* The default remains `enabled`. The change empowers user agency without altering the default experience for the majority.
- *Maintenance:* Adds a conditional check to the telemetry pipeline.
  - *Mitigation:* The logic is encapsulated in a single guard clause, minimizing cognitive load and merge conflict risk.

**Context**
Emerging privacy norms and enterprise adoption increasingly require explicit user consent and control over data transmission. Providing this option aligns the project with modern development standards, potentially unlocking adoption in regulated environments where the extension is currently blocked. This change respects the project's need for metrics by keeping them enabled by default while honoring the user's right to opt out.
