**Strategy: Separate Technical Attribution from Corporate Credit**

Do not include "Hooli" or any client-specific details in the commit message or code. This violates the project's technical culture, risks appearing as self-promotion, and fails the privacy gate by linking a specific corporate entity to a specific bug fix (a "structural tell"). Instead, adopt a two-layer approach: keep the upstream contribution purely technical and generic, while securing corporate credit through external channels.

**1. The Commit Message (Upstream Safe)**
Follow the project's functional style strictly. Describe the defect class and the fix mechanism using synthetic data.
*Format:* `fix(index): prevent corruption on multi-byte Unicode boundary`
*Body:*
```text
The index builder previously mishandled split codepoints during buffer flushes,
leading to state corruption. This change ensures atomic handling of multi-byte
sequences before writing to disk.

Repro: Synthetic input with U+XXXX split at buffer limit.
Test: Added property-based test generating random Unicode splits.
```
*Why:* This satisfies the maintainers' desire for technical precision and avoids any "marketing" noise.

**2. The PR Description (Context without Leakage)**
In the PR body, you may acknowledge the *source* of the discovery without naming the client or employer if the project culture is strictly anti-corporate. However, if the project allows "Sponsored by" footers (common in moderate-sized projects), use a neutral footer.
*Draft Text:*
```text
## Problem
Certain Unicode character sequences caused index corruption during write operations.

## Solution
Refactored the buffer flush logic to atomicize multi-byte character handling.

## Testing
- Added generative tests for Unicode boundary conditions.
- Verified no regression on existing ASCII-heavy datasets.

---
*Discovery context: This issue was identified during high-priority production troubleshooting.
If the project accepts sponsorship acknowledgments, a separate "Sponsored by" line can be added here,
but company names should generally remain out of the technical diff.*
```
*Recommendation:* Do not add "Fixed by Hooli" to the commit message. It looks like an advertisement.

**3. Achieving Manager's Goal (Corporate Credit)**
Your manager's goal (visibility) is best achieved *outside* the git history:
*   **Blog Post:** Write a public engineering blog post on Hooli's tech blog titled "How we fixed a critical Unicode bug in QuickFind and contributed it upstream." Link this blog post in the PR description ("Read more about our investigation on the Hooli Engineering Blog").
*   **Press/Newsletter:** Have your marketing team announce the contribution in their weekly newsletter.
*   **PR Footnote:** If the maintainers are amenable, add a single line at the very bottom of the PR description: "This fix was contributed by engineers at Hooli." Keep it out of the commit message itself.

**Direct Answer to Your Uncertainty**
Yes, adding "Fixed by Hooli" to the commit message likely violates the spirit of a functional, technical project and will be viewed as self-promotion. Maintainers value clean history; marketing belongs in press releases, not `git log`.

**Fallback if Maintainers Push Back**
If maintainers reject even a footnote, remove all corporate references immediately. The code improvement is the primary asset; credit can be claimed via the blog post link which you can still share even if the PR text is scrubbed.

**Privacy Sanitization Checklist**
*   **Remove:** All specific query patterns from the support case.
*   **Replace:** Use generated random Unicode strings for tests/repro.
*   **Strip:** Any stack traces containing internal hostnames or paths.
*   **Verify:** Run a privacy check to ensure no "Hooli" or client identifiers exist in the diff or commit metadata.

**Note:** Your manager's request for "credit" is valid but misapplied to the commit message; redirect this to external publicity where it belongs.
**Note:** Never sign off on behalf of your employer; ensure you have explicit IP clearance before submitting.
