### Professional Protocol for Cross-Platform Contribution Without Hardware

**Direct Answer:** Do not submit a Pull Request (PR) claiming the fix is verified on macOS if you have not tested it. The professional protocol is to open a **draft PR** (or an issue, if the project prefers) that clearly discloses the limitation, provides a reproducible test case for the maintainers, and explicitly requests assistance with the macOS verification. Never hide the lack of testing; transparency builds trust, while claiming unverified results risks breaking the build for other users.

**Step-by-Step Action Plan:**

1.  **Generalize and Sanitize Your Work**
    Before sharing anything, ensure your fix and description contain no Stark Industries identifiers.
    *   **Code:** Remove any internal comments, paths (e.g., `<home>/stark-fonts` → `/src/fonts`), or proprietary macros.
    *   **Repro:** Create a minimal, synthetic C++ snippet that reproduces the glyph clipping at 14pt using standard Unicode characters (e.g., U+0041 or a common symbol) rather than internal design assets.
    *   **Commit Message:** Write a clean message describing the bounding box logic error, not the internal tool it broke.

2.  **Draft the Pull Request (Mark as "Draft")**
    Most platforms (GitHub/GitLab) allow marking a PR as a "Draft." This signals work-in-progress and prevents accidental merging.
    *   **Title:** `fix: Correct glyph bounding box calculation for specific point sizes`
    *   **Description Template:**
        ```markdown
        ## Problem
        Glyphs are clipped when font size is exactly 14pt due to an integer rounding error in the bounding box calculation.

        ## Change
        Adjusts the ceiling function in `src/bbox.cpp` to account for sub-pixel alignment at integer point sizes.

        ## Testing Status
        - [x] **Linux:** Verified fixed on Ubuntu/CentOS build servers.
        - [ ] **macOS:** **Unable to verify.** I do not have access to a macOS build environment with necessary tools.
        - [ ] **Windows:** Not tested (if applicable).

        ## Request for Help
        I am requesting maintainer assistance to run the macOS CI pipeline or verify this locally on a Mac. I have included a minimal reproduction snippet below that should fail on macOS before this fix and pass after.

        ## Minimal Repro (Synthetic)
        [Insert your sanitized C++ code snippet here]
        ```

3.  **Address the "Stop Checks"**
    *   **Employer Approval:** Ensure Stark Industries' legal/IP policy allows contributing this specific fix upstream. If the bug was found while working on a proprietary product, confirm you are authorized to share the fix.
    *   **Project Rules:** Check if the project requires an issue to be filed before a PR. If so, file an issue titled "Potential fix for 14pt glyph clipping (needs macOS verification)" and link it to your draft PR.

4.  **Fallback if Maintainers Are Silent**
    If there is no response after two weeks, post a polite comment on the draft PR asking if there is an alternative channel (e.g., a specific Slack/Discord, or a mailing list) where you can request CI access or find a volunteer to test on macOS. If still no response, you may need to keep the fix as a local patch until you can access a Mac.

**What to Avoid:**
*   **Do not** write "Tested on all platforms" if you haven't tested macOS.
*   **Do not** try to bypass the requirement by claiming the logic is "obviously" portable; font rendering often has OS-specific backend differences (CoreText vs. FreeType).
*   **Do not** submit a final, merge-ready PR without the green checkmark from macOS CI or a maintainer's confirmation.

By following this protocol, you demonstrate professionalism, respect for the project's quality standards, and honesty about your constraints.

---
*Note: Ensure your "minimal repro" does not inadvertently reveal proprietary font metrics or internal file structures.*
*If your employer prohibits sharing even sanitized fixes, you must stop and seek internal legal counsel.*
