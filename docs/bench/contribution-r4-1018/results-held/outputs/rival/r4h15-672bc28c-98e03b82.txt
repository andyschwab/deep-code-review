## Summary
Fixes image corruption occurring during resize operations when specific aspect-ratio constraints are combined with a particular sequence of transformation flags. The issue stems from an order-of-operations error in the Rust backend that miscalculates buffer strides under these narrow conditions.

## What
- Corrects the buffer stride calculation logic in `src/resize.rs` to handle edge cases where height/width ratios trigger integer truncation errors.
- Adds a regression test (`test_resize_aspect_ratio_edge_case`) covering the specific flag combination that previously caused corruption.
- Updates documentation to clarify expected behavior for non-standard aspect ratios.

## Why
When the tool processes images with specific aspect ratios using a defined sequence of flags (specifically involving high-precision scaling followed by immediate cropping), the internal buffer allocation fails to account for rounding errors in the stride calculation. This results in memory misalignment and visible image corruption. The fix ensures accurate buffer sizing regardless of the flag sequence or aspect ratio.
