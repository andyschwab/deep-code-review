**Immediate Action Plan**

1.  **Do Not Close or Reopen Yet:** Closing the PR immediately draws attention to a "mistake" without context and creates a new PR that still lacks the necessary transparency. Reopening creates noise. Keep the current PR open for now.
2.  **Post a Transparent Disclosure Comment Immediately:** You must proactively address the leak before a maintainer investigates the edit history. Post a comment on the PR with this exact structure:

**Why this approach:**
GitHub edit histories are visible, but proactive honesty usually mitigates "malicious intent" assumptions. By admitting the error and clarifying the link was dead to the public, you remove the "security threat" element, leaving only a "process error." Most open-source projects value transparency over perfection; hiding it guarantees a ban if discovered, while owning it often results in a warning.

**Note:** Do not attempt to scrub git history for a description edit; it is impossible and unnecessary. Only the PR body history exists, which you have already addressed by disclosing it.
