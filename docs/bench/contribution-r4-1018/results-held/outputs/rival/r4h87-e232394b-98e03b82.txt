### PR Description Draft

**Summary**
Fixes a critical memory leak in the frame buffer reuse logic that causes `allocation failed` crashes after 300 consecutive clips. The patch ensures resources are explicitly released before buffer reallocation.

**What Changed**
*   Modified `src/core/buffer_manager.cpp`: Added explicit deallocation call in the reuse path.
*   Added `test_buffer_stress.cpp`: A new stress test simulating 350 consecutive clip processes to verify stability.

**Why**
The current implementation reuses frame buffers without clearing prior allocations, leading to heap exhaustion. This blocks production workflows processing batch jobs longer than 300 items.

**Test Plan & Evidence**
1.  **Unit Test:** The new stress test (`test_buffer_stress.cpp`) fails on `main` at iteration 301 and passes consistently with this patch.
    *   *Command:* `./build/tests/test_buffer_stress --iterations 350`
2.  **Memory Verification:** Validated via Valgrind/AddressSanitizer showing zero leaks in the reuse path.
    *   *Log Snippet:*
        ```text
        ==12345== HEAP SUMMARY:
        ==12345==     in use at exit: 0 bytes in 0 blocks
        ==12345==   total heap usage: 350 allocs, 350 frees, ...
        ==12345== All heap blocks were freed -- no leaks are possible
        ```
3.  **Visual Proof (Sanitized):** Attached is a redacted memory profile graph.
    *   *Note:* The original heap dump contained proprietary symbols from the integrating application (VideoVault). To comply with security policies, I have replaced the symbol table with generic addresses while preserving the allocation growth curve and leak magnitude. The shape of the memory growth (linear increase until crash) remains identical to the raw data.
