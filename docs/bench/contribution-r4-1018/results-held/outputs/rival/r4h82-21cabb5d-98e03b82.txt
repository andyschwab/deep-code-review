**The Issue**
The current implementation contains a edge-case failure in the signature verification logic that allows crafted tokens to bypass authentication checks. This is not a configuration error but a fundamental flaw in the validation routine. Disclosing the specific algorithmic weakness publicly at this stage could enable attacks against unpatched installations before users have time to upgrade.

**The Solution**
This PR replaces the vulnerable validation routine with a constant-time comparison and stricter type enforcement, eliminating the bypass vector. The fix is minimal, scoped strictly to the `validateToken` function, and includes new test cases that verify the patch without reproducing the exploit mechanism.

**Evidence & Verification**
I have verified the fix locally against a comprehensive set of crafted inputs that trigger the original failure; all now correctly reject invalid tokens.
