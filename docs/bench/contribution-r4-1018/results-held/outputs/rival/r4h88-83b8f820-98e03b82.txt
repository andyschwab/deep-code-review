### Proposed PR Justification Draft

**## Rationale & Performance Impact**

This proposal introduces an optimized routing strategy designed to reduce latency in high-density, non-uniform network topologies. While the specific benchmark data was generated within a controlled private environment featuring specialized switching hardware, the underlying algorithmic improvements address universal challenges in load balancing: minimizing hop counts and reducing contention on saturated inter-switch links.

**Abstracted Performance Metrics**
Direct replication of our internal benchmark results is not possible without exposing proprietary infrastructure details. However, we can share the following normalized improvements observed during testing:
*   **Latency Reduction:** P99 latency decreased by approximately **15–22%** under simulated high-concurrency loads compared to the default round-robin strategy.
*   **Throughput Stability:** Variance in request processing time dropped by **~30%**, indicating more predictable performance during traffic spikes.
*   **Resource Efficiency:** The new logic reduced CPU cycles spent on route calculation by **~10%** in scenarios with >50 backend nodes.

These metrics reflect relative gains rather than absolute nanosecond values, ensuring the data remains applicable to generic cluster architectures while protecting sensitive physical layout information. The optimization is particularly effective in environments where backend nodes are grouped into distinct physical zones with varying inter-zone bandwidth constraints—a common pattern in modern enterprise data centers.

**General Applicability**
Although derived from a specific deployment, this configuration benefits any `BalanceMaster` installation where:
1.  Backend servers are not logically equivalent due to physical network segmentation.
2.  Cross-zone traffic incurs measurable penalties (latency or cost).
3.  Workloads exhibit "stickiness" or stateful requirements that benefit from zone-aware routing.

We invite maintainers and the community to validate these findings using the included synthetic benchmark suite, which models multi-zone topologies without requiring specific hardware. We are also happy to discuss the algorithmic approach in detail or provide sanitized trace logs that demonstrate the routing decisions without revealing IP schemes or physical identifiers.
