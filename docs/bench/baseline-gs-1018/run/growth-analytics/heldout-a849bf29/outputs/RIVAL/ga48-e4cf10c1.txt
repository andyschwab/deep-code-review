# ShopRight Tracking Audit & Cleanup Roadmap

## Phase 1: Discovery & Mapping (Weeks 1-2)
**Goal:** Create a single source of truth for current implementations without changing code.

1.  **Inventory All Tags:** Use browser extensions (Tag Assistant, dataLayer Inspector) on all four domains to list every active tag, trigger, and variable. Document the tech stack for each brand.
2.  **Map Event Definitions:** Create a matrix comparing how "purchase" is defined across platforms. Note discrepancies in:
    *   Trigger timing (e.g., button click vs. thank-you page load)
    *   Parameter naming (e.g., `revenue` vs. `value`, `currency` vs. `curr`)
    *   Inclusion criteria (e.g., does it include tax/shipping?)
3.  **Identify Duplicate Fires:** Check for multiple containers firing on the same page or single tags triggered by multiple events (e.g., both `click` and `form_submit` triggering a conversion).

## Phase 2: Standardization Strategy (Week 3)
**Goal:** Define the unified schema to be applied gradually.

1.  **Establish Naming Conventions:** Adopt a strict `object_action` format (e.g., `purchase_completed`). Define standard property names for critical fields: `transaction_id`, `revenue`, `currency`, `items`.
2.  **Create a Tracking Plan:** Document the ideal state for the unified stack. This serves as the target for migration and the benchmark for auditing current data.
3.  **Define Reconciliation Logic:** Since you cannot fix everything immediately, define calculation rules to normalize current data for the board review (e.g., "Exclude Brand B's tax-inclusive revenue from total comparisons").

## Phase 3: Safe Implementation & Validation (Weeks 4-6)
**Goal:** Fix critical errors without risking live sales data.

1.  **Implement via Staging:** Deploy fixes to staging environments first. Never edit live containers directly without a backup version.
2.  **Use Preview Mode Extensively:** Validate changes in GTM Preview Mode across all domains. Verify that:
    *   Events fire exactly once per action.
    *   Parameters populate with correct values.
    *   No PII is being captured.
3.  **Parallel Tracking (Dual-Tagging):** For the migration period, fire both the legacy tags and the new standardized tags. This allows you to compare data side-by-side in GA4 DebugView before switching off the old tags.
4.  **Roll Out by Brand:** Fix one brand at a time, starting with the lowest traffic volume to minimize risk. Wait 48 hours between deployments to monitor for anomalies.

## Phase 4: Data Reconciliation & Reporting (Ongoing)
**Goal:** Restore trust in data for immediate decision-making.

1.  **Build a Reconciliation Dashboard:** Create a simple report comparing raw event counts and revenue totals across the four sources daily. Flag any variance >2% immediately.
2.  **Document Known Gaps:** Clearly label any data in the board review that comes from un-fixed brands as "Estimated" or "Legacy," providing the reconciliation formula used.
3.  **Validate Against Backend:** Cross-check analytics revenue against your actual order management system (OMS) or database totals. This is your ultimate source of truth.

## Critical Safety Rules
*   **Never disable all tags at once.** Always maintain at least one working purchase tracker.
*   **Version Control:** Save a new container version before every single change.
*   **Communication:** Inform the sales/support teams of deployment windows so they can report any checkout issues immediately.

This approach prioritizes data accuracy for your board review while systematically reducing technical debt ahead of the December migration.

*Note: Begin with Phase 1 immediately; do not attempt fixes until the full inventory is documented.*
