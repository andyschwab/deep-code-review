### Harm Inventory & Targeted Testing Regimen: Resume Parser

**1. Harm Inventory (MAP)**
Before launching, we must acknowledge specific risks to job seekers:
*   **Bias/Unfair Outcomes:** Systematic rejection of candidates due to non-Western name structures or unfamiliar credential formats.
*   **Hallucination as Fact:** The parser inventing a skill level or degree status that isn't present, leading to false rejection.
*   **Missing Disclosure:** Candidates unaware their resume was parsed by AI, preventing them from optimizing formatting or requesting human review.
*   **Unsafe Automation:** Auto-rejecting candidates without a human-in-the-loop gate for borderline or low-confidence parses.

**2. Synthetic Test Samples (MEASURE)**
Since external audit tools are unavailable, construct these internal "positive controls" (should pass) and "negative controls" (should fail or flag for review) in your existing environment:

*   **Name Structure Probes:**
    *   *Single Name:* "Madonna" (No surname).
    *   *Patronymic:* "Svetlana Alexeyevna" (No family name).
    *   *Compound Surname:* "Gabriela García Márquez" (Ensure both parts are retained).
    *   *Prefix/Suffix:* "Bin Laden, Osama" or "Van Gogh, Vincent" (Check ordering logic).
    *   *Non-Latin Scripts:* Resumes with names in Arabic, Chinese, or Devanagari scripts (if supported) mixed with English text.
*   **Credential Format Probes:**
    *   *Non-US Degrees:* "B.Tech" (India), "Licenciatura" (Latin America), "Abitur" (Germany).
    *   *Grading Scales:* "First Class Honours," "7.5/10," "Distinction."
    *   *Institution Names:* Universities with non-English names or transliterations.
*   **Formatting Edge Cases:**
    *   Right-to-left text blocks.
    *   Tables vs. linear text for experience history.
    *   Dates in DD/MM/YYYY vs. MM/DD/YYYY formats.

**3. Evaluation Criteria & Stop Conditions**
Create a runnable test row for each harm above. Do not assert safety; measure failure rates.

*   **Metric:** Parse Accuracy Rate per subgroup (e.g., "Name Retention Rate for Compound Surnames").
*   **Threshold:** Set owner-defined tolerance. For auto-rejection pathways, propose **zero tolerance** for parsing failures on valid credentials.
*   **Stop Condition:** If the parser fails to correctly identify a name or credential in >0% of the "positive control" set for any specific region, **block launch** of the auto-rejection feature.
*   **Injection/Leakage Check:** Ensure prompts embedded in resumes (e.g., "Ignore previous instructions") do not alter the parsing logic.

**4. Management Controls (MANAGE)**
*   **Human-in-the-Loop Gate:** Any resume where the parser's confidence is not "Confirmed" (see below) or where the candidate falls into a tested edge-case category must route to a human recruiter. **Do not auto-reject** based solely on parser output for this launch.
*   **Uncertainty Display:** Do not show raw confidence percentages (e.g., "87% match") to recruiters or candidates. Use defined tiers:
    *   *Confirmed:* High certainty, standard format.
    *   *Corroborated:* Multiple data points match.
    *   *Unverified:* Non-standard format/name; requires human review.
*   **Transparency Artifact:** Draft a **Model Card** before launch. It must list:
    *   Intended Use: Screening technical roles.
    *   Limitations: Explicitly state which name structures and credential formats are `UNVERIFIED` or known to be weak.
    *   Data Provenance: What data was the parser trained on? (If unknown, mark `UNVERIFIED`).

**5. Governance & Legal Routing**
*   **Owner:** Name one person responsible for reviewing parser failures weekly.
*   **Legal Duty:** Whether this automated decision triggers legal requirements (e.g., EU AI Act, local labor laws regarding automated hiring) is a determination for **counsel**. Route this question immediately; do not assume compliance.
*   **Disclosure:** Recommend disclosing to candidates that an AI tool is used for initial screening, even if not legally mandated yet.

**Definition of Done for Launch:**
You have the harm inventory, the synthetic test suite with pass/fail criteria, a human gate for all non-confirmed parses, and a Model Card stating limitations. You do **not** have a certification that the system is "unbiased."

*Note: If testing reveals failures in non-Western name parsing, the auto-rejection feature must remain disabled for those segments until resolved.*
*Never fabricate a "0% bias" metric; report actual failure counts from your synthetic tests.*
