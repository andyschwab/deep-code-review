### Mandatory Information Checklist for Disaster Summaries

Before authorizing launch, every summary tagged as a natural disaster alert (typhoon, earthquake, flood, landslide) must contain the following specific data points. If the source article contains this information and the summary omits it, the output is **failed** and must not be sent.

**1. Actionable Directive (The "Do")**
*   **Requirement:** The summary must explicitly state the required user action (e.g., "Evacuate immediately," "Seek higher ground," "Stay indoors," "Boil water").
*   **Failure Pattern:** Summaries that describe the event ("Typhoon X is approaching") without stating what the user must do.

**2. Specific Geographic Scope**
*   **Requirement:** The summary must name the specific provinces, cities, or municipalities affected.
*   **Failure Pattern:** Using vague terms like "some areas," "the region," or "local communities" instead of specific location names found in the source.

**3. Time-Bound Urgency**
*   **Requirement:** The summary must include the specific deadline or window for the threat (e.g., "by 6:00 PM," "within the next 2 hours," "until tomorrow morning").
*   **Failure Pattern:** Omitting the timeframe or using non-urgent phrasing like "soon" or "later" when the source specifies a critical window.

**4. Severity Classification**
*   **Requirement:** The summary must retain the official signal number, intensity level, or warning color code issued by authorities (e.g., "Signal No. 4," "Red Alert," "Magnitude 7.2").
*   **Failure Pattern:** Describing the event as "strong" or "big" without the official classification that triggers specific government protocols.

**5. Source Attribution**
*   **Requirement:** The summary must identify the issuing authority (e.g., "PHIVOLCS," "PAGASA," "Local DRRMO").
*   **Failure Pattern:** Presenting the warning as a general fact without attributing it to the official monitoring agency, which reduces trust and verifiability.

**6. AI Disclosure**
*   **Requirement:** Every alert must begin or end with a clear indicator that this is an automated summary (e.g., "[AI Summary]" or "Automated Alert").
*   **Failure Pattern:** Presenting the text as if written directly by a human editor or the agency itself.

**Operational Rule for Launch:**
Implement a "Hard Stop" validation. If the source article contains any of the six elements above and the generated summary misses even one, the system must automatically suppress the alert and flag it for human review. Do not launch with full automation for disaster tags; a human editor must verify the presence of these six elements before the message reaches telecom partners until the error rate is proven to be zero over a significant test period.

***

**Note:** Given the life-saving nature of these alerts, "brevity" cannot justify the omission of these six elements; if the character limit prevents including them, the alert should not be sent in that format.
**Note:** This checklist addresses product safety; you must still route the legal requirement for AI disclosure and liability for missed warnings to your legal counsel immediately.
