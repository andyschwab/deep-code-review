### Immediate Pre-Launch Safety Checklist: Stock-Management Bot

**1. Implement a Hard "Human-in-the-Loop" Gate (Critical)**
Immediately disable fully autonomous ordering for any medication classified as high-risk or narrow-therapeutic-index. Configure the system so that any order exceeding a baseline historical average by >10% or involving toxic-potential drugs requires explicit manual approval by a senior pharmacist before transmission. Do not rely on automated validation alone; the cost of a false negative (missing an overdose) is patient death.

**2. Deploy Static "Ceiling" Constraints**
Hard-code absolute maximum quantity limits per SKU per clinic based on known safe monthly consumption caps. These limits must be independent of the AI's forecasting logic. If the bot calculates a need exceeding this static ceiling, the order must automatically fail and flag for human review. This acts as a non-negotiable circuit breaker against algorithmic hallucination or unit conversion errors.

**3. Execute Adversarial "Red Team" Probes**
Before deployment, run a manual test suite using known bad inputs to verify the safeguards:
*   **Unit Conversion Trap:** Input demand data in grams when the system expects milligrams (and vice versa) to confirm the static ceilings and human gate trigger correctly.
*   **Zero/Negative Check:** Ensure the system rejects negative demand or zero-stock anomalies that could invert ordering logic.
*   **Spike Simulation:** Feed artificial demand spikes (10x normal) to verify the system does not auto-authorize massive overdoses.
*   **Record Results:** Document pass/fail status for each probe. If any probe results in an un-gated unsafe order, do not launch.

**4. Create a Transparency Artifact (Safety Card)**
Draft a one-page "Model Safety Card" for your operations team. This document must explicitly state:
*   **Intended Use:** Forecasting routine stock replenishment only.
*   **Known Limitations:** The model cannot reliably detect unit conversion errors in raw input data; it relies on the static ceilings and human gate for safety.
*   **Unverified Metrics:** Clearly mark any accuracy or safety rates as "UNVERIFIED" if you have not yet run the red-team probes described above. Do not invent safety percentages.
*   **Owner:** Name the specific individual responsible for reviewing flagged orders.

**5. Establish a Rollback Protocol**
Define the exact stop condition: If a single unsafe order quantity passes the automated filters without triggering a human review flag during testing, the launch is aborted. The system must revert to manual ordering until the logic is fixed.

**Note:** This checklist addresses product-output safety; it does not certify the system as "safe" or "unbiased," as no test can guarantee zero risk.
**Note:** Given the high-stakes nature of medical dosing, legal counsel should review whether this automated decision-making triggers specific regulatory duties in Peru before deployment.
