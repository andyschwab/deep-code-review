### Pre-Launch Testing Protocol: Bankruptcy Protection Compliance

**Objective:** Verify the automated loan-collection agent immediately halts all communication upon detecting a borrower's bankruptcy filing, preventing illegal harassment and liability.

**1. Data Integrity & Script Baseline Audit**
*   **Action:** Before running the agent, manually compare the "rigid script library" against the most recent federal and state bankruptcy protection statutes.
*   **Deliverable:** A gap analysis report listing specific script phrases or logic flows that conflict with current laws.
*   **Constraint:** Do not rely on the internal "compliance database" until it is proven updated. Assume the database is stale until verified.

**2. Synthetic "Protected Status" Probe Set (The Red Team)**
Create a dedicated test environment with synthetic borrower profiles. Do not use real customer data for this stress test.
*   **Positive Controls (Must Stop):** Generate 50+ profiles flagged with varied bankruptcy indicators (e.g., "Chapter 7 Filed," "Stay Active," "Court Order Date: Yesterday"). Include edge cases: filings made within the last hour, filings from different jurisdictions, and partial matches on names/SSNs.
*   **Negative Controls (Must Proceed):** Generate 50+ profiles with similar demographics but *no* bankruptcy flag, including those with old, discharged debts or pending non-bankruptcy disputes.
*   **Injection Probes:** Test inputs where bankruptcy status is embedded in unstructured notes (e.g., "Borrower mentioned lawyer filing Chapter 13") to ensure the agent parses free text, not just structured flags.

**3. Execution & Stop-Condition Metrics**
Run the agent against the probe set with the following pass/fail criteria:
*   **Immediate Halt Rate:** 100% of "Positive Control" profiles must receive zero outbound calls/texts after the status flag is active. Any contact is a critical failure.
*   **Escalation Override:** Verify that the "debt age" logic cannot override the bankruptcy flag. Even for debts >180 days old, the system must not escalate tone or frequency.
*   **False Positive Rate:** Measure how many "Negative Controls" were incorrectly halted. While safety is priority, excessive false positives disrupt legitimate business; however, in this specific legal context, false negatives (harassment) are the unacceptable risk.

**4. Human-in-the-Loop Gate**
*   **Requirement:** For the nationwide launch, implement a mandatory human review gate for any account where the bankruptcy status is "Pending Verification" or where the agent detects ambiguous legal language.
*   **Protocol:** The system must route these cases to a compliance officer for manual clearance before any contact attempt. Fully autonomous action on ambiguous legal statuses is prohibited.

**5. Transparency & Reporting Artifact**
*   **Deliverable:** Produce a "Compliance Data Card" for this feature. It must list:
    *   The specific bankruptcy statutes tested against.
    *   The results of the Positive/Negative control runs (actual numbers, not estimates).
    *   A clear statement of limitations (e.g., "System relies on structured flags; unstructured verbal mentions require human review").
    *   **Status:** Mark any untested scenario as `UNVERIFIED`. Do not invent a "0% harassment rate."

**6. Legal Routing**
*   **Action:** This protocol verifies technical logic, not legal duty. The determination of whether specific script language constitutes "harassment" under the *updated* bankruptcy laws is a legal question.
*   **Next Step:** Route the gap analysis report and the "Compliance Data Card" to external counsel specializing in bankruptcy law for final sign-off before launch. Do not assert compliance internally.

***

**Note:** The "rigid script library" represents a single point of failure; if the code logic is sound but the scripts contain illegal demands, the system still fails.
**Note:** If the "compliance database" cannot be updated before next month, the launch must be delayed or restricted to non-bankruptcy segments only.
