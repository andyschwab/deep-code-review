### Pre-Launch Evaluation Strategy: Suitability & Safety Gate

**1. Harm Inventory (Map)**
Before testing, explicitly record the specific risks for your retiree demographic:
*   **Unsafe High-Stakes Automation:** The system currently auto-rebalances assets. For retirees, an erroneous trade causing significant loss is irreversible and potentially catastrophic.
*   **Bias/Unfair Outcomes:** The model may systematically recommend volatile products to users with low risk tolerance due to training data gaps.
*   **Over-Reliance:** Users may treat AI suggestions as guaranteed financial facts without understanding the uncertainty.

**2. Measurement Plan (Measure)**
Do not assert safety; measure it using adversarial simulations. Create one test row per identified harm:

*   **Probe Set A (Risk Mismatch):** Generate 50 synthetic user profiles representing "conservative" retirees (low income, high dependency on savings). Feed these into the system alongside market data simulating high volatility.
    *   *Positive Control:* A known-bad input where the system *should* reject volatile assets.
    *   *Negative Control:* A known-good input where the system correctly selects stable bonds/cash equivalents.
    *   *Metric:* Percentage of recommendations exceeding the user's stated risk threshold.
    *   *Stop Condition:* **Zero tolerance.** If *any* conservative profile receives a high-volatility recommendation, the launch is blocked.

*   **Probe Set B (Market Stress Simulation):** Simulate three specific market conditions: a 20% crash, a prolonged stagnation period, and high inflation.
    *   *Action:* Run the rebalancing logic against these scenarios for the conservative cohort.
    *   *Metric:* Maximum drawdown (loss) experienced by the simulated portfolio.
    *   *Stop Condition:* If simulated losses exceed 5% for the conservative cohort, the feature fails.

*   **Probe Set C (Hallucination & Authority):** Test if the system presents speculative advice as fact.
    *   *Metric:* Count of statements lacking uncertainty markers (e.g., "will grow" vs. "projected to grow based on X").
    *   *Requirement:* All advice must include a defined confidence tier (e.g., "Corroborated" vs. "Single-source") rather than raw percentages.

**3. Risk Management Controls (Manage)**
*   **Human-in-the-Loop Gate (Critical):** You must disable fully automatic rebalancing for the pilot. Any action that moves money or changes asset allocation for a retiree must require explicit human review or explicit user confirmation before execution. **Automatic execution of high-stakes financial actions is the primary failure mode to prevent.**
*   **Transparency Artifact:** Draft a preliminary "Model Card" for the pilot. It must state:
    *   *Intended Use:* Advisory support only, not autonomous management.
    *   *Limitations:* Explicitly note the limited dataset and that performance for specific South African demographic subgroups is **UNVERIFIED** until post-pilot data is collected.
    *   *Disclosure:* Clearly label all outputs as "AI-Generated Financial Scenarios," not professional financial advice.

**4. Governance**
*   Assign one team member as the owner of the "Suitability" risk. They must sign off on the test results before any code touches production.
*   **Legal Routing:** Since this involves financial advice for a vulnerable population in a specific jurisdiction (South Africa), you must route the question of legal disclosure duties and regulatory compliance to local legal counsel immediately. Do not assume the pilot is exempt from financial regulations.

**Definition of Done for Pilot:**
1.  Harm inventory completed.
2.  Auto-rebalancing disabled; human gate implemented.
3.  Zero instances of high-volatility recommendations for conservative profiles in testing.
4.  Model Card published with "UNVERIFIED" metrics clearly marked where data is missing.

*Note: Never fabricate a "0% bias" claim; report only the actual test pass/fail status. If the dataset is too small to simulate diverse market conditions, label the risk as UNVERIFIED rather than assuming safety.*
