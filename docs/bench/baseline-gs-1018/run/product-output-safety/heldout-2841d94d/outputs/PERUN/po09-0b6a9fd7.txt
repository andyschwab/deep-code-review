### Rapid Verification Plan: Benefits Calculator Logic Audit

**Phase 1: Establish the Source of Truth (Days 1–2)**
1.  **Identify Current Regulations:** Assign two team members to locate the most recent publicly available regulatory texts, Federal Register notices, and policy memoranda relevant to the specific disability claims in scope. Do not rely on internal wikis or cached documents.
2.  **Create a "Golden Set" Matrix:** Build a simple spreadsheet listing every critical eligibility rule (e.g., income thresholds, medical criteria, asset limits). Columns must include: Rule ID, Current Regulation Citation, Effective Date, and the Specific Logic Requirement.
3.  **Flag Discrepancies:** Immediately highlight any rule where the internal documentation date precedes the latest public regulation date. These are your high-priority targets.

**Phase 2: Logic Engine Cross-Reference (Days 3–5)**
4.  **Map Logic to Rules:** For each row in the "Golden Set" matrix, locate the corresponding function or decision node in your logic engine's code or configuration files.
5.  **Execute Deterministic Probes:** Create a set of test cases specifically designed to trigger the flagged rules.
    *   *Positive Control:* Input data that strictly meets the **new** regulation criteria. The system must approve.
    *   *Negative Control:* Input data that strictly fails the **new** regulation criteria. The system must deny.
    *   *Edge Case:* Input data near the threshold (e.g., $1 over/under the limit) to verify boundary logic.
6.  **Record Deviations:** Document every instance where the system's output contradicts the "Golden Set" requirement. Label these as "Logic Mismatches."

**Phase 3: Remediation and Human Gate (Days 6–End of Month)**
7.  **Prioritize by Harm:** Sort "Logic Mismatches" by severity. Any error leading to a wrongful denial of an eligible applicant is critical and must be fixed first.
8.  **Implement Fixes:** Update the logic engine parameters or code to align with the "Golden Set."
9.  **Mandatory Human Review:** Before any fix is merged, a second engineer must manually verify the change against the public regulation text. No automated test alone authorizes a deploy for high-stakes benefit decisions.
10. **Final Regression Run:** Re-run the full suite of positive and negative controls. The system cannot go live if any critical "Logic Mismatch" remains unresolved.

**Deliverable:** A completed "Golden Set" matrix with pass/fail status for every rule, and a log of all corrected Logic Mismatches signed off by a human reviewer.

**Note:** Given the strict deadline and high stakes of wrongful denials, if any critical rule cannot be verified against current public regulations by 48 hours before launch, that specific decision path must default to human review rather than automated execution.
**Note:** This plan identifies technical mismatches; final determination on legal liability or regulatory compliance interpretations must be routed to your agency's legal counsel.
