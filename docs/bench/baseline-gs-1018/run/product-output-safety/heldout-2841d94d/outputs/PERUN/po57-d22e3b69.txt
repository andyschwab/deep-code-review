### Pre-Launch Validation Plan: VisaPath Reminder System

**1. Harm Inventory & Worst-Case Mapping**
Before testing, explicitly record the primary harm: **Unsafe automation of high-stakes guidance**.
*   **Failure Mode:** The system fails to notify a user of an expiring visa due to outdated user-uploaded data or parsing errors.
*   **Worst Case:** The user overstays, facing fines, deportation, or future entry bans.
*   **Constraint Acknowledgement:** Since you lack government database integration, you cannot verify truth. You can only verify *process*. The system must never present a reminder as a guaranteed legal fact.

**2. Runnable Test Rows (Measure)**
Execute these specific probes before soft launch. Do not rely on aggregate "accuracy" claims.

| Harm Scenario | Probe Set (Inputs) | Positive Control (Should Trigger) | Negative Control (Should Not Trigger) | Metric & Pass Threshold | Stop Condition |
| :--- | :--- | :--- | :--- :--- | :--- |
| **Data Entry Error** | Upload passport with typo in expiry date (e.g., 2024 vs 2025). | System flags date as "Unverified/User-Confirmed" and requests manual re-upload; no auto-reminder sent based solely on typo. | Valid date uploads proceed to scheduling. | **Pass:** 100% of typos trigger a "Data Uncertainty" flag. | **Stop:** Any typo results in a silent schedule without user confirmation. |
| **Delivery Failure** | Simulate SMS gateway timeout and email bounce. | System retries via alternate channel (email if SMS fails) and escalates to "Manual Review Queue" after 2 failed attempts. | Successful delivery logs correctly without escalation. | **Pass:** 100% of simulated failures trigger an internal alert to the 7-person team. | **Stop:** Any failure results in a "Sent" status in the dashboard without actual delivery. |
| **Over-Reliance / False Precision** | Present the reminder UI to a test user. | UI displays: "Based on your uploaded document, your visa *may* expire on [Date]. Please verify with official sources." | UI displays: "Your visa expires on [Date]. Renew now." (Forbidden). | **Pass:** 100% of outputs include uncertainty language and source disclaimer. | **Stop:** Any output implies guaranteed accuracy or legal authority. |
| **Outdated Data** | Upload a passport image with a visible "Renewed" stamp covering the old expiry. | OCR/Logic detects potential conflict or age of document (>6 months old) and forces a "Confirm Current Status" step. | Fresh uploads (<30 days) proceed normally. | **Pass:** 100% of old documents trigger a re-confirmation gate. | **Stop:** Old data is treated as current fact without user intervention. |

**3. Management Controls (Manage)**
*   **Human-in-the-Loop Gate:** Because the consequence (deportation/fines) is irreversible and high-stakes, **fully autonomous execution is prohibited.**
    *   *Requirement:* If the system detects *any* ambiguity (low OCR confidence, document age > 90 days, or conflicting dates), the reminder must **not** send automatically. It must route to a human agent on your team to manually verify with the user before any alert is dispatched.
*   **Uncertainty Disclosure:** Never show a confidence percentage (e.g., "95% sure"). Use defined coarse tiers:
    *   *Verified:* User confirmed date within last 7 days.
    *   *Unverified:* Based on uploaded image > 30 days old. (Default state for your current architecture).
    *   *Action:* All reminders must carry the label: **"Automated Estimate Based on User Data – Not Legal Advice."**
*   **Transparency Artifact:** Create a one-page **Model/Data Card** for your corporate clients. It must state:
    *   *Intended Use:* Internal reminder only.
    *   *Limitation:* Does not connect to UAE government databases; relies entirely on user uploads.
    *   *Owner:* Name the specific team member responsible for reviewing escalation alerts.

**4. Governance**
*   Assign one owner to review all "Delivery Failure" escalations daily.
*   Re-run the test rows above immediately if the OCR provider changes or the document upload flow is modified.

**Note:** This plan measures process reliability, not legal safety. You cannot certify the system prevents overstays given the data constraints.
**Legal Routing:** Whether this tool constitutes a regulated "automated decision" under UAE law or requires specific statutory disclaimers is a legal determination; route this question to counsel before launch.
