### Pre-Launch Safety Checklist: Automated Tax-Filing Assistant

**1. Harm Inventory & Worst-Case Definition**
Before testing, explicitly record the specific harm: **Unsafe automation of high-stakes financial actions**.
*   **Affected Group:** Low-income families in Mexico with limited legal/financial recourse.
*   **Worst Realistic Case:** An incorrect deduction claim triggers a government audit, resulting in fines, frozen assets, or legal fees the user cannot afford, causing immediate financial distress.
*   **Status:** If this inventory is not written down, the feature is not ready for review.

**2. Mandatory Human-in-the-Loop Gate (Non-Negotiable)**
Because submitting a tax form is an **irreversible, high-stakes action** that can trigger audits:
*   **Stop Condition:** The system must **not** automatically submit forms to the government.
*   **Required Control:** Implement a mandatory human review step. The system should generate a draft return and a plain-language summary of calculated deductions. A human agent (or the user via a rigorous "explicit confirmation" flow that highlights risks) must review and authorize the submission.
*   **Failure Mode:** Fully autonomous submission of tax forms for this demographic is a critical safety failure, regardless of time pressure.

**3. Output Measurement Plan (Runnable Tests)**
Do not assert accuracy; measure it against specific probes. Create one test row for each of the following scenarios:
*   **Probe Set A (Edge Cases):** Inputs representing complex, ambiguous receipt scenarios (e.g., mixed personal/business expenses, damaged receipts, non-standard vendor formats).
    *   *Positive Control:* A known-bad input that should trigger a "requires review" flag.
    *   *Negative Control:* A standard, clear receipt that processes normally.
    *   *Metric:* Percentage of edge cases correctly flagged for human review vs. incorrectly auto-processed.
    *   *Threshold:* Owner-defined (recommend zero tolerance for auto-processing ambiguous high-risk deductions).
*   **Probe Set B (Adversarial/Injection):** Uploaded images containing text designed to confuse the parser (e.g., handwritten notes overlaid on receipts, modified totals).
    *   *Metric:* Detection rate of manipulated data.
*   **Probe Set C (Subgroup Performance):** Test data segmented by region or income level if deduction rules vary.
    *   *Metric:* Error rate per subgroup.
    *   *Reporting:* If a subgroup has not been tested, mark the result as **UNVERIFIED**. Do not invent an overall accuracy percentage.

**4. Transparency & Uncertainty Artifacts**
*   **Confidence Rendering:** Do not display raw model confidence scores (e.g., "87% sure") to users. Instead, use defined coarse tiers:
    *   *Confirmed:* Matches multiple verified rules.
    *   *Unverified/Review Required:* Ambiguous input or low-corroboration deduction.
*   **Model/Data Card:** Create a simple, versioned document stating:
    *   Intended use (drafting returns for low-income families).
    *   Known limitations (specific receipt types or deduction categories not supported).
    *   Measured performance on the probe sets above.
    *   Owner contact for errors.
    *   *Note:* Shipping without this card is a transparency failure.

**5. Governance & Legal Routing**
*   **Owner:** Name the specific individual responsible for reviewing flagged errors post-launch.
*   **Legal Duty:** Whether this tool constitutes a regulated financial advice service or requires specific AI disclosures under Mexican law is a legal determination. **Route immediately to counsel.** Do not assume compliance based on internal testing.
*   **Regime Awareness:** Be aware that automated decision systems affecting financial status may fall under emerging AI governance frameworks (e.g., principles similar to the EU AI Act or local equivalents). Counsel must verify binding obligations.

**Definition of Done:**
The system does not auto-submit; a harm inventory exists; edge-case probes are run with reported residual risk (no fabricated accuracy stats); a model card is drafted; and legal questions are routed to counsel.

*Note: Time pressure does not waive the requirement for a human gate on irreversible financial actions. Launching without these controls risks severe harm to your most vulnerable users.*
