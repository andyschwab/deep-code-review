### Validation Workflow: Grant-Writer Credibility Gate

To stop immediate rejections caused by fabricated qualifications, implement a "Human-in-the-Loop" gate focused on **claim verification** rather than full text review. Given your two-week deadline and lack of a donor database, this workflow prioritizes catching hallucinations before submission.

**1. The "Fact Extraction" Step (Automated)**
Before the draft is shown to the user, run a lightweight extraction process on the generated text. Identify and tag any sentence containing:
*   Specific metrics (e.g., "served 5,000 beneficiaries").
*   Certifications or legal statuses (e.g., "ISO certified," "registered since 2010").
*   Past performance claims (e.g., "successfully completed a similar project in 2023").
*   Specific donor names or partnership claims.

**2. The "Uncertainty Tier" Display (Interface Change)**
Do not present the draft as a finished document. Instead, present it with a **Credibility Sidebar** that lists every extracted claim above. Label each claim with a coarse confidence tier based on the input data:
*   **Confirmed:** Directly quoted from the user's input fields.
*   **Inferred:** Logically derived from user input but phrased by the AI (e.g., user said "large team," AI wrote "50 staff").
*   **Unverified:** Specific facts generated by the AI with no source in the user input (High Risk).

*Crucial Rule:* Never show a percentage (e.g., "87% accurate"). Use only these text labels. Percentages imply a precision your current system cannot measure and will encourage dangerous over-reliance.

**3. The Mandatory Human Gate**
The application **cannot be submitted** until the "Unverified" list is cleared.
*   **Action:** The user (or your support staff, if acting as an intermediary) must explicitly click "Confirm" or "Edit" next to every item in the **Unverified** list.
*   **Default State:** If the user does not confirm a claim, the system must automatically redact it or replace it with a placeholder like "[Insert verified metric here]" before allowing the final export.
*   **Stop Condition:** If more than 30% of the critical eligibility criteria fall into the "Unverified" category, block the generation entirely and prompt the user to provide more specific source data before trying again.

**4. The "No-Fabrication" Prompt Instruction**
Update your system prompt immediately. Instruct the model: "If the user input does not contain specific evidence for a qualification, do not invent one. Instead, insert a bracketed placeholder like `[User to confirm specific year/certification]` and flag this section for review."

**5. Rapid Red-Team Test (Before Launch)**
With your team of eleven, spend two hours running "adversarial inputs." Have five people provide vague, incomplete profiles (e.g., "We help people, we are good").
*   **Pass Criteria:** The system produces *zero* specific fabricated numbers or false certifications in the final export without a human click.
*   **Fail Criteria:** Any specific fact appears in the final text that was not in the input and not explicitly confirmed by a human.

**Note:** This workflow treats unverified AI output as a potential liability, not a draft fact. Since you cannot verify against a donor database automatically, the human confirmation step is your only safety net against rejection.
