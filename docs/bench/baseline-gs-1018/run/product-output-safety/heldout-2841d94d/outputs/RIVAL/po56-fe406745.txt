### Critical Verification Workflow for Structural Modification Suggestions

To prevent catastrophic structural failures, the following checks and warnings must be implemented immediately before launch. These measures prioritize safety over automation, ensuring no demolition suggestion proceeds without human expert validation.

#### 1. Mandatory Input Validation Checks
*   **Load-Bearing Annotation Flag:** If the uploaded blueprint lacks explicit "load-bearing" or "structural" annotations for a specific wall, the system must automatically classify that wall as "Structural/Unknown" and disable any removal suggestion.
*   **Building Age & Type Filter:** If the building age exceeds 40 years or the construction type is identified as older masonry/wood frame without modern engineering stamps, trigger an immediate "High Risk" flag. The system must refuse to generate removal plans for these properties without a uploaded professional structural assessment.
*   **Blueprint Completeness Scan:** Verify the presence of foundation details, roof framing plans, and floor joist directions. If any of these three elements are missing from the upload, block all structural modification outputs.

#### 2. Automated Logic Guards (System-Side)
*   **The "Zero-Confidence" Rule:** Configure the AI's confidence threshold for structural analysis to 0%. The system must be hard-coded to never assert that a wall is "safe to remove." It can only suggest that a wall *might* be non-structural, pending review.
*   **Keyword Blocking:** Implement a negative constraint list. The AI output must never contain phrases like "safe to demolish," "non-structural," or "remove this wall." Allowed phrasing is limited to "potential candidate for opening, subject to engineering verification."
*   **Forced Interruption Point:** Any generation flow that identifies a wall for potential modification must halt and require a manual "Proceed to Engineering Review" click by the user before displaying even a theoretical layout.

#### 3. Mandatory User Warnings & Disclaimers
*   **Pre-Generation Warning:** Before the AI processes the request, display a non-dismissible modal: *"WARNING: This tool cannot determine load-bearing status. Any suggestion to remove a wall is a theoretical design concept only and requires validation by a licensed structural engineer. Proceeding without professional review may result in structural collapse."*
*   **Output Watermarking:** Every generated plan suggesting a wall removal must be watermarked diagonally across the image with: **"UNVERIFIED CONCEPT - DO NOT CONSTRUCT."**
*   **Final Report Disclaimer:** The downloadable renovation plan must include a bold, first-page statement: *"This document does not constitute structural engineering advice. The removal of any wall indicated herein requires a site visit and calculation by a licensed professional. DesignAI assumes no liability for structural failures resulting from unauthorized demolition."*

#### 4. The "Human-in-the-Loop" Requirement
*   **Contractor Verification Gate:** Since you are in beta with private contractors, configure the system to require a digital signature or license number entry from the contractor before they can view or share any plan involving wall removal.
*   **Engineering Review Checklist:** Generate a mandatory PDF checklist accompanying any removal suggestion, listing items the human engineer must verify (e.g., "Verify header size," "Check foundation footing," "Analyze roof load path").

#### 5. Data Handling & Liability
*   **Dataset Limitation Disclosure:** Explicitly state in the user interface that the training dataset lacks detailed load-bearing annotations for older buildings, making the AI's structural judgment unreliable by design.
*   **Audit Logging:** Log every instance where a user attempts to generate a removal plan, including the timestamp, user ID, and the specific warning messages displayed. This creates an audit trail demonstrating that the system actively discouraged unsupervised action.

By implementing these hard stops and clear communications, DesignAI shifts the system's role from an authority on safety to a conceptual aid that strictly enforces the necessity of professional engineering review.

*Note: This workflow assumes no real-time connection to municipal building databases; if such integration becomes available, it should be added as an additional validation layer.*
