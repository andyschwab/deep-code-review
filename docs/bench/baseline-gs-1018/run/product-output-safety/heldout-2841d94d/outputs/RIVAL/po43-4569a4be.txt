### Scholarship Matcher Parsing Validation Checklist

**1. Structural Layout Variations**
*   **Header/Footer Interference:** Submit essays where contact information or page numbers overlap with the first/last lines of text to ensure the parser does not truncate critical content.
*   **Columnar Formats:** Test documents using multi-column layouts (common in newspaper-style resumes) to verify the reading order remains linear and does not jumble sentences.
*   **Indentation & Spacing:** Validate essays with non-standard indentation (e.g., deep nesting for lists) and irregular line spacing (single vs. double) to ensure paragraph boundaries are detected correctly.
*   **Mixed Alignment:** Check documents containing a mix of left-aligned, centered, and justified text blocks to confirm the extractor does not skip centered titles or pull quotes.

**2. Content Embedding & Objects**
*   **Text within Images:** Submit resumes where key skills or awards are embedded as images rather than selectable text to verify if the system flags these as missing data or attempts OCR (if applicable).
*   **Tables and Grids:** Test academic records presented in complex tables with merged cells to ensure GPA and course names are mapped to the correct fields without shifting columns.
*   **Hyperlinks & Footnotes:** Verify that URLs, email addresses, and footnote markers do not break the sentence structure or get stripped entirely, altering the context of the essay.
*   **Special Characters & Diacritics:** Run tests with names and essays containing accented characters (e.g., José, Müller) and non-Latin scripts to ensure no data corruption occurs during ingestion.

**3. File Format & Encoding Edge Cases**
*   **PDF Versions:** Compare parsing results between text-based PDFs, scanned image-only PDFs, and password-protected files to ensure appropriate error handling versus silent failure.
*   **DOCX vs. DOC:** Validate legacy `.doc` files alongside modern `.docx` to ensure macros or older formatting tags do not introduce garbage characters into the text stream.
*   **Encoding Anomalies:** Test files saved with different character encodings (e.g., UTF-8 vs. Windows-1252) to prevent symbol replacement errors that could obscure meaning.
*   **File Size Extremes:** Submit extremely short (one sentence) and extremely long (50+ pages) documents to check for timeout errors or truncation limits.

**4. Logical Consistency & False Negatives**
*   **Keyword Context:** Ensure the matcher distinguishes between a student *having* an award versus *mentioning* an award in a hypothetical context (e.g., "I hope to win" vs. "I won").
*   **Date Parsing:** Verify that date formats (MM/DD/YYYY vs. DD/MM/YYYY) are interpreted correctly to avoid disqualifying students based on incorrect age or graduation year calculations.
*   **GPA Scale Variations:** Test transcripts using different scales (4.0, 5.0, 10.0, percentages) to ensure the normalization logic does not inadvertently filter out high-performing students from non-standard grading systems.
*   **Missing Section Handling:** Confirm that if an optional section (e.g., "Extracurriculars") is missing, the system does not crash or assign a zero score that drops the candidate below the threshold.

**5. Error Recovery Workflow**
*   **Partial Parse Alerts:** Verify that if only 80% of a document parses, the system flags it for human review rather than auto-rejecting the applicant.
*   **Readable Error Logs:** Ensure failure logs specify exactly which element failed (e.g., "Table on page 2 unreadable") to guide manual correction.

*Note: Prioritize running these tests against a dataset of known "eligible" candidates to measure the false-negative rate directly. Given the three-week timeline, automate the execution of these cases to allow for daily regression testing.*
