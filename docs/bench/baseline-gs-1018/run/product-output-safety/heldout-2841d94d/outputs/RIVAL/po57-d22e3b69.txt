### Pre-Launch Validation Plan for VisaPath Reminder System

Given the constraint of relying solely on user-uploaded data without government database integration, the validation plan must prioritize data integrity checks at the point of entry and robust failure handling during the notification phase. The following testing plan simulates critical failure points to ensure system reliability before the soft launch.

**1. Data Ingestion and Parsing Simulation**
Since the system depends on user uploads, the primary risk is incorrect data extraction.
*   **Test Case A: Format Variability.** Upload passport scans in various formats (PDF, JPG, PNG) with different resolutions and lighting conditions. Verify that the OCR (Optical Character Recognition) engine correctly identifies the expiry date field regardless of document layout.
*   **Test Case B: Manual Entry Errors.** Simulate manual correction scenarios where users override OCR results. Input invalid date formats (e.g., DD/MM/YYYY vs. MM/DD/YYYY), impossible dates (e.g., February 30), and dates already expired. The system must reject these immediately with clear error messages rather than storing flawed data.
*   **Test Case C: Tampered or Obsolete Documents.** Upload images of passports that are visually altered or clearly expired prior to upload. Implement a logic check that flags any document where the "Issue Date" is after the "Expiry Date" or where the expiry date is in the past, triggering a manual review flag instead of an automated reminder schedule.

**2. Notification Logic and Timing Verification**
Ensure the calculation engine correctly determines when to send alerts based on UAE visa regulations (typically 30, 60, and 90 days prior to expiry).
*   **Test Case D: Boundary Conditions.** Create test profiles with expiry dates falling exactly on the trigger thresholds (e.g., exactly 90 days from today). Verify that notifications are sent on the correct day, not a day early or late.
*   **Test Case E: Time Zone Handling.** Simulate users uploading data from different time zones while residing in the UAE. Ensure the system normalizes all dates to UAE local time (GST) to prevent off-by-one-day errors in notification scheduling.

**3. Delivery Failure and Redundancy Testing**
Simulate communication breakdowns to ensure no user is left uninformed due to a single channel failure.
*   **Test Case F: Channel Outages.** Mock SMS gateway failures and email bounce-backs (e.g., invalid email addresses, full inboxes). The system must detect these failures within minutes and automatically attempt the secondary channel (e.g., if SMS fails, send Email; if both fail, flag for human intervention).
*   **Test Case G: Escalation Protocols.** For high-risk cases (e.g., visa expiring in <7 days with failed delivery), test the escalation workflow. Verify that the system alerts the internal support team immediately so they can attempt direct contact via phone.

**4. End-to-End User Journey**
*   **Test Case H: The "Happy Path" vs. "Sad Path".** Run a full cycle for a valid user receiving all alerts on time. Contrast this with a user who uploads a blurry document, fails to correct it, and misses the first reminder. Verify that the system continuously retries and escalates rather than giving up after one error.

**Implementation Note:** All tests should use synthetic data representing your seven team members and a small group of beta corporate clients. Do not use real passport data during testing to maintain privacy compliance.

**Critical Success Metric:** The system must achieve 100% detection of invalid date inputs and 100% escalation of failed delivery attempts before any real user relies on it for legal compliance.
