### Internal Bias Stress-Test Protocol for AI Career Counselor

**Phase 1: Construct the Synthetic Control Matrix (Days 1–3)**
Create a dataset of 40–60 synthetic resumes where qualifications, experience years, education, and skills are identical across pairs, varying only in demographic indicators.
*   **Base Profiles:** Draft 10 distinct "base" personas covering different seniority levels (Junior, Mid, Senior) and domains (Engineering, Marketing, Finance, Healthcare).
*   **Demographic Variables:** For each base persona, create variants altering only gendered pronouns (he/she/they), names (culturally distinct names associated with specific genders/races), and affiliation markers (e.g., "Women in Tech" club membership vs. a neutral coding club).
*   **Control Check:** Ensure no other text changes occur. A change from "John" to "Jane" must not accidentally alter "managed a team" to "assisted a team."

**Phase 2: Execution and Data Capture (Days 4–7)**
Run the synthetic profiles through your suggestion engine in a isolated batch process.
*   **Blind Processing:** Strip any internal metadata that might reveal the test nature of the input to the model.
*   **Output Standardization:** Record the top 3 industry recommendations and the specific confidence scores or reasoning text provided for each.
*   **Volume:** Run each profile variant 3–5 times to account for any inherent model stochasticity (randomness), averaging the results.

**Phase 3: Disparity Analysis (Days 8–10)**
Compare outputs within each "base persona" group to identify statistical skew.
*   **Recommendation Divergence:** Flag cases where Variant A (e.g., male-coded) receives "Leadership/Executive" recommendations while Variant B (female-coded) receives "Support/Administrative" roles despite identical experience.
*   **Confidence Gaps:** Note significant differences in confidence scores. If the model is 90% confident a male profile fits "Software Architect" but only 60% confident for the identical female profile, this indicates bias.
*   **Reasoning Audit:** Manually review the generated justification text for stereotypical language (e.g., attributing success to "aggressiveness" for one group and "collaboration" for another).

**Phase 4: Mitigation and Validation (Days 11–14)**
*   **Prompt Engineering:** If biases are detected, introduce explicit constraints in your system prompt (e.g., "Ignore gender, name, or demographic markers; base recommendations strictly on skills and years of experience").
*   **Few-Shot Correction:** Add examples to your prompt showing unbiased evaluations of diverse profiles.
*   **Re-test:** Run the failing synthetic pairs again. The goal is <5% variance in recommendation categories between demographic variants of the same base profile.

**Phase 5: Documentation for Beta (Days 15–17)**
Compile a "Bias Safety Report" summarizing the methodology, the specific disparities found, the mitigations applied, and the final pass rates. This serves as your internal audit trail for stakeholders and early beta users.

**Note:** This process relies entirely on your existing infrastructure and requires no external tools. Prioritize fixing high-severity disparities (e.g., job role downgrading) over minor phrasing differences before launch.
