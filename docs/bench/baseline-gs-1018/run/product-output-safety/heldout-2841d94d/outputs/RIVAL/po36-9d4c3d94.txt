**Controlled Vocabulary Validation Workflow for Pharmaceutical Label Translation**

To ensure patient safety without external services, implement a deterministic, rule-based validation pipeline that acts as a mandatory gate between the translation engine and the final print output. This workflow relies on strict string matching and context flagging rather than semantic interpretation, minimizing the risk of the validator itself making errors.

**1. Construct the Bilingual Safety Lexicon**
Create a localized JSON or CSV database containing only critical medical terms relevant to your specific drug portfolio. Do not attempt to translate the entire dictionary; focus exclusively on high-risk categories:
*   **Dosage Units:** (e.g., "mg", "mL", "drops", "tablets").
*   **Frequency Indicators:** (e.g., "once daily", "every 4 hours", "before meals").
*   **Contraindications & Warnings:** (e.g., "do not crush", "keep refrigerated", "pregnancy category").
*   **Drug Names & Active Ingredients.**

For each English source term, define the *only* acceptable Thai translation(s). Mark any variation outside this list as a critical failure. Include common false friends or look-alike Thai characters that often cause OCR or rendering errors.

**2. Implement the Pre-Flight Validation Script**
Develop a lightweight script (executable by your engineering team) that processes every translated label file before it reaches the printer. The logic must follow this sequence:
*   **Tokenization:** Break the translated Thai text into segments.
*   **Forward Check:** Scan the English source for terms existing in your Safety Lexicon.
*   **Reverse Verification:** For every identified critical term in the source, verify that the *exact* approved Thai equivalent appears in the corresponding position of the translated output.
*   **Anomaly Detection:** Flag any instance where a critical English term is present, but the expected Thai term is missing, misspelled, or substituted with an unapproved synonym.
*   **Hard Fail Mechanism:** If any critical mismatch is detected, the script must immediately halt the printing queue and generate a discrepancy report highlighting the specific character offset and the expected vs. actual term.

**3. The Three-Person Review Protocol**
Leverage your small team by dividing responsibilities based on the script's output:
*   **Engineer A (System Integrity):** Maintains the Safety Lexicon and the validation script. They ensure the code correctly identifies boundaries and handles edge cases like pluralization or spacing variations in Thai script.
*   **Linguist B (Contextual Triage):** Reviews only the items flagged by the script. Since the script filters out correct translations, the linguist focuses entirely on potential errors. They determine if a flag is a true positive (dangerous error) or a false positive (acceptable variation not yet in the lexicon). If it is a new acceptable variation, they update the lexicon; if it is an error, they reject the batch.
*   **Engineer/Linguist C (Final Release):** Performs a random spot check of 5% of the *passed* batches to ensure the validator is not suffering from "blind spots" (e.g., missing entirely new types of errors). They hold the final authority to release files to print.

**4. Iterative Lexicon Expansion**
Treat the two-week timeline as an agile sprint. Every time the Linguist identifies a valid translation that the script missed, immediately add it to the Safety Lexicon. This rapidly increases the coverage of your automated checker, reducing manual review time as the deadline approaches.

By restricting the automated check to exact matches against a pre-approved list, you remove the ambiguity of AI-based quality estimation. The system does not guess; it only verifies known safety constraints, ensuring that any deviation triggers a human review before a label is ever printed.

*Note: Ensure your team validates the script against a set of intentionally flawed "dummy" labels before processing real data to confirm the "hard fail" mechanism works.*
