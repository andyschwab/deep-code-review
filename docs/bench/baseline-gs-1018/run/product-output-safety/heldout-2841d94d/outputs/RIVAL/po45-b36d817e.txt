### Synthetic Resume Samples and Evaluation Criteria for Equitable Parsing

To verify your resume parser treats diverse name structures and credential formats equitably, use the following targeted testing regimen. These samples are designed to stress-test specific failure modes common in global recruitment tools without requiring external audit software.

#### 1. Synthetic Resume Samples (Text Inputs)

Create test cases covering these four high-risk categories. Ensure each sample contains identical core qualifications (e.g., "5 years Python experience," "Master's in Computer Science") so that any variance in parsing results indicates bias or error rather than skill differences.

**A. Non-Western Name Structures**
*   **Patronymic/Matronymic Formats:**
    *   *Input:* "Fatima al-Sayed bin Ahmed" (Arabic patronymic)
    *   *Input:* "Ravi Krishnan s/o Subramanian" (South Indian "son of" format)
    *   *Failure Mode:* Parser truncates the name, misidentifies "bin" or "s/o" as a middle name, or flags the entry as malformed.
*   **Single-Name Mononyms:**
    *   *Input:* "Suharto" (Indonesian) or "Madonna" (Global mononym)
    *   *Failure Mode:* System forces a "First/Last" split, creating a null last name or hallucinating a placeholder.
*   **Compound Surnames:**
    *   *Input:* "Gabriela García Márquez" (Hispanic dual surname)
    *   *Input:* "Nguyen Van An" (Vietnamese family name first)
    *   *Failure Mode:* Parser treats "García" as the sole surname, dropping "Márquez," or misorders Vietnamese names as "An Nguyen."

**B. Educational Credential Variations**
*   **Non-US Degree Equivalencies:**
    *   *Input:* "B.Tech from IIT Delhi" or "Licenciatura from UNAM"
    *   *Failure Mode:* System fails to map these to "Bachelor's Degree," downgrading the candidate's qualification level.
*   **Grading Scales:**
    *   *Input:* "Final Grade: 1.5 (German System)" or "7.8/10 (French System)"
    *   *Failure Mode:* Parser interprets "1.5" as a low GPA (confusing it with the US 4.0 scale) or rejects the format entirely.
*   **Institution Name Formats:**
    *   *Input:* "University of Tokyo" vs. "Todai" (Common abbreviation)
    *   *Failure Mode:* Abbreviations are not recognized, causing the institution to be flagged as unaccredited or unknown.

**C. Date and Formatting Conventions**
*   **Date Ambiguity:**
    *   *Input:* "05/06/2015" (Could be May 6 or June 5)
    *   *Context:* Explicitly state "June 2015 – May 2018" in the text body to see if the parser overrides the ambiguous numeric header.
*   **Contact Information:**
    *   *Input:* International phone formats (+91, +86) and non-.com email domains.
    *   *Failure Mode:* Regex filters discard valid contact info as invalid.

**D. Language and Character Sets**
*   **Mixed Script:**
    *   *Input:* Name in native script alongside Latin transliteration (e.g., "张伟 (Zhang Wei)").
    *   *Failure Mode:* Parser strips non-ASCII characters, leaving only parentheses or garbled text.

#### 2. Evaluation Criteria

Run these samples through your internal environment and measure the following metrics. Any deviation greater than 0% between groups constitutes a critical failure before launch.

*   **Name Integrity Rate:** Percentage of samples where the full legal name is captured without truncation, reordering, or character loss.
    *   *Pass Condition:* 100% of mononyms and compound surnames are stored exactly as input.
*   **Credential Mapping Accuracy:** Percentage of non-US degrees correctly mapped to the internal "Bachelor/Master/PhD" taxonomy.
    *   *Pass Condition:* "B.Tech" and "Licenciatura" must map to "Bachelor's Equivalent" with confidence scores equal to US degrees.
*   **Data Retention Ratio:** Percentage of valid contact details and dates retained after parsing.
    *   *Pass Condition:* No valid international phone numbers or dates are discarded due to format rigidity.
*   **Scoring Parity:** If the parser assigns a "match score" or ranking, the average score for the diverse test set must be statistically identical to the control set (Western names/US degrees) containing the exact same skills.
    *   *Pass Condition:* Mean score variance < 1% between control and test groups.

#### 3. Execution Steps

1.  **Baseline Control:** Run 5 resumes with standard US/UK naming and education to establish the "perfect parse" benchmark.
2.  **Blind Batch Testing:** Run the 20+ diverse samples mixed with the controls. Ensure the engineering team does not know which are test cases to prevent manual correction bias.
3.  **Log Inspection:** Manually inspect the raw JSON/database output for every failure. Do not rely solely on the UI display, as the database may store errors the UI hides.
4.  **Regex Audit:** If failures occur, immediately review the specific regular expressions handling name splits and date formats. Hardcoded assumptions about name length or order are the most likely culprits.

*Note: Since you cannot use external bias tools, manual inspection of the raw parsed output against the original text is your primary validation method.*
*Prioritize fixing name truncation and degree mapping first, as these directly disqualify candidates.*
