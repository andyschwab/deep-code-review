**Primary Failure Modes:**
1.  **Revenue Model Collapse:** The projection of $720k relies on students paying $60/month for "bundled lessons," yet you state individual lessons are $2. To generate $720k from 3,600 users (30% of 12k), each must spend $200/year. At $2/lesson, that requires 100 lessons per student annually (nearly 2 per week). If the $60 is a subscription cap rather than a usage fee, the $720k figure is valid, but the mention of $2 transaction pricing creates a contradiction that will undermine credibility with the CFO.
2.  **Margin Insufficiency:** A 3% commission on a $2 lesson is $0.06. This is likely below the payment processing fee alone (typically ~2.9% + $0.30 fixed), meaning every transaction could lose money before server costs. The model ignores negative unit economics.
3.  **Unpriced Infrastructure:** Presenting a budget with a "$30k estimated" line item that is "not priced yet" signals poor preparation. If the gamified features drive high concurrency, this estimate could easily double, eroding the pilot's contingency fund.

**Early Indicator to Pull the Plug:**
Monitor **Net Revenue Per User (NRPU)** in the first 30 days. If NRPU is less than the variable cost of serving that user (payment fees + server load), halt the rollout immediately. Do not wait for churn data; negative unit economics cannot be solved by retention.
