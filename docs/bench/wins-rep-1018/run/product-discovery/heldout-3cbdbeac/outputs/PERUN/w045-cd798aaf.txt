# Recommendation: Do Not Prioritize Referral Map Yet; Run a 5-Day Concierge Test First

**Decision:** Reject the immediate build of the referral network visualization for the upcoming release. Instead, allocate engineering bandwidth to the planned billing improvements (which directly impact revenue viability) and dedicate product/design time to a **concierge experiment** to validate the referral map assumption.

**Rationale:**
The request to visualize referral networks is based on **stated intent** ("eight physicians asked") rather than **behavioral evidence**. In product discovery, users frequently request features they believe they want but never use. Your assumption—that this map will increase retention by 15%—is the **riskiest assumption** because it drives a four-week engineering investment against an unproven usage pattern ("daily use" vs. "nice-to-have").

Building this now violates the **riskiest-assumption gate**: you are about to incur high engineering costs (4 weeks) to solve a problem where the core uncertainty is whether the solution delivers the predicted value. If the map is built and rarely used, you have wasted a release cycle on a feature that does not move the retention needle, while potentially delaying billing improvements that secure the business's financial health.

**The Alternative Plan: The Concierge Test**
Before writing code, validate the "daily use" hypothesis with a manual test that costs zero engineering hours:
1.  **Select 3 of the 8 requesting physicians.**
2.  **Manually generate** a static PDF or image of their referral network using existing data exports.
3.  **Deliver it personally** and ask them to use it for one week.
4.  **Measure behavior:** Did they open it more than once? Did they make a decision based on it? Did they ask for it again without prompting?

**Kill Threshold:** If fewer than 2 of the 3 doctors use the manual map more than twice in a week, the assumption that this drives daily value is false. Do not build the automated feature.

**Prioritization Logic (ICE Framework):**
*   **Billing Improvements:** High Confidence (direct revenue impact), High Ease (likely well-defined scope), High Impact (viability).
*   **Referral Map (Current State):** Low Confidence (unverified usage), Low Ease (4-week build), Unknown Impact (15% retention is a guess).

Until the concierge test converts "Low Confidence" to "High Confidence," billing improvements remain the superior priority.

**Action Items for Friday's Committee:**
1.  Approve billing improvements for the 4-week window.
2.  Authorize the 5-day concierge test for the referral map.
3.  Set a review date in 10 days to decide on the map build based on actual usage data from the test.

*Note: This approach prevents building a "ghost feature" that looks good in demos but fails in daily workflows. The 15% retention target must be re-calculated based on the actual baseline retention rate of the specific cohort using the manual map.*
