We possess internal loss data ($12k/8 weeks) and a hypothesis (ethylene/temperature monitoring enables dynamic rerouting). We lack the external evidence required to validate that this specific feature solves the root cause or that the proposed technical path is viable. Building the feature now violates the riskiest-assumption gate.

**Riskiest Assumption Gate**
*Assumption:* Real-time ethylene/temperature data will allow us to reroute shipments effectively enough to cut spoilage by 50%.
*Status:* Untested.
*Required Action:* Do not build software or retrofit trucks yet. Run the cheapest possible disconfirmation test first.
*Proposed Test:* Manual "Concierge" Simulation.
*Method:* Select 5 high-risk shipments. Manually log temperature/ethylene at checkpoints using portable, rentable handheld meters (no fleet retrofit). Simulate a "reroute decision" based on this data.
*Kill Threshold:* If manual data does not identify a viable reroute opportunity in at least 3 of 5 cases, or if the cost of the handheld meters + labor exceeds the projected savings, **drop the feature idea**.
*Decision Rule:* Only proceed to development if the manual test proves the data leads to actionable, profitable rerouting decisions.
