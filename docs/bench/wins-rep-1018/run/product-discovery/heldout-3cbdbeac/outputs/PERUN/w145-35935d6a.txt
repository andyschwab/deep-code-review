### Riskiest-Assumption Gate: Cold Chain Validation Tool

**Verdict:** Do not build the custom tool yet. The proposed solution targets *data entry latency*, but your evidence suggests *sensor calibration drift* is an equally probable root cause. Automating a check on faulty sensor data will not prevent FDA warnings; it will only generate false negatives faster.

#### 1. The Core Conflict
Your assumption ("automation reduces human error by 40%") holds true **only if** the root cause is manual review failure. If the root cause is hardware degradation (sensor drift in older trucks), the tool will validate incorrect data as "compliant," increasing regulatory risk rather than reducing it.

#### 2. Required Evidence (Empty-Slot Template)
To decide whether to build, you must fill these slots with real data before Tuesday. **Do not guess these numbers.**

| Evidence Slot | How to Obtain (Action Required) | Decision Rule |
| :--- | :--- | :--- |
| **A. False Negative Rate** | Audit the last 4 warning letters: Did the manual log show "OK" while the actual product spoiled? Or did the log show "Excursion" but was ignored? | If logs showed "OK" for spoiled goods → **Sensor/Hardware issue**. Tool won't help. |
| **B. Latency vs. Drift Ratio** | Sample 20 recent flagged shipments. Measure time from "log complete" to "review complete" vs. time from "sensor reading" to "actual temp change." | If >50% of errors are time-gap related → **Build Tool**. <br> If >50% are sensor-read errors → **Fix Hardware**. |
| **C. Calibration History** | Pull maintenance records for the specific trucks cited in the 4 warnings. When were sensors last calibrated? | If calibration is >6 months old on cited trucks → **Hardware Fix First**. |

#### 3. The Cheap Test (Run this before coding)
**Test:** Manual "Shadow Audit" on 10 shipments tomorrow morning.
*   **Action:** Have a quality engineer physically verify the sensor reading against a calibrated handheld thermometer *before* the driver leaves, then compare it to the logged data.
*   **Metric:** Discrepancy count between (Handheld vs. Truck Sensor) AND (Truck Sensor vs. Log Entry).
*   **Kill Threshold:** If **≥3 out of 10** shipments show a discrepancy between the Handheld and the Truck Sensor, **drop the software build**. The problem is hardware reliability, not review speed. Proceed with a sensor recalibration program instead.

#### 4. Strategic Recommendation for Tuesday's Meeting
Present the **"Hardware-First" Hypothesis** alongside the software proposal.
*   **If the Shadow Audit fails (Hardware is the culprit):** Propose an immediate sensor recalibration sprint. The "tool" becomes a secondary phase to monitor the *new* hardware integrity.
*   **If the Shadow Audit passes (Human error is the culprit):** Proceed with the tool, but narrow the scope to "Real-time Alerting" rather than "Post-log Validation" to eliminate the 3-hour delay entirely.

**Non-Goal for This Stage:** Building a full dashboard, historical reporting, or integration with ERP systems. These are useless until the data source (the sensor) is proven trustworthy.
