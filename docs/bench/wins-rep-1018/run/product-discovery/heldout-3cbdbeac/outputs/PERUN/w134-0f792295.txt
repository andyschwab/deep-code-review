**SUBJECT:** Go/No-Go Recommendation: River Transport Scheduler vs. Adoption Validation

**Executive Summary**
We cannot yet justify the Q3 engineering budget for the automated river transport scheduler. While the pain point is verified (five formal complaints, average three-day delays), our core value hypothesis rests on an untested assumption: that local boat captains will adopt a digital interface over established phone workflows. Building the scheduler now risks creating a polished tool that yields zero operational improvement if adoption fails. The recommendation is to **pause full development** and execute a low-cost "Wizard-of-Oz" test to validate captain behavior before committing engineering resources.

**The Riskiest Assumption**
*Assumption:* Captains will consistently use a digital scheduling interface instead of reverting to phone calls.
*Impact:* If false, the automated optimizer produces no schedule adherence, and the 40% delay reduction target is impossible to hit.
*Uncertainty:* High. No behavioral data exists regarding captains' current smartphone usage or willingness to change communication channels.

**Recommended Path: Validate Before Build**
Instead of building the full automated system, we will run a two-week concierge test:
1.  **The Test:** Dispatchers manually create optimized schedules using existing river depth data and send them to captains via a simple channel they already use (e.g., WhatsApp or SMS), pretending it is from the new system.
2.  **The Metric:** Percentage of captains who acknowledge and adhere to the digital schedule without requesting a phone confirmation.
3.  **Kill Threshold:** If fewer than 60% of captains follow the digital instruction without a phone follow-up within two weeks, we **drop** the current interface approach and pivot to driver training or a voice-based solution.
4.  **Cost:** Minimal (dispatcher time only). No engineering spend.

**Decision Required**
Authorize a two-week behavioral test with zero engineering allocation. If the test meets the 60% adherence threshold, we will return to the steering committee with validated evidence to unlock the full Q3 build budget. If it fails, we save the engineering budget for a more viable solution.
