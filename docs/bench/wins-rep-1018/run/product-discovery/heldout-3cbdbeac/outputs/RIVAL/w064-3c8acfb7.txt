### Strategic Recommendation: Specialist Directory Launch

**Recommendation:** Proceed with a **Manual MVP (Minimum Viable Product)** launch immediately, but strictly limit the scope to the top 20% of specialists driving 80% of the confusion. Do not wait for automation.

The current volume of support tickets (30% of total) indicates an active bleeding of resources and patient trust. Waiting for automated data syncing delays value delivery and allows the problem to compound. However, launching a directory with known inaccurate data poses a severe **Usability and Value risk**: if a patient calls a listed specialist who is not accepting new patients, trust in CareConnect erodes faster than if no directory existed.

**Resource Requirements for Manual MVP**
To mitigate the data accuracy risk without automation, you must shift the burden from "system syncing" to "curated verification."
*   **Administrative Hours:** Dedicate 10–15 hours/week initially. One team member must manually verify availability for the limited subset of specialists weekly.
*   **Process:** Implement a "Verified Last Updated" timestamp on each profile. If a profile is older than 7 days, hide it from search results automatically.
*   **Feedback Loop:** Add a "Report Incorrect Info" button on every profile to crowdsource data maintenance, turning users into validators.

**Potential Risks of Launching with Incomplete Data**
1.  **Trust Erosion (High Impact):** The primary risk is not technical failure but reputational damage. Sending a distressed patient to a closed practice validates their frustration with the healthcare system and blames CareConnect for the error.
    *   *Mitigation:* Clearly label the directory as "Beta" and display verification dates prominently. Only list providers confirmed within the last 48 hours.
2.  **Operational Drag (Medium Impact):** Manual updates may consume more admin time than the support tickets saved if the scope is too broad.
    *   *Mitigation:* Restrict the initial launch to Neurology and Cardiology only (the source of 30% of tickets). Do not expand to other specialties until automation is built.
3.  **Strategic Distraction (Low Impact if Scoped):** Investors fear this distracts from core telemedicine.
    *   *Mitigation:* Frame this not as a new product, but as a **retention feature** for the core offering. A successful telemedicine platform requires successful referrals; this directory closes the loop on care continuity.

**Decision Framework**
*   **Build Now If:** You can commit to a manual verification process for a limited subset of providers and can tolerate a "good enough" rather than "perfect" data set.
*   **Wait If:** You cannot spare 10+ hours/week for manual curation. In this case, do not build a half-baked directory; instead, create a simple static PDF guide updated monthly, which sets lower expectations for real-time accuracy.

**Next Steps**
1.  Extract the list of the top 50 neurologists and cardiologists from recent support tickets.
2.  Assign one staff member to call and verify availability for these 50 providers.
3.  Launch the searchable directory for these 50 only, with clear "Last Verified" timestamps.
4.  Measure support ticket volume regarding specialist finding over the next 14 days to validate the 75% reduction assumption.

*Note: This approach validates the Value hypothesis immediately while containing the Usability risk through strict scoping.*
*Delaying for automation assumes the problem remains static, which support ticket trends suggest is false.*
