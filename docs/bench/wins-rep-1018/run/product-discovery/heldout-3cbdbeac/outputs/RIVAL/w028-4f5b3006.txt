### Comparative Analysis: PWA vs. Native App for Rural Telemedicine

**Context Summary**
*   **Network:** Average 1.5 Mbps, dropping to 0.3 Mbps peak.
*   **Device:** 90% low-end Android, storage-constrained.
*   **Critical Failure Point:** 12% consultation failure due to connection drops.
*   **Goal:** Maximize successful consultation completion via reliable offline sync.

#### 1. Progressive Web App (PWA) Approach
**Strengths:**
*   **Acquisition Friction:** Near-zero. Users access via URL; no download required. This aligns perfectly with the 90% low-end device constraint where storage is premium.
*   **Updates:** Instant deployment without user action or app store approval.
*   **Storage:** Minimal footprint compared to native binaries.

**Weaknesses (Critical for DesaHealth):**
*   **Offline Sync Reliability:** While Service Workers enable offline caching, browser implementations on low-end Android devices (often running older OS versions with outdated WebView components) are inconsistent. Background synchronization is frequently killed by aggressive battery savers common on budget devices.
*   **Data Persistence:** Browsers may evict cached data (medical history) if storage pressure is high, risking data loss before sync occurs.
*   **Connection Handling:** Managing complex state transitions during the 0.3 Mbps spikes is harder in the browser environment than in native code.

**Projected Outcome:** High initial sign-up, but likely **higher consultation failure rates** than the current 12% baseline if offline sync fails during the critical handoff between patient input and doctor review.

#### 2. Native Mobile Application Approach
**Strengths:**
*   **Offline Sync Robustness:** Native SQLite or Realm databases provide deterministic local storage. Background services can be configured to retry synchronization aggressively once connectivity returns, even on unstable networks.
*   **Network Optimization:** Native code allows for finer control over data compression and packet management, crucial for 0.3 Mbps environments.
*   **Device Integration:** Better access to hardware features (camera, microphone) with lower latency, improving consultation quality.

**Weaknesses:**
*   **Acquisition Friction:** High. Requires download (storage space) and installation. On low-end devices, users may refuse or fail to install due to "Storage Full" errors.
*   **Maintenance:** Requires manual updates by users, which may lag in rural areas.

**Projected Outcome:** Lower initial acquisition due to install friction, but significantly **higher consultation completion rates**. Once installed, the reliability of offline sync directly addresses the 12% failure rate caused by connection drops.

#### Recommendation
Given that **consultation completion** is the primary success metric and the critical unknown is **offline sync reliability**, the **Native Mobile Application** is the superior technical choice for the pilot phase, despite the acquisition friction.

**Rationale:**
1.  **Reliability Over Reach:** A user who installs the app but completes 95% of consultations provides more value than a user who accesses the PWA easily but fails 15-20% of the time due to sync issues. The 12% failure rate is a clinical risk that outweighs acquisition ease.
2.  **Hardware Reality:** Low-end Android devices in rural markets often have fragmented browser support. Native APIs offer the only guaranteed method for robust background synchronization and data persistence under 0.3 Mbps conditions.
3.  **Mitigation Strategy:** To address the storage/install friction:
    *   Optimize the APK size strictly (<15MB).
    *   Implement an "Lite" version containing only essential consultation modules.
    *   Use local community health workers to pre-install the app on patient devices during onboarding, bypassing the self-service friction.

**Conclusion for Investors:**
Prioritize **clinical reliability** (Native) over **viral acquisition** (PWA) for the pilot. The cost of a failed medical consultation exceeds the cost of user acquisition friction. Re-evaluate PWA only after native sync stability is proven and device storage constraints are mitigated through partnerships or hardware subsidies.

*Note: This analysis assumes standard Android fragmentation in rural Indonesia; specific OS version data from the pilot villages would refine the browser compatibility risk.*
