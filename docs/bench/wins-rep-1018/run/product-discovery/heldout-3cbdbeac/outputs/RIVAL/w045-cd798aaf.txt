# Recommendation: Defer Referral Network Visualization; Prioritize Billing Improvements

**Executive Summary**
Do not prioritize the referral network visualization for the upcoming release. While the request comes from eight physicians, the evidence suggests this is a "nice-to-have" feature rather than a critical retention driver. The team should proceed with the planned billing improvements to secure core viability before investing engineering bandwidth in strategic visualization tools.

**Rationale**

1.  **Insufficient Evidence of Daily Utility (Value Risk)**
    The primary assumption—that the map increases retention by 15%—is unvalidated. The feedback represents a single instance of interest ("asked if we can") rather than observed behavior. There is no data indicating these physicians currently manually map referrals or lose patients due to a lack of visualization. Without evidence that this solves a frequent, painful problem, building it risks creating unused functionality. The "unknown variable" of daily usage is a significant red flag; features that are not used daily rarely drive double-digit retention gains in scheduling tools.

2.  **Core Viability Takes Precedence**
    Billing improvements address **Viability** (revenue capture, cash flow, and compliance), which is foundational for primary care clinics. If the billing system has friction, it directly impacts the clinic's ability to operate. A referral map addresses **Value** (strategic insight), which is secondary to operational stability. In product discovery, fixing broken core workflows (billing) almost always outweighs adding new strategic layers (visualization) until the core is flawless.

3.  **Engineering Bandwidth Constraints**
    With a four-week window, the team cannot afford to build a complex visualization feature based on unvalidated assumptions. Developing a network map requires significant front-end and data engineering effort. If the feature fails to drive the projected 15% retention lift, the opportunity cost is high: the billing improvements would be delayed, potentially causing churn or revenue loss for the entire user base, not just the eight requesting physicians.

**Proposed Action Plan**

*   **Immediate Term (Next 4 Weeks):** Execute the planned billing improvements. This secures the product's fundamental value proposition for all 2,000+ monthly referral users.
*   **Validation Step (Concurrent):** Before building the map, conduct five rapid customer interviews with the requesting physicians. Ask specifically about the *last time* they tried to analyze their referral gaps, what tools they used, and what happened. Do not ask if they *would* use a map; verify if they are actively trying to solve this problem today.
*   **Future Consideration:** If interviews reveal that physicians are manually spending hours mapping referrals and losing patients as a result, revisit the visualization feature in the subsequent cycle. Until then, treat the request as a hypothesis, not a requirement.

**Conclusion**
The steering committee should reject the proposal to swap priorities. The risk of building an unused feature outweighs the potential reward, especially when core billing functionality requires attention. Validate the need for the map through behavioral research before committing development resources.

*Note: This recommendation assumes billing improvements address known friction points; if billing is already perfect, the context changes.*
*Next step: Schedule interviews with the 8 requesting physicians immediately to test the "daily use" assumption.*
