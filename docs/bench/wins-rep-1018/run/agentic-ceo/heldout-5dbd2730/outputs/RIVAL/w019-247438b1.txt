1.  **Engineer A (Data Integrity):** Script the validation checks to compare row counts and checksums between the live database and the backup. Prepare the rollback script that restores the pre-migration state if the new schema fails verification.

    *   **Critical Point:** This is irreversible. Ensure the old queue is paused but not purged until the first successful end-to-end test is confirmed.

4.  **Verification & Release (Hours 3.5–4):**
    *   Inject a test report and verify it flows through the new system to the notification endpoint.
    *   Monitor the dashboard for error spikes.

5.  **Post-Launch Monitoring:**

    *   Do not purge the old queue data until the morning shift confirms successful processing of at least 500 live reports.

**Full Flow Summary:**
Backup → Parallel Prep (Validation/Simulation/Alerting) → Maintenance Mode → Schema Migration → Stream Switch → Test Injection → Traffic Resume → Morning Handover.

**Notes:**

*   If the dry-run (Engineer B) reveals critical incompatibilities, halt the cutover and notify hospital partners of a potential delay before the SLA breach occurs.
