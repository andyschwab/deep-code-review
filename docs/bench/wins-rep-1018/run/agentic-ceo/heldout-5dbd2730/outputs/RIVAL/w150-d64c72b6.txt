### Disaster Recovery Failover Preparation Plan

**Phase 1: Pre-Simulation Drills (Monday)**
1.  **Configuration Syntax Drill:** The five Site Reliability Engineers (SREs) must manually write and peer-review the exact quorum and split-brain resolution commands on a isolated sandbox environment. This verifies syntax without touching live data.
2.  **Communication Dry-Run:** Conduct a 15-minute "tabletop" exercise with the four Network Architects and SREs. Simulate the alert trigger and practice the verbal confirmation chain required before any command execution. No actual systems are touched; focus strictly on role clarity and latency in decision reporting.
3.  **Rollback Rehearsal:** Execute a simulated failure of the failover itself. Practice the specific steps to abort the process and revert to the primary region configuration before the point of no return.

**Phase 2: Critical Command Decisions Requiring Authorization**
During the live simulation next Tuesday, you must personally authorize the following three gates. No automation should proceed past these points without your explicit verbal or written confirmation:
1.  **The Isolation Confirmation:** Authorize the final verification that the primary region is successfully artificially isolated and accepting no new external traffic before secondary activation begins.
2.  **The Quorum Threshold Commit:** Authorize the execution of the split-brain resolution command that sets the new quorum. This is the irreversible action where misconfiguration risks permanent data divergence.
3.  **The Traffic Cutover:** Authorize the DNS or load balancer update that shifts 100% of read-write traffic to the secondary region only after the quorum is confirmed stable.

**Phase 3: Immediate First Steps for Secondary Site Readiness**
To ensure the secondary site is ready for the switch, execute these steps immediately:
1.  **Data Lag Audit:** Verify the current replication lag between primary and secondary regions. It must be under 1 second. If higher, pause all non-essential writes to the primary until synchronization is caught up.
2.  **Quorum Configuration Freeze:** Lock the configuration files on the secondary region. Ensure no automated deployment pipelines can alter the cluster membership or quorum settings between now and the simulation.
3.  **Network Path Validation:** Have the Network Architects run a one-time trace route and bandwidth saturation test from key engineering hubs to the secondary region to confirm low-latency paths are established and routable.

**Note:** Ensure a dedicated scribe records the exact timestamp of every command entered during the simulation for the post-mortem analysis. Do not attempt to fix minor latency issues during the 15-minute window; prioritize completing the failover sequence over perfection.
