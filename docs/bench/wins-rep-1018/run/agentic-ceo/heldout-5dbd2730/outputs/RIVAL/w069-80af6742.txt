**Emergency Migration Plan: Clearwater Dialysis Data Operations**

**Immediate Decision:** The first focus must be **finalizing the rollback protocol**. Without a verified, executable rollback plan, switching the primary database connection violates the zero-tolerance policy for data loss. Parallel tests and training are secondary to ensuring the "undo" button works perfectly before the "go" button is pressed.

**Role Allocation**

**Decisions for You (Team Lead):**
1.  **Go/No-Go Criteria:** Define the exact metrics that constitute "100% complete" backup verification. You must hold the authority to abort the migration if these metrics are not met by 5:30 AM.
2.  **Communication Chain:** Establish the single line of command for the 4-hour window. You will be the only person authorizing the switch from legacy to new systems.
3.  **Audit Sign-off:** You must personally verify the final checksum report before the legacy connection is severed.

**Tasks for Technicians (6 Staff):**
1.  **Backup Verification Team (2 Techs):** Immediately run integrity checks on the legacy log backup. Their sole output is a binary "Pass/Fail" report on data completeness for the 150 daily sessions.
2.  **Rollback Execution Team (2 Techs):** Draft and dry-run the script to revert the database connection to the legacy system within 15 minutes. They must prove this works in a sandbox simulation now.
3.  **Monitoring & Logging Team (2 Techs):** Set up real-time dashboards to track the migration progress session-by-session. They will document every timestamp and error code during the 2 AM – 6 AM window.

**The Very First Action**
Convene the team immediately to **simulate the rollback procedure**. Do not discuss training or parallel testing yet. Have the Rollback Execution Team walk through the steps to revert the database connection while the Backup Verification Team confirms the integrity of the source data. If this simulation fails or takes longer than 15 minutes, the migration cannot proceed. This action validates the safety net before any risk is introduced.

**Schedule Overview (2 AM – 6 AM)**
*   **02:00 – 02:30:** Final Rollback Simulation & Backup Integrity Sign-off.
*   **02:30 – 04:30:** Execute Migration (Switch connection, monitor 150 sessions).
*   **04:30 – 05:30:** Verification Phase (Compare new dashboard data against backup logs).
*   **05:30 – 06:00:** Final Go/No-Go Decision. If verified, stand down. If not, execute rollback immediately.

**Note:** Training for the night shift on the new dashboard must occur *after* the migration is stable or during the verification phase only for the Monitoring Team; it is not a prerequisite for the cutover.
**Note:** Parallel system tests are too time-consuming for this 4-hour window; rely on the pre-migration backup verification and post-migration spot checks.
