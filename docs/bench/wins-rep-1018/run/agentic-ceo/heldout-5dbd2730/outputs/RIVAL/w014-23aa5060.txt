### CardioGen Portal Launch: Verification Session Plan

**Phase 1: Critical Risk Assessment (Immediate Priority)**
Before any code execution or team delegation, the **Screening Logic Integrity Audit** must occur. This is the single point of failure. Since the data-locking mechanism is irreversible after 100 confirmations, verifying the algorithm that filters the 12,000 pre-screened candidates is the mandatory first step. If this logic contains even a minor error (e.g., incorrect inclusion/exclusion criteria mapping), the trial protocol is compromised upon locking. No other task takes precedence over validating that the software correctly interprets the regulatory inclusion/exclusion rules against the candidate database.

**Phase 2: Team Delegation Strategy**
Once the core logic is theoretically validated, delegate tasks as follows to maximize efficiency while maintaining safety:

*   **Junior Developers (Safe Delegations):**
    *   **Data Sanitization Checks:** Verify that the 12,000 candidate records are formatted correctly and contain no null values in critical fields (e.g., age, consent status).
    *   **UI/UX Flow Testing:** Manually walk through the applicant journey to ensure forms submit correctly and error messages are clear. This does not touch the core screening logic.
    *   **Load Simulation Scripts:** Run non-destructive performance tests to ensure the server can handle the initial surge, provided these tests do not trigger the actual data-lock mechanism.
    *   **Documentation Review:** Cross-reference current system behavior against the technical specification documents.

*   **Senior Developers & Compliance Officer (Restricted Tasks):**
    *   **Core Logic Code Review:** Only seniors and the compliance officer should review the actual screening algorithm code.
    *   **Regulatory Mapping:** The compliance officer must sign off that the digital rules exactly match the FDA/ethics board-approved protocol.
    *   **Lock Mechanism Trigger Test:** A controlled dry-run in a staging environment (with dummy data) to confirm the lock activates precisely at the 100th confirmed participant and freezes the correct fields.

**Phase 3: Final Approval Checklist (Pre-Launch)**
You must personally approve the following three items before authorizing the switch to live applications:

1.  **The "Golden Record" Validation Report:** A signed document from the Compliance Officer and Lead Developer confirming that a specific set of test candidates (representing edge cases) were processed by the staging system and resulted in the exact expected accept/reject decisions.
2.  **The Rollback/Containment Protocol:** While the lock is irreversible, you must approve the procedure for *stopping* the intake immediately if errors are detected in the first 10 live submissions, preventing the system from reaching the 100-participant lock threshold with bad data.
3.  **The Go/No-Go Sign-off:** A formal declaration that the Screening Logic Integrity Audit is complete, all high-priority bugs are resolved, and the staging environment results match production expectations.

Do not flip the switch until these three approvals are physically or digitally signed.
