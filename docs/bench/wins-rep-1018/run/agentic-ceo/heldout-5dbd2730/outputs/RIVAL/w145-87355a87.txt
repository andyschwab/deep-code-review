### Helios Data Platform Launch: Critical Deletion Session Plan

**Phase 1: Pre-Commit Validation & Approvals (Hours 0–0.5)**
1.  **Secure Compliance Approval:** Before any technical action, obtain written sign-off from the Compliance Officer specifically authorizing the irreversible deletion of the *legacy test environment* instances. Verify the approval lists the exact database identifiers to ensure no production or backup instances are included.
2.  **Run Final Validation Script:** Execute the validation script immediately after approval is secured. This script must confirm two things: (a) the target instances match the four million records slated for deletion, and (b) the live cluster and regression backups are completely disconnected and read-only protected. **Do not proceed** if the script flags any ambiguity.

**Phase 2: The Commit Point & Deletion Protocol (Hour 0.5)**
3.  **The Commit Moment:** Once the validation script returns a "PASS" status and compliance approval is physically/digitally present, the Lead Engineer issues the verbal "Commit to Delete" command. This is the point of no return.
4.  **Initiate Deletion:** Trigger the deletion protocol on the verified test instances. Log the start time immediately.

**Phase 3: Parallel Workstream (Hours 0.5–3.5)**
While the deletion process runs (approx. 3 hours), delegate the following to junior engineers:
*   **Documentation Audit:** Update the system architecture diagrams to reflect the removal of the legacy test environment.
*   **Launch Prep:** Finalize the deployment checklist for the live cluster, ensuring all post-launch monitoring hooks are active.
*   **Communication Drafting:** Prepare the "Launch Successful" and "Launch Delayed" stakeholder notifications based on potential outcomes.

**Phase 4: Contingency & Completion (Hour 3.5+)**
5.  **Successful Completion:** If the process finishes without error, run a verification query to confirm zero records remain in the test shard. Archive the deletion logs for audit purposes and proceed to the live deployment.
6.  **Stall Protocol:** If the process stalls halfway:
    *   **Immediate Action:** Do not restart or kill the process manually. Freeze all related network traffic to the test shard.
    *   **Escalation:** Alert the core engineering lead and the database vendor support channel immediately with the specific error codes.
    *   **Hold Pattern:** Pause the live cluster deployment until the stall is resolved and data integrity is re-verified. The launch cannot proceed until the test environment status is definitively "Cleared" or "Restored to Known State."

**Note:** This plan prioritizes compliance verification before technical execution to mitigate the risk of accidental data loss. The "Commit to Delete" is strictly gated by the validation script's success.
