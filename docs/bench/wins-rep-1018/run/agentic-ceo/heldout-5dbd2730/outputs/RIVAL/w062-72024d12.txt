### Work Session Structure: Haven Hospice Family Portal

**1. Order of Operations**
*   **Phase A: Cryptographic Foundation (Days 1–3)**
    *   Define key generation protocol and storage architecture.
    *   Execute dry-run of key generation in an isolated sandbox environment.
    *   Establish the "break-glass" recovery procedure for master keys.
*   **Phase B: Core Integration (Days 4–14)**
    *   Build the secure messaging module with end-to-end encryption (E2EE) enforced at the client level.
    *   Develop the read-only adapter for the existing patient database (450 families).
    *   Implement strict access controls linking family accounts to patient records.
*   **Phase C: Security Validation (Days 15–25)**
    *   Internal threat modeling and code review by the three backend engineers.
    *   Engage the two external security auditors for targeted penetration testing and key management verification.
    *   Remediate findings immediately.
*   **Phase D: Deployment & Handover (Days 26–30)**
    *   Final production key generation (the irreversible step).
    *   Secure backup of master keys in multiple geographically separated locations.
    *   Go-live monitoring and staff training.

**2. Decision Matrix: Sign-off Required vs. Engineer Authority**

| Decision Area | Requires Your Sign-off | Engineers Can Handle |
| :--- | :--- | :--- |
| **Key Management** | Final approval of the key storage location and the specific individuals authorized to hold key shards. | Selection of cryptographic libraries and algorithms (e.g., AES-256, RSA-4096). |
| **Compliance** | Acceptance of the residual risk profile and final privacy policy wording for families. | Implementation of audit logs and data retention rules per compliance officer guidance. |
| **Integration** | Approval of the data mapping schema between the portal and the patient database. | Writing the ETL scripts and API connectors for the 450 family records. |
| **Timeline** | Authorization to halt launch if auditor findings are critical near the Dec 1st deadline. | Task scheduling, code refactoring, and internal testing protocols. |

**3. First Immediate Task: Mitigate Key Management Risk**
**Execute a "Dry-Run" Key Generation Ceremony.**
Before writing any application code, the team must simulate the master key generation process in a completely isolated, air-gapped environment. This task involves:
1.  Drafting the exact step-by-step script for generating the keys.
2.  Running the script to verify the output format and ensuring the backup mechanism works.
3.  Deliberately attempting to "lose" the keys in this sandbox to prove that the system correctly renders historical data unreadable, confirming the risk model.
4.  Documenting the exact commands and conditions required for success.

This ensures that when the real irreversible step occurs, the team is executing a proven, muscle-memory procedure rather than untested theory.

***

*Note: Ensure the compliance officer validates the dry-run procedure before execution to meet audit trails.*
*The two external auditors should be briefed on the key management protocol immediately upon hiring to align their testing scope.*
