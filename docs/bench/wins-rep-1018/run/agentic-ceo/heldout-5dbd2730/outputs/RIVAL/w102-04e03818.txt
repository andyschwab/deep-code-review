**Work Session Plan: Harvest Marketplace Launch**

**Session Objective:** Finalize the critical path to launch by September 1st, ensuring system stability for high concurrency and securing initial liquidity (farmers and carriers).

**1. Feature Build vs. User Registration Priority**
**Decision:** Prioritize the **Matching Engine** over the User Registration flow.
*Reasoning:* The irreversible risk is broken matching logic destroying trust. A beautiful registration flow is useless if loads spoil due to poor matching. We will implement a bare-bones, secure registration wrapper solely to support engine testing. The engine must be stress-tested with simulated high concurrency data before any public outreach begins.

**2. Go-Live Criteria (Requires Your Approval)**
You must personally approve the following before public registration opens:
*   **Matching Accuracy Threshold:** The engine must successfully match 95% of simulated test loads within 2 minutes under peak load conditions (simulating 500 farmers posting simultaneously).
*   **Data Integrity Check:** Zero data loss or corruption in transaction logs during a 4-hour stress test.
*   **Rollback Protocol:** A verified, one-click mechanism to freeze new postings and revert to a maintenance mode if critical errors occur post-launch.

**3. Delegated Outreach Activities (Marketing Lead)**
The Marketing Lead will execute the following immediately, independent of the final code freeze:
*   **Carrier Pre-Screening:** Secure verbal commitments from 50 core carriers to ensure baseline capacity, collecting only essential contact info manually for now.
*   **Farmer Waitlist Campaign:** Launch a "Reserve Your Spot" landing page to gauge interest and collect emails, clearly stating the launch date without exposing the unfinished platform.
*   **Trust Asset Creation:** Develop case studies from last season's spoilage data to highlight the platform's value proposition in upcoming communications.

**4. Work Session Agenda (4 Hours)**
*   **Hour 1: Risk & Architecture Review.** Engineering lead presents the stress-testing protocol for the matching engine. Product defines the "minimum viable match" criteria.
*   **Hour 2: Sequencing & Dependencies.** Map the 7-week timeline backward from Sept 1st. Identify the "code freeze" date for the engine vs. the "soft launch" date for registration.
*   **Hour 3: Resource Allocation.** Assign the 7-person team: 4 on engine/stability, 2 on essential registration/security, 1 liaising with marketing for data integration.
*   **Hour 4: Final Go/No-Go Gates.** Define the specific metrics for the "Go-Live Criteria" listed above. Sign off on the Marketing Lead's delegated tasks.

**The Single Most Important First Step (Today)**
**Define and document the "Minimum Viable Match" algorithm specifications.**
Before writing code or calling a single farmer, the product and engineering leads must agree on the exact logic that determines a successful match (e.g., distance radius, temperature requirements, timing windows). This definition is the foundation for all stress testing. If this logic is ambiguous, the resulting engine will fail under pressure, causing the very spoilage we aim to prevent. Everything else—registration, marketing, UI—is secondary to proving this core logic works.

*Note: The fixed $100k budget should be reserved primarily for server infrastructure scaling during the first week of harvest, not ad spend.*
*Delaying the engine build to perfect registration features is the highest risk to the September 1st deadline.*
