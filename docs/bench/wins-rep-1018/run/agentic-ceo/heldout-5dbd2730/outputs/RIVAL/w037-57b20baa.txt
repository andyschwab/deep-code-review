### VitalLink Kickoff Plan

**Immediate Decision:** Start with the **Field Workflow Review**.
Given the irreversible risk of the data schema lock and the hard deadline, technical constraints must be defined by actual field behaviors, not assumptions. A technical spike on storage limits is secondary; if the schema does not match the coordinators' real-world data collection flow, the storage capacity is irrelevant. The two field coordinators must define the exact data points and sequence before a single line of code is written.

**Sequence of Steps (Planning to Pilot):**

1.  **Workflow & Schema Definition (Days 1–3):**
    *   Coordinators map the exact offline journey.
    *   Developers draft the immutable data schema based *strictly* on this map.
    *   **Approval Required:** You must sign off on the final data schema. This is the point of no return.

2.  **Technical Architecture & Spike (Days 4–7):**
    *   Developers validate that the approved schema fits within local storage limits for a 3-day offline window.
    *   Establish the sync protocol for the district hub.
    *   **Team Execution:** Developers choose the specific local database technology; no approval needed unless it violates the schema or sync requirement.

3.  **Core Development Sprints (Weeks 2–6):**
    *   Build the data entry interface and local storage engine.
    *   Implement the "store-and-forward" sync logic.
    *   **Team Execution:** Daily standups and sprint planning are managed by the lead developer.

4.  **Internal Simulation (Week 7):**
    *   Simulate 3-day offline usage with dummy data matching expected volume.
    *   Test sync integrity upon reconnection.
    *   **Approval Required:** You must review the simulation results to confirm data integrity before field testing.

5.  **Limited Pilot (Week 8):**
    *   Deploy to 10 workers (2% of the base) in one district.
    *   Monitor for schema mismatches or sync failures.
    *   **Team Execution:** Coordinators manage the pilot feedback loop.

6.  **Full Deployment (By November 10):**
    *   Roll out to all 500 workers, ensuring a 5-day buffer before the November 15th deadline.

**Decision Matrix:**

*   **Requires Your Direct Approval:**
    *   Final Data Schema (Critical Path).
    *   Go/No-Go decision after Internal Simulation.
    *   Any change to the November 15th deadline scope.
*   **Team Independent Execution:**
    *   Technology stack selection (provided it meets offline criteria).
    *   UI/UX design details.
    *   Sprint task allocation and daily management.
    *   Pilot logistics and coordinator training.

**First Concrete Action:**
When opening workboards, create a single high-priority ticket titled **"Schema Lock Workshop."** Assign it to yourself, the lead developer, and both field coordinators. The description must read: "Define and freeze the immutable data schema based on current field workflows. Output: A signed JSON schema draft ready for architectural validation." Do not create any coding tickets until this item is moved to "Done."

*Note: The 3-day offline constraint dictates that data compression strategies should be discussed during the workshop, but not at the expense of workflow accuracy.*
*Ensure the coordinators have veto power on any data field that complicates their rural workflow.*
