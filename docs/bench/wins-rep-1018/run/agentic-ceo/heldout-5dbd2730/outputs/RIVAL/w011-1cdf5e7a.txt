**Migration Work Session Plan**

**1. Volume and Time Analysis**
*   **Total Volume:** 2,000,000 images.
*   **Problematic Files:** 3,000 (require manual intervention).
*   **Clean Files:** 1,997,000.
*   **Transfer Rate:** 50,000 images/hour.
*   **Available Window:** 14 days (336 hours).

**2. Processing Sequence**
To maximize efficiency and isolate risks, execute the migration in three distinct phases:

*   **Phase A: Manual Remediation (Days 1–4)**
    *   **Action:** Assign all 15 specialists to resolve the 3,000 known metadata errors *before* bulk transfer begins.
    *   **Workload:** 200 files per specialist over 4 days (approx. 50 files/day/specialist). This is well within capacity, allowing time for verification.
    *   **Goal:** Convert the 3,000 risky files into "clean" status so they can be included in the automated stream, ensuring a single, unified ledger.

*   **Phase B: Automated Bulk Transfer (Days 5–10)**
    *   **Action:** Run continuous automated transfers for the full 2,000,000 images (now all pre-validated).
    *   **Calculation:** 2,000,000 images / 50,000 per hour = 40 hours of pure transfer time.
    *   **Schedule:** Run two 10-hour shifts per day for 4 days, or one continuous shift over 5 days to allow for system cooling and monitoring buffers.
    *   **Buffer:** This leaves 4–5 days of the 14-day window for unexpected delays or re-transfers.

*   **Phase C: Integrity Verification & Ledger Generation (Days 11–13)**
    *   **Action:** Perform hash-check validation on the new archive against source logs. Generate the final audit ledger.
    *   **Contingency:** Use remaining time to re-migrate any files failing hash checks.

*   **Phase D: Decommissioning (Day 14)**
    *   **Action:** Wipe old servers only after the audit ledger is signed off internally.

**3. Error-Handling Protocols Requiring Approval**
The following protocols must be approved by you before Phase A begins:
*   **The "Stop-the-Line" Threshold:** Define the exact number of *unexpected* corruption errors (discovered during Phase B) that will halt the entire migration for root cause analysis (Recommended threshold: >0.1% of a batch).
*   **Manual Intervention Scope:** Confirm that specialists are authorized to modify metadata only, and not to alter image binary data, during Phase A.
*   **Fallback Procedure:** Approval to extend the timeline beyond 14 days if >5,000 files fail integrity checks during Phase C, rather than forcing a risky decommission.

**4. First Concrete Action to Verify Data Integrity**
Initiate a **cryptographic hash sampling (SHA-256)** on a random 1% subset (20,000 images) of the legacy storage immediately. Compare these hashes against the existing source manifest. This validates the current health of the source drives before any movement occurs, ensuring we are not migrating pre-existing corruption.

**Note:** This plan assumes the 3,000 metadata errors do not require image reconstruction, only data entry correction.
**Note:** The audit ledger must include both the transfer logs and the final hash verification report to satisfy compliance.
