**Session Plan: Acupuncture Records Migration**

**1. Safest Sequence of Operations**
*   **Phase A: Isolation & Backup (Immediate):** Create a read-only snapshot of the legacy database. Generate a full, verified backup stored on separate, immutable media. This is the only step before any script execution.
*   **Phase B: Staging Environment Dry-Run:** Deploy a clone of the new database in an isolated staging environment. Run the migration script against this clone using a 10% sample of data first, then 100%.
*   **Phase C: ID Conflict Resolution:** Execute a pre-migration script specifically designed to detect conflicting Patient IDs. Instead of overwriting, flag conflicts in a quarantine table for manual review by clinical liaisons.
*   **Phase D: Final Migration:** Once the dry-run is validated, execute the full migration to the production new database during a maintenance window.
*   **Phase E: Integrity Verification:** Run automated checksums and record counts. Clinical liaisons perform spot-checks on high-risk records.
*   **Phase F: Sign-off & Access:** Medical director reviews the integrity report. Upon signature, access restrictions for clinical staff are lifted.

**2. Approval Matrix**
*   **Requires Your Direct Approval:**
    *   Authorization to create the immutable backup snapshot.
    *   Approval of the "Conflict Resolution Strategy" (how conflicting IDs are quarantined vs. merged).
    *   Final sign-off on the Data Integrity Report before lifting access bans.
    *   Go/No-Go decision for the final production cutover.
*   **Team Autonomous Execution:**
    *   Data Specialists: Writing and testing the migration scripts in the staging environment; running the dry-run samples; generating the initial conflict reports.
    *   Clinical Liaisons: Reviewing quarantined ID conflicts; performing random spot-checks on migrated patient notes; drafting the summary for the medical director.

**3. The Very First Action**
**Execute a full, verified, immutable backup of the legacy system and physically disconnect the backup media from the network.**
Do not write a single line of migration code, do not map a single field, and do not analyze the schema until this backup is confirmed restorable. This ensures that even if the migration script catastrophically overwrites data or corrupts the source, the original 12,000 files from 2018–present remain untouched and recoverable, satisfying compliance requirements for zero data loss.

**Note:** The November 30th deadline requires starting the dry-run phases immediately after the backup is secured.
**Note:** Ensure the "overwrite" function in the legacy script is logically disabled or patched to "fail-safe" before any testing begins.
