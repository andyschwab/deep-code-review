**GreenPath Logistics Carbon Emission Tracker: Work Session Plan**

**Phase 1: Data Validation & Schema Preparation (Weeks 1-2)**
1.  **Audit Current Data:** Isolate a representative sample of the 2,000 vehicles to quantify the specific types of errors within the current 15% manual error rate.
2.  **Develop Adaptive Schema:** Create a flexible data ingestion layer that accepts raw telemetry now but maps to a configurable output template. This accommodates the upcoming government schema change without requiring code refactoring later.
3.  **Define Validation Rules:** Establish automated checks for data plausibility (e.g., fuel consumption vs. distance) to replace manual entry, targeting a reduction of error rates to under 1%.

**Phase 2: Safe Integration Strategy (Weeks 3-5)**
1.  **Sandbox Simulation:** Build a digital twin or software simulator of the engine control units (ECUs). All integration code must pass 100% of test cases in this simulated environment before touching physical hardware.
2.  **Read-Only Pilot:** Deploy the tracker to a control group of five vehicles in "read-only" mode. Verify that the software can poll data without sending any write commands or configuration changes to the ECUs.
3.  **Graduated Rollout:** Upon successful pilot validation, expand deployment in batches of 50 vehicles, monitoring system stability for 48 hours between batches.

**Phase 3: Reporting & Submission (Weeks 6-7)**
1.  **Schema Finalization:** Once the new government schema is released, configure the output mapping layer developed in Phase 1.
2.  **Full Fleet Aggregation:** Compile validated data from all 2,000 vehicles.
3.  **Regulatory Submission:** Generate the final report and submit before the May 1st deadline.

**Critical Decision: Fleet Risk Mitigation**
You must decide on the **hardware interface protocol** for the ECU connection. The critical choice is whether to utilize a dedicated, isolated diagnostic port (OBD-II) with strict hardware-level write protection, or to attempt a direct software integration into the vehicle's internal network (CAN bus).
*   **Recommendation:** Mandate a **hardware-isolated, read-only gateway**. Do not allow the tracker to send any signals to the ECU. This eliminates the risk of "bricking" the computers entirely, as the tracker physically cannot write malicious or corrupt data to the engine control unit. Accepting any level of write access introduces an unacceptable risk of grounding the entire fleet.

**First Immediate Action**
Direct the data science team to **build the ECU simulator and halt all plans for direct hardware connection** until the simulation proves the code is safe. Simultaneously, task two team members with analyzing the historical manual data to document the specific patterns of the 15% error rate, which will define the validation rules for the new system.

*Note: The adaptive schema approach ensures compliance despite the upcoming regulatory changes. Strict adherence to the read-only pilot phase is non-negotiable for fleet safety.*
