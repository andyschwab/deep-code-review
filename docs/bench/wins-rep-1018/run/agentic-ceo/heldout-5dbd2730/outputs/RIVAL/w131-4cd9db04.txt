### Fleet Routing Migration: Structured Session Plan

**Phase 1: Data Validation & Schema Reconciliation (Days 1–2)**
*   **Data Engineers (Independent):** Execute full-scale schema comparison scripts between legacy and new environments. Perform checksum validation on the first 10% of historical traffic data batches. Identify and log any field-type mismatches or null-value discrepancies.
*   **Your Review:** Review the "Schema Mismatch Report" and the "Data Integrity Sample Results." You must explicitly approve the data mapping logic before any further transfer occurs.

**Phase 2: Shadow Mode Testing (Days 3–4)**
*   **Data Engineers (Independent):** Configure the new environment to receive a live copy of telemetry streams without processing them for routing (shadow mode). Run parallel calculations using historical data replayed at 2x speed to stress-test the new algorithm.
*   **Your Review:** Analyze the "Latency Differential Report" (Old vs. New) and the "Route Deviation Analysis." You must sign off only if the new system's route generation stays under 3 seconds and deviates less than 0.5% from the legacy system's output.

**Phase 3: Final Switchover Preparation (Day 5 – Monday)**
*   **Data Engineers (Independent):** Pre-stage the final delta sync scripts. Prepare the rollback playbook, ensuring all manual override tools are accessible offline. Freeze non-essential code deployments.
*   **Your Review:** Conduct a "Go/No-Go" meeting based on the "Readiness Checklist." Verify that the rollback procedure has been dry-run successfully in a sandbox.

**Phase 4: Execution (Tuesday – Cutoff Date)**
*   **Action:** Execute the final delta data sync. Upon your verbal confirmation, flip the DNS switch.
*   **Post-Switch:** Monitor real-time dashboards for the first 60 minutes.

**Critical Performance Metrics Requiring Your Personal Review**
1.  **Schema Compatibility Score:** Must be 100% before Phase 2.
2.  **Route Calculation Latency:** Must average <3 seconds during shadow testing.
3.  **Data Throughput Stability:** Zero packet loss during the 2x speed stress test.
4.  **Rollback Success Rate:** 100% success in the sandbox dry-run.

**Tasks for Data Engineers (Independent Execution)**
*   Running checksum validations on historical data batches.
*   Setting up and maintaining the shadow mode telemetry pipeline.
*   Generating daily discrepancy reports between legacy and new outputs.
*   Preparing the final delta sync scripts and offline rollback tools.
*   Executing the sandbox dry-run of the rollback procedure.

**First Diagnostic Run to Execute Immediately**
Initiate a **"Schema Dry-Fit" diagnostic**. This involves taking a representative 1GB sample of the most complex recent telemetry data (including edge cases like GPS dropouts and high-density urban traffic) and attempting to ingest it into the new database schema without modification. The goal is not to process the data, but to immediately surface any hard failures in data typing, constraint violations, or missing fields that would cause the irreversible DNS flip to fail.

*Note: This plan assumes the new cloud environment is already provisioned and accessible. Ensure all stakeholders are available for the Tuesday Go/No-Go decision window.*
