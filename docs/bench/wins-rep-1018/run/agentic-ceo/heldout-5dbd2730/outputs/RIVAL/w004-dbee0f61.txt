### Genomic Data Migration Work Session Plan

**Session Objective:** Define the critical path for migrating 4PB of genomic data by November 15th, ensuring zero data loss and minimizing the 12-hour analysis cluster downtime.

**Critical Path Sequence:**
1.  **Pre-Migration Integrity (Weeks 1-3):** Generate cryptographic checksums (SHA-256) for all source data while the cluster remains online. This establishes the baseline for validation.
2.  **Bandwidth Optimization & Pilot (Weeks 4-6):** Calculate exact transfer duration based on current bandwidth constraints. Execute a pilot migration with a non-critical 10TB subset to validate throughput and error handling.
3.  **Incremental Synchronization (Weeks 7-9):** Begin continuous background replication of static historical data to the new region, reducing the delta required during the final cutover.
4.  **Downtime Window Execution (Target: October 30th - Buffer included):**
    *   Halt active experiments (12-hour window).
    *   Perform final delta sync.
    *   Validate integrity of the full 4PB against pre-generated checksums.
    *   Switch DNS and mount points to the new region.
5.  **Post-Migration Verification (Immediate + 48 hours):** Run application-level sanity checks on random datasets before releasing the cluster to researchers.

**Delegation vs. Authorization Matrix:**

*   **Delegate to Data Engineering Team:**
    *   Scripting and execution of pre-migration checksum generation.
    *   Configuration of transfer tools (e.g., AWS Snowball, GSUTIL, or specialized cloud transfer appliances) to maximize bandwidth usage.
    *   Execution of the pilot migration and analysis of transfer logs.
    *   Automation of the final delta sync process.
    *   Post-migration technical validation scripts.

*   **Require Your Direct Intervention/Authorization:**
    *   **Scheduling the Downtime:** You must negotiate the specific 12-hour window with the 20 researchers and principal investigators to minimize experimental impact.
    *   **Risk Acceptance:** Formal sign-off on the "Go/No-Go" criteria before the downtime window begins.
    *   **Emergency Rollback Trigger:** Defining the specific failure thresholds that would abort the migration and revert to the old region.
    *   **Resource Allocation:** Approving any temporary budget increases for expedited bandwidth or physical transfer appliances if the network calculation proves insufficient.

**The Very First Concrete Step:**
Immediately commission the Data Engineering team to calculate the **exact theoretical minimum transfer time** for 4PB given your current bandwidth cap, then subtract this from the November 15th deadline. If the result is less than 21 days (allowing for testing and buffer), you must immediately procure a physical data transfer appliance solution (e.g., AWS Snowmobile or Azure Data Box) today, as network transfer alone will mathematically fail the deadline.

---
*Note: This plan assumes a "lift and shift" strategy; any data transformation during move will extend the timeline. Ensure legal/compliance reviews for cross-region data movement are initiated parallel to technical planning.*
