### Work Session Structure & Execution Plan

**Phase Order:**
1.  **Architecture & Risk Mitigation (Immediate):** Define the sandbox strategy and data isolation protocols before writing code.
2.  **Testing (Core Focus):** Execute rigorous simulation in a non-production environment; live integration is the final step, not the testing ground.
3.  **Deployment (Final):** Roll out to production only after successful sandbox certification.

**Decision Matrix:**

*   **Decisions You Must Make Personally (Executive Risk):**
    *   **Sandbox Authorization:** Explicitly authorize the creation of a dedicated "sandbox" or "test" merchant ID with the customs authority, ensuring it is legally distinct from your production credentials.
    *   **Go/No-Go Threshold:** Define the specific success metrics (e.g., 100% successful mock transactions over 48 hours) required before you authorize the switch to live API keys.
    *   **Rollback Protocol:** Approve the manual fallback procedure (e.g., manual email clearance) if the automated tracker fails post-launch, accepting the operational cost to prevent API suspension.

*   **Decisions Developers Can Handle (Technical Execution):**
    *   **Mock Data Generation:** Creating realistic but fake shipment datasets that mirror the 800 shipments/month volume without using real container IDs.
    *   **Error Handling Logic:** Coding the system to catch and log API errors locally without retrying failed authentication attempts that could trigger security locks.
    *   **Environment Segregation:** Architecting the codebase to strictly separate test endpoints from production endpoints via configuration files, preventing accidental cross-contamination.

**The Very First Task:**
**Establish a Isolated Sandbox Environment.**
Before any code is written or architecture diagrams finalized, your team must contact the customs authority to obtain specific **test credentials** and a **sandbox endpoint URL**. If a formal sandbox does not exist, the team must build a "wiremock" service that simulates the government API's responses exactly. No connection attempts should be made to the live government API until this isolated environment is verified to accept and process test data safely. This ensures that even if the developers make catastrophic errors during the first week, your live credentials remain untouched and safe from suspension.
