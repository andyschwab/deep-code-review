**Emergency Migration Plan: Occupational Health Records to ComplianceHub**

**Absolute First Action:**
Before touching any data, the Compliance Officer must sign off on a **Data Privacy Impact Assessment (DPIA) addendum** specific to this emergency transfer. This document must explicitly define the secure transfer protocol (e.g., encrypted local network only, no cloud intermediaries) and restrict access to the three team members. No extraction occurs until this is signed to ensure legal compliance.

**Recommended Starting Strategy:**
Do **not** start with an automated cleansing script or a manual spot-check alone. Start with a **Rapid Schema Mapping and Duplicate Logic Definition** session (30 minutes).
*   **Reasoning:** An automated script will fail without knowing the specific rules for "messy" legacy data (e.g., how to handle typos in names vs. actual duplicates). A manual spot-check is too slow for 5,000 files. You must first define the *rules* of cleaning based on a small sample, then encode those rules into the script.

**Sequence of Events:**

1.  **Secure Environment Setup & Legal Sign-off (Immediate):**
    *   Isolate the migration workstation from the internet.
    *   Compliance Officer signs the DPIA addendum.
    *   Role assignment: Analyst A (Extraction/Scripting), Analyst B (Manual Validation), Compliance Officer (Threshold Approval).

2.  **Sample Analysis & Rule Definition (Hours 0–1):**
    *   Extract a random sample of 50 records (mix of recent and old).
    *   Manually identify common duplicate patterns (e.g., "John Doe" vs. "Doe, John", SSN typos).
    *   Define the "Golden Record" logic: Which field takes precedence if duplicates exist? (e.g., most recent date vs. most complete record).

3.  **Script Development & Dry Run (Hours 1–3):**
    *   Analyst A writes the cleansing script based on the defined rules.
    *   Run the script against the *sample only*.
    *   Analyst B verifies the sample output manually.

4.  **Threshold Approval Gate 1 (Critical Stop):**
    *   **Present to You:** The success rate of the sample clean (e.g., "48/50 records resolved automatically").
    *   **Approval Required:** You must approve the automated logic before full execution. If accuracy is <98%, return to Step 2.

5.  **Full Extraction & Automated Cleansing (Hours 3–6):**
    *   Extract all 5,000 records.
    *   Run the approved script.
    *   Segregate records: "Clean/Ready," "Ambiguous/Review Needed," and "Unresolvable."

6.  **Manual Triage of Ambiguous Records (Hours 6–9):**
    *   Analyst B manually reviews the "Ambiguous" set (estimated 5–10% of total).
    *   Compliance Officer spot-checks the manual decisions.

7.  **Threshold Approval Gate 2 (Critical Stop):**
    *   **Present to You:** The final count of records ready for import vs. those held back.
    *   **Approval Required:** You must authorize the import of the "Clean" batch and decide on the disposition of held-back records (e.g., manual entry post-deadline).

8.  **Staged Import & Verification (Hours 9–11):**
    *   Import "Clean" batch in chunks of 500 to monitor system performance.
    *   Verify checksums: Count records in Legacy vs. ComplianceHub.
    *   Generate a "Failure Log" of any rejected records due to unique constraint violations.

9.  **Final Sign-off (By 4:30 PM):**
    *   Compliance Officer validates the audit trail.
    *   Submit completion report to Legal.

**Data Quality Thresholds Requiring Your Explicit Approval:**
*   **Duplicate Resolution Logic:** The specific rules used to merge or discard duplicate entries.
*   **Ambiguous Record Handling:** The criteria for flagging records for manual review rather than auto-rejection.
*   **Final Import Authorization:** The go/no-go decision once the "Clean" batch is prepared and the volume of excluded records is known.

Note: Prioritize accuracy over speed; importing bad data locks accounts permanently, causing more delay than a missed 5 PM deadline. Ensure all temporary files are securely wiped immediately after verification.
