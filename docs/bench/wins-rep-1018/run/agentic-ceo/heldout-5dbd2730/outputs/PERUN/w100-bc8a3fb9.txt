**Decision:** Execute a **Limited Pilot on five robots** immediately; do not start with shadow mode simulation. Shadow mode cannot validate the irreversible database schema change or the real-time latency under load, which are the primary failure points. A pilot on 10% of the fleet provides the only valid proof of the cutover procedure within the four-hour constraint.

**Work Session Plan & Sequencing**

1.  **Preparation (Weeks 1–2):** Isolate the three legacy experts to document the exact rollback limits (even if schema is irreversible, data export must be possible). Junior engineers build the automated deployment scripts and the "kill switch" that reverts network traffic to the old system if the new software hangs, even if the DB remains migrated.
2.  **Staging (Week 3):** Run the pilot on five non-critical robots during a low-volume shift. Measure the exact time for DB migration, binary swap, and health check. If this exceeds 45 minutes, the four-hour total window for 50 robots is mathematically impossible without parallelization.
3.  **Cutover Strategy (October 20–24):** Do not migrate all 50 at once. Batch them into groups of 10. Migrate one batch per night. If a batch fails, halt the sequence. This limits the blast radius to 20% of capacity rather than 100%.
4.  **Final Deadline:** Complete all batches by October 24th to leave October 25th as a pure buffer day for stabilization before Q4.

**Contingency Plans Requiring Your Sign-off**

You must explicitly approve the following three scenarios before the pilot begins:
1.  **Data Loss Acceptance:** Acknowledge that if the schema migration corrupts data, there is no automated undo. You must sign off on the manual data reconstruction plan (estimated 48 hours of downtime) as the fallback.
2.  **Partial Fleet Operation:** Authorize operations to run at 80% capacity (40 robots) indefinitely if the final batch fails and requires a full system rebuild.
3.  **Hard Stop Time:** Define the exact minute (e.g., 4:00 AM) when we abort the current batch and revert network routing, regardless of migration progress, to ensure the assembly line starts on time.

**Delegation to Junior Engineers**

Assign the junior engineers these specific, isolated tasks to free up the legacy experts:
*   **Telemetry Dashboard:** Build a real-time view showing the migration status of each robot (Pending, Migrating, Active, Failed) with alerting on any step taking >5 minutes.
*   **Dry-Run Automation:** Script the pre-checks (disk space, network connectivity, version matching) to run automatically on all 50 robots nightly, producing a "Go/No-Go" report each morning.
*   **Communication Templates:** Draft the status update messages for the warehouse floor staff for three scenarios: Success, Delayed, and Aborted, ready for your review.

**First Immediate Task**

**Conduct a timed dry-run of the database schema migration on a full-volume data clone.** You must prove that the migration script completes in under 30 minutes on hardware identical to production. If this single step takes longer than 30 minutes, the four-hour window for 50 robots is insufficient, and the plan must be redesigned before writing any other code.

*Note: This plan assumes the network revert is instantaneous; if network switching takes >10 minutes, the batch size must be reduced to 5 robots.*
*Do not proceed to the pilot until the dry-run timing is verified.*
