**Decision:** Proceed with a "Parallel Run & Verify" strategy before any purge; do not delete old reference tables until three full monthly cycles match between systems. The single number driving this is **zero tolerance for unrecoverable audit data**, making the old system a read-only archive until Q2 next year, not a five-week sunset.

**Figures:** 5 weeks available vs. 2M line items = 400k items/week total, or 133k/week per technical expert. At a conservative 5 minutes per complex mapping rule, one expert handles ~10k items/week. **Gap:** You are short ~120 technical weeks of effort. The plan must assume 90% of mappings are automated via rules, with humans only handling exceptions, or the deadline is missed.

### Planning Session Agenda

**1. Source Integrity Validation (Immediate First Step)**
*   **Action:** Run a "Golden Record" audit on the legacy database before touching a single migration script.
*   **Method:** Select a statistically significant sample (e.g., 500 high-value transactions from each of the last 3 years). Manually verify duty calculations against original customs entries.
*   **Goal:** Establish a baseline error rate in the *source*. If the source is corrupt, migration amplifies the error.

**2. Data Cleansing & Mapping Strategy**
*   **Focus:** Define the "Exception Threshold." Determine which data patterns can be auto-mapped (e.g., standard HS codes) and which require human review.
*   **Output:** A mapping rulebook approved by the three technical leads.

**3. Pilot Migration (The "Dry Run")**
*   **Scope:** Migrate only the last 90 days of data.
*   **Verification:** Compare total duty liability, tax amounts, and line-item counts between old and new systems. Discrepancy tolerance must be set to $0.00 for liability fields.

**4. Parallel Run Phase (Critical Risk Mitigation)**
*   **Process:** For 30 days, enter new transactions into *both* systems (or shadow the new system against the old).
*   **Gate:** No purge of old tables occurs until three consecutive months show 100% reconciliation.

**5. Final Cutover & Archive**
*   **Action:** Switch primary operations to the new database.
*   **Policy:** Move old tables to "Write-Protected Archive" status, not deletion.

### Required Data Governance Policies for Approval

1.  **Retention & Archive Policy:** Explicitly forbids the deletion of legacy reference tables for a minimum of 7 years (or statutory limit), regardless of migration status. The old system becomes a read-only audit trail.
2.  **Reconciliation Tolerance Policy:** Defines the maximum allowable variance between systems (recommended: 0% for financial/tax fields, <0.1% for non-financial metadata) before a rollback is triggered.
3.  **Exception Handling Protocol:** Mandates that any unmapped or failed records during migration are quarantined for manual review by a technical expert before being forced into the new system.
