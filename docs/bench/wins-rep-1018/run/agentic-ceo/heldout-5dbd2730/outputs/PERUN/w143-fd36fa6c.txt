**Decision:** Start with **mapping data fields and technical integration gaps**, not the audit evidence report. You cannot document compliance for a system you have not yet proven can technically function without data loss. The audit report is an output of a successful integration, not a precursor to it.

**Progression Plan (9 Weeks to Oct 1st):**

1.  **Weeks 1–2: Technical Discovery & Gap Analysis.** Map every data field between the legacy system and VerifyNow. Identify missing fields, format mismatches, and latency differences. Build a "shadow mode" environment where VerifyNow processes traffic in parallel without affecting users.
2.  **Weeks 3–5: Integration & Parallel Testing.** Engineers integrate the new API. Run 100% of live traffic through both systems (legacy as primary, VerifyNow as shadow). Compare results automatically. Fix discrepancies immediately.
3.  **Week 6: Compliance Dry-Run.** With technical stability proven, Compliance Officers draft the audit evidence report using actual data from the shadow run. Verify that VerifyNow's logs meet the specific October 1st audit requirements.
4.  **Week 7: Cutover Rehearsal.** Perform a full dress rehearsal in a staging environment that mirrors production exactly. Time the switch. Validate that the "no toggle back" constraint is understood and that the one-day business impact scenario is mitigated (e.g., by pausing non-critical verifications during the window).
5.  **Week 8: Final Approval & Change Freeze.** Secure sign-off from you and the compliance lead. Freeze all other code changes to the identity module.
6.  **Week 9: Go-Live.** Execute the switch during a low-traffic window. Monitor intensely. Decommission legacy keys only after 48 hours of stable operation.

**Risks Requiring Your Personal Evaluation:**

*   **The Point of No Return:** Since you cannot toggle back without invalidating pending verifications for a full day, you must personally approve the "Go/No-Go" criteria. Define exactly what metrics (error rates, latency, match scores) must be met in the shadow phase to trigger the switch.
*   **Data Integrity Loss:** If a specific user attribute (e.g., middle name or secondary ID) does not map perfectly, verify if VerifyNow can still pass the compliance audit without it. This is a business risk, not just a technical one.
*   **Vendor SLA Failure:** If VerifyNow experiences downtime during your critical cutover window, do you have a manual fallback process to keep the business running while avoiding the "invalidated verifications" trap?

**First Action Item:**

Instruct your five security engineers to produce a **Field Mapping Matrix** within 48 hours. This document must list every data point sent to the old provider, the corresponding field in VerifyNow, and a status flag for "Match," "Transformation Required," or "Missing." Do not write a single line of integration code or audit documentation until this matrix is complete and reviewed.

*Note: The "no toggle back" constraint dictates that your testing phase must be exhaustive; there is no room for a "fix it in prod" approach.*
*Ensure your compliance officers are embedded with engineers during Weeks 1–2 to witness the gap analysis firsthand, rather than waiting for a final report.*
