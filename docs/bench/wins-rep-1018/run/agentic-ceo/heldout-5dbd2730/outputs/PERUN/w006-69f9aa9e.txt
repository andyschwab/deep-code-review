**Decision:** Execute a "Parallel Shadow Cutover" where historical data migration completes and validates fully before enabling any real-time updates, with the legacy system running read-only during the final 48-hour overlap. The single number driving this is **zero data loss tolerance**; attempting simultaneous migration and live traffic on a one-way trip creates an unrecoverable state if the new vendor's ingestion rate lags.

**Figures:** 60M records / 20 specialists = 3M records/specialist. At a conservative 5,000 records/hour validation rate, full historical migration requires 600 hours per specialist. With 20 specialists working 10-hour days, this requires 30 days of pure validation time. Stated timeline to Sept 20 is tight; if today is later than August 20, the historical batch must start immediately or the deadline is missed.

**Sequence of Operations:**
1.  **Freeze & Fork (Days 1-3):** Lock legacy schema. Begin full historical dump to new vendor sandbox.
2.  **Shadow Mode (Days 4-25):** New system ingests live traffic in read-only mode while historical backfill continues. No writes to new system yet.
3.  **Validation Gate (Days 26-28):** Compare checksums between legacy and new system for 100% of historical data + shadow traffic.
4.  **Cutover Window (Sept 18-19):** Disable legacy writes. Enable new system writes. Legacy becomes read-only archive.
5.  **Go-Live (Sept 20):** Full operation on new vendor.
