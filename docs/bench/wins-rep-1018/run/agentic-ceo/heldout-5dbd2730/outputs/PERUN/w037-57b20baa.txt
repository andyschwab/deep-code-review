**Decision:** Start immediately with the **field workflow review** with the coordinators. Do not begin the technical spike on local storage yet.

**Reasoning:** Your data schema is immutable post-deployment. If you design the storage engine before validating exactly what data points the workers need to capture offline, you risk locking in a schema that misses critical fields or includes unnecessary ones, bloating the limited local storage. The workflow review defines the *requirements* for the schema; the technical spike validates the *feasibility* of those requirements. You cannot validate feasibility without the requirements.

**Execution Sequence & Approval Gates:**

1.  **Workflow Definition (Days 1–3):** Coordinators map the exact offline journey.
    *   *Team Execute:* Draft the "Offline Data Contract" (list of every field needed).
    *   *Owner Approval:* **Sign-off on the Data Contract.** This locks the schema requirements.
2.  **Technical Spike (Days 4–7):** Developers test local storage limits against the signed Data Contract.
    *   *Team Execute:* Build a prototype storing 3 days of worst-case data.
    *   *Owner Approval:* **Go/No-Go on Architecture.** Only if the prototype proves the schema fits within device limits without corruption.
3.  **Schema Lock & Core Build (Days 8–30):**
    *   *Team Execute:* Finalize database schema (immutable) and build sync logic.
    *   *Owner Approval:* None required unless the spike failed.
4.  **Pilot Deployment (Days 31–45):** Deploy to 10 workers.
    *   *Team Execute:* Monitor sync success rates at the hub.
    *   *Owner Approval:* **Authorization for Full Rollout** based on pilot sync metrics.
5.  **Full Launch (By Nov 15):** Deploy to 500 workers.

**Decision Rights Summary:**
*   **You Must Approve:** The final list of data fields (schema requirements), the architectural go-ahead after the spike, and the final rollout authorization.
*   **Team Decides Independently:** Choice of local database technology, UI implementation details, sync retry logic, and pilot recruitment logistics.

**First Concrete Action:**
Open your workboards and create a single ticket titled "Define Offline Data Contract." Assign it to the two field coordinators with a due date of 48 hours from now. The acceptance criterion is a signed list of every data element a worker must capture during a 72-hour offline period. Do not create any coding tasks until this ticket is closed.

*Note: If the coordinators cannot define the data needs in 48 hours, the November 15 deadline is at immediate risk regardless of development speed.*
*Ensure the "Data Contract" document is version-controlled as the single source of truth before any code is written.*
