**Decision:** Adopt a "Shadow-Mode Validation" approach first. Do not migrate logic directly; instead, run the new automated planner in parallel with your manual process for two weeks to compare outputs before any real container is stuffed. This is the only way to meet the October 10 validation deadline without risking port rejection.

**Figures:**
*   **Timeline:** Today to Oct 10 (Validation) = ~21 days. Oct 11 to Nov 1 (Execution) = 21 days.
*   **Volume:** 500 containers total.
*   **Waste Cost:** 15% space waste on 500 containers = 75 lost containers worth of freight capacity.
*   **Risk:** 1 mislabeled hazmat unit = 100% port rejection for that shipment + fines.

**Owner Decisions (Safety Compliance):**
You must personally sign off on three specific items before code is written:
1.  **The Hazmat "Hard Stop" Rule:** Define the exact data fields in your legacy database that trigger an automatic "Do Not Stuff" flag. If these fields are ambiguous, you must decide the default behavior (recommendation: default to "Hold for Manual Review" rather than "Auto-Reject" to prevent workflow blockage, but never "Auto-Pass").
2.  **The Liability Threshold:** Decide the acceptable false-positive rate for hazmat detection. A 0% false negative rate is mandatory; a 5% false positive rate (holding safe goods for review) is acceptable to ensure safety.
3.  **The Override Protocol:** Name the single individual authorized to override an automated hazmat flag during the execution phase. No analyst may have this power.

**Immediate Analyst Tasks (Start Today):**
Your three logistics analysts should not wait for the system to be built. They must execute these parallel tracks:
1.  **Data Sanitization (Analyst 1):** Audit the legacy inventory database specifically for hazmat fields. Produce a report of all records where hazmat status is null, conflicting, or non-standard. This is the highest risk vector.
2.  **Baseline Capture (Analyst 2):** Document the last 20 manual stuffing plans in detail, including the specific "rules of thumb" used to achieve the current 15% waste. This creates the benchmark the new system must beat.
3.  **Test Case Generation (Analyst 3):** Create 50 synthetic container manifests that include edge cases (mixed hazmat/non-hazmat, odd dimensions, priority goods). These will be used to validate the automated system's logic during the shadow mode.

**Work Session Sequence:**

1.  **Days 1–3: Risk & Data Definition.** You define the Hazmat Hard Stop rules. Analyst 1 completes the data audit. We freeze the requirements for the "Safe Path."
2.  **Days 4–10: Prototype & Shadow Setup.** Build the minimal automation logic focused *only* on space optimization and hazmat flagging. Analyst 3 prepares the 50 test cases.
3.  **Days 11–17: Parallel Validation (Shadow Mode).** Run the automated system on historical data and new incoming orders alongside manual planning. Compare space utilization and hazmat flags.
4.  **Days 18–21: Gap Analysis & Sign-off.** Review discrepancies. If the automated system matches manual safety decisions and improves space usage by >5%, you sign off. If not, revert to manual for hazmat-heavy loads only.
5.  **Oct 11–Nov 1: Phased Execution.** Automate 20% of containers in Week 1, 50% in Week 2, 100% in Week 3, maintaining the "Hard Stop" review for any flagged items.

**Halt Trigger:** If Analyst 1 finds >10% of hazmat records are ambiguous, halt automation planning and focus 100% on data cleanup until resolved.
**Fallback Trigger:** If the Shadow Mode shows even one false negative on hazmat classification by Oct 5, revert to 100% manual planning for hazmat goods and automate only general cargo.

*Note: This plan prioritizes the hard constraint of port acceptance over the soft constraint of speed. The 15% waste reduction is secondary to avoiding fines.*
