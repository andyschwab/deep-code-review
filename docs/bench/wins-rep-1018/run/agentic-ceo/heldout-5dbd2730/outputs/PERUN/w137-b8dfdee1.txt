**Decision:** Proceed with a linear "Schema-First" delivery model where data collection and algorithm validation run in parallel only after the schema is locked, with dashboard design occurring last to ensure data integrity.

**Figures:** 40 hours/week manual effort × 8 weeks (Nov 15 to Dec 12) = 320 hours at risk if delayed; 300 vehicles ÷ 3 regions = 100 vehicles per region for parallel testing.

**Logical Order of Stages:**
1.  **Schema Locking (Now – Nov 15):** Define and freeze all data fields, types, and relationships. No code is written until this is signed off.
2.  **Parallel Execution (Nov 16 – Nov 30):**
    *   *Data Collection:* Build pipelines to ingest the 300 vehicle feeds based on the locked schema.
    *   *Algorithm Validation:* Test efficiency calculations against historical manual records using the same schema.
3.  **Dashboard Design & Integration (Dec 1 – Dec 10):** Visualize the validated data. This must happen last so the visual layer never dictates data structure changes.
4.  **Executive Review Prep (Dec 11):** Final dry run.

You must decide the **Business Logic Definitions**: specifically, how "fuel efficiency" is calculated for the board (e.g., MPG vs. L/100km, inclusion/exclusion of idle time, and handling of outlier data from broken sensors). The team owns the **Technical Implementation**: database selection, ETL tool choice, specific coding languages, server infrastructure, and the visual color palette or chart types (provided they meet accessibility standards). They also decide the **Error Handling Protocols**: how to flag missing data points without stopping the whole pipeline.
