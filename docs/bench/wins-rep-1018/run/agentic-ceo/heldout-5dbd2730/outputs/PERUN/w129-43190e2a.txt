**Session Agenda: Customs Broker Migration**

**Phase 1: Data Mapping & Gap Analysis (Days 1–3)**
*   **Objective:** Define the exact schema delta between current output and new regulatory requirements.
*   **Engineering Leads:** Delegate the extraction of current shipment payloads and the drafting of the new JSON/XML schema to junior staff. Leads must review the mapping logic for the 10 highest-volume commodity codes personally.
*   **Owner Sign-off Required:** Approval of the final "Field Mapping Matrix" confirming that all new mandatory regulatory fields are accounted for and sourced from existing ERP data or manual entry workflows.

**Phase 2: Build & Unit Testing (Days 4–10)**
*   **Objective:** Implement the transformation layer and new API client.
*   **Engineering Leads:** Delegate unit test creation and mock service implementation to junior staff. Leads are responsible for the integration logic and error-handling routines (specifically retry logic for border timeouts).
*   **Owner Sign-off Required:** None during build, unless a required data field is found to be missing from source systems, requiring a business process change.

**Phase 3: Integration & Compliance Validation (Days 11–17)**
*   **Objective:** End-to-end testing with the new broker's sandbox.
*   **Engineering Leads:** Leads must execute the "Cutover Simulation" personally; do not delegate the failure-mode testing (e.g., what happens if the new broker rejects a packet?). Junior staff can run regression suites on existing functionality.
*   **Owner Sign-off Required:** **Critical.** Sign-off on the "Compliance Test Report" confirming successful transmission of the 5 most complex shipment types. This is the legal gate before go-live.

**Phase 4: Cutover Preparation (Days 18–24)**
*   **Objective:** Finalize the rollback (or rather, "forward-fix") plan and communication protocols.
*   **Engineering Leads:** Delegate the writing of runbooks and status page updates. Leads must verify the monitoring alerts for the new API latency and error rates.
*   **Owner Sign-off Required:** Approval of the "Emergency Contingency Plan" detailing manual workaround procedures if the API fails post-launch, acknowledging the risk of fines.

**Phase 5: Go-Live Weekend (December 28–29)**
*   **Objective:** Switch endpoints and monitor.
*   **Action:** Execute the handshake. If the handshake fails, trigger the contingency plan immediately (manual filing via broker portal if available, or halting shipments to avoid fines).
*   **Owner Sign-off Required:** The "Go/No-Go" decision based on the Phase 3 report.
