**Decision:** Execute a **full mock migration with dummy data** as the immediate first step. Do not freeze admissions (unethical and operationally impossible) and do not rely on a manual paper backup as the primary strategy (too slow and error-prone for 3,000 daily meals). The mock migration is the only way to validate the irreversible database schema compatibility before touching live allergy data.

**Execution Strategy: Weekend Cutover Plan**

**Phase 1: Validation (Weeks 1–3)**
1.  **Synthetic Data Generation:** Create a dummy dataset mirroring the exact structure of your live database, including the 45 high-risk patient profiles with complex allergy constraints.
2.  **Dry Run Migration:** Perform the database transfer to the new system using this dummy data.
3.  **Verification:** Have clinical staff verify that the 45 high-risk profiles display correct dietary restrictions in the new POS interface.
4.  **Rollback Test:** Intentionally break the migration mid-stream to prove you can revert to the old system without data loss within the 48-hour window.

**Phase 2: Preparation (Weeks 4–5)**
1.  **Hybrid Contingency:** Instead of a full paper system, prepare "Allergy Alert Cards" for the 45 high-risk patients only. For general meals, the kitchen will operate on a simplified, pre-set menu for Monday breakfast/lunch if the digital system fails.
2.  **Staff Drill:** Conduct a tabletop exercise with the 5 IT specialists and 2 vendor reps simulating a failed migration at 3:00 AM Saturday. Define the exact "Go/No-Go" decision time (e.g., Sunday 2:00 PM) to abort and revert.

**Phase 3: The Weekend Cutover (Saturday Night – Monday Morning)**
1.  **Saturday 8:00 PM:** Stop all cafeteria transactions. Finalize live data export.
2.  **Saturday 10:00 PM:** Begin database migration.
3.  **Sunday 6:00 AM:** Complete data transfer. Begin validation scripts.
4.  **Sunday 12:00 PM:** Clinical lead verifies the 45 high-risk patient records manually.
5.  **Sunday 2:00 PM (Go/No-Go Gate):** If validation passes, unlock the system for Monday prep. If failed, initiate immediate rollback to the legacy system.
6.  **Monday 6:00 AM:** System live for breakfast. IT team stationed at registers and kitchen pass.
