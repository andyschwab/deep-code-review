**Decision:** Proceed with a phased rollout starting with a single-floor pilot; do not attempt a hospital-wide launch on September 20th without validating the token push mechanism first. The single number driving this is **1**: one factory reset event on 300 devices creates a catastrophic operational failure that outweighs the benefit of meeting the date.

**Figures:**
*   **Training Capacity:** 150 staff / 8 days (Aug 20–Sep 20) = ~19 staff/day. With 2 floor managers, this allows ~9 staff per manager daily, assuming 1-hour sessions. This is tight but feasible only if development is already complete.
*   **Risk Exposure:** 300 devices × 1 wrong batch = 300 physical factory resets. Estimated time: 30 mins/unit × 300 = 150 hours of biomedical engineering downtime.

**Sequenced Plan:**

1.  **Phase 1: Safety & Token Protocol (Days 1–5)**
    *   Define the "Golden Batch" procedure for device registration.
    *   Implement a "dry-run" mode in the app that validates tokens against a sandbox without touching real devices.
    *   **Milestone:** Signed-off protocol for token generation and verification.

2.  **Phase 2: Core Development & Offline Sync (Days 6–25)**
    *   Build the checkout logic with 48-hour offline caching.
    *   Integrate the token push feature with a mandatory "double-blind" verification step (two distinct admins must approve the batch).
    *   **Milestone:** Feature-complete beta on dev devices.

3.  **Phase 3: Single-Floor Pilot (Days 26–35)**
    *   Deploy to **one** floor (approx. 12–15 devices) with the two floor managers.
    *   Test offline resilience (simulate 48-hour outage).
    *   Execute a live token push on this small subset to validate the irreversible step.
    *   **Milestone:** Successful pilot with zero lockouts; go/no-go decision for full rollout.

4.  **Phase 4: Training & Staged Rollout (Days 36–45)**
    *   Train staff floor-by-floor immediately following successful pilot validation.
    *   Roll out to remaining 23 floors in batches of 4 floors per day.
    *   **Milestone:** 100% staff trained, 100% devices registered by Sept 20th.

**Risks Requiring Your Personal Evaluation:**

*   **Offline Data Integrity:** You must decide the conflict resolution policy. If two therapists check out the same nebulizer while offline, whose transaction wins when connectivity returns?

*   **Verification Checklist:** A physical card required to be signed before any token batch is approved.

**Very First Task to Prevent Mass Device Lockout:**
Create a **non-production mirror environment** containing digital twins of the 300 ventilators and nebulizers. Before writing a single line of production token logic, the six developers must successfully push a "dummy" batch to these twins and verify that a failed push leaves the twins in a usable state. If you cannot simulate the failure safely, you cannot build the feature.
