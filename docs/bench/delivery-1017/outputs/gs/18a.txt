### Delivery Plan: Patient Intake Flow Update

#### 1. Work Lanes & Parallelism
*   **Lane A (UX/UI Design):** Redesign the insurance verification step for clarity and apply recent branding updates. This runs **in parallel** with Lane B. Deliverable: High-fidelity mockups and asset package.
*   **Lane B (Backend Logic):** Refactor the intake data capture logic to prevent incomplete records. Ensure strict adherence to the immutable encryption config (read-only). This runs **in parallel** with Lane A. Deliverable: API updates and unit tests.
*   **Lane C (Integration & QA):** Merge A and B into a feature branch. Implement the workaround for the known flaky insurance validation check (e.g., retry logic or specific test tagging). Run the full suite. This lane **starts only after** A and B are complete.

#### 2. Gates & Checks
*   **Gate 1 (Design Review):** Lane A output must be approved by the Product Lead for usability (elderly demographic focus) and Brand Manager for consistency.
*   **Gate 2 (Security & Compliance Scan):** Lane B code must pass static analysis. **Critical Check:** Verify zero attempts to modify the immutable patient data encryption config. Any write attempt triggers an immediate halt.
*   **Gate 3 (CI Pipeline):** Run on the final release candidate commit.
    *   *Constraint:* Due to credit costs, this runs only once the code is frozen.
    *   *Flake Handling:* If the insurance validation module fails, a human engineer must manually verify the log to distinguish a flake from a regression before proceeding.
*   **Gate 4 (Dual Approval):** Before merging, explicit written approval is required from both the **Lead Architect** (technical soundness) and the **Compliance Officer** (regulatory readiness for the upcoming audit).

#### 3. Review Strategy
*   **Primary Reviewer:** Senior Engineer (not the author of Lane A or B) to check code quality and integration.
*   **Independent Compliance Review:** The Compliance Officer reviews the *behavioral* change specifically regarding data completeness and audit trails, independent of the technical implementation details.
*   **User Acceptance:** A sandbox demo must be validated by one Clinic Manager to confirm the "stuck" issue is resolved before production scheduling.

#### 4. Landing & Rollback
*   **Merge Window:** Tuesday, 02:00 – 04:00 UTC only.
*   **Process:**
    1.  Merge to `main` at 02:00 UTC.
    2.  Trigger deployment pipeline.
    3.  Verify health checks in production.
    4.  Notify requester ("Live") only after successful health verification.
*   **Human Decision Point:** If the CI pipeline fails due to the flaky check, the On-Call Engineer must decide whether to bypass (with documented justification) or fix. If the Compliance Officer withholds approval, the launch is canceled regardless of technical readiness.
*   **Rollback Plan:**
    *   **Trigger:** Critical data loss, security lockout, or blocking bug reported within the first 2 hours.
    *   **Action:** Initiate manual database restore from the nightly snapshot.
    *   **Impact:** Approximately 45 minutes of downtime/data reversion. Front desk staff must be notified immediately to pause intake processing during restoration.

#### 5. Post-Launch
*   Once live, coordinate with the requester to schedule front-desk training.
*   Monitor incomplete record rates daily leading up to the regulatory audit.
