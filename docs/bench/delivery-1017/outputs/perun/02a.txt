### Delivery Plan: Seasonal Trend Filter

**1. Lanes & Serialization**
*   **Lane A (Spec & Design):** Product Analyst defines the exact date-mapping logic for "corresponding dates" and the persistence schema (localStorage key). Output: Updated spec and mockups. *Serial prerequisite for Lane B.*
*   **Lane B (Implementation):** Builder implements the toggle, overlay rendering, and state persistence in a dedicated worktree. Constraint: Uses current visualization library (no v2.4 upgrade). Includes unit tests for logic.
*   **Lane C (Accessibility & UX):** Independent reviewer audits the new toggle for keyboard navigation, screen reader labels, and contrast ratios on low-resolution viewports. *Runs parallel to Lane B, merges after.*
*   **Lane D (Evidence Capture):** QA engineer executes the change in a headed browser on a low-resolution viewport. Records the required video proof of the overlay rendering and persistence after refresh. *Runs only on the exact integrated SHA from Lane B+C.*

**2. Gates & Checks**
*   **G1 (Spec):** Product Lead approves the date-mapping logic and persistence strategy.
*   **G3 (Design):** Accessibility Champion signs off on the component design before code is written.
*   **G4 (Build):** Builder commits code with unit tests. CI runs lint/type/unit checks only (skipping full suite to save cost/time).
*   **G5 (Verify):**
    *   **Functional:** Lane D produces the video receipt on the exact commit SHA.
    *   **Visual:** Manual verification of the overlay; automated screenshot comparison is **skipped** due to known flakiness on animations.
    *   **Persistence:** Verified by refreshing the page in the recorded session.
*   **G6 (Review):**
    *   **Code:** Senior Frontend Engineer (not the Builder) reviews the diff.
    *   **Accessibility:** Accessibility Champion provides final approval on the implementation.
    *   **Product:** Product Lead confirms the feature matches the spec.

**3. Review Independence**
*   The Builder (Lane B) never reviews their own code.
*   The Accessibility Champion (Lane C/G6) acts independently of the Builder and Product Lead.
*   QA (Lane D) verifies the exact revision provided by the merge of B and C, not the Builder's narrative.

**4. Landing & Human Decisions**
*   **Integration:** Lanes B and C merge to an integration branch. Lane D verifies this specific SHA.
*   **Staging:** Automated deployment to staging occurs immediately after G6 approval.
*   **Human Gate (Production):**
    *   **Approver:** VP of Engineering.
    *   **Condition:** Manual sign-off required during business hours only.
    *   **Action:** Once signed, the release manager triggers the production push.
*   **Rollback:** If the overlay causes rendering errors or persistence failures in production, the release manager reverts the integration commit immediately. The rollback plan is verified in staging before the production request is submitted.

**Cost Control:** Full CI suites ($45/run) are triggered only for the final integration SHA and the release candidate, not for intermediate builder commits.
