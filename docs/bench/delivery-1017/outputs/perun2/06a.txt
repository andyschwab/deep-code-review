### Delivery Plan: Daily LLM Spend Cap

**Objective:** Enforce a $450 daily hard cap on external LLM calls with user-facing feedback, live before Tuesday's marketing blast.

#### 1. Lanes & Parallelism
*   **Lane A (Implementation):** Modify `parser-service` to check daily usage against the $450 limit before invoking the external API. Implement the "try again tomorrow" user message.
    *   *Constraint:* Must use the production database schema (irreversible migration).
    *   *Parallel:* Yes, starts immediately.
*   **Lane B (Infrastructure/Config):** Update the global configuration file shared with the billing daemon to expose the current daily cost counter to the parser service.
    *   *Parallel:* Yes, runs alongside Lane A.
*   **Lane C (Pipeline Optimization):** Refactor the CI regression suite to skip historical dataset re-processing for this specific change, targeting only the `parser-service` logic.
    *   *Dependency:* Must complete before Lane D (Verification) to avoid 28-minute delays.
    *   *Serialized:* Runs after Lane A/B code is committed to a feature branch.

*   **Constraint:** The Builder cannot approve their own code. Reviewers must be distinct from the implementers.

#### 4. Landing & Human Gates

*   **Cost Control:** The optimized CI pipeline (Lane C) is mandatory to prevent $12/run waste during iterative testing.
