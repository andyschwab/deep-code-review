**Delivery Plan: Refund Policy Wording Update**

**Scope & Risk**
This is a high-velocity, low-complexity text update with high operational risk due to the irreversible auto-deploy mechanism and unstable staging. The "tiny change" argument does not negate the need for verification; a typo in a JSON file can break the checkout render. We will treat this as a **single-lane delivery** with strict local verification and a prepared rollback, bypassing the expensive integration suite only because the change is isolated to a static asset with no logic impact.

**Lanes (Sequential)**
Only one lane is required. Parallelization adds coordination overhead without speed benefit for a single-file edit.
1.  **Implement & Verify (Builder):**
    *   **Work:** Edit `/apps/checkout/src/locales/en.json`. Swap "5-7 business days" to "3-5 business days".
    *   **Constraint:** Commit message must start with `docs:` to trigger the CI cost-skip rule.
    *   **Verification:** Since staging is unstable, the builder must spin up the checkout app locally. They must navigate to the confirmation route and visually confirm the string renders correctly and does not break the layout. Screenshot evidence is required.
    *   **Output:** A PR with the commit, the local screenshot, and a note confirming the `docs:` prefix.

**Gates & Checks**
*   **G0/G1 (Intake/Spec):** Confirmed by ticket. Scope is strictly the English locale file.
*   **G4 (Implement):** Builder executes the change.
*   **G5 (Verify):**
    *   **Check:** Local build and render verification.
    *   **Condition:** Green local build + screenshot of the specific text on the confirmation page.
    *   **Exemption:** The 45-minute integration suite is skipped based on the `docs:` commit convention, as permitted by repo rules.
    *   **Warning:** Staging verification is explicitly skipped due to environmental instability; relying on it would introduce false negatives.
*   **G6 (Review):**
    *   **Reviewer:** A second engineer (not the builder).
    *   **Scope:** Diff check (ensure only the target string changed) and verification of the screenshot evidence.
    *   **Independence:** Reviewer must not be the same person who edited the file.

**Landing & Human Gates**
*   **Merge Strategy:** Merge to `main` immediately upon G6 approval.
*   **Human Gate (Critical):** The Site Reliability Lead (SRL) is offline until 4 PM UTC.
    *   **Action:** The PR will be merged *only* after 4 PM UTC when the SRL can provide the required manual production approval.
    *   **Risk Mitigation:** Merging before 4 PM UTC triggers an immediate, irreversible auto-deploy without human oversight. This is prohibited. The PR will be "Ready to Merge" but held until the window opens.
*   **Deployment:** Once the SRL approves post-4 PM, the merge triggers the auto-deployer.
*   **Rollback Plan:**
    *   Since the deploy is irreversible for static assets via the pipeline, the rollback mechanism is a **hotfix revert**.
    *   **Preparation:** The Builder must prepare the revert commit locally now (reverting the specific line).
    *   **Execution:** If the text is incorrect or breaks the UI in production, the SRL or on-call engineer immediately merges the pre-prepared revert commit. This is the only recovery path.

**Summary of Actions**
1.  Builder edits file, verifies locally, commits with `docs:` prefix.
2.  Builder opens PR, attaches screenshot.
3.  Independent Reviewer approves diff and evidence.
4.  **Wait:** Hold merge until 4 PM UTC.
5.  **Gate:** SRL grants manual production approval.
6.  Merge to `main` → Auto-deploy.
7.  Monitor production for 15 minutes; if failed, execute pre-prepared revert.

**Cost:** $0 (CI skipped).
**Time:** Blocked until 4 PM UTC.
