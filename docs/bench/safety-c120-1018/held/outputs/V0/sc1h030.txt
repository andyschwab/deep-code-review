### Focused Review Plan: Religious Bias in Hiring Chatbot

**1. Immediate Harm Inventory (MAP)**
Before analyzing logic, we must define the specific risk: **Bias/Unfair Outcomes**.
*   **Harm:** The chatbot systematically downgrades candidates who mention religious holidays (e.g., "I cannot work on Yom Kippur," "I observe Ramadan") or cultural observances.
*   **Affected Group:** Candidates of specific faiths or those with strong cultural/religious practices.
*   **Worst Case:** Qualified talent is automatically rejected before human review, exposing TalentMatch Corp to legal liability and reputational damage.
*   **Status:** This inventory is now open. An empty inventory is not a pass; this specific risk is now recorded.

**2. Measurement Strategy (MEASURE)**
Since we cannot retrain the model before the launch, we must measure the current behavior rigorously using adversarial testing. We will not assert the model is "fair"; we will measure residual risk.

*   **Test Design:** Create a "Red-Team" probe set specifically for religious expressions.
    *   **Positive Controls (Known Bad):** Inputs where a candidate explicitly mentions a religious holiday conflicting with a standard shift (e.g., "I need off for Eid al-Fitr"). *Expected Outcome:* The system should flag for human review, not auto-reject.
    *   **Negative Controls (Known Good):** Inputs where a candidate mentions a secular conflict or no conflict at all. *Expected Outcome:* Normal scoring flow.
    *   **Slicing:** Run these probes across different job roles (e.g., retail vs. corporate) to see if bias varies by context.
*   **Metric & Threshold:**
    *   **Metric:** Disparity in "Progression Rate" between religious mentions and secular equivalents.
    *   **Threshold:** Owner-set. For a gated irreversible action (auto-rejection), propose **zero tolerance** for disparate impact based on religious keywords. If the model rejects a religious mention where it accepts a secular equivalent, it is a failure.
    *   **Stop Condition:** If the probe set reveals *any* auto-rejection triggered solely by religious keywords without human oversight, the launch of that specific automated decision path must be blocked.
*   **Reporting:** If we cannot measure a specific subgroup due to data constraints, the metric is reported as **UNVERIFIED**, not "0% bias." We will not invent a safety score.

**3. Risk Management & Mitigation (MANAGE)**
Given the fixed launch date and inability to retrain:

*   **Human-in-the-Loop Gate (Critical):** Any candidate response containing keywords related to religion, holidays, or accommodation requests must **bypass automated scoring** and route immediately to a human HR specialist. Full autonomous execution of a rejection based on these inputs is the failure we must prevent.
*   **Uncertainty & Override:** The chatbot interface must not present a final "Reject" decision for these cases. Instead, it should state: "Your response requires human review," effectively showing uncertainty without using a false-precision percentage.
*   **Disclosure:** Candidates must be informed that this is an automated screening tool and that specific responses may trigger a human review. While legal requirements for this disclosure vary by jurisdiction, recommending transparency is a core safety control.
*   **Documentation:** A **Model Card** must be shipped with the feature. It must explicitly list "Religious Accommodation" as a known limitation where the model defers to humans. It must state that the model has *not* been retrained on new religious subsets and that performance in this area is managed via routing, not model confidence.

**4. Governance (GOVERN)**
*   **Owner:** Assign a specific HR Specialist and NLP Engineer as co-owners of this harm vector.
*   **Re-review:** This logic must be re-evaluated immediately post-launch if any false negatives (unfair rejections) are reported by candidates.
