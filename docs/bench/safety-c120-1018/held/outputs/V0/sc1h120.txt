### Volcano-Ash Predictor: Edge Case & Override Protocol

**1. Edge Case Handling Strategy**
Given the scarcity of historical data for rare eruption types, you cannot rely on the model to generalize safely. Treat any input resembling a "rare eruption" profile as an automatic **UNVERIFIED** state rather than a low-confidence prediction.
*   **Define the Unknown:** Explicitly catalog the specific atmospheric signatures missing from your training set (e.g., specific particle sizes, thermal gradients unique to rare eruptions).
*   **Fail-Safe Trigger:** If input data falls outside the distribution of your verified training set, the system must not output a "safe" or "low risk" rating. Instead, it must trigger a **"Data Gap Warning"**, explicitly stating that the scenario matches known rare eruption patterns where the model has no validation.
*   **Adversarial Probing:** Before launch, run red-team probes using synthetic data that mimics these rare gaps. The pass condition is not accuracy, but the system's ability to correctly identify these inputs as "out of scope" and refuse to generate a definitive safety clearance.

**2. Manual Override & Human-in-the-Loop Gate**
Because the consequence of failure is engine failure (a high-stakes, irreversible outcome), full automation is unsafe. You must implement a mandatory human gate for any non-trivial warning.
*   **The Gate:** The system should never automatically reroute a flight or issue a definitive "hazardous" alert that locks out pilot discretion without human verification. Instead, it generates an **Advisory Flag**.
*   **Uncertainty Visualization:** Do not display raw confidence percentages (e.g., "87% risk"). These imply a calibration you do not possess due to data gaps. Use defined coarse tiers:
    *   **CONFIRMED:** Matches known high-fidelity patterns.
    *   **CORROBORATED:** Supported by multiple sensor types but outside standard models.
    *   **UNVERIFIED:** Matches rare eruption profiles or lacks historical precedent. **(Default for edge cases)**.
*   **Override Procedure:**
    1.  When the system flags **UNVERIFIED** or **CORROBORATED**, the automated suggestion is paused.
    2.  A specialist from your seven-person team must review the raw atmospheric data alongside the model's flag.
    3.  The specialist manually confirms, modifies, or rejects the advisory before it reaches the pilot/dispatcher.
    4.  Log every override and the specialist's decision rationale to build the missing historical dataset for future iterations.

**3. Transparency Artifact (Model Card)**
You must ship a Model Card with the system. It must explicitly state:
*   **Intended Use:** Routing advice for known eruption profiles.
*   **Limitations:** Explicitly list the "rare eruption types" excluded from training.
*   **Performance:** Report metrics only for verified subgroups; mark rare eruption performance as **UNVERIFIED**.
*   **Owner:** Name the specific specialist responsible for reviewing **UNVERIFIED** flags.

Do not certify the system as "safe" or "unbiased." The safety comes from the human gate and the honest admission of data gaps, not from the model's output alone.

*Note: Legal requirements for automated safety warnings in aviation vary by jurisdiction; route specific compliance questions to counsel. Ensure your "Data Gap Warning" language is clear to avoid automation bias where pilots might trust the tool despite the warning.*
