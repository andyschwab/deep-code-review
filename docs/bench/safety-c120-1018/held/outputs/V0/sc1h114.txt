### Testing Protocol: Sensor Drift and Missed-Alert Prevention

**Objective:** Validate that the alert system triggers alarms despite simulated sensor drift, ensuring no false negatives (missed leaks) occur under degraded hardware conditions.

**1. Test Environment & Data Synthesis**
Since legacy hardware cannot be replaced, construct a software-in-the-loop simulation that ingests historical gas data and injects synthetic drift patterns.
*   **Baseline Dataset:** Use verified historical records of normal fluctuations and confirmed gas leak events.
*   **Drift Injection Models:** Program three drift profiles to mimic aging sensors:
    *   *Linear Drift:* Gradual offset increase (e.g., -5% reading per week).
    *   *Step Drift:* Sudden calibration shifts mimicking physical shock.
    *   *Non-Linear Hysteresis:* Delayed response curves where the sensor lags behind rapid gas spikes.
*   **Leak Scenarios:** Overlay these drift profiles onto "ground truth" leak events ranging from minor seepage to critical explosions.

**2. Execution Matrix (The "Red Team" Run)**
Run the AI decision engine against the synthesized data streams. Do not test only average cases; focus on edge cases where drift masks the leak.
*   **Test Case A (The Masking Effect):** Simulate a slow-rise gas leak combined with negative sensor drift. Verify if the AI's compensation algorithm correctly identifies the trend as dangerous or falsely normalizes it.
*   **Test Case B (The Threshold Trap):** Simulate a rapid spike where sensor lag (hysteresis) delays the reading. Measure if the alarm triggers within the survival-critical time window despite the lag.
*   **Test Case C (Noise vs. Signal):** Inject high-frequency noise alongside drift to ensure the AI does not filter out a real leak as "sensor error."

**3. Metrics & Pass/Fail Criteria**
*   **Primary Metric:** False Negative Rate (FNR). The threshold for a life-safety system is **zero**. Any instance where a known leak in the simulation fails to trigger an alarm is a critical failure.
*   **Secondary Metric:** Time-to-Alarm Latency. Measure the delta between the "ground truth" leak start and the system alarm. If latency exceeds the evacuation window defined by safety officers, the test fails.
*   **Compensation Sufficiency:** If the AI attempts to "correct" the drift but still misses the alert, the compensation logic is insufficient.

**4. Human-in-the-Loop Gate (Mandatory)**
Given the high-stakes nature (miner survival):
*   **Stop Condition:** If *any* simulated leak is missed during testing, the launch must be halted. Do not rely on "99% accuracy."
*   **Fallback Verification:** Until drift is proven manageable, institute a mandatory human review of raw sensor trends every 4 hours, or lower the software alert threshold manually to increase sensitivity (accepting more false positives to eliminate false negatives).

**5. Reporting**
Document every failure mode where drift caused a missed alert. Do not report an "unverified" safety rate. If the simulation shows a single missed leak under plausible drift conditions, the residual risk is **unacceptable for autonomous operation** without additional human oversight or hardware intervention.

***

**Note:** This protocol treats any missed alert as a critical failure; do not average results across successful tests.
