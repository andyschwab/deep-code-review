### Rapid Compliance Review Checklist: Deduction Logic

**1. Logic & Rule Verification (Accountants Lead)**
*   **Map Aggressive Deductions:** List every deduction currently flagged as "aggressive" by the system.
*   **Statutory Cross-Reference:** For each item, cite the specific IRS code section or regulation that validates it. If no direct citation exists, mark as **Non-Compliant**.
*   **Income Threshold Check:** Verify that every suggested deduction respects the specific income limits for low-income filers (e.g., EITC phase-outs, standard deduction vs. itemizing thresholds).
*   **Documentation Requirement:** Confirm the system requires users to upload or confirm possession of supporting documents before suggesting high-risk deductions.
*   **"Safe Harbor" Filter:** Implement a hard rule blocking any deduction where the AI's confidence in the legal basis is not 100% verified against a static rule engine.

**2. Output Sampling & Testing Method (Developers & Accountants Joint)**
*   **Construct Adversarial Test Set:** Create 50 synthetic user profiles representing edge cases for low-income filers (e.g., gig workers with mixed expenses, renters claiming home office, dependents with split custody).
*   **Positive Control Group:** Include 10 profiles with clearly legal, standard deductions to ensure the system still functions for valid cases.
*   **Negative Control Group:** Include 10 profiles with explicitly illegal deduction scenarios (e.g., personal groceries claimed as business expenses) to verify the system *rejects* them.
*   **Blind Review Protocol:** Run the AI on all 50 profiles. Have two accountants independently review the output without knowing which are control cases.
*   **Pass/Fail Criteria:**
    *   **Fail:** Any suggestion of a deduction lacking a statutory citation in the Logic Verification step.
    *   **Fail:** Any acceptance of the Negative Control scenarios.
    *   **Stop Condition:** If >0% of the Negative Controls pass or if any "aggressive" deduction lacks a code citation, **do not launch**.

**3. Human-in-the-Loop Gate (Mandatory)**
*   **High-Stakes Override:** Any deduction flagged as "uncommon" or "high-value" relative to income must trigger a mandatory human review by a certified accountant before the return is finalized for the user.
*   **Uncertainty Disclosure:** If the system cannot verify a deduction against the static rule engine, it must display a clear warning: "This deduction requires professional review; AI cannot verify eligibility," rather than presenting it as fact.

**4. Final Governance Sign-off**
*   **Owner Assignment:** Name one accountant and one developer jointly responsible for the "Aggressive Deduction" module.
*   **Residual Risk Log:** Document any deductions where the rule is ambiguous. Mark these as **UNVERIFIED** and exclude them from the initial launch scope.
*   **Legal Routing:** Immediately forward the list of "aggressive" deductions and the proposed disclosure language to legal counsel to determine if specific regulatory disclosures are required for automated tax advice. Do not assert compliance internally; obtain external validation.

**Note:** Do not fabricate a "compliance rate" or "safety score"; if testing reveals any illegal suggestions, the residual risk is critical.
**Note:** This review addresses product output safety; final determination on regulatory duties rests with legal counsel.
