**Immediate Halt Recommendation:** Do not launch this feature in its current state. Encouraging users to "push through" based solely on simulated heart rate variability (HRV) without real-time clinical validation or a human-in-the-loop gate for high-stakes health decisions constitutes an unsafe automation of an irreversible action. The risk of inducing cardiac events in users with underlying conditions is a critical, unmitigated harm.

**Harm Inventory & Critical Risks**
*   **Unsafe High-Stakes Automation:** The system provides real-time coaching that could directly lead to severe physical injury or death (heart attack) if it fails to distinguish between athletic exertion and cardiac distress.
*   **Hallucination as Fact:** The algorithm may interpret noise or atypical HRV patterns in simulated data as "ready for more intensity," presenting this fabrication as authoritative coaching.
*   **Over-Reliance:** Users trusting the device for real-time safety warnings may ignore their own bodily signals of distress because the device encourages them to continue.
*   **Bias/Exclusion:** Simulated data often fails to capture the physiological signatures of underlying cardiac conditions, systematically disadvantaging users with these hidden risks.

**Testing Roadmap & Measurement Plan**
Since you cannot run live clinical trials, your testing must assume the model is unsafe until proven otherwise via rigorous adversarial simulation.

1.  **Adversarial Probe Set (The "Heart Attack" Simulation):**
    *   **Input:** Generate synthetic HRV data specifically modeled on known pre-infarction (pre-heart attack) patterns, not just "low fitness" baselines. Consult your sports physiologists to define these specific signal anomalies.
    *   **Positive Control:** Inputs representing clear cardiac distress must trigger an immediate "STOP" warning, not encouragement.
    *   **Negative Control:** Inputs representing peak athletic performance should trigger encouragement.
    *   **Metric:** False Negative Rate (instances where distress inputs yield encouragement).
    *   **Pass Threshold:** **Zero tolerance.** Any instance where the system encourages exertion during a simulated cardiac event is a hard block on launch.
    *   **Stop Condition:** If *any* probe in the distress set results in an "increase intensity" output, the feature fails QA immediately.

2.  **Uncertainty & Override Mechanism:**
    *   **Requirement:** The system must not output precise confidence percentages (e.g., "87% safe"). Instead, implement coarse, defined tiers: "Confirmed Safe," "Corroborated," or "Unverified/Consult Physician."
    *   **Action:** If the HRV signal falls into an ambiguous zone (common in simulated data), the default behavior must be to **warn** or **pause**, never to encourage.
    *   **Human Gate:** For any user flagged with irregular HRV history (if known) or ambiguous real-time data, the system must default to a conservative mode requiring explicit user confirmation that they feel safe before continuing high-intensity prompts.

3.  **Transparency Artifact (Model Card):**
    *   Draft a Model Card explicitly stating: "This system was trained/tested exclusively on simulated data. It has not been validated against real-time clinical cardiac events. It is not a medical device and cannot detect heart attacks."
    *   This disclaimer must be prominent in the UI before every workout, not buried in terms of service.
