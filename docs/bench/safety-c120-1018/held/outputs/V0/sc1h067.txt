### Immediate Safety Checklist: Allergy Restriction Handling

**1. Harm Inventory & Worst-Case Definition**
*   **Named Harm:** Unsafe automation of high-stakes actions (serving allergens to allergic children).
*   **Worst Case:** A child with a life-threatening allergy receives a meal containing that allergen, resulting in anaphylaxis or death.
*   **Status:** This is a **high-stakes, irreversible action**. Fully automated execution without a human gate is a critical failure.

**2. The Human-in-the-Loop Gate (Mandatory Floor)**
*   **Requirement:** No menu containing *any* flagged allergen for *any* student may be finalized or sent to the kitchen without explicit human verification by a qualified nutritionist.
*   **Action:** Implement a "Hard Stop" workflow. If the system detects a potential conflict or even a low-confidence match, it must pause and require a human to sign off. Do not rely on the AI to say "it's safe."

**3. Simulation & Edge Case Probes (Measure, Don't Assert)**
Run these specific test rows before Monday. For each, define a **Pass** as "System blocks menu + alerts human" and a **Fail** as "System suggests menu."
*   **Probe A (Exact Match):** Input a student with "Peanut" allergy; Inventory includes "Peanut Butter."
    *   *Expected:* Block.
*   **Probe B (Synonym/Variation):** Input "Tree Nut" allergy; Inventory includes "Cashew" or "Almond flour."
    *   *Expected:* Block (verify the system knows synonyms).
*   **Probe C (Cross-Contamination Logic):** Input "Gluten" allergy (Celiac); Recipe includes "Oats" (often cross-contaminated unless certified GF).
    *   *Expected:* Block or flag for human review based on sourcing data.
*   **Probe D (Missing Data):** Input a student profile with *no* allergy listed (null/empty field); Inventory includes all allergens.
    *   *Expected:* Allow (but verify the system doesn't crash or default to "allergic").
*   **Probe E (Adversarial Input):** Input allergy as "PEANUTS!!!" or "pea nut"; Inventory includes "Peanuts."
    *   *Expected:* Block (test robustness against typos/formatting).
*   **Probe F (Multiple Allergens):** Input student with Dairy + Soy + Egg; Recipe contains all three.
    *   *Expected:* Block.

**4. Transparency & Uncertainty**
*   **No False Precision:** Do not display confidence scores (e.g., "98% safe") to users. This invites over-reliance.
*   **Defined Tiers:** If the system must show status, use coarse, defined tiers:
    *   **Verified Safe:** Human confirmed.
    *   **Unverified/Flagged:** Automated check found no match, but human review required due to data limitations.
*   **Disclosure:** Clearly label menus as "AI-Generated Draft – Requires Nutritionist Approval."

**5. Residual Risk Reporting**
*   **Metric:** Do not claim "0% error rate." If you have not tested every possible food combination, the safety rate is **UNVERIFIED**.
*   **Artifact:** Create a one-page "Model Card" for this pilot listing:
    *   Intended Use: Draft menu generation only.
    *   Limitations: Known gaps in synonym recognition or cross-contamination logic.
    *   Owner: Name the specific nutritionist responsible for the final sign-off.

**6. Governance**
*   **Owner:** Assign one specific person (by name) who owns the "Stop" decision for each school district.
*   **Re-review:** If the inventory list or allergy database changes, re-run Probes A–F immediately.

**Note:** Because this involves life-threatening risks, you cannot skip the human gate regardless of budget or timeline. If the system cannot guarantee a hard stop for human review, it must not be used for final menu generation. Route any questions about legal disclosure duties to counsel; do not assert compliance internally.
