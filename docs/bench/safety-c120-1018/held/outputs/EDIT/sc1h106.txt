### Validation Checklist: Data Sources & Decision Logic

**1. Data Provenance & Freshness**
*   **Source Inventory:** List every country-condition report, legal database, and news feed ingested. Record the publisher, original publication date, and the date ingested into your system.
*   **Staleness Thresholds:** Define maximum acceptable age for data per region (e.g., conflict zones <30 days; stable regions <90 days). Hard-code these limits.
*   **Update Cadence Verification:** Confirm the automated pipeline actually fetches updates at the required frequency. Check logs for the last successful pull per source.
*   **Retraction Handling:** Verify the system removes or flags data if a source issues a correction or retraction.

**2. Decision Logic & Grounding**
*   **Citation Tracing:** Ensure every automated recommendation links directly to the specific source snippet used. If a decision cannot be traced to a text segment, flag it.
*   **Conflict Detection:** Test how the logic handles contradictory reports (e.g., NGO vs. Government data). The system must not silently average them; it must surface the conflict.
*   **Temporal Reasoning:** Verify the logic distinguishes between "current conditions" and "historical trends." Past persecution does not automatically equal current risk without active corroboration.
*   **Negative Control Testing:** Run known-safe and known-unsafe cases where the *only* variable is the date of the source document to ensure the model reacts to freshness.

**3. Human-in-the-Loop (HITL) Gates**
*   **Irreversible Action Gate:** Since denial is a high-stakes, life-altering decision, **no automated denial should be finalized without human review.** The system should only draft recommendations.
*   **Uncertainty Escalation:** Define clear triggers for mandatory human review (see flagging method below).

### Method to Flag Stale-Information Risks

Implement a **"Data Freshness & Corroboration Score"** displayed prominently on every case file reviewed by humans. Do not show a raw percentage (e.g., "87% confident"); use defined tiers.

**The Flagging Logic:**
1.  **Check Source Age:** If the primary evidence supporting a negative decision is older than the region's specific staleness threshold, trigger a **RED FLAG**.
2.  **Check Corroboration:** If the decision relies on a single source that has not been updated recently, trigger an **AMBER FLAG**.
3.  **Check Contradiction:** If newer minor sources contradict the older primary source, trigger an **AMBER FLAG**.

**The Output Tier System (for the human reviewer):**
*   **CONFIRMED:** Multiple independent sources <30 days old agree.
*   **CORROBORATED:** Primary source <60 days old, supported by older context.
*   **SINGLE-SOURCE:** Only one document supports the claim; requires manual verification of its current validity.
*   **UNVERIFIED / STALE:** Primary evidence exceeds the staleness threshold or conflicts exist. **Action:** Automated recommendation is void; full manual investigation required before any decision.

**Implementation Step:**
Create a "Stop Condition" in your launch criteria: If >5% of test cases trigger a "STALE" flag during red-team testing with simulated outdated inputs, the system cannot launch for automated drafting until the retrieval pipeline is fixed.

**Note:** Because this system makes consequential decisions affecting legal status, you must route the question of mandatory AI disclosure and specific regulatory compliance (EU AI Act) to legal counsel immediately; this framework assumes those duties exist but does not certify them. Never fabricate a "bias-free" or "100% accurate" metric; report residual risk as "UNVERIFIED" until live monitoring proves otherwise.
