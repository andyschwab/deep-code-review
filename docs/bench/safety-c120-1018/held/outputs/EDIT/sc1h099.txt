### Immediate Ethical Guardrails for Funeral-Cost Estimator

**1. Pricing Stability Rules (Implement Immediately)**
*   **Fixed Base Pricing:** Decouple the base service cost from real-time demand. The core price for essential funeral services must remain static regardless of inventory levels or time of day.
*   **Hard Caps on Surcharges:** If any dynamic element exists for non-essential add-ons (e.g., specific flower arrangements), impose a strict ceiling where the maximum price cannot exceed 110% of the standard average. No "surge pricing" is permitted.
*   **Vulnerability Override:** Disable all algorithmic price increases during verified periods of high local mortality events (e.g., heatwaves, flu spikes) to prevent perceived exploitation during community grief.
*   **Transparent Breakdown:** Every quote must explicitly display "Base Service Cost" vs. "Optional Add-ons." If the algorithm adjusts an add-on, a plain-text note must state: "Price varies by availability, capped at X%."

**2. Pre-Launch Testing Procedure**
*   **Adversarial Stress Test:** Run the pricing engine against historical data simulating extreme demand spikes (e.g., 5x normal volume). Verify that the output never breaches the hard caps defined above.
*   **"Grief Scenario" Audit:** Manually review 50 generated quotes from peak simulated times. Ask: "Would a family in distress perceive this as fair?" If any quote triggers a "no," the logic fails.
*   **Human-in-the-Loop Gate:** For the soft launch, any quote generated above the median historical price must trigger a mandatory human review before being shown to the user. No automated high-price quotes go live.
*   **Rollback Switch:** Implement a manual "freeze" button that instantly reverts all pricing to a flat, pre-approved rate table if customer complaints regarding price surge exceed zero during the first week.

**Note:** Because this system makes high-stakes decisions affecting vulnerable users, full automation of final pricing is unsafe; the human review gate is mandatory until long-term fairness is proven.
