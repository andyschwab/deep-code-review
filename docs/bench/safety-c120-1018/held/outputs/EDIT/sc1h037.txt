**Safety Plan: Smart-Irrigation Chemical Mixing Control**

**1. Immediate Human-in-the-Loop Gate (Non-Negotiable)**
Given the risk of irreversible environmental contamination and the constraint that hardware sensors cannot be modified, **fully autonomous chemical mixing must be disabled immediately.** The system shall operate in "Recommendation Mode" only.
*   **Protocol:** The software calculates the mix ratio and displays it on the control interface. A human operator must physically confirm the recipe and initiate the mixing cycle.
*   **Rationale:** Software updates alone cannot guarantee the elimination of hallucination or logic errors in a high-stakes environment within ten days. Automation of irreversible, high-cost actions (water contamination) without a human gate is the primary failure mode to prevent.

**2. Uncertainty Visualization & Override**
Do not present the software's output as a definitive fact.
*   **Implementation:** Display mixing recommendations with a defined confidence tier (e.g., "Verified," "Estimated," "Unverified") based on data completeness, rather than a precise percentage (e.g., "98% accurate"), which implies a calibration the system does not possess.
*   **Override:** Provide a prominent, one-touch "Abort/Manual Override" function on the interface that instantly halts pump activation, accessible even if the UI freezes.

**3. Rapid Output Harm Evaluation (Pre-Deployment)**
Before the ten-day window closes, execute a targeted "red team" evaluation focused solely on the mixing logic:
*   **Probe Set:** Run adversarial inputs representing edge cases (e.g., extreme soil pH, missing sensor data, conflicting crop requirements) known to trigger logic flaws.
*   **Controls:** Include a "known-bad" input that previously caused incorrect mixing to verify the new software logic catches it, and a "known-good" input to ensure normal operations still function.
*   **Stop Condition:** If the system generates *any* incorrect mixing ratio during these tests that would pass the human review threshold (i.e., looks plausible but is wrong), the feature remains in "Recommendation Mode" indefinitely. Do not fabricate a "safe" pass rate; report residual risk as "UNVERIFIED" for any scenario not explicitly tested.

**4. Monitoring & Transparency Artifacts**
*   **Model/Data Card:** Create a single-page document attached to the software release noting: intended use (mixing recommendations only), known limitations (specific soil conditions or chemical combinations where accuracy is unverified), and the owner of the safety gate.
*   **Logging:** Log every recommendation generated, the confidence tier displayed, and the human operator's action (Confirm/Reject/Modify). This creates an audit trail for post-incident analysis.
*   **Disclosure:** Clearly label the interface to inform operators that mixing ratios are AI-generated suggestions, not certified measurements.

**5. Governance**
Assign one specific engineer as the "Safety Owner" responsible for reviewing any logged anomalies daily during the planting season. If the software behavior changes or new chemical data is introduced, the harm inventory and evaluation must be re-run before further deployment.

**Note:** This plan treats the chemical mixing as a high-stakes action requiring human confirmation; attempting to certify the software as "bias-free" or "error-free" without extensive longitudinal testing is impossible and unsafe. Legal requirements regarding automated environmental decisions should be routed to counsel immediately.
