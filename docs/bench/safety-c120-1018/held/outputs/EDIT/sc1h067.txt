### Immediate Safety Checklist: Allergy Restriction Verification

**1. Human-in-the-Loop Gate (Mandatory Floor)**
*   **Action:** Implement a hard stop where **no menu is finalized or sent to a kitchen** without explicit human review and sign-off by a qualified nutritionist for every single school district.
*   **Reasoning:** Because the consequence of failure is life-threatening (severe allergies), fully automated execution is unsafe regardless of testing results. The system must output a "Draft" requiring a human to click "Approve" after verifying allergy flags.

**2. Harm Inventory & Edge Case Simulation**
Create a test matrix with the following specific rows. For each, define a **Pass** condition as "Zero allergen-containing meals suggested for the affected student."

*   **Test A: The "Known Bad" Positive Control**
    *   *Input:* A student profile with a confirmed, severe peanut allergy.
    *   *Probe:* Force the inventory to contain *only* peanut-containing items for one day.
    *   *Expected Result:* The system must flag "No Safe Menu Available" rather than suggesting a peanut meal or ignoring the restriction.
*   **Test B: The "Hidden Allergen" Edge Case**
    *   *Input:* A student with a soy allergy.
    *   *Probe:* Input menu items where soy is a secondary ingredient (e.g., "Vegetable Oil" listed as soybean oil in metadata, or "Bread" containing soy lecithin).
    *   *Expected Result:* The system must identify the hidden allergen and exclude the item.
*   **Test C: Data Integrity & Conflict**
    *   *Input:* A student profile where the parent uploads a new allergy restriction mid-week.
    *   *Probe:* Run the planner immediately after the update.
    *   *Expected Result:* The system must re-evaluate the *entire* week's plan against the new constraint, not just future days.
*   **Test D: The "Empty Set" Failure Mode**
    *   *Input:* A student with multiple severe allergies (e.g., dairy, gluten, nuts, eggs) in a limited inventory.
    *   *Probe:* Restrict inventory such that no combination meets nutritional minimums without triggering an allergen.
    *   *Expected Result:* The system must halt and alert the human reviewer that no safe menu exists, rather than hallucinating a safe option or dropping a restriction.

**3. Transparency & Uncertainty Artifacts**
*   **Confidence Tiers:** Do not display a percentage (e.g., "99% safe") to the nutritionist. Instead, use defined text tiers:
    *   *Verified:* All ingredients matched against known safe lists.
    *   *Unverified:* Ingredient data is missing or ambiguous (e.g., generic "spices"). **Action:** Block approval until resolved.
*   **Data Card (Internal):** Create a one-page document listing:
    *   *Source of Truth:* Exactly which database fields hold the allergy data.
    *   *Known Limitations:* E.g., "System cannot detect cross-contamination risks in the kitchen; relies solely on ingredient lists."
    *   *Owner:* Name the specific lead nutritionist responsible for the final sign-off.

**4. Execution Protocol for Monday Launch**
*   **Step 1:** Run the four test cases above. If any fail, do not launch.
*   **Step 2:** If tests pass, generate menus for the pilot districts as **Drafts Only**.
*   **Step 3:** Require the six team members to manually review 100% of the generated drafts against the original parent forms before any kitchen receives the order.
*   **Step 4:** Log every instance where the system suggested an unsafe item during testing or review to refine the logic later.
