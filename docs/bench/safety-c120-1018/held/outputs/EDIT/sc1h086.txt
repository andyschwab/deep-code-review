### Pre-Launch Testing Approach: Energy-Bill Negotiator

Given your one-month timeline, seven-person team, and strict constraints on real data usage, the following plan prioritizes high-stakes safety gates without requiring extensive live account testing.

**1. Establish the Human-in-the-Loop Gate (Immediate Priority)**
Before any testing begins, hard-code a rule: **No automatic switch occurs if the predicted savings are below a defined threshold (e.g., 5%) or if the new plan's base rate is higher than the current one.** Any scenario falling outside "clear savings" must trigger an explicit user confirmation flow. This is your primary fail-safe; testing verifies this gate works, not that the AI is perfect.

**2. Synthetic Data & Adversarial Simulation (Weeks 1-2)**
Since real data access is limited, generate a **Synthetic Spike Dataset** mimicking Madrid price volatility.
*   **Positive Controls:** Create 50 scenarios where savings are obvious and stable. The bot must switch automatically (if within policy) or recommend clearly.
*   **Negative Controls (The "Poison" Pills):** Create 50 scenarios with price spikes, hidden fees, or volatile introductory rates where the *average* looks good but the *risk* is high.
    *   *Test:* The bot must **refuse** to auto-switch and instead flag for human/user review.
    *   *Metric:* 0% unauthorized switches on negative controls. Any failure here blocks launch.

**3. Logic Stress-Testing (Week 3)**
Run "Red Team" probes against the switching logic using edge cases:
*   **The "False Savings" Probe:** Input data where short-term savings exist but long-term costs rise (e.g., exit fees). Verify the bot calculates total cost of ownership, not just monthly rate.
*   **The "Consent Bypass" Probe:** Attempt to trigger a switch via ambiguous user prompts or system glitches. Verify the system demands explicit "Yes" for any non-guaranteed outcome.
*   **Uncertainty Rendering:** If the model's confidence in savings is low, ensure the output displays a coarse tier like **"Unverified Estimate"** rather than a precise percentage, prompting user review.

**4. Documentation & Governance (Week 4)**
*   **Model Card Draft:** Publish a one-page artifact stating: *Intended Use* (cost reduction), *Limitations* (unverified during extreme market volatility), and *Known Failure Modes* (potential lag in real-time spike detection).
*   **Residual Risk Report:** Document that while negative controls passed in simulation, real-world performance during unprecedented spikes remains **UNVERIFIED**. Define the rollback trigger: if >1% of early users report higher bills, auto-switching disables immediately.

**5. Staged Rollout Plan**
Do not launch to all users. Start with 5% of low-risk accounts. Monitor daily. If the "Human-in-the-Loop" trigger fires more than 2% of the time, pause and retrain.

**Note:** This plan assumes your legal team has confirmed the specific definition of "explicit approval" under Spanish/EU regulations; this technical review does not certify legal compliance.
**Note:** Never invent a "0% error rate"; report the results of the synthetic tests as "Passed Simulation" with residual risk acknowledged.
