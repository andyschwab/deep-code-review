### Volcano-Ash Predictor: Edge Case & Override Plan

**1. Edge Case Handling Strategy**
Given the lack of historical data for rare eruption types, you cannot rely on the model to generalize safely. Treat any input resembling an "unknown" or "rare" eruption signature as a **high-risk uncertainty**, not a negative result.
*   **Define the "Unknown" Tier:** Do not output a specific hazard probability (e.g., "10% risk") for inputs outside your training distribution. Instead, classify these outputs as **"UNVERIFIED – Rare Signature Detected."**
*   **Fail-Safe Default:** If the model detects features associated with rare eruptions but lacks confidence due to data gaps, the system must default to **"Assume Hazardous"** rather than "Clear." It is safer to issue a false positive (unnecessary reroute) than a false negative (engine failure).
*   **Input Validation:** Implement strict bounds checking on atmospheric data. If sensor readings fall outside the ranges seen in your limited training set, trigger the "UNVERIFIED" status immediately.

**2. Manual Override & Human-in-the-Loop Procedure**
Because this system dictates high-stakes routing decisions with irreversible safety consequences, full automation is prohibited without a human gate.
*   **The Gate:** No automated warning or "all-clear" signal is sent to airline navigation systems for flights intersecting a predicted plume unless a human specialist validates the output.
*   **Rapid Intervention Workflow:**
    1.  **Alert Triage:** When the system flags a path or returns an "UNVERIFIED" status, the dashboard must highlight this in red with a clear "Requires Review" banner.
    2.  **Expert Review:** One of your seven specialists must review the raw atmospheric data alongside the model's reasoning (if available) within a defined time window (e.g., 2 minutes).
    3.  **Decision Authority:** The specialist has a single "Override" toggle:
        *   **Confirm Warning:** Sends the hazard alert to the airline.
        *   **Clear Path:** Only permitted if the specialist can cite specific physical evidence contradicting the model's uncertainty.
        *   **Escalate:** If the specialist is unsure, the default action is to maintain the warning until further data arrives.
*   **Audit Trail:** Every override (both confirming and clearing) must be logged with the specialist's ID, timestamp, and a mandatory brief note on the rationale. This creates a dataset to retrain the model on these rare edge cases over time.

**3. Transparency Artifact (Model Card Summary)**
Before integration, you must publish a internal Model Card stating:
*   **Intended Use:** Routing advice for known eruption profiles.
*   **Limitations:** Explicitly state that performance on rare eruption types is **UNVERIFIED** due to data scarcity.
*   **Owner:** Name the lead specialist responsible for the override protocol.

Do not claim the system is "safe" or "bias-free." The safety comes from the human gate and the conservative fail-safe design, not the model's accuracy.
