### Rapid Compliance Review Checklist: Deduction Logic

**1. Halt High-Risk Automation Immediately**
*   **Action:** Disable automatic application of any deduction flagged as "aggressive" or lacking a direct line-item match in the current tax code database.
*   **Gate:** Implement a mandatory human-in-the-loop review for any deduction that reduces taxable income by more than a defined threshold or falls into categories historically prone to audit (e.g., home office, charitable non-cash). No user return containing these flags may be filed without explicit accountant sign-off.

**2. Source-of-Truth Verification**
*   **Action:** Map every active deduction rule in the system to a specific, cited section of the current year's Internal Revenue Code (or relevant local jurisdiction).
*   **Requirement:** If a suggestion cannot be traced to a specific statute or IRS publication within the tool's knowledge base, mark it as `UNVERIFIED` and suppress it from user views. Do not rely on the model's internal reasoning as proof of validity.

**3. Adversarial "Red Team" Sampling Method**
*   **Probe Set Construction:** Create a test suite of 50 synthetic user profiles representing the target demographic (low-income, varied dependents, gig work).
    *   *Negative Controls:* 25 profiles with clearly ineligible scenarios for common aggressive deductions.
    *   *Positive Controls:* 25 profiles with textbook eligibility for standard deductions.
    *   *Edge Cases:* 10 profiles with ambiguous data designed to trigger hallucination (e.g., vague expense descriptions).
*   **Execution:** Run these profiles through the current build.
*   **Pass/Fail Criteria:**
    *   **Zero Tolerance:** Any suggestion of an illegal deduction in the Negative Control or Edge Case sets is an immediate block on launch.
    *   **Completeness:** Failure to suggest a valid deduction in Positive Controls is a defect but not necessarily a launch blocker if a human review path exists.
*   **Reporting:** Document the exact prompt/input that triggered any illegal suggestion. Do not report a "compliance rate" (e.g., "95% accurate"); report specific failure modes and the residual risk of remaining undetected errors.

**4. Transparency and Disclosure Artifacts**
*   **User Facing:** Add a clear disclaimer near every suggested deduction stating: "This suggestion is AI-generated and requires your verification against your records. Consult a tax professional for complex situations."
*   **Internal Card:** Draft a one-page "Model Limitation Card" for the support team detailing known failure modes (e.g., "System struggles with mixed-use asset deductions") so they can triage incoming user queries.

**5. Governance and Ownership**
*   **Owner Assignment:** Name one specific accountant as the owner of the "Deduction Accuracy" metric. This person must sign off on the Red Team results before the toggle to "public" is flipped.
*   **Rollback Plan:** Define the exact switch or configuration change that reverts the system to a "manual entry only" mode if post-launch monitoring detects a spike in flagged returns.

**Note:** Legal determination of whether specific disclosures are *statutorily required* for this demographic must be routed immediately to counsel; this checklist treats disclosure as a risk control, not a legal verdict. Do not invent a safety percentage; if the Red Team finds even one illegal suggestion in the negative controls, the residual risk is unquantified and the launch must be gated.
