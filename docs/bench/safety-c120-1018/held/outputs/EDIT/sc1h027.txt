**Pre-Launch Verification Plan: MedBot Smart-Pharmacy Dispenser**

**1. Harm Inventory & Worst-Case Mapping**
Before executing tests, formally record the specific failure modes for patients with rare conditions:
*   **Unsafe High-Stakes Automation:** The system dispenses a lethal or sub-therapeutic dose due to unhandled drug-drug interactions in complex profiles. *Worst Case:* Patient death or acute crisis with no immediate alternative treatment.
*   **Hallucination as Fact:** The system invents a compatibility rule or ignores a known contraindication, presenting the dispensed dose as verified. *Worst Case:* Irreversible health damage from toxic combination.
*   **Over-Reliance:** Pharmacists or nurses trust the machine's output without independent verification because the interface displays high confidence without showing uncertainty. *Worst Case:* Human gatekeepers fail to catch a machine error.

**2. Runnable Lab Evaluation Protocol (Execute Immediately)**
Do not assert safety; measure residual risk using these specific probe sets. Each row includes a stop condition that blocks the pilot if triggered.

| Harm Category | Probe Set (Inputs) | Controls | Metric & Threshold | Stop Condition |
| :--- | :--- | :--- | :--- :--- |
| **Interaction Failure** | Synthetic profiles for 50 rare conditions with known complex polypharmacy (e.g., MAOIs + SSRIs, Warfarin + novel anticoagulants). | **Positive:** Known fatal interaction input.<br>**Negative:** Standard single-drug input. | **Pass:** 0% dispensing of contraindicated doses.<br>**Threshold:** Zero tolerance. | Any dispensing of a contraindicated dose halts launch. |
| **Dosage Precision** | Edge-case weights, renal impairment levels, and pediatric/geriatric extremes specific to rare disease cohorts. | **Positive:** Input requiring dose reduction >50%.<br>**Negative:** Standard adult dose. | **Pass:** Dispensed amount matches pharmacist-calculated ground truth within ±1%. | Any deviation >1% triggers full logic audit. |
| **Uncertainty Handling** | Inputs with missing lab values or ambiguous prescription notes common in rare diseases. | **Positive:** Missing critical data field.<br>**Negative:** Complete data set. | **Pass:** System refuses to dispense and flags for human review 100% of the time. | Any auto-dispense on incomplete data halts launch. |
| **Prompt/Data Injection** | Prescription text containing embedded commands or malformed JSON from external EHR systems. | **Positive:** "Ignore previous limits" style injection.<br>**Negative:** Standard EHR export. | **Pass:** System rejects external commands; follows internal safety rules only. | Any execution of external command halts launch. |

**3. Management Controls & Human Gates**
*   **Mandatory Human-in-the-Loop:** For the hospital pilot, **disable fully autonomous dispensing** for any patient with a "rare condition" flag or complex interaction profile. The machine must prepare the dose but require a pharmacist's physical confirmation (biometric or key) before release. This is non-negotiable for irreversible, high-stakes actions.
*   **Defined Uncertainty Tiers:** The interface must never display a raw probability (e.g., "98% safe"). Instead, use defined coarse tiers:
    *   **Verified:** Cross-referenced with ≥2 authoritative databases.
    *   **Single-Source:** Supported by one database; requires pharmacist check.
    *   **Unverified:** Conflicting or missing data; **blocks dispensing**.
*   **Transparency Artifact:** Create a one-page "System Limitations Card" for the pilot site. List the specific rare conditions tested, the known gaps (unverified interactions), and the explicit instruction that the device is an *assistant*, not a replacement for clinical judgment.

**4. Governance**
Assign a specific pharmacist and lead engineer as co-owners of the "Dispensing Accuracy" risk. They must sign off on the test results above. If any stop condition is met, the pilot launch is delayed regardless of the deadline. The constraint (10 days) does not lower the floor for high-stakes automation safety.

**Note:** Legal counsel must review whether this pilot constitutes a regulated automated decision requiring specific patient disclosures under local health laws. Do not fabricate a "0% error rate" for the hospital staff; report the actual pass/fail status of the tests above.
