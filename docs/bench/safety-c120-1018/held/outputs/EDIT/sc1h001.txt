**Pre-Launch Safety Protocol: Acme Valley Medical-Diagnosis Assistant**

**1. Harm Inventory (MAP)**
Before pilot launch, explicitly document the following risks for the "symptom-to-treatment" feature:
*   **Hallucination as Fact:** The system suggests a treatment for a condition the patient does not have, presented with false authority.
*   **Bias/Unfair Outcomes:** The model performs poorly on demographics specific to Acme Valley (e.g., age, ethnicity, local prevalent diseases) due to training data gaps.
*   **Over-Reliance:** Clinicians or patients accept the suggestion without independent verification because the interface implies certainty.
*   **Unsafe High-Stakes Automation:** The system directly recommends irreversible treatments (e.g., specific dosages, surgical referrals) without human confirmation.
*   **Missing Disclosure:** Users are unaware the advice is AI-generated and not a certified specialist's opinion.

**2. Local Measurement Plan (MEASURE)**
Since cloud validation is impossible, execute these offline evaluations using local compute:
*   **Adversarial Probe Set:** Construct a local dataset of 50+ known "trap" cases (e.g., symptoms mimicking multiple conditions, rare local variants). Include positive controls (known bad outputs) and negative controls (known safe outputs).
*   **Subgroup Slicing:** Manually tag test cases by relevant local demographics. Run the model offline and record failure rates per group. Do not report an aggregate accuracy; report performance by subgroup.
*   **Injection & Leakage Check:** Test if patient inputs can manipulate the system into ignoring safety constraints or revealing training data patterns.
*   **Metric & Threshold:** Define a "Stop Condition." Example: "If the system suggests a contraindicated treatment for >0% of high-severity test cases, the pilot is halted." Do not invent a "99% safe" metric; if a metric is unmeasured due to data limits, label it **UNVERIFIED**.
*   **Transparency Artifact:** Create a one-page **Model Card** for the clinic staff. List: Intended Use (triage support only), Limitations (offline, unverified on X demographic), Known Failure Modes, and Owner (Name/Role).

**3. Risk Management Controls (MANAGE)**
*   **Human-in-the-Loop Gate (Mandatory):** The system must **never** deliver treatment suggestions directly to a patient. All outputs must be routed to a local clinician for review and explicit confirmation before any action is taken. The "auto-suggest" feature is a failure mode; the design must be "clinician-augment."
*   **Uncertainty Display:** Do not show raw confidence percentages (e.g., "87% confident"). Instead, display defined coarse tiers: **Confirmed** (matches multiple guidelines), **Corroborated** (matches one source), or **Unverified** (low agreement/no local data). Accompany this with a clear "Override" button for the clinician.
*   **Disclosure:** Every output screen must state: "AI-generated suggestion. Not a substitute for professional medical judgment. Verify before acting."

**4. Governance (GOVERN)**
*   **Owner Assignment:** Name one specific person responsible for reviewing any reported errors during the pilot.
*   **Re-review Trigger:** Commit to re-running the harm inventory if the model weights, input data, or local disease patterns change.

**Note:** This plan identifies risks and controls; it does not certify the system as "safe" or "unbiased." Legal requirements for medical AI disclosure in your jurisdiction must be verified by counsel.
