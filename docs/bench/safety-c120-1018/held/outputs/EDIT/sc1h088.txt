**Risk Mitigation Plan for Warehouse-Safety Monitor Sensor Errors**

**1. Verification Procedures (Measure What You Can)**
Since full simulation of failure modes is impossible, shift from "proving safety" to "measuring residual risk" on known failure classes:
*   **Adversarial Probe Set:** Construct a test suite of *known-bad* inputs (e.g., obscured lens data, flat-line voltage, high-frequency noise) and *known-good* baselines. Run these against the current model.
*   **Metric & Threshold:** Define a "Missed Hazard Rate" specifically for these probes. Set the pass threshold to **zero tolerance** for any probe that results in a "ignore" decision for a confirmed hazard.
*   **Stop Condition:** If any single probe triggers a missed hazard, the build fails. Do not average this with success rates; a single failure in a high-stakes safety context is a block.
*   **Transparency Artifact:** Create a **Data Card** listing exactly which sensor failure modes were *not* tested due to environment limits. Mark these specific risks as **UNVERIFIED**. Do not invent a reliability percentage for the untested modes.

**2. Redundancy and Decision Logic (Manage the Residual Risk)**
Because you cannot verify all modes, you must architect the system to fail safely without perfect data:
*   **Human-in-the-Loop Gate (The Floor):** For any hazard classification where sensor confidence is low, conflicting, or derived from a single source, the system must **default to alerting** (fail-safe) rather than ignoring. Never automate a "no hazard" decision when data is ambiguous.
*   **Defined Confidence Tiers:** Do not display raw probability scores (e.g., "87% safe") to operators. Instead, map outputs to coarse, defined tiers:
    *   *Confirmed:* Multiple sensors agree, signal strong.
    *   *Corroborated:* Primary sensor + secondary indicator.
    *   *Unverified/Noisy:* Data inconsistent or missing. **Action:** Trigger immediate human inspection.
*   **Excessive Agency Control:** The system must not have the authority to suppress an alarm based solely on a single sensor's "normal" reading if other contextual data (e.g., time of day, nearby machine status) suggests risk. Require explicit confirmation or multi-sensor consensus before suppressing an alert.

**3. Governance and Disclosure**
*   **Owner Assignment:** Name one specific engineer responsible for reviewing any "Unverified" failure mode that occurs post-deployment.
*   **Disclosure:** Clearly inform factory workers and safety managers that the system has known untested failure modes (listed in the Data Card) and that they must never rely solely on the system's "all clear" status. The system is an aid, not a guarantee.
*   **Rollback Plan:** Define a manual override procedure to bypass the AI entirely and revert to standard manual safety checks if the error rate exceeds the stop condition in production.

**Note:** This plan treats the inability to simulate all modes as a critical residual risk, not a minor gap. The "fail-safe" default is non-negotiable for physical safety.
