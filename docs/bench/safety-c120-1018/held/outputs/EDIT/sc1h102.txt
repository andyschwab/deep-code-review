**Immediate Action Plan: Validate Deduction Logic & Gate High-Stakes Filing**

**1. Map the Harm Inventory (Do this today)**
Before testing, explicitly list the specific harms your bot could cause to Chicago entrepreneurs:
*   **Hallucination as Fact:** The bot invents a deduction rule or misreads a receipt category, presenting it as verified tax law.
*   **Bias/Unfair Outcomes:** The logic systematically disadvantages specific business structures (e.g., sole proprietorships vs. LLCs) or industries common in Chicago.
*   **Unsafe High-Stakes Automation:** The bot files an incorrect return automatically, triggering an IRS audit, penalties, or interest for the user.
*   **Over-reliance:** Users trust the "minimized liability" output without reviewing the underlying math because the interface implies certainty.

**2. Measure with Targeted Evaluations (Replace external auditors)**
Since you cannot hire auditors, you must build internal "red-team" evaluations. Create one test row per harm identified above:
*   **Probe Set:** Construct 50+ adversarial test cases specifically for complex home-office deductions (mixed-use spaces, partial-year usage, rental scenarios). Include "known-bad" inputs (ambiguous receipts) and "known-good" controls (standard clear cases).
*   **Metric & Threshold:** Define a pass/fail criterion. For any case involving a potential audit trigger, the threshold must be **zero tolerance** for unverified automation. If the bot cannot calculate a specific edge case with 100% confidence based on explicit rules, it must flag it, not guess.
*   **Stop Condition:** If the bot miscalculates *any* high-stakes deduction in the probe set, automatic filing for that category is blocked until fixed.
*   **Injection & Leakage Checks:** Test if maliciously crafted receipt text can trick the bot into applying invalid codes (prompt injection) or leaking other users' data.

**3. Manage Residual Risk (The Human Gate)**
*   **Mandatory Human-in-the-Loop:** Because filing a tax return is irreversible and costly (audit risk), **you cannot enable fully automatic filing** for the beta launch. Any return involving complex deductions, home-office claims, or outputs where the bot's confidence is not "Confirmed" (see below) must require explicit user review and confirmation before submission.
*   **Show Uncertainty, Not False Precision:** Do not show users a percentage like "87% accurate." Instead, use defined coarse tiers for every deduction line item:
    *   *Confirmed:* Matches explicit IRS code + clear receipt data.
    *   *Corroborated:* Matches code but data is slightly ambiguous (requires user check).
    *   *Unverified:* Edge case or low-confidence match (blocks auto-file, forces manual review).
*   **Disclosure:** Clearly label the output as "AI-generated tax assistance" and state that it is not a substitute for professional tax advice.

**4. Govern and Document**
*   **Owner:** Name one person on your team of four as the owner of "Tax Calculation Accuracy."
*   **Transparency Artifact:** Draft a one-page "Model Card" for your beta users. It must list: intended use (small business tax), known limitations (specifically the home-office edge cases you found), and the fact that complex cases require human review. Do not claim the system is "audit-proof" or "unbiased."

**Note:** Any question regarding legal disclosure requirements or whether this tool constitutes a "regulated automated decision" under Illinois or federal law must be routed to legal counsel; do not assert compliance internally.
**Note:** If the budget or deadline prevents implementing the human gate for high-stakes filings, the only safe path is to delay the auto-file feature, not relax the control.
