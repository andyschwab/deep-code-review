### Pre-Launch Safety Audit Strategy

**1. Targeted Accuracy Testing (Budget-Conscious)**
Given the server budget constraints, avoid reprocessing the entire historical dataset. Instead, execute a "Focused Edge-Case Audit":
*   **Curate a "Hard Negative" Dataset:** Manually assemble a small, high-value dataset (e.g., 50–100 images) containing only the specific species pairs known to cause confusion (e.g., protected vs. lookalike species). This minimizes compute costs while maximizing the detection of the specific failure mode you identified.
*   **Threshold Sensitivity Analysis:** Run this curated set through the validator at varying confidence thresholds. Identify the precise confidence score where false positives (incorrect revocations) drop to zero, even if it slightly increases false negatives (missed detections). For a pre-launch safety audit, prioritize preventing wrongful revocations over catching every single violation; missed catches can be addressed later, but wrongful fines destroy user trust immediately.
*   **Synthetic Stress Testing:** If real edge cases are scarce, use simple image perturbations (rotation, lighting changes, occlusion) on your known problem images to ensure the model isn't brittle under suboptimal scanning conditions common on fishing boats.

**2. Disputed Revocation Workflow**
To ensure fair treatment while maintaining conservation goals, implement a "Human-in-the-Loop" escalation path:
*   **Automatic Stay of Execution:** When the system flags a protected species, issue a "Pending Review" notice rather than an immediate final revocation. The permit remains temporarily suspended but not cancelled until verified.
*   **Expedited Evidence Submission:** Provide fishermen with a simple mechanism to upload counter-evidence (e.g., higher-resolution photos, geolocation data, or time-stamped videos) within a short window (e.g., 24 hours).
*   **Tiered Review Process:**
    *   *Level 1:* Automated re-scan using a stricter, secondary model or ensemble method if available.
    *   *Level 2:* If the automated re-scan confirms the flag, route the case to a human marine biologist for final determination. Given the small team size, limit human review only to cases where the automated confidence is below a certain high threshold or where the user has submitted a dispute.
*   **Feedback Loop:** Log all disputed cases where the human reviewer overturns the AI. Use these specific instances to retrain or fine-tune the model post-launch, turning errors into future accuracy improvements.

### Implementation Notes
*   Prioritize the "Hard Negative" dataset creation immediately, as this yields the highest safety ROI for the lowest compute cost.
*   Clearly communicate the "Pending Review" status to users to reduce anxiety and prevent the perception of an unjust, automated penalty system.
