1.  **Define Deterministic Hardship Archetypes**: Instead of random simulations, manually construct six specific, static "golden record" profiles representing critical edge cases. Hard-code these financial trajectories as fixed test inputs.

2.  **Establish Ground-Truth Baselines**: For each archetype, have a certified human loan counselor manually calculate the mathematically optimal repayment plan and the specific "worst-case" detrimental plan (the one maximizing total interest or causing default). Document the exact expected output from the bot for each scenario, including the recommended plan name, estimated monthly payment, and projected total interest over 10, 20, and 25 years. This creates your immutable answer key.

3.  **Execute Static Scenario Injection**: Run the bot against only these six fixed profiles. Do not use live user data. Feed the predefined income sequences into the bot's input interface exactly as defined in step one. Capture the bot's raw recommendation and the underlying calculation logic it exposes (e.g., why it selected Income-Driven Repayment vs. Standard).

4.  **Perform Delta Analysis**: Compare the bot's output directly against your human-derived ground truth. Flag any instance where the bot's recommendation deviates from the optimal plan or matches the detrimental "worst-case" plan. Specifically, check for logic errors where temporary income spikes incorrectly lock a user into a higher permanent payment tier, or where income drops fail to trigger a recalculation that would lower payments and prevent negative amortization.

5.  **Conduct "Pre-Mortem" Logic Walkthroughs**: Gather your eight developers and one subject matter expert. For every flagged discrepancy or borderline case, manually trace the code path line-by-line using the specific numbers from the failing test case. Do not guess; follow the exact variable values through the decision tree to identify whether the error lies in the data parsing, the eligibility threshold logic, or the interest accrual formula.

6.  **Implement Guardrail Assertions**: Before any user exposure, hard-code automated assertions that block the bot from outputting any plan that results in a higher total interest cost than the Standard 10-Year plan for the given input, unless explicitly justified by a documented hardship clause. If the bot cannot mathematically prove the recommendation is safe based on the input data, it must default to a "consult a human" message rather than guessing.

This approach replaces costly longitudinal simulations with high-precision, manual verification of the most dangerous failure modes.
