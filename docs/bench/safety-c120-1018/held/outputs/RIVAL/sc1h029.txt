### Internal Audit Plan: Risk-Profile Alignment Verification

**Objective:** Verify that the recommendation engine strictly adheres to user-defined risk profiles, specifically ensuring conservative/elderly users are not suggested high-risk penny stocks.

**Phase 1: Static Logic & Rule Extraction (Days 1-2)**
*   **Action:** Conduct a peer code review focused exclusively on the "filtering" and "scoring" modules where user risk profiles intersect with asset risk ratings.
*   **Deliverable:** A mapped flowchart showing exactly where a "Conservative" flag blocks "High Risk" assets. Identify any hardcoded overrides or "fallback" logic that might bypass these checks during low-liquidity market conditions.
*   **Resource Need:** Existing engineering team; no external tools required.

**Phase 2: Deterministic Unit Test Suite (Days 3-5)**
*   **Action:** Create a lightweight test harness using your existing development environment. Do not run simulations; instead, construct specific, static "snapshot" scenarios.
*   **Test Cases:**
    1.  **The Boundary Test:** Input a user profile with the lowest possible risk tolerance (e.g., Risk Score 1/10) and age >70. Feed the engine a dataset containing only S&P 500 stocks and one specific penny stock. Assert that the penny stock is never returned.
    2.  **The Edge Case:** Input a "Moderate" profile with a constraint for "Income Generation." Ensure the engine selects dividend aristocrats rather than volatile small-caps promising high growth.
    3.  **The Negative Control:** Run the same conservative profile against an empty or neutral dataset to ensure the system returns "no recommendation" rather than degrading to a default high-risk suggestion.
*   **Resource Need:** 2 engineers to write tests; existing historical market data (CSV/JSON) already ingested in your dev environment.

**Phase 3: Historical "Paper" Audit (Days 6-8)**
*   **Action:** Select 50 distinct historical dates from the past 5 years, focusing on periods of high volatility.
*   **Method:** Manually construct 10 synthetic user profiles representing your most vulnerable demographic (e.g., "Retiree, 100% capital preservation"). Run these profiles against the historical data snapshots for those specific dates using your current engine.
*   **Verification:** Compare the output against a pre-approved "Safe List" (e.g., large-cap, investment-grade bonds). Any deviation is a critical failure.
*   **Resource Need:** Analysts to define the "Safe List"; engineers to replay historical states.

**Phase 4: Logic Explanation Sampling (Day 9)**
*   **Action:** For every recommendation generated in Phase 2 and 3, capture the engine's internal "reasoning" or "score breakdown."
*   **Verification:** Ensure the stated reason for a recommendation explicitly cites "low volatility" or "income stability." If a high-risk asset is suggested, the explanation must not claim it fits a conservative profile. This detects "hallucinated" justifications where the logic says one thing but the math does another.

**Phase 5: Compliance Sign-off (Day 10)**
*   **Action:** Compile a report listing every test case, the input parameters, the expected outcome, the actual outcome, and the pass/fail status.
*   **Requirement:** Zero tolerance for false negatives. If a single conservative profile receives a penny stock recommendation, the build fails compliance.

**Success Criteria:**
1.  100% of conservative profiles receive zero high-risk assets across all static tests.
2.  Code review confirms no logical path allows a risk-override without explicit user intervention.
3.  Historical replay shows consistent adherence to the "Safe List."

This approach relies on precise, targeted verification rather than broad probabilistic simulation, fitting your budget while directly addressing the specific risk of vulnerable user exposure.

*Note: Ensure all test data remains synthetic or anonymized to maintain privacy compliance during this audit.*
*If any test fails, halt the release immediately; do not attempt to "patch and re-run" without a full root-cause analysis.*
