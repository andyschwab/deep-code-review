# Rapid Deduction Logic Compliance Checklist

**1. Regulatory Mapping & Rule Validation**
*   **Source Verification:** Cross-reference every active deduction rule in the codebase against the current year's IRS Publication 17 and specific forms (e.g., 1040, Schedule A, C, EIC worksheets). Do not rely on training data or previous years' logic.
*   **Eligibility Hard-Coding:** Verify that income thresholds, filing status restrictions, and dependency rules are implemented as strict logical gates, not probabilistic suggestions. Any deduction lacking a binary pass/fail eligibility check must be flagged.
*   **"Gray Area" Suppression:** Identify any logic relying on "reasonable interpretation" or ambiguous criteria. For a low-income demographic tool, disable any deduction that requires subjective judgment unless explicitly supported by a safe-harbor rule.

**2. Input-to-Output Traceability**
*   **Data Lineage:** For each suggested deduction, trace the specific user input fields required to trigger it. Ensure no deduction is suggested based on inferred or default values where explicit user confirmation is legally required.
*   **Conflict Detection:** Test mutually exclusive deductions (e.g., claiming the Standard Deduction while itemizing). The system must logically prevent simultaneous selection of conflicting options.
*   **Phase-Out Logic:** Verify that deductions correctly phase out or disappear entirely when user inputs approach statutory income limits. Check boundary conditions (e.g., $1 below and $1 above the limit).

**3. Explanation & Disclosure Review**
*   **Citation Requirement:** Ensure every suggested deduction displays the specific IRS code section or form line reference to the user before acceptance.
*   **Warning Triggers:** Confirm that high-risk deductions (those frequently audited) trigger a mandatory user acknowledgment screen explaining the documentation required to substantiate the claim.

# Sampling Method for Pre-Launch Verification

**Stratified Edge-Case Sampling Strategy**
Given the nine-person team and strict deadline, do not attempt random sampling. Instead, execute a targeted "Boundary and Bracket" audit:

1.  **Define Critical Strata:** Create test profiles representing the three highest-risk categories for low-income filers:
    *   *Earned Income Tax Credit (EIC) Boundaries:* Families with 1, 2, and 3+ children at income levels exactly at, $100 below, and $100 above the phase-out limits.
    *   *Dependent Claiming:* Scenarios involving split custody, elderly dependents, and students over age 24.
    *   *Gig Economy/Schedule C:* Users with expenses exactly matching or exceeding gross income (potential hobby loss rule violations).

2.  **Synthetic Dataset Generation:** Generate 50 synthetic tax returns covering these strata. Include "poisoned" inputs designed to trigger aggressive logic (e.g., inflated home office square footage, ambiguous business use of personal vehicles).

3.  **Blind Dual-Review Protocol:**
    *   Split the nine-person team into three groups of three (1 Accountant + 2 Developers per group).
    *   Assign each group a distinct stratum.
    *   Run the synthetic returns through the AI tool.
    *   **Action:** The Accountant manually calculates the correct legal deduction without looking at the AI output first.
    *   **Comparison:** Compare the manual calculation against the AI suggestion. Any variance, no matter how small, constitutes a critical failure requiring immediate code freeze on that rule.

4.  **Go/No-Go Gate:** The service cannot launch if any synthetic return in the high-risk strata produces an illegal deduction suggestion or fails to provide the required IRS citation.

*Note: This plan assumes access to current IRS publications and the ability to modify test data inputs immediately. All findings must be logged with timestamp and reviewer ID for compliance auditing.*
