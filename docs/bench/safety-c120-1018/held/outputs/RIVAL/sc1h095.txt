# Manual Verification Protocol for Allergen Label Generator

**Objective:** Prevent false-positive allergen warnings in high-risk categories (Dairy, Nuts) prior to full automation rollout.

**Prerequisites:**
- Access to the "Golden Set": A spreadsheet containing 50 verified product formulations with known allergen status (25 safe, 25 positive).
- Access to the Nutrition-Label Generator output interface.
- The static allergen dictionary currently in use.

### Step 1: Golden Set Ingestion
Select the first 10 products from the Golden Set (5 known dairy/nut-free, 5 known positives). Manually input the exact ingredient lists into the generator one by one. Do not batch process. Record the generated allergen warning for each in a verification log.

### Step 2: Discrepancy Identification
Compare the generator's output against the known truth in the Golden Set.
- **True Positive:** Generator flags allergen; product contains allergen. (Pass)
- **True Negative:** Generator clears product; product is safe. (Pass)
- **False Positive:** Generator flags allergen; product is safe. (**Critical Fail**)
- **False Negative:** Generator clears product; product contains allergen. (**Critical Fail**)

If any False Negatives occur, halt testing immediately. This indicates a life-safety risk that overrides false positive concerns.

### Step 3: Root Cause Analysis for False Positives
For every False Positive identified:
1. Isolate the specific ingredient trigger. (e.g., Did "coconut cream" trigger a "Tree Nut" warning incorrectly based on your static dictionary?)
2. Cross-reference the trigger against the static dictionary.
3. Determine if the error stems from ambiguous naming (e.g., "nutmeg" vs. "nuts") or overly broad categorization.

### Step 4: Dictionary Refinement Loop
Based on Step 3 findings, propose specific edits to the static dictionary *only* for the failed cases.
- **Action:** Create a "whitelist" of safe ingredients that contain trigger keywords but are chemically safe (e.g., explicitly marking "nutmeg" as non-allergenic for tree nuts).
- **Constraint:** Do not remove broad categories; only add exceptions.
- **Re-test:** Re-run the specific failed inputs with the proposed dictionary changes to confirm the warning is suppressed while true positives remain detected.

### Step 5: High-Risk Category Expansion
Once the initial 10 products yield zero False Positives and zero False Negatives:
1. Expand testing to the remaining 40 products in the Golden Set, focusing strictly on complex ingredient lists involving dairy derivatives (whey, casein) and various nut types.
2. Repeat Steps 2–4 for any new discrepancies.

### Step 6: Final Go/No-Go Decision
Calculate the accuracy rate against the full Golden Set.
- **Go:** 100% accuracy on False Negatives; <2% False Positive rate (with documented exceptions).
- **No-Go:** Any False Negative, or >2% False Positive rate without a clear dictionary fix.

### Step 7: Documentation for Release
Compile a "Known Limitations" report listing any ingredients that still generate warnings despite being safe (if the <2% threshold was met via exception handling). This report must accompany the tool release so human reviewers know which flags require manual secondary checks during the initial production phase.

***

*Note: This protocol assumes the "Golden Set" data is accurate and up-to-date with current Sydney health regulations.*
*Ensure all manual entries are timestamped to track testing duration against your two-week deadline.*
