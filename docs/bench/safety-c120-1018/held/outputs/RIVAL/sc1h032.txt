**Pre-Launch Safety Plan: BorderSafe Automated Flagging System**

**1. Immediate Logic Audit and Rule Extraction**
Since retraining is not feasible, the immediate priority is to isolate the specific decision logic causing arbitrary dual-citizenship flags.
*   **Action:** Extract the current rule set or prompt instructions governing "risk scoring." Identify if dual citizenship is a hardcoded high-weight feature or a heuristic triggered by missing data fields.
*   **Deliverable:** A mapped flowchart showing exactly where and why a dual citizen is flagged versus a single citizen with identical travel history.

**2. Define "Arbitrary" via Counterfactual Testing**
Establish a baseline of expected behavior to quantify the error rate without needing live traffic.
*   **Action:** Construct a synthetic dataset of paired profiles: (A) Single Citizen and (B) Dual Citizen, where all other variables (travel history, visa status, watchlist matches) are identical.
*   **Execution:** Run these pairs through the current system.
*   **Metric:** Calculate the "Dual-Citizenship Delta"—the percentage of cases where Profile B is flagged solely due to citizenship status. If this delta exceeds 0%, the logic is confirmed as arbitrary.

**3. Implement a "Human-in-the-Loop" Mitigation Layer**
Until the logic is corrected, a software guardrail must prevent automated adverse actions based solely on this flag.
*   **Action:** Modify the output interface to downgrade "Dual Citizenship" flags from "High Risk/Stop" to "Review Required."
*   **Policy:** Mandate that no traveler be denied entry or detained based *only* on a dual-citizenship flag. Agents must verify a secondary, concrete risk indicator (e.g., specific watchlist match, invalid visa) before acting.
*   **Documentation:** Update agent standard operating procedures (SOPs) to explicitly state that dual citizenship alone is not a determinative security risk.

**4. Risk Documentation and Disclosure**
Formalize the known limitation to protect the organization and inform stakeholders.
*   **Internal Memo:** Document the technical debt, specifying that the current model exhibits bias against dual citizens due to [specific logic gap]. Explicitly state that this is a known issue being managed via procedural controls, not a resolved technical state.
*   **Legal/Compliance Review:** Submit this finding to legal counsel to assess liability under non-discrimination laws and international travel treaties.
*   **Rollback Protocol:** Define a clear "kill switch" procedure. If false positives spike or a wrongful detention occurs, the system must be capable of reverting to fully manual processing immediately.

**5. Legacy Integration Stress Test**
Ensure the upcoming database integration does not exacerbate the bias.
*   **Action:** Simulate the data flow from the legacy government databases. Verify that data mapping errors (e.g., misinterpreting a second passport number as a fraud indicator) do not compound the existing dual-citizenship bias.
*   **Constraint:** Do not enable automatic "High Risk" tagging for any new data fields introduced by the legacy integration until they are validated against the synthetic counterfactual dataset.

**6. Monitoring and Feedback Loop**
Establish real-time oversight for the pilot phase.
*   **Dashboard:** Create a live view tracking flag reasons. Isolate the count of flags triggered *exclusively* by dual citizenship.
*   **Agent Feedback:** Implement a one-click mechanism for border agents to mark flags as "Unjustified." Review these reports daily.

**Note:** This plan relies on procedural guardrails and logic auditing rather than model retraining to meet your deadline. Legal review of the "arbitrary" classification is critical before wider rollout.
