### Validation Workflow for Name-Based Background Checks

**1. Establish a Synthetic Control Dataset**
Before processing real volunteers, create a local dataset of 20–30 synthetic profiles representing high-risk scenarios for false positives.
*   **Common Name Clusters:** Generate profiles using the top 10 most common first and last names in Ottawa (e.g., "Michael Smith," "Marie Tremblay") paired with random birth dates.
*   **Near-Match Variants:** Create profiles with slight spelling variations (e.g., "Jon" vs. "John," "Catherine" vs. "Katherine") to test fuzzy matching logic.
*   **Known Negatives:** Include profiles with common names that you have manually verified have *no* public record issues. These serve as your "must-pass" control group.

**2. Define the "Human-in-the-Loop" Triage Protocol**
Since you lack unique identifiers, no match should result in an automatic rejection. Implement a three-tier status system:
*   **Green (Clear):** No name/DOB match found. Proceed to onboarding.
*   **Amber (Review Required):** Name matches, but DOB differs by more than 2 years, or the name is extremely common (e.g., top 5% frequency). This triggers a manual review, not a rejection.
*   **Red (Potential Match):** Exact name and DOB match (within a 1-year window). This requires senior analyst verification.

**3. Execute the "Blind" Pilot Run**
Run your synthetic control dataset through the system without telling the screening team which profiles are fake or known negatives.
*   **Measure False Positive Rate:** Calculate how many "Known Negatives" were flagged as Amber or Red. If this exceeds 5%, your matching thresholds are too sensitive.
*   **Calibrate Thresholds:** Adjust your logic based on results. For example, if "Marie Tremblay" with a DOB mismatch triggers a Red flag, adjust the rule to require exact DOB matches for the top 20 most common surnames in the region.

**4. Implement a Candidate Appeal & Verification Step**
For any real volunteer flagged as Amber or Red:
*   **Request Secondary ID:** Ask the candidate to provide a government-issued ID number (if legally permissible for your final check) or a secondary document (e.g., passport) to manually verify the birth date and spelling before making a final decision.
*   **Contextual Review:** Have a second team member review the specific public record found. Does the location (Ottawa vs. elsewhere) or the nature of the record make a match plausible?

**5. Final Go/No-Go Gate**
Do not process the first batch of real volunteers until the synthetic dataset yields zero false rejections (i.e., no "Known Negative" profile is marked as a definitive "Fail").

*Note: Given the three-week timeline, prioritize calibrating the "Amber" threshold to ensure manual review capacity is not overwhelmed. Ensure all synthetic data is kept separate from production records to prevent contamination.*
