### Edge Case Handling Review & Manual Override Procedure

**1. Edge Case Handling Strategy**
Given the scarcity of historical data for rare eruption types, the system must prioritize "fail-safe" uncertainty detection over precise prediction in ambiguous scenarios.

*   **Confidence Thresholding:** Implement a dynamic confidence score for every prediction. If the model's confidence falls below a strict threshold (e.g., 85%) due to input patterns resembling known data gaps, the system must automatically default to a "High Risk/Unknown" status rather than issuing a "Clear" path.
*   **Anomaly Detection Layer:** Deploy a secondary statistical monitor that flags input data points falling outside the distribution of the training set (out-of-distribution detection). Any atmospheric reading identified as an anomaly triggers an immediate "Review Required" alert, bypassing the standard automated routing recommendation.
*   **Conservative Bias:** In the absence of definitive negative evidence (i.e., when the model cannot confirm safety due to data gaps), the logic must assume the presence of hazardous ash. The default state for uncertain regions is "Avoid," ensuring that missing data never results in a false negative (clearing a dangerous path).

**2. Manual Override Procedure: "Ash-Stop Protocol"**
This procedure ensures your seven specialists can intervene instantly before any prediction reaches airline navigation systems.

*   **Step 1: The Hold State:** All automated predictions enter a mandatory 3-minute "Hold Queue" before transmission to external airline systems. During this window, the prediction is visible only to the specialist dashboard.
*   **Step 2: Triage Dashboard:** Specialists view a unified interface displaying:
    *   The predicted flight path.
    *   The model's confidence score.
    *   Any triggered anomaly flags.
    *   Raw atmospheric data visualizations for the specific region in question.
*   **Step 3: Intervention Triggers:** A specialist must manually approve the prediction if:
    *   Confidence is below the defined threshold.
    *   An anomaly flag is present.
    *   The predicted path intersects with a known data-gap region.
    *   Intuition or external intelligence (e.g., pilot reports, satellite imagery not yet ingested) contradicts the model.
*   **Step 4: The Override Action:**
    *   **Reject:** The specialist clicks "Override – Unsafe." The system immediately broadcasts a "Route Unavailable" warning to all connected airlines for that sector, regardless of the model's output.
    *   **Modify:** The specialist manually draws a corrected safe corridor. This human-defined path overrides the algorithmic suggestion and is dispatched immediately.
    *   **Escalate:** If the situation is unprecedented, the specialist triggers a "Team Consensus" lock, requiring approval from at least two other specialists before any data is released.
*   **Step 5: Audit and Learning:** Every override is logged with the specialist's ID, timestamp, reason code, and the specific data snapshot. These logs form a high-priority dataset for retraining the model, directly addressing the historical data gap by capturing expert-labeled edge cases.

**Implementation Note:** This protocol places the burden of proof on the system to demonstrate safety; if it cannot, the human expert acts as the final gatekeeper.

**Operational Note:** Ensure the dashboard latency is under 200ms so the 3-minute hold does not disrupt real-time dispatch workflows.
