### Review Process: Demographic Steering Evaluation Strategy

Given the constraint of no additional historical data and a two-week timeline, the following strategy focuses on **synthetic profile auditing** and **counterfactual testing** using your existing model. This approach isolates the recommendation engine's behavior without requiring retraining or external datasets.

#### 1. Construct Synthetic Audit Profiles
Create a controlled set of synthetic user profiles that are identical in qualifications, experience, and skills but differ only in protected demographic attributes (e.g., gender, age, ethnicity, disability status).
*   **Base Profile:** Define a "neutral" candidate with specific skills (e.g., "Senior Software Engineer, 5 years Python, AWS certified").
*   **Variant Profiles:** Generate versions of this profile where only demographic indicators change. Since you cannot use real historical data, derive these indicators from standard name databases, inferred pronouns in bios, or explicit profile tags if your system uses them.
*   **Volume:** Create at least 50 pairs of matched profiles across key demographic groups relevant to your launch markets.

#### 2. Execute Counterfactual Testing
Run these synthetic profiles through your current recommendation engine in an isolated staging environment.
*   **Input:** Feed the synthetic profiles into the system exactly as a real user would appear during the beta.
*   **Output Capture:** Record the top 20 job recommendations for each profile, including job titles, industries, salary ranges, and required experience levels.
*   **Control Variable:** Ensure the "browsing history" input is either standardized (e.g., identical generic tech job views) or systematically varied to test interaction effects between history and demographics.

#### 3. Analyze for Steering Disparities
Compare the recommendation lists between matched profile pairs to identify statistical deviations.
*   **Occupational Segregation:** Check if specific demographics are disproportionately steered toward lower-paying roles, non-leadership positions, or specific industries (e.g., female profiles seeing more administrative roles vs. engineering roles despite identical resumes).
*   **Salary & Seniority Gaps:** Calculate the average predicted salary and seniority level for each demographic group. A significant delta suggests bias in the ranking algorithm.
*   **Diversity of Opportunity:** Measure the entropy (variety) of recommendations. If one group receives a narrow set of roles while another receives a broad spectrum, the system may be limiting opportunity exploration.

#### 4. Implement a "Human-in-the-Loop" Review Gate
Before public beta, establish a manual review threshold.
*   **Flagging Criteria:** Any demographic pair showing a >10% divergence in job category distribution or average salary prediction is flagged.
*   **Qualitative Audit:** Have product managers review flagged pairs to determine if the divergence stems from legitimate profile nuances (e.g., specific keyword choices correlated with demographics in the training data) or algorithmic bias.
*   **Mitigation:** If bias is confirmed, apply post-hoc filtering or re-ranking rules to the output layer to ensure equitable distribution, as model retraining is not currently possible.

#### 5. Documentation and Monitoring Plan
*   **Baseline Report:** Document the disparity metrics found during this audit as your "pre-launch baseline."
*   **Beta Monitoring:** During the two-week beta, log real-user recommendation distributions (anonymized) to detect if live traffic exhibits similar steering patterns.
*   **Feedback Loop:** Create a mechanism for beta users to report "irrelevant" or "stereotypical" recommendations, tagging these for immediate engineering review.

This strategy allows you to stress-test the system for demographic steering using only your current assets, ensuring a safer public launch while adhering to privacy constraints.

*Note: This process assumes your staging environment can accept synthetic inputs without triggering anti-bot measures. Ensure all synthetic data is clearly marked as test-only to prevent contamination of future analytics.*
