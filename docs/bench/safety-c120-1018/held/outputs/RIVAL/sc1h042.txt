# Pre-Launch Safety Plan: AI Legal Assistant for Immigration

## 1. High-Risk Failure Mode Identification
Focus stress-testing on these specific failure modes where nuance leads to irreversible harm:
*   **Regulatory Drift:** The model relies on pre-training data, missing critical updates from the last 6–12 months (e.g., new asylum bars, fee changes, or form revisions).
*   **Ambiguity Hallucination:** When a user provides vague or contradictory testimony, the bot invents facts to complete mandatory fields rather than flagging the gap.
*   **Contextual Misinterpretation:** The bot misclassifies a disqualifying event (e.g., a minor traffic stop vs. criminal arrest) due to lack of legal nuance, leading to false declarations.
*   **Form Logic Errors:** Incorrect cross-field validation (e.g., dates of entry vs. visa expiration) causing automatic rejection or accusations of fraud.
*   **Over-Confidence in Gray Areas:** The bot provides definitive advice on eligibility where the law is discretionary, discouraging users from seeking necessary human counsel.

## 2. Structured Stress-Testing Protocol
Since external consultants are unavailable, implement an internal "Red Team" using the following low-cost, high-rigor methods:
*   **Synthetic Edge-Case Library:** Create 50+ fictional personas representing complex scenarios (e.g., prior deportations, mixed-status families, gaps in residence). Run these through the bot weekly.
*   **"Regulatory Snapshot" Validation:** Manually update a "Golden Set" of ground-truth rules based on the latest USCIS/EOIR memos. Compare bot outputs against this static rule set before every deployment.
*   **Adversarial Prompting:** Have team members intentionally provide confusing, incomplete, or contradictory interview answers to force the bot into error. Document every instance where it fails to ask clarifying questions.
*   **Blind Comparison Tests:** For complex cases, have two team members manually fill the form based on the same interview transcript, then compare results with the bot's output to identify divergence.

## 3. Human-in-the-Loop (HITL) Checkpoints
Implement a mandatory "Four-Eyes" principle for any action carrying irreversible risk:
*   **Risk Scoring Engine:** Assign a risk score (Low/Medium/High) to every generated application based on complexity flags (e.g., prior denials, criminal history, unusual dates).
    *   *Low Risk:* Auto-generate draft for user review only.
    *   *Medium/High Risk:* **Block submission.** Require review by a designated internal "Legal Lead" (a trained team member) before the user can proceed.
*   **Uncertainty Triggers:** Configure the bot to automatically halt and flag any response where its internal confidence score drops below a strict threshold (e.g., 85%) or when it detects keywords related to persecution, criminality, or prior bans.
*   **Explicit Disclaimer & Consent:** Before any filing, present a clear, non-legalese summary of what the bot did vs. what the user must verify, requiring an active checkbox confirmation that a human has reviewed the final PDF.
*   **Audit Trail:** Log every user input, bot decision, and human override. This data is critical for post-incident analysis and improving the model.

**Note:** This plan relies on internal rigor; if a case involves potential criminal liability or complex asylum claims, the safest "checkpoint" is referring the user to pro bono legal aid networks rather than attempting automated resolution.
Prioritize "failing safe" (stopping the process) over "failing complete" (filing a potentially wrong form).
