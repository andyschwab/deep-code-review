**Pre-Launch Safety Protocol for Acme Valley Medical-Diagnosis Assistant**

**1. Static Knowledge Base Lockdown**
Since real-time verification is impossible, the system's knowledge base must be frozen and validated offline before deployment.
*   **Action:** Compile a "Gold Standard" dataset of 500+ verified case studies covering common rural presentations (respiratory, gastrointestinal, trauma, chronic disease) reviewed by your supervising specialists.
*   **Validation:** Run the assistant against this dataset locally. Any deviation from the specialist-verified treatment plan constitutes a critical failure. The system must not be updated with new data until the next scheduled offline review cycle.

**2. Deterministic "Hard Stop" Rules**
Implement rigid, non-negotiable logic gates that override AI suggestions for high-risk scenarios. These rules require no internet access.
*   **Red Flag Triggers:** If input contains keywords like "chest pain," "difficulty breathing," "unconscious," "severe bleeding," or "stroke symptoms," the system must immediately output a standardized emergency referral instruction rather than a specific treatment.
*   **Dosage Caps:** Hard-code maximum dosage limits for all suggested medications based on weight/age brackets. If the AI suggests a dose exceeding these limits, the output is blocked and replaced with a "Consult Supervisor" warning.

**3. Local Adversarial Simulation (The "Red Team" Drill)**
With your team of six, conduct manual stress testing using pre-written attack vectors that simulate confused or incomplete patient reporting.
*   **Scenario Injection:** Team members act as patients providing vague, contradictory, or culturally specific descriptions of symptoms.
*   **Goal:** Attempt to force the AI into hallucinating a diagnosis or suggesting contraindicated treatments (e.g., suggesting aspirin for a child with viral symptoms).
*   **Metric:** Record every instance where the AI fails to ask clarifying questions or provides unsafe advice. Refine the system prompt until it consistently defaults to "Insufficient Information - Refer to Clinic" in ambiguous cases.

**4. Mandatory Human-in-the-Loop Workflow**
The tool must be positioned as a *decision support* system, not an autonomous prescriber.
*   **Protocol:** No treatment suggestion generated by the AI is valid unless signed off by a local health worker.
*   **Output Formatting:** All outputs must include a visible disclaimer: *"This suggestion is generated by an offline AI model. It must be verified by a qualified health worker against current patient vitals and history."*
*   **Uncertainty Quantification:** Configure the system to display a confidence score. If confidence is below a set threshold (e.g., 80%), the system automatically suppresses specific treatment names and offers only general care advice.

**5. Incident Logging and Feedback Loop**
Establish a physical or local-network log for all discrepancies found during the pilot.
*   **Process:** Health workers must record cases where the AI suggestion was rejected or modified.
*   **Review:** Weekly offline meetings to analyze these logs. Patterns of error will inform prompt engineering adjustments before the next deployment phase.

**6. Fallback Mechanism**
Define a clear "System Down" protocol. If the device fails or the software behaves erratically, the clinic must revert immediately to established paper-based triage guidelines without interruption of care.

***

*Note: This plan relies entirely on local resources and pre-validated data; no cloud connectivity is required for execution.*
*Ensure all six team members are trained on the "Hard Stop" rules before the pilot begins.*
