## Summary
Refactors the flaky `test_dns_resolution` integration test to use a local mock DNS server, eliminating intermittent failures caused by external network timeouts and corporate firewall restrictions on specific domains.

## What
- Replaced live DNS lookup to `example-public-record.net` with a lightweight local mock server.
- Preserved the assertion logic: the test still validates that the library correctly parses DNS responses and handles connection establishment.
- Removed the external network dependency from the CI pipeline for this specific test case.

## Why
The original test failed intermittently (approx. 15% failure rate in CI logs) due to DNS timeout under load. Furthermore, specific external domains required for the live test are unreachable in isolated build environments (such as those with strict egress filtering), making the test impossible to verify locally for many contributors. This change aligns with the project guideline forbidding reliance on "unreliable external services" while maintaining the "real-world condition" requirement by simulating valid DNS protocol responses rather than hardcoding return values.
