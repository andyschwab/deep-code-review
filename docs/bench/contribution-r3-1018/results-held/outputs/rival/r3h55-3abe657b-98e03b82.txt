### Revised PR Description (Safe for Public Viewing)

**Summary**
Fixes an out-of-memory panic in the LogStream analyzer when parsing malformed log entries. The issue stemmed from an inefficient memory allocation pattern during error handling, which has been replaced with a bounded streaming approach.

**Root Cause**
When encountering malformed data, the previous implementation attempted to buffer excessive intermediate states before validation completed. In edge cases with specifically crafted malformed inputs, this led to unbounded memory growth and eventual application crash. The logic did not enforce strict upper limits on temporary buffers during the parsing phase.

**Solution**
Refactored the parsing loop to enforce strict memory bounds on all temporary allocations. Instead of buffering potentially invalid data, the parser now validates chunk sizes incrementally and discards malformed segments immediately without retaining them in memory. This ensures memory usage remains constant regardless of input malformedness.

**Test Plan**
- Added fuzz tests targeting malformed entry patterns to verify memory stability.
- Confirmed no panic occurs under high-load scenarios with 1GB+ of malformed input.
- Verified existing valid log parsing remains unaffected via regression suite.

**Backward Compatibility**
Fully backward compatible; only affects error-handling paths for invalid inputs.
