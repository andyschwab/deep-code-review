3.  **Verify the Race Condition**: Run your fix against this mock-clock test. If the bug reproduces with arbitrary numbers that match the *pattern* of your real logs, you have a valid MRE. If it only reproduces with the real logs, your fix may be addressing a symptom specific to your environment rather than the core race condition in the library.
4.  **Document the Logic, Not the Data**: In your PR description and test comments, explain the *condition* required to trigger the bug (e.g., "This test simulates a clock skew where the dequeue time precedes the enqueue time by 5ms") without referencing Acme Corp, billing logs, or real transaction times.
