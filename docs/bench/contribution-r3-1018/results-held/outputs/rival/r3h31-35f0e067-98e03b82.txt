If your mock data contains real table names or business logic, the PR will be rejected for leaking proprietary information.

Modify the error handling pipeline to accept an optional `errorTransformer` function in the client configuration.
*   **Signature:** `(rawError: GraphQLError[]) => GraphQLError[]`
*   **Behavior:** If provided, the client passes raw server errors to this function before returning them to the user. If undefined, the client behaves exactly as it does today.
*   **Implementation:** Ensure the transformer is strictly typed against the standard GraphQL error interface, not your custom Acme types.

**Title:** feat(core): Add optional `errorTransformer` hook for custom error normalization

**Summary**
This PR introduces a generic `errorTransformer` configuration option, allowing consumers to intercept and normalize raw GraphQL errors before they are returned to the application. This solves compatibility issues with legacy backends that use non-standard error envelopes without requiring the core library to maintain vendor-specific parsers.

**Motivation**
Several enterprise users operate behind legacy gateways that wrap standard GraphQL errors in proprietary nested structures (e.g., specific numeric codes or nested payload fields). Currently, integrating these systems requires fragile local forks of the error handler. A generic hook enables these teams to implement custom normalization logic safely while keeping the upstream library agnostic.

**Implementation Details**
*   Added an optional `errorTransformer` field to the client configuration.
*   The transformer receives the raw `GraphQLError[]` and must return a valid `GraphQLError[]`.
*   Zero breaking changes: the default behavior is unchanged if no transformer is provided.
*   Includes a new example (`examples/legacy-adapter.ts`) demonstrating how to unwrap a nested error envelope and map custom numeric codes. *Note: The example uses generic mock data and contains no proprietary schema definitions.*

**Test Plan**
*   Unit tests verify the hook is called when provided and skipped when undefined.
*   Type checks confirm the transformer adheres to standard GraphQL error interfaces.
*   Verified locally against a mock server returning nested error structures; the example adapter successfully normalizes them to standard format.

**Backward Compatibility**
Fully backward compatible. Existing clients will see no change in behavior or performance unless they explicitly opt into the new configuration option.

**Related Issue**
Addresses the need for custom error handling discussed in community channels regarding legacy backend integration.
