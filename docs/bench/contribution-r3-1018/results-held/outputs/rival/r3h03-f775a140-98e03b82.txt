**Technical Root Cause (Sanitized)**
The vulnerability exists due to a missing boundary validation when processing `[Specific Image Header/Chunk]`. When the library encounters an image with a `[Specific Malformed Value, e.g., width/height]` exceeding the allocated buffer size, it proceeds to copy data without verifying the destination capacity.

*   **Trigger Condition:** The crash is reproducible by feeding the library an image file where the `[Field X]` value is set to `[Value Y]`, causing the internal pointer to exceed the allocated stack/heap frame.
*   **Memory Impact:** This results in a write-out-of-bounds error. The severity is deterministic regardless of the host environment's memory layout or network configuration.
*   **Reproduction:** The issue is isolated entirely to the input file structure. It does not depend on specific IP configurations, server topology, or runtime environment variables. Any instance of the library processing this specific malformed input will exhibit identical failure behavior.

**The Fix**

2.  Returns a specific error code (`ERR_INVALID_DIMENSION`) if the check fails, preventing the write operation.
3.  Includes a new unit test (`test_malformed_image_bounds.c`) that reproduces the crash condition and verifies the fix prevents the overflow.
