### Proposed Solution: The "Mock-First, Env-Optional" Pattern

To satisfy the requirement for runnable code without exposing secrets or forcing complex setup, you should structure the examples to **default to safe, in-memory mock data** while optionally accepting real connections via environment variables. This ensures the CI suite passes immediately (using the mock path) and users can copy-paste to see instant results, while advanced users can plug in real data by setting a single variable.

#### 1. Updated Example Code Structure (`examples/streaming_demo.py`)

```python
import os
import sys
from data_processor import StreamHandler

def get_data_source():
    """
    Returns a data source based on environment configuration.
    Defaults to a safe, in-memory mock generator for documentation and CI.
    """
    # Check for real connection details (optional)
    db_url = os.getenv("DOC_EXAMPLE_DB_URL")
    api_key = os.getenv("DOC_EXAMPLE_API_KEY")

    if db_url and api_key:
        # Real production-style usage (only if user explicitly sets env vars)
        from data_processor import DatabaseConnector
        return DatabaseConnector(url=db_url, key=api_key)

    # Default: Safe mock data generator built into the library/docs
    # This ensures the script runs standalone without errors or leaks
    from data_processor import MockStreamGenerator
    print("Running in documentation mode with mock data...")
    return MockStreamGenerator(count=100)

def main():
    source = get_data_source()
    handler = StreamHandler(source)

    # Demonstrate the efficient streaming pattern
    for chunk in handler.process_stream():
        print(f"Processed batch: {chunk.id}")

if __name__ == "__main__":
    main()
```
