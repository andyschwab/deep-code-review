### Draft GitHub Issue: Inquiry Regarding Security Contact and Process

**Title:** Question: Security contact point and vulnerability disclosure process?

**Body:**

Hello maintainers,

I am an engineer at Acme Analytics, where we rely heavily on `QueueManager` in our production data pipelines. We are preparing to contribute some performance optimizations and minor bug fixes to the project.

As part of our internal open-source contribution governance, we are required to verify that projects we contribute to have a defined mechanism for reporting security vulnerabilities (such as a `SECURITY.md` file or a dedicated contact email). Currently, we could not locate this information in the repository.

Could you please clarify:
1. Is there a preferred private channel or email address for reporting potential security issues?
2. Are there plans to formalize a security response process or add a `SECURITY.md` file?

We want to ensure our contributions align with your project's governance and that any potential security concerns discovered during our work can be reported responsibly. If no formal process exists yet, please let us know how you would prefer we handle sensitive findings.

Thank you for your time and for maintaining this excellent library.

### Strategic Advice

**Do not start coding yet.** Your company's policy likely prohibits *any* contribution (even minor fixes) if the security posture is undefined, because contributing code creates a legal relationship and potential liability if a vulnerability is later found in your code without a way to report it.

**Post the issue first.** This draft is neutral and frames the question as "we want to help/contribute safely" rather than "you are non-compliant." If the maintainers do not respond within 5–7 days or state they have no plans for a security process, you must escalate internally at Acme Analytics to request a policy exception or halt the contribution effort; you cannot bypass this control unilaterally.
