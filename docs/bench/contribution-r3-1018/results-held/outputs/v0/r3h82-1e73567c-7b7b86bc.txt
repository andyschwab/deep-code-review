### Sanitized Load Test Strategy

**1. Generalize the Test Script**
Replace all specific identifiers with synthetic placeholders to isolate the concurrency defect from your environment.
*   **Endpoints:** Change `https://api.globex.corp/v1/stream/ingest` to `http://localhost:8080/mock/stream`.
*   **Authentication:** Replace proprietary headers (e.g., `X-Globex-Auth-Token`) with a generic `Authorization: Bearer <mock-token>` or remove them entirely if the bug exists at the connection pool level rather than the auth middleware.
*   **Paths:** Rewrite `/home/jsmith/globex-billing/src` to `/app/src` in any logged paths within the script.

**2. Describe Load Patterns Numerically (Without Revealing Volume)**
Do not share absolute request counts (e.g., "50k RPS") which reveal your scale. Instead, define the load relative to the server's saturation point or using abstract concurrency units:
*   **Concurrency Factor:** "The bug reproduces when concurrent workers exceed $N$, where $N$ is the number of available CPU cores multiplied by 4."
*   **Queue Depth:** "Failure occurs when the internal request queue depth sustains >90% capacity for 30 seconds."
*   **Timing Window:** "Race condition triggers when inter-arrival time between requests drops below 2ms while connection keep-alive is set to 5s."
*   **Stress Profile:** Use a step-function description: "Ramp up from 10 to 1000 concurrent connections over 10 seconds, hold for 60 seconds, then spike by 200% instantly."

**3. Delivery Format: Docker vs. Raw Script**
**Provide a Docker container.** This is the superior approach for concurrency bugs because it eliminates environmental variance (OS scheduler differences, network stack tuning) that often masks race conditions.
*   **Image Structure:** Create a `Dockerfile` that builds your sanitized test runner and includes a minimal, mock Go HTTP server (the "backend") that simulates the latency characteristics of your internal system without containing any business logic.
*   **Reproducibility:** The maintainer can run `docker-compose up` to spin up both the target server and the load generator, ensuring the exact timing window required to trigger the bug is present.
