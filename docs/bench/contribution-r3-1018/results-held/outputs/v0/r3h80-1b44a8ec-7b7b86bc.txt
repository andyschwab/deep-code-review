### Design Strategy: Pluggable Trace ID Codec

To resolve the conflict between community utility and internal privacy, you must decouple the **propagation mechanism** (injecting headers) from the **ID generation strategy** (formatting the ID). Do not contribute your custom Acme format. Instead, contribute a **SPI (Service Provider Interface)** or Strategy pattern that allows the framework to accept any ID generator.

**Implementation Steps:**

1.  **Define an Interface:** Create a `TraceIdGenerator` interface within MicroFlow with a single method: `String generate()`.
2.  **Provide a Default Implementation:** Implement a `StandardTraceIdGenerator` that uses a widely accepted, non-proprietary format (e.g., W3C Trace Context standard UUIDs or 16-byte hex strings). This ensures the framework works out-of-the-box for the community without exposing your internal logic.
3.  **Inject via Configuration:** Modify the framework's initialization to accept a custom `TraceIdGenerator` bean. If none is provided, it defaults to the standard implementation.
4.  **Internal Usage:** In your private fork at Acme, implement `AcmeTraceIdGenerator` containing your proprietary logic and inject it at runtime. This code never leaves your private repository.
