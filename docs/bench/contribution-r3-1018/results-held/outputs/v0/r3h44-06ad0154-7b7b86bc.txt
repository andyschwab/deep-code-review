### Pull Request Draft

**Title:** test: replace flaky external DNS resolution with local mock in tunnel handshake test

**Problem:**
The `test_secure_tunnel_handshake` integration test fails intermittently (approx. 15% failure rate under CI load) due to timeouts when resolving `example-validation-net.org`. This external dependency violates the project guideline forbidding tests that rely on unreliable external services, causing false negatives in the continuous integration pipeline.

**Change:**
Refactored the test to inject a lightweight, local mock DNS server instead of performing real-world public DNS resolution.
- Removed direct dependency on public DNS resolvers within the test scope.
- Introduced a deterministic mock server that responds to specific validation queries with predefined records.
- Preserved the logical flow of the handshake protocol; only the name resolution layer is simulated.

**Justification & Alignment with Quality Standards:**
While the project emphasizes real-world conditions, the guidelines explicitly prioritize test stability and forbid reliance on unreliable external services. The previous implementation conflated "integration" with "external network dependency," leading to flakiness that obscured genuine regressions.
- **Reliability:** The mock eliminates non-deterministic network latency, ensuring failures reflect actual code defects rather than infrastructure noise.
- **Fidelity:** The mock strictly adheres to the DNS protocol response structure expected by the library, maintaining high fidelity to the real-world interaction without the volatility of the public internet.
- **Precedent:** This approach aligns with standard practices for testing networked applications where external service availability cannot be guaranteed in isolated build environments.
