### Sanitized Bug Report Draft

**Title:** Log rotation fails when service name length exceeds threshold during disk usage check

**Description:**
The logging framework fails to trigger log rotation when the combined path length of the log file and the service identifier exceeds a specific character count, even when disk usage thresholds are met. This causes the application to crash due to unbounded log growth. The issue appears tied to how the rotation logic calculates available space relative to the fully qualified file path length.

**Steps to Reproduce:**
1. Configure the logger with a service name of 45+ characters (e.g., `dept-security-clearance-level-service-node-01`).
2. Set disk usage threshold to 80%.
3. Fill disk to 85% capacity.
4. Observe that rotation does not trigger, and the application crashes upon further write attempts.
5. Reduce service name to 20 characters (e.g., `app-service-01`) and repeat; rotation triggers correctly.

**Sanitized Configuration Snippet:**
```yaml
logging:
  service-name: "dept-security-clearance-level-service-node-01" # Use 45+ char string
  rotation:
    enabled: true
    disk-threshold-percent: 80
    max-file-size-mb: 100
  path-pattern: "/var/logs/${service-name}/app.log"
```

**Expected Behavior:**
Rotation should trigger based on disk usage regardless of service name length.

**Actual Behavior:**
Rotation fails silently when the service name causes the total path length to exceed an internal buffer limit, leading to crashes.
