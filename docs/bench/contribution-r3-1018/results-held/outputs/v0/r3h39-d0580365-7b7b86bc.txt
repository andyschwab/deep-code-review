### Strategy: Synthetic Font Metrics Mocking

Do not include the proprietary font file, subsets, or converted formats. Instead, create a synthetic test fixture that replicates the specific **metrics** (advance width, ascent, descent, line-gap) causing the overflow without containing any actual glyph outlines or licensed data.

**Technical Approach for the PR:**

1.  **Extract Metrics Only:** Locally measure the specific character widths and line-height values of 'Acme-Sans-Pro' that trigger the bug. Record these as raw numbers (e.g., `width: 14.2px`, `ascent: 18px`).
2.  **Create a Mock Font Face:** Generate a minimal, open-source-compatible CSS `@font-face` definition using a generic system font or a blank SVG font file.
3.  **Apply Metric Overrides:** Use CSS variables or a testing utility (like `jest-canvas-mock` or a custom CSS shim) to force the mock font to report the exact measured metrics of the proprietary font.
    *   *Example:* If the bug occurs because the font is wider than expected, define a test class `.test-font-mock` that applies `font-family: monospace` (or a standard web-safe font) but uses `transform: scaleX(1.15)` or specific `letter-spacing` adjustments to mimic the overflow behavior precisely.
4.  **Update Visual Tests:** Configure the visual regression suite to apply this `.test-font-mock` class specifically for the failing test case. Document that this mock deterministically reproduces the layout shift without requiring the binary font asset.
