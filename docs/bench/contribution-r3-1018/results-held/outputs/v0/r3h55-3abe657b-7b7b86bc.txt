### Generalized Technical Explanation (For PR Body)
**Problem:**
The parser enters an unbounded memory allocation loop when encountering specifically malformed log entries containing nested, unclosed delimiters. Instead of failing fast or enforcing a depth limit, the current logic recursively buffers intermediate states, causing resident set size (RSS) to spike until the process panics.

**Root Cause:**
The state machine lacks a guard clause for excessive recursion depth during tokenization. When faced with pathological input, it prioritizes completeness over resource safety, accumulating buffers proportional to the input's malformed complexity rather than its logical size.

**Solution:**
Introduced a hard limit on parsing depth and a maximum buffer threshold per entry. If these thresholds are exceeded, the parser now aborts the specific entry with a structured error (`ParseError::ResourceLimitExceeded`) rather than continuing to allocate. This ensures memory usage remains bounded regardless of input malignancy.

**Testing:**
Added a fuzz test case that generates deeply nested, unclosed delimiter streams.
- **Before:** Process crashes with `panic: out of memory` within 200ms.
- **After:** Process returns an error immediately, with memory footprint remaining stable under 5MB.
