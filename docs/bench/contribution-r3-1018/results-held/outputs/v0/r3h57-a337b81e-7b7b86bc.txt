### Discussion Post Draft

**Title:** [RFC] Handling Leap Seconds in `formatDate`: Breaking Change vs. Workaround

**Body:**

Hi maintainers,

I'm proposing a discussion regarding a limitation in the current `formatDate` implementation within CoreUtils. Specifically, the function does not account for leap seconds, leading to timestamp mismatches in high-precision domains like financial applications.

**The Problem**
Currently, calculations involving time intervals crossing a leap second event produce off-by-one-second errors. While rare, these mismatches are critical for compliance and auditing in financial systems.

**Proposed Solution**
The cleanest fix involves modifying the `formatDate` signature to accept an optional configuration object (e.g., `{ handleLeapSeconds: boolean }`). This allows precise control over time calculation logic without altering default behavior for existing simple use cases, though it technically constitutes a breaking change for type definitions and strict callers.

**Why This Approach?**
I considered a non-breaking workaround (e.g., global flags or environment variables), but these introduce hidden state and potential race conditions in multi-threaded environments, making the library less predictable. The configuration object approach ensures explicit, local control and long-term maintainability.

**Request for Feedback**
I understand the project's preference for small, incremental patches and the hesitation toward breaking changes. However, given the critical nature of time accuracy in downstream financial applications, I believe a major version update might be the responsible path forward.

Before drafting any code or PR, I wanted to gauge the community's interest:
1. Is the leap second issue affecting others significantly enough to warrant a major version bump?
2. Would the maintainers be open to reviewing a proposal for this configuration-based approach, or is there a preferred alternative pattern for handling such edge cases without breaking changes?

I am happy to provide synthetic reproduction cases and benchmark data if helpful. Looking forward to your thoughts.
