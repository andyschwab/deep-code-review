### Solution Description (for PR Body)

**Title:** feat: support loading additional trust anchors from user-provided paths

**Problem:**
Users in enterprise environments with private Certificate Authorities (PKI) often face SSL handshake failures because the default trust store does not include their internal root certificates. Currently, the server lacks a configuration option to append custom CA certificates to the default trust store without replacing it entirely.

**Change:**
This PR introduces a `extra_trust_roots` configuration field (or CLI flag) that accepts a path to a PEM file containing additional CA certificates. When provided, these certificates are added to the default `rustls::RootCertStore` (or equivalent) alongside the system defaults.

**Implementation Details:**
- Added `extra_trust_roots: Option<PathBuf>` to the server configuration struct.
- Updated the TLS builder to read the specified PEM file and append valid certificates to the root store.
- If the file is missing or contains invalid PEM data, the server fails to start with a clear error message, preventing silent security degradation.
- No default certificates are included; the feature is opt-in.

**Testing:**
- Verified that the server starts successfully with a valid custom CA bundle.
- Verified that the server rejects invalid PEM files with a descriptive error.
- Confirmed that default behavior (no extra roots) remains unchanged.

use rustls::{RootCertStore, Certificate};
use std::fs::File;
use std::io::BufReader;
use std::path::Path;

fn load_extra_trust_roots(
    base_store: &mut RootCertStore,
    pem_path: Option<&Path>,
) -> Result<(), Box<dyn std::error::Error>> {
    if let Some(path) = pem_path {
        let file = File::open(path)?;
        let mut reader = BufReader::new(file);
        let certs = rustls_pemfile::certs(&mut reader)?;

        // Inject generic logic: add all found certs to the store
        for cert in certs {
            base_store.add(&Certificate(cert))?;
        }
    }
    Ok(())
}
