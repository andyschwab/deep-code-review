**Proposed Pull Request Justification**

**Title:** test: replace flaky external DNS resolution with local mock in tunnel handshake test

**Problem**
The `test_tunnel_handshake` integration test exhibits intermittent failures (approx. 15% flake rate on CI) due to timeouts when resolving a specific public DNS record under load. This violates the project guideline forbidding dependence on unreliable external services, causing false negatives in the continuous integration pipeline.

**Solution**
This change replaces the live DNS lookup with a lightweight, local mock DNS server that synthesizes the expected response. The mock preserves the exact network I/O behavior of the tunnel handshake while eliminating the non-deterministic dependency on external infrastructure.

**Justification**
While the project prioritizes real-world conditions, relying on an uncontrollable third-party service for test stability contradicts the requirement for reliable verification. The previous implementation tested the *availability* of an external domain rather than the *correctness* of the NetLink library's handshake logic. The new approach isolates the library's behavior, ensuring that failures reflect actual regressions in the code rather than transient network conditions or external DNS outages. This aligns with the principle of testing the system under test, not its dependencies.

**Verification**
- The test now passes consistently (100% success rate over 500 local runs).
- The mock server validates that the library correctly handles standard DNS response structures.
- No changes were made to the core tunneling logic; only the test harness was modified.
