### Strategy for Safe Validation

Since connecting to the live Globex Manufacturing read-replica is forbidden, you must validate the driver using a **protocol-level simulation** rather than a database-level connection. Do not attempt to mock the high-level SQL interface, as this misses the timing and byte-level quirks of the mainframe.

1.  **Capture and Sanitize Traffic:** Use a network proxy (like Wireshark or a specialized JDBC logger) on a *non-destructive* read-only query already running in your lower environments (if any exist) or request a sanitized packet capture from the DBA team. If no capture exists, you must synthesize traffic based on the official mainframe protocol specification.
2.  **Build a Wire-Level Recorder/Replayer:** Create a test harness that acts as a "fake mainframe." This harness should not implement database logic; it should simply replay the recorded (or synthesized) byte streams back to your driver with the exact timing intervals observed in the specification or logs.
3.  **Inject Faults Deterministically:** Program the replayer to introduce specific latency spikes, connection resets, and malformed packets defined in the legacy protocol docs. This proves your driver handles edge cases better than a simple mock would.
4.  **Verification:** Your integration test suite will start this local "fake mainframe" on `localhost`, run your driver against it, and assert that the byte-handling logic correctly parses the legacy response format. This satisfies the requirement for "comprehensive integration tests" without touching a single production table.
