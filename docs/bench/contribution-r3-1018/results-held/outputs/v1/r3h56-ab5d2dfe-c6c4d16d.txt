### Synthetic Test Artifact Generation Strategy

To satisfy the requirement for a reproducible test case without violating legal constraints, you must generate a **synthetic file** that mimics the byte structure of the problematic encoding rather than anonymizing existing data. Anonymization (masking) often alters byte lengths or character sequences, which destroys the specific edge case you are fixing. Instead, construct a new file from scratch using the following method:

1.  **Identify the Byte Signature:** Isolate the specific byte sequences in your original customer files that trigger the corruption. In rare character sets, this is often a specific multi-byte sequence, an unassigned code point, or a boundary condition (e.g., a specific character at the end of a buffer line). Note the exact hex values (e.g., `0x8F 0xA2`).
2.  **Construct Dummy Payload:** Create a new text file using a script (Python or C++) that writes these exact byte sequences into a generic context.
    *   Replace "John Doe" with "User A".
    *   Replace real addresses with "123 Test Street".
    *   **Crucially:** Ensure the dummy text surrounding the problematic bytes has similar length and structure to the original to maintain buffer alignment, but contains no real PII.
    *   If the bug relies on a specific character appearing at a specific offset (e.g., byte 1024), pad your dummy file with standard ASCII characters until that offset, then insert the problematic hex sequence.
3.  **Verify Encoding:** Save this constructed file explicitly in the rare character set (e.g., EBCDIC, Shift_JIS, or a specific ISO variant) using a hex editor or a conversion tool that allows raw byte injection. Verify via a hex dump that the problematic byte sequence exists exactly as it did in the customer file.
4.  **Validation:** Run your fixed TextConvert utility against this new synthetic file. It should produce the same "garbled" output on the unpatched version and correct output on your patched version. This proves the fix addresses the *encoding mechanics*, not the specific customer data.
