### Sanitized Reproduction Steps (Draft)

**Test Case: High-Volume Burst Deadlock in Queue Manager**

1.  **Environment**: Standard Java Messaging System (vX.Y+) with default broker configuration.
2.  **Setup**: Initialize a `QueueManager` with a single consumer thread and a producer pool of $N$ threads (where $N > 2 \times$ CPU cores).
3.  **Trigger**:
    *   Configure the producer pool to send messages in synchronous bursts of size $B$ (e.g., $B=5000$) with zero inter-message delay.
    *   Simultaneously induce a artificial latency of $T$ milliseconds (e.g., $T=50$ms) on the consumer's `acknowledge()` call to mimic slow downstream processing.
    *   Execute the burst loop for $D$ seconds.
4.  **Observation**: The system hangs indefinitely. Thread dumps reveal a circular wait condition where producer threads hold the internal queue lock while waiting for consumer acknowledgment slots, while the consumer thread is blocked attempting to acquire the same queue lock to process the backlog.
5.  **Verification**: The deadlock resolves immediately if the burst size $B$ is reduced below the internal buffer threshold or if the consumer latency $T$ is removed.
