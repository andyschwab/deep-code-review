### Rewritten Pull Request Description

**Title:** Fix out-of-memory panic when parsing malformed log entries

**Problem**
The LogStream analyzer currently consumes excessive memory and crashes with an "out of memory" panic when encountering specific malformed log entries. This occurs because the parser allocates unbounded buffers while attempting to process invalid data structures, failing to enforce strict size limits during the decoding phase.

**Root Cause**
The parsing logic lacks adequate validation for edge cases in malformed inputs. When the parser encounters unexpected data patterns, it enters a state where it continuously accumulates data in memory without triggering early termination or error handling. This behavior allows a single malformed entry to exhaust available system resources.

**Solution**
This change introduces strict bounds checking and early exit conditions in the parsing loop. The fix ensures that:
1. Buffer allocations are capped at a safe maximum size.
2. Invalid data patterns trigger immediate error returns rather than continued processing.
3. Memory usage remains constant regardless of input malformedness.

**Testing**
- Added unit tests with malformed log entries that previously caused crashes.
- Verified memory usage remains stable under fuzz testing with invalid inputs.
- Confirmed existing valid log processing is unaffected.
