To prove ROI to municipal partners by March while adhering to the $0.05/device/month data budget, we will instrument only events that directly answer named business questions. We reject vanity metrics (total logins) in favor of value-based actions.

### 1. North Star Metric
**Weekly Active Units Completing Automated Cycles.**
*Definition:* A unit is "active" only if it executed a scheduled irrigation event that week.
*Why:* Cumulative installations and raw app logins rise regardless of value. This metric rises only when the customer receives the core benefit (water saved via automation).

### 2. Input Metrics & Event Taxonomy
We will transmit only the following three event classes. All other telemetry is suppressed to meet the budget.

| Event Name | Properties Sent | Question Answered | Decision Rule |
| :--- | :--- | :--- | : |
| `schedule_created` | `days_since_install`, `schedule_type` (auto/manual) | Does early setup predict the 25% savings hypothesis? | If `days_since_install` ≤ 3 correlates with >20% savings, prioritize onboarding flows that force day-1 setup. |
| `cycle_executed` | `mode` (auto/manual), `water_volume_est` | Are users actually saving water? (North Star Input) | If `mode`=auto volume is <75% of manual baseline, the 25% hypothesis holds; report verified savings to municipalities. |
| `login_session` | `duration_sec`, `screens_viewed_count` | Do frequent logins mean engagement or confusion? | **Critical Cut:** If `duration_sec` > 120s AND `screens_viewed_count` > 5 without a `schedule_created` event, flag as **Confusion**. If duration is short and followed by execution, flag as **Engagement**. |

### 3. Measurement Strategy by Stage
*   **Activation:** Track the % of new units firing `schedule_created` within 72 hours. This validates the "critical window" assumption.
*   **Retention:** Cohort users by `schedule_type`. Compare `cycle_executed` frequency in Week 4 vs. Week 1. If manual users drop off faster, the automation is the retention driver.
*   **Revenue/ROI:** Aggregate `water_volume_est` from `cycle_executed` events. Multiply by local water cost to generate the dollar-value ROI report for March.

### 4. Data Budget Control
*   **Aggregation:** `cycle_executed` events will batch daily totals per device rather than per-cycle transmission if individual cycle data exceeds bandwidth.
*   **Sampling:** `login_session` events will be sampled at 10% for devices with >5 logins/week to prevent noise from power-users flooding the server.
*   **Suppression:** No heartbeat pings. No screen-level clickstreams. Only the three events above are transmitted.
