# Diagnostic Plan: Power User Churn Analysis
**To:** Marcus Thorne, Chief Product Officer
**From:** Growth Analytics
**Date:** April 2024
**Subject:** Evidence-Based Retention Strategy for Power Users (Jan–Mar)

### 1. Define the North Star & Input Metrics
*   **North Star:** Weekly Active Power Users completing a "Complex Workflow" (defined as >5 layers used in a single session).
*   **Primary Input Metric:** Time-to-Complete for workflows with >5 layers.
*   **Guardrail Metric:** Overall platform latency (to rule out infrastructure issues).
*   **Rejection of Vanity:** Ignore total signups or raw session counts; they mask the specific erosion of high-value behavior.

### 2. Event Taxonomy: Instrument the "Moment of Friction"
Do not instrument everything. Add these three specific events to the session logs immediately to answer named questions:
*   `layer_action_latency`: Captures milliseconds between layer addition and UI render.
    *   *Properties:* `user_tier` (power), `layer_count`, `workflow_id`.
    *   *Question:* Did latency spike for complex files in Feb/March compared to Jan?
*   `workflow_abandonment`: Fired when a user closes a project without saving after >10 minutes of activity.
    *   *Properties:* `last_action_type`, `session_duration`, `error_code` (if any).
    *   *Question:* Is abandonment correlated with high `layer_count`?
*   `competitor_exit_click`: (If applicable) Tracks clicks on external links or export formats often used for migration.
    *   *Question:* Are users exporting assets to move elsewhere?

*Note on Data:* If these events are not currently logged, any analysis of "exact moments" is **UNVERIFIED**. We must rely on proxy metrics (e.g., session duration drops) until instrumentation is live.

### 3. Diagnostic Method: Cohort & Sequence Analysis
Execute this analysis on the existing logs using the stable User ID (pseudonymous):
*   **Step A: Retention Cohort Split.**
    *   Compare Jan vs. Mar cohorts of power users.
    *   Plot retention curve specifically for the action "Save Project with >5 Layers."
    *   *Hypothesis Test:* If the drop-off occurs *during* the editing phase (not at login), the tool performance is the likely driver.
*   **Step B: The "Slowdown" Correlation.**
    *   Correlate `layer_action_latency` with `churn_status` (0=retained, 1=churned).
    *   Calculate the threshold: At what millisecond delay does the probability of churn exceed 50%?
*   **Step C: Competitor Signal Check.**
    *   Analyze support ticket tags and survey text for competitor names alongside the churn date.
    *   If churn spikes uniformly across all workflow types (simple and complex), suspect a competitor/market shift. If spikes are isolated to complex workflows, suspect the layering tool.

### 4. Decision Matrix & Next Actions
Present these findings to the board with the following "If/Then" actions:

| Finding | Interpretation | Immediate Action (Next Week) |
| :--- | :--- | :--- |
| **High correlation** between latency >200ms and churn in complex files. | Tool slowdown is the primary driver. | **Rollback** recent layering changes for power users; initiate A/B test on optimized rendering. |
| **No latency change**, but churn up across all project types. | External factor (competitor/pricing). | Launch targeted win-back campaign; accelerate roadmap for differentiating features. |
| **Data Gap:** No latency events logged. | Cause is currently **UNVERIFIED**. | Deploy hotfix to log `layer_action_latency` within 48 hours; pause major UI changes until data arrives. |
