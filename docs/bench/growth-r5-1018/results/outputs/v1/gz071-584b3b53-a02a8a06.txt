### Executive Summary: Tender Posting Funnel Redefinition

To secure engineering resources for the Q2 board review, we must replace the current binary "visited vs. completed" view with a granular, five-stage funnel. This structure isolates the document upload hypothesis and accounts for the unknown mobile/desktop variance.

**Proposed Event Taxonomy & Stages**
Instrument the following discrete events immediately. Each event must capture `device_type`, `browser`, and `file_count` (where applicable) to resolve the mobile unknown.

1.  **Tender_Initiated**: User clicks "Post New Tender."
    *   *Question:* Is the entry point clear?
2.  **Form_Details_Completed**: User fills core metadata (title, budget, deadline) and clicks "Next."
    *   *Question:* Is the form length or complexity causing early abandonment?
3.  **Upload_Started**: User triggers the file selector or drag-and-drop zone.
    *   *Question:* Do users attempt to upload? (Distinguishes intent from technical failure).
4.  **Upload_Success**: Backend confirms all required documents are stored.
    *   *Question:* **Critical Friction Point.** If `Upload_Started` is high but `Upload_Success` is low, the hypothesis is confirmed: the module is failing users (timeout, format rejection, UI bug).
5.  **Tender_Published**: Final confirmation screen loaded.
    *   *Question:* Are there final review hesitations?

**Interpretation Logic for the Steering Committee**
Do not present raw counts alone. Present **Stage-to-Stage Conversion Rates** compared to your historical baseline for other forms, or week-over-week trends if no baseline exists.

*   **Validating the Hypothesis:** If the drop between *Upload_Started* and *Upload_Success* exceeds 40% (or is significantly higher than the drop in *Form_Details_Completed*), the data proves the upload module is the primary blocker. This justifies the engineering request.
*   **Resolving the Mobile Unknown:** Segment every stage by `device_type`. If mobile conversion at *Upload_Started* is <50% of desktop conversion, the friction is likely UI-related (touch targets, file picker compatibility) rather than backend logic.
*   **The "Vanity" Trap:** Ignore the 4,200 unique visitors for this specific decision. High traffic with low completion is a symptom; the *stage* where they leave is the diagnosis. Focus the board's attention solely on the **abandonment rate** at stage 3 and 4.

**Immediate Next Steps (This Week)**
1.  **Instrument:** Deploy tracking for the five events above with `device_type` properties by [Date + 3 days].
2.  **Query:** Run a cohort analysis for March 12–Present grouping by `device_type` to calculate the exact drop-off percentage at *Upload_Started* vs. *Upload_Success*.
3.  **Decide:** If the upload drop-off is >2x higher than form completion drop-off, approve the engineering sprint for the upload module immediately; otherwise, investigate form field complexity.
