### Prioritized Event Taxonomy for GreenFlow Irrigation Beta

To justify funding and validate value without fabricating benchmarks, instrument only these three events. They shift the North Star from "engagement frequency" (vanity) to "reliable automation" (customer value).

**1. `automation_cycle_completed`**
*   **Definition:** Triggered when the valve executes a full watering schedule automatically without user intervention.
*   **Properties:** `zone_id`, `scheduled_duration`, `actual_duration`, `weather_override_applied` (boolean), `season_tag`.
*   **Why this matters:** This is your true North Star input. In irrigation, high value equals *zero* necessary interaction. If users are satisfied, this count stays high while manual adjustments stay low. It proves the "set and forget" promise is working.
*   **Interpretation:** A rising trend here indicates trust. If this drops while `manual_override` rises, the automation logic is failing specific crops or weather conditions.

**2. `manual_override_applied`**
*   **Definition:** Triggered when a user manually starts, stops, or modifies a scheduled cycle before it completes.
*   **Properties:** `override_type` (start/stop/duration_change), `time_since_last_auto_cycle`, `reason_code` (if UI allows selection, e.g., "rain expected," "system error").
*   **Why this matters:** This is your primary failure signal. High frequency here contradicts the "high engagement = good" assumption; it signals the system is not meeting agronomic needs.
*   **Interpretation:** Cluster these by `season_tag`. If overrides spike during harvest or frost seasons, the algorithm lacks specific seasonal rules. If they are random, the hardware may be unreliable.

**3. `system_health_acknowledged`**
*   **Definition:** Triggered when a user views or clears a critical alert (e.g., "low battery," "connectivity lost," "valve stuck").
*   **Properties:** `alert_type`, `time_to_acknowledge`, `resolution_action` (auto-resolved vs. user-fixed).
*   **Why this matters:** Farmers cannot afford crop loss due to silent failures. This measures "peace of mind." If alerts go unacknowledged for days, the user has abandoned the tool, regardless of past schedule settings.
*   **Interpretation:** Long `time_to_acknowledge` suggests the notification channel (SMS/app push) is broken or the user has disengaged. High volume of `connectivity_lost` explains sudden drops in `automation_cycle_completed`.

### Interpreting Sparse Usage & Seasonality

Do not compare your retention to SaaS benchmarks; they are irrelevant to seasonal hardware. Instead, compare the user's current behavior to their own baseline established in the first 30 days.

*   **The "Silent Success" Pattern:** If `automation_cycle_completed` remains consistent week-over-week while `manual_override_applied` is near zero, the user is deriving maximum value. Sparse login sessions are a *positive* signal, not churn.
*   **The "Abandonment" Pattern:** If `automation_cycle_completed` drops to zero and no `manual_override_applied` events occur for 14+ days during an active growing season, the unit is likely offline or abandoned.
*   **Seasonal Baseline:** Segment all data by `season_tag`. Do not expect winter activity to match summer. A "retention leak" is only real if activity drops relative to the *expected* seasonal curve for that crop type.
