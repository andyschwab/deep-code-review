**Subject:** Proposed Conversion Funnel & Tracking Plan for Developer Week Launch

**1. The North Star Metric**
**Metric:** *Weekly Active Integrations* (Developers who successfully make a production API call within 7 days of key generation).
**Rationale:** Registered keys and signups are vanity metrics; they rise regardless of value. Real business value occurs only when the API is integrated into a live project.

**2. Proposed Funnel Structure (Acquisition → Activation)**
To identify the drop-off between identity verification and project creation, instrument these specific stages. Each stage must answer a named question.

*   **Stage A: Event Engagement (Acquisition)**
    *   *Event:* `content_consumed`
    *   *Properties:* `content_type` (keynote vs. blog), `user_id`.
    *   *Question:* Does keynote viewership correlate with higher intent? (Validates the 3x hypothesis).
*   **Stage B: Registration Initiation**
    *   *Event:* `signup_started`
    *   *Properties:* `referrer_source`, `timestamp`.
    *   *Question:* Where is the top-of-funnel leakage?
*   **Stage C: Identity Verification (Critical Drop-off Point 1)**
    *   *Event:* `identity_verification_started` / `identity_verification_completed`
    *   *Properties:* `verification_method`, `error_code` (if failed).
    *   *Question:* Is friction at the ID check preventing account creation?
*   **Stage D: Project Creation (Critical Drop-off Point 2)**
    *   *Event:* `project_created`
    *   *Properties:* `project_type`, `time_to_complete`.
    *   *Question:* Do users stall after getting an account but before defining a use case?
*   **Stage E: Key Generation (Activation Threshold)**
    *   *Event:* `api_key_generated`
    *   *Properties:* `key_scope`, `environment` (sandbox vs. prod).
    *   *Question:* Did the user reach the "Aha!" moment of possessing access?
*   **Stage F: First Successful Call (North Star Input)**
    *   *Event:* `first_successful_api_call`
    *   *Properties:* `endpoint`, `latency`, `status_code`.
    *   *Question:* Is the integration actually working, or does it fail post-key?

**3. Real-Time Reporting Strategy for Executive Committee**
Since the event is live (Oct 10–12), the dashboard must display **conversion rates between adjacent stages** rather than cumulative totals.
*   **Primary View:** Funnel visualization showing % drop-off from `identity_verification_started` → `project_created`. This directly answers the unknown bottleneck.
*   **Segmentation:** Split the funnel by `content_type` (Keynote vs. Blog) to test the "3x likelihood" assumption in real-time. If the hypothesis fails, reallocate promotional focus immediately.
*   **Guardrail:** Monitor `identity_verification_error_rate`. If this spikes above 5%, engineering must intervene immediately, as this blocks all downstream revenue.

**4. This-Week Action Plan**
1.  **Instrument Now:** Deploy the six events listed above with the specified properties before October 10th. Do not instrument "pageviews"; only instrument these specific actions.
2.  **Define Baseline:** Set the current (pre-event) conversion rate from `signup_started` to `api_key_generated` as the baseline. Any lift during the event is measured against this, not an external benchmark.
3.  **Prepare the Query:** Pre-build the dashboard filter for "Keynote Viewers" vs. "Blog Readers" to validate the 3x hypothesis on Day 1.

**Note:** No external benchmarks for "good" B2B API conversion rates are used here; success is defined strictly by improvement against CloudBridge's own pre-event baseline.
**Note:** Ensure `user_id` is pseudonymous in analytics tools to comply with privacy standards; route PII handling to the compliance team.
