**From:** Search Quality Analyst
**Subject:** Recommendation on Search Ranking Update – Immediate Action Plan

**Decision:** Do not roll back yet; execute a targeted 24-hour diagnostic hold to validate revenue impact before the weekend peak. An 8% CTR gain with a 15% Average Order Value (AOV) drop suggests the algorithm is successfully surfacing engaging content that is systematically lower-priced, or burying high-margin titles beyond visibility. Rolling back now sacrifices the engagement win without confirming if the revenue loss is structural (cheaper books) or fixable (ranking bias).

**Step-by-Step Analysis Plan (Next 24 Hours):**

1.  **Segment AOV by Price Tier (Immediate Query)**
    Run a cohort analysis comparing pre- and post-launch AOV across three book price tiers: Low (<$10), Mid ($10–$25), and High (>$25).
    *   *Hypothesis A:* If AOV dropped only in the High tier while volume shifted to Low/Mid, users are finding cheaper books they prefer. This is a mix shift, not necessarily a failure of relevance.
    *   *Hypothesis B:* If AOV dropped uniformly across all tiers, the ranking is likely suppressing premium titles entirely or disrupting upsell logic.

2.  **Calculate Revenue Per Search (RPS) Net Impact**
    Stop optimizing for CTR or AOV in isolation. Compute **Revenue Per Search = CTR × Conversion Rate × AOV** for the last 48 hours vs. the prior week.
    *   *Decision Rule:* If RPS is flat or up despite the AOV drop, the higher volume compensates for lower basket size. Let the test run through the weekend. If RPS is down >5%, the engagement gain is vanity masking revenue leakage.

3.  **Analyze "Premium Title" Visibility**
    Isolate the top 50 highest-margin/premium titles by SKU. Check their average rank position pre- and post-launch.
    *   *Action:* If these specific titles have fallen from page 1 to page 3+, manually inject a "business weight" boost for high-margin categories as a temporary patch rather than a full rollback. This preserves the new ranking's relevance gains while protecting margin.

4.  **Define the Weekend Guardrail**
    Allow the update to run through the weekend sales peak under one strict condition: **Real-time RPS monitoring.**
    *   *Tripwire:* If hourly RPS drops more than 10% below the baseline for 4 consecutive hours during peak traffic, trigger an immediate partial rollback (revert weighting factors only, keep index fresh).
    *   *Success Metric:* Weekend total revenue must match or exceed last weekend's total, even if AOV remains lower.

**Recommended Immediate Steps:**
1.  Run the price-tier segmentation query now to distinguish between "users buying cheaper books" vs. "premium books hidden."
2.  Set up the RPS dashboard alert with the 10% tripwire before peak traffic begins tomorrow.
3.  Prepare a "business weight" configuration ready to deploy if premium titles are confirmed buried, avoiding a full code rollback.

The goal is to capture the engagement upside while surgically protecting revenue, rather than reverting to a state where users were less engaged but spent more per transaction.

*Note: All metrics must be compared strictly against BookFindr's own prior week baseline; no external benchmarks apply. If raw counts for price tiers are unavailable, the RPS calculation cannot be verified and the safe path is a partial revert of ranking weights.*
