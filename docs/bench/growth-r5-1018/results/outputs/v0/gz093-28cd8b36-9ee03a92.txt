**Executive Summary**
To enable real-time reporting during the October 10th Developer Week, we must shift from vanity metrics (total registrations) to a value-based funnel focused on **API Key Activation**. The following structure isolates the specific drop-off points between identity verification and project creation, allowing immediate intervention if conversion stalls.

**Proposed Funnel Structure (Bottom-Up Retention Focus)**
We define success not by sign-up, but by the first successful API call. The funnel stages are:

1.  **Acquisition (Entry Point)**
    *   *Event:* `session_start`
    *   *Property:* `traffic_source` (Keynote Viewer vs. Blog Reader).
    *   *Goal:* Validate the hypothesis that Keynote viewers convert at 3x the rate of blog readers.
2.  **Activation (Account Creation)**
    *   *Event:* `registration_complete`
    *   *Definition:* Email verified and account active.
    *   *Drop-off Check:* Compare `session_start` to `registration_complete`.
3.  **Critical Milestone A: Identity Verification**
    *   *Event:* `identity_verification_started` → `identity_verification_completed`
    *   *Diagnostic:* If `started` is high but `completed` is low, the friction is in the ID provider or document upload UI.
4.  **Critical Milestone B: Project Creation**
    *   *Event:* `project_creation_started` → `project_created`
    *   *Diagnostic:* If users pass ID check but fail here, the "New Project" workflow or required metadata fields are the blocker.
5.  **North Star: Value Realization**
    *   *Event:* `first_successful_api_call`
    *   *Definition:* A 200 OK response from the gateway using a generated key.
    *   *Why this matters:* This is the only metric that proves the marketplace is delivering value. All prior steps are vanity without this.

**Instrumentation Rules for Real-Time Reporting**
To answer your specific unknowns during the event, every event above must include:
*   `user_id` (Pseudonymous, stable across sessions).
*   `timestamp` (UTC).
*   `step_duration` (Time spent in current stage).
*   `error_code` (If the step fails).

**Reading the Data During the Event**
*   **The Drop-Off Question:** Do not look at aggregate completion rates alone. Plot the conversion rate *between* Stage 3 (ID) and Stage 4 (Project). If the drop from `identity_verification_completed` to `project_creation_started` exceeds 40% of your baseline expectation, the friction is in the project setup, not the ID check.
*   **The Hypothesis Check:** Segment the funnel by `traffic_source`. If Keynote viewers do not show a statistically higher conversion rate at the "Project Created" stage by Day 2, the content-to-product link is broken, regardless of total signups.

**This-Week Action Plan**
1.  **Implement Event Taxonomy:** Instrument the five events listed above with the specified properties before October 10th. Do not instrument "page views" unless they map directly to these steps.
2.  **Build the Live Dashboard:** Configure the real-time view to display the conversion rate *between* Identity Verification and Project Creation specifically, updated hourly.
3.  **Define the Intervention Trigger:** If the conversion rate from `identity_verification_completed` to `project_created` drops below 50% for two consecutive hours during the keynote, the engineering team must deploy a simplified "Quick Start" project template immediately.

*Note: No benchmark values (e.g., "good conversion is X%") are asserted here; thresholds must be derived from your internal pilot data or set as provisional targets for this event. Ensure all `user_id` handling complies with privacy standards before ingestion.*
