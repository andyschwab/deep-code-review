### Essential Event Taxonomy: Unboxing & Setup

Track only these five events to isolate the impact of goal setting while respecting privacy constraints. Each event includes the specific question it answers and required properties.

**1. `device_first_sync`**
*   **Question:** Did the user successfully pair and sync the device after unboxing? (Activation baseline)
*   **Properties:** `device_id` (pseudonymous), `firmware_version`, `os_type`, `timestamp`.
*   **Action:** Triggers the "Welcome" email sequence. If this drops off, the hardware or pairing flow is broken.

**2. `setup_step_viewed`**
*   **Question:** Are users reaching the goal configuration screen, or abandoning before?
*   **Properties:** `step_name` (e.g., "profile_creation", "goal_setting"), `session_id`.
*   **Action:** Identifies friction points in the setup wizard.

**3. `goal_config_submitted`**
*   **Question:** Did the user explicitly set a weekly step goal? (The core independent variable)
*   **Properties:** `goal_type` (e.g., "weekly_steps"), `goal_value` (integer), `time_to_complete` (seconds from setup start), `is_skipped` (boolean).
*   **Action:** Segments users into "Goal Setters" vs. "Skippers" for the A/B analysis. Triggers tailored onboarding emails reinforcing the specific goal value.

**4. `setup_completed`**
*   **Question:** Did the user finish the entire onboarding flow?
*   **Properties:** `total_duration` (seconds), `steps_completed` (count), `goal_set` (boolean mirror).
*   **Action:** Finalizes the activation cohort. Marketing stops onboarding nudges and begins engagement content.

**5. `wear_time_daily_snapshot`**
*   **Question:** Is the user wearing the device ≥18 hours/day? (The core dependent variable)
*   **Properties:** `date`, `wear_duration_hours` (aggregated locally on device, no continuous HR), `device_id`.
*   **Action:** Calculates the retention metric at Day 7, Day 30, and Day 60.

### Analysis Plan for the Hypothesis

To determine if goal setting *drives* adherence or merely *correlates*:

1.  **Cohort Split:** Divide users into Group A (Set Goal) and Group B (Skipped Goal) based on `goal_config_submitted.is_skipped`.
2.  **Retention Comparison:** Compare the % of users in each group hitting the 18-hour threshold at Day 60.
3.  **The "Leak" Check:** Since you have a historical 25% drop-off without goals, measure if Group A's drop-off is statistically lower than Group B's.
4.  **Causality Note:** If Group A performs better, it may still be self-selection (motivated users set goals). To prove causality, you must eventually run an experiment forcing the UI flow (e.g., making goal setting mandatory for half of new users), but this event taxonomy provides the observational baseline required first.
