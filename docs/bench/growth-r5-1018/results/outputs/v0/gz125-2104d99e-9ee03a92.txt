To prove ROI to municipal partners by March while adhering to the $0.05/device/month data budget, we will instrument only events that directly answer named business questions. We reject "track everything" approaches; unused data is cost without value.

### 1. The North Star Metric
**Metric:** *Weekly Active Controllers Executing Automated Schedules.*
**Why:** This rises only when customers receive real value (water saved via automation). Cumulative installs or raw app logins are vanity metrics; they increase regardless of whether the device actually saves water.
**Input Metrics:**
*   Activation Rate: % of installed units with an automated schedule set within 72 hours.
*   Schedule Adherence: % of days the controller runs the automated plan vs. manual override.

### 2. Event Taxonomy (Prioritized by Value/Cost)
We will transmit only the following three event types. All other interactions remain local to the device/app to preserve bandwidth.

| Priority | Event Name | Properties Sent | Question Answered | Cost Justification |
| :--- | :--- | :--- | :--- :--- |
| **P0** | `schedule_created` | `timestamp`, `is_automated` (bool), `days_since_install` | Does the user activate the core value prop within the critical 3-day window? | Essential to validate the 25% savings hypothesis. |
| **P0** | `water_cycle_executed` | `mode` (auto/manual), `duration_minutes`, `estimated_gallons` | Are users actually saving water? (Direct ROI proof for municipalities). | Directly maps to the 1.2M gallon savings claim. |
| **P1** | `session_summary` | `session_duration_bucket` (<2m, 2-10m, >10m), `actions_count` | Do frequent logins indicate confusion (long duration, many actions) or engagement? | Solves the "login ambiguity" without sending every click. |

**Excluded Events:** Individual button clicks, screen views, or heartbeat pings >24hrs. These are noise under our current budget constraints.

### 3. Reading the Data (The Method)
*   **Retention First:** Before analyzing new installs, we must verify if users who set up automation in Week 1 are still executing automated cycles in Week 4. If retention leaks, acquisition spend is wasted.
*   **The Login Hypothesis:** We will correlate `session_summary` duration with `schedule_created`.
    *   *If* long sessions correlate with *no* automation setup → Interface confusion.
    *   *If* long sessions correlate with *active* management → High engagement.
*   **Baseline Comparison:** We will compare current automation rates against the installed base from last summer. No external benchmarks will be used; success is defined by improvement over our own prior performance.
