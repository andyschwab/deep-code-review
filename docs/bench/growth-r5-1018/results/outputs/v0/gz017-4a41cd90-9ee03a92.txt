# PayForward Brazil Beta: Core Metric Framework for Board Dashboard

**North Star Metric:** Weekly Active Users completing a successful local payment (PIX or boleto) within 7 days of signup.
*Rationale:* Raw signups are vanity; value is only delivered when a user successfully moves money. This metric rises only when the core value proposition works in the Brazilian context.

### 1. Acquisition (Top of Funnel)
*Do not optimize for total installs.* Track only high-intent entry.
*   **Metric:** Cost Per Qualified Lead (CPQL).
*   **Definition:** Marketing spend divided by users who complete identity verification (KYC) and link a funding source.
*   **Why:** In Brazil, many users may download the app out of curiosity but fail strict local banking compliance. Measuring cost against *verified* users prevents wasting budget on unconvertible traffic.

### 2. Activation (The "Aha" Moment)
*Hypothesis to Validate:* "Integration speed drives adoption."
*   **Metric:** Time-to-First-Successful-Transaction (TTFST).
*   **Definition:** Median time elapsed from account creation to the first confirmed PIX transfer.
*   **Segmentation:** Split by device type (iOS vs. Android) and funding source (bank transfer vs. credit card).
*   **Board Question Answered:** "Is our assumption about speed correct? If TTFST > 24 hours, speed is the blocker. If TTFST is low but volume is low, the blocker is awareness or trust."

### 3. Early Retention (The Truth Teller)
*Read this before scaling acquisition.*
*   **Metric:** Day-7 Repeat Transaction Rate.
*   **Definition:** Percentage of users who perform a second distinct payment transaction within 7 days of their first.
*   **Why:** A single transaction may be a one-off test. Repeat usage proves the wallet is becoming a habit. If this number is low, pouring money into acquisition (the 10k user goal) will burn cash without building a business.

### Event Taxonomy (Instrument Only These)
Every event below answers a specific board-level question. Do not instrument "clicks" without a named question.
1.  `kyc_completed` (Properties: `method`, `duration_seconds`) → *Question: Is local compliance friction killing activation?*
2.  `payment_initiated` (Properties: `type` [PIX/boleto], `amount`) → *Question: Are users attempting the right local methods?*
3.  `payment_succeeded` (Properties: `latency_ms`, `retry_count`) → *Question: Does integration speed correlate with success?*
4.  `payment_failed` (Properties: `error_code`, `step`) → *Question: Where exactly does the local rail break?*

### Critical Constraints & Baselines
*   **No External Benchmarks:** We cannot assert a "good" conversion rate for Brazil as no verified public benchmark exists for PayForward's specific niche. All targets must be set against **PayForward's own Week 1 baseline**.
*   **The 10k Goal Risk:** Reaching 10,000 active users is a volume target, not a health target. If Day-7 Retention is <15% (hypothetical internal threshold to be set after Day 7 data), the goal must shift from "acquire 10k" to "fix retention," or the churn will invalidate the growth.
*   **Data Source:** All figures must be pulled directly from the Brazilian beta environment analytics. Any metric labeled "UNVERIFIED" indicates missing instrumentation, not an estimated number.
