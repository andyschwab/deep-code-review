# Diagnostic Plan: Power User Churn Analysis
**To:** Marcus Thorne, Chief Product Officer
**From:** Growth Analytics
**Subject:** Evidence-Based Retention Strategy for Power Users (Jan–Mar)

### 1. Define the North Star & Input Metrics
*   **North Star:** Weekly Active Power Users completing a "Complex Workflow" (defined as >5 layers used in a single session).
*   **Input Metrics:**
    *   Layering Tool Latency (p95) per action.
    *   "Abandonment Rate" at the layering step (session ends within 2 mins of last layer action).
    *   Competitor Referral Traffic (if trackable) or search terms leading away.

### 2. Event Taxonomy: Answering Named Questions
Instrument only these events to isolate the "moment of decision":
*   `layer_action_start` / `layer_action_complete`: Measures duration. *Question: Did latency increase for power users specifically between Jan–Mar?*
*   `workflow_abandon`: Triggered when a user with >20 projects/month exits during a complex workflow without saving. *Question: Is the drop-off correlated with high-latency events?*
*   `competitor_comparison_view`: If users visit pricing/feature compare pages before leaving. *Question: Is there a spike in comparison behavior?*
*   `export_failure` or `slow_render`: Specific error/slow states. *Question: Are technical failures driving the exit?*

### 3. Diagnostic Method: Bottom-Up Funnel (Retention First)
Do not analyze acquisition yet. Focus entirely on why retained users are now leaking.
*   **Cohort Segmentation:** Split power users into two groups: those who churned in Jan–Mar vs. those who remained.
*   **Session Replay Analysis:** Sample 50 churned sessions and 50 retained sessions from March. Compare the time-to-complete for the "Add Layer" action.
    *   *Hypothesis Check:* If the average time increased by >20% for churned users but stayed flat for retained users, the tool change is the primary driver.
*   **Competitor Signal:** Analyze survey text data for keyword frequency ("slow," "lag," "competitor name," "alternative"). If "slow" correlates 3:1 with "competitor," prioritize performance. If "competitor" dominates without performance complaints, investigate feature parity.

### 4. Experiment Rigor & Validation
*   **Baseline Comparison:** Compare March latency metrics against December (pre-change) baseline. Do not use industry benchmarks; use PixelPerfect's own historical data.
*   **Confounder Check:** Verify if the churn spike aligns exactly with the deployment date of the layering update. If churn rose gradually before the deploy, the update is likely not the sole cause (check for seasonality or competitor launches).
*   **Verification Status:** Any claim regarding "competitor superiority" without direct user migration data is `UNVERIFIED`. Rely on the correlation between latency spikes and session termination.

### 5. This-Week Action Plan
1.  **Query Execution:** Run a SQL query joining `user_tier='power'`, `event='layer_action'`, and `session_duration` for Jan–Mar. Calculate the correlation coefficient between layer latency and immediate session exit.
2.  **Targeted Survey:** Send a micro-survey (1 question) to users who abandoned a workflow in the last 48 hours: "Did technical performance or missing features cause you to stop today?" (Options: Performance, Features, Other).
3.  **Decision Threshold:**
    *   If latency correlation > 0.6: Roll back the layering update for power users immediately (canary release).
    *   If latency correlation < 0.2 and competitor mentions > 40%: Initiate a feature gap analysis against the suspected competitor.

**Note:** All metrics must be derived from PixelPerfect's internal logs; no external benchmarks are applied. If session logs lack precise timestamps for layer actions, the latency hypothesis remains `UNVERIFIED` until instrumentation is updated.
