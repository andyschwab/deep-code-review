### Tracking Schema Audit and Consolidation Plan

**Objective:** Reduce event volume by 30% and storage costs while ensuring 100% compliance with UK healthcare regulations (including 7-year retention mandates) by December 1.

#### Phase 1: Legal & Compliance Baseline (Days 1–5)
*Action:* Before touching technical logs, define the "Must-Keep" list.
1.  **Regulatory Mapping:** Collaborate with Legal to list every data point legally required for 7-year retention (e.g., specific audit trails for record access, consent changes, clinical modifications).
2.  **Definition Lock:** Create a single source of truth for core actions ('patient login', 'record view'). Document the exact property set required for each to satisfy compliance.
3.  **Output:** A "Protected Events Registry" listing event names and properties that cannot be archived or altered without legal sign-off.

#### Phase 2: Usage & Value Audit (Days 6–15)
*Action:* Identify what is actually used versus what is noise.
1.  **Stakeholder Interrogation:** Survey compliance, clinical, and product teams. For every reported dashboard or alert, map it back to the specific source events.
2.  **The "Named Question" Test:** For the remaining ~300 unmapped events, ask: "What specific business or clinical question does this answer?"
    *   If no named question exists: Mark as **Candidate for Archive**.
    *   If the question is valid but the event is duplicated across legacy systems: Mark as **Candidate for Consolidation**.
3.  **Traffic Analysis:** Query the last 90 days of logs. Flag events with zero or near-zero volume as **Immediate Archive Candidates**.

#### Phase 3: Consolidation Strategy (Days 16–25)
*Action:* Design the new, lean schema.
1.  **Merge Duplicates:** Map conflicting legacy definitions (e.g., `login_v1` vs `user_auth`) to the single standard defined in Phase 1.
2.  **Deprecation Plan:** Create a list of events to stop instrumenting immediately.
3.  **Archiving Protocol:** Define the technical process to move "Candidate for Archive" data to cold storage (ensuring it remains accessible for the 7-year mandate but stops incurring hot storage costs).
4.  **Output:** A "Target Schema" document showing the reduced event list, new standard definitions, and the mapping from old to new.

#### Phase 4: Validation & Execution (Days 26–30)
*Action:* Verify safety before cutting costs.
1.  **Parallel Run:** Instrument the new "Target Schema" alongside legacy systems for 7 days. Verify that critical compliance reports generate identical results.
2.  **Sign-off:** Present the "Target Schema" and "Archiving Protocol" to the Chief Compliance Officer and IT Director.
3.  **Cut-over:** Once signed off, disable logging for deprecated events and migrate historical data to cold storage.

#### Decision Matrix for Event Handling
| Event Category | Action | Retention Policy |
| :--- | :--- | :--- |
| **Legally Required** (Protected Registry) | Keep & Standardize | 7 Years (Hot/Cold as per access needs) |
| **Active Business Value** (Named Question) | Keep & Consolidate | Standard Product Lifecycle |
| **Unused / No Named Question** | Stop Logging | Archive existing data, then delete |
| **Duplicate / Conflicting** | Merge to Standard | Migrate history to new standard ID |
