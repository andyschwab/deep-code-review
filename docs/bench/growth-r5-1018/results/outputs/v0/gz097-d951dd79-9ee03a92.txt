# Pilot Success Criteria Proposal: GlobalManufacturing Inc.
**Prepared for:** Jessica Alverez, Account Executive
**Review Date:** Next Tuesday (with Chief Legal Officer)
**Pilot Window:** April 1 – June 29 (90 Days)

## 1. The North Star: Value-Adjusted Cycle Time
Reject "average approval time" as a standalone North Star; it is a vanity metric that rises even if legal risk increases. Instead, adopt **Value-Adjusted Cycle Time**: the average time to approve contracts *that pass all compliance checks without manual rework*. This aligns speed with the Legal team's likely priority on risk mitigation.

*   **Input Metrics:**
    *   **Activation Rate:** % of pilot users who execute at least one contract workflow in Week 1.
    *   **Rework Rate:** % of contracts returned for correction due to system-extracted clause errors.
    *   **Zero-Error Compliance:** % of contracts with 100% accurate clause extraction (critical if the CLO prioritizes risk).

## 2. Baseline & Target Framework (Addressing Data Gaps)
Since historical baseline data is missing, we cannot assert a "14-day to 7-day" improvement as a verified fact. We must establish the baseline *during* the pilot's first 14 days using a parallel tracking method.

*   **Phase 1: Baseline Discovery (April 1 – April 14)**
    *   **Action:** Run the new tool alongside the existing manual process for a control group (or track the "time spent" manually logged by users before adoption).
    *   **Metric:** Record the actual "Time-to-Approval" and "Error Rate" of the *current* manual process for the specific contract types in scope.
    *   **Outcome:** Replace the assumed "14 days" with the **Verified Manual Baseline**. If the manual average is actually 5 days, the 7-day target is a failure, not a win.

*   **Phase 2: Target Validation (April 15 onwards)**
    *   **Primary Target:** Reduce *Value-Adjusted Cycle Time* by 40% compared to the **Verified Manual Baseline**.
    *   **Guardrail Metric:** Maintain a **Clause Extraction Error Rate < 1%**. If speed increases but errors exceed 1%, the pilot is a failure regardless of time saved. This directly addresses the CLO's potential preference for risk mitigation over speed.

## 3. Event Taxonomy (Instrument Only What Answers a Question)
Do not instrument "everything." Track only these three events to answer specific pilot questions:

1.  `contract_submitted` (Properties: `contract_type`, `user_role`)
    *   *Question:* Are users activating the core workflow?
2.  `clause_extraction_completed` (Properties: `confidence_score`, `manual_override_required`)
    *   *Question:* Is the system accurate enough to trust, or is legal rework negating speed gains?
3.  `contract_fully_approved` (Properties: `total_duration_hours`, `rework_cycles`)
    *   *Question:* Did we achieve value-adjusted speed?

## 4. Decision Rules for the 90-Day Pilot
*   **Ship (Expand):** If *Value-Adjusted Cycle Time* improves by >30% AND *Error Rate* remains <1% by Day 60.
*   **Extend:** If activation is low (<40% of pilot users) but error rates are excellent. Extend by 30 days to drive adoption before judging speed.
*   **Stop/Pivot:** If *Error Rate* exceeds 2% at any point. Speed is irrelevant if risk is unmanaged; pivot to tuning extraction models before measuring time.

2.  **Configure Guardrails:** Set the analytics dashboard to flag any day where `clause_extraction_completed` shows an error rate >1%.
3.  **Align with CLO:** Present the "Value-Adjusted" definition to confirm that "speed with errors" is unacceptable, ensuring the guardrail matches their risk tolerance.

*Note: All metrics are `UNVERIFIED` until the Phase 1 baseline is recorded; do not compare against the assumed 14-day figure.*
