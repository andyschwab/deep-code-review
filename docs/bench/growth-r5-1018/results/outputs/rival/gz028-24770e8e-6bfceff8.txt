# Analysis Plan: Mortgage Application Upload Friction

**Objective:** Isolate causes of leakage in the document upload step to inform experiments targeting a 10% increase in pre-approval conversion by year-end.

**Current State:** 10,000 application starts; 850 pre-approvals (8.5% overall conversion). Suspected friction: PDF tax return upload.

## Phase 1: Quantitative Funnel Diagnostics (Week 1)
*Goal: Pinpoint exactly where and how users drop off.*

1.  **Micro-Funnel Mapping:** Break the "upload step" into discrete events:
    *   `upload_viewed` (User lands on upload screen)
    *   `file_selector_triggered` (User clicks "Choose File")
    *   `file_selected` (File chosen from OS)
    *   `upload_started` (Progress bar appears)
    *   `upload_completed` (Success state reached)
    *   `upload_error_displayed` (Error message shown)
2.  **Error Code Segmentation:** Tag all `upload_error_displayed` events with specific error types:
    *   `error_file_too_large`
    *   `error_invalid_format`
    *   `error_timeout`
    *   `error_unknown`
3.  **Drop-off Rate Calculation:** Compute conversion rates between each micro-step. Identify the single largest drop-off point (e.g., if 60% click "Choose File" but only 20% trigger `upload_started`, the friction is pre-upload).

## Phase 2: Qualitative Context Gathering (Week 2)
*Goal: Understand the "why" behind the numbers.*

1.  **Session Replay Analysis:** Review 50–100 session recordings of users who triggered `upload_viewed` but did not complete `upload_completed`. Look for:
    *   Rage clicks or repeated attempts.
    *   Time spent searching for documents (idle time).
    *   Tab switching away from the application (indicating missing docs).
2.  **Exit Survey Trigger:** Implement a one-question intercept survey triggered on exit intent from the upload page:
    *   *"What stopped you from continuing?"* (Options: "Can't find docs," "File too big," "Too complicated," "Other")
3.  **Support Ticket Audit:** Review Q3 support tickets tagged "upload" or "document" for recurring themes (e.g., "How do I compress PDF?").

## Phase 3: Hypothesis Validation & Experiment Design (Week 3)
*Goal: Translate findings into testable hypotheses.*

Based on data, prioritize one of these paths:

*   **Hypothesis A (Technical Friction):** If >40% of drop-offs occur after `file_selected` with `error_file_too_large` or `error_invalid_format`:
    *   *Experiment:* Implement client-side file compression, clearer format instructions, and real-time validation before upload starts.
*   **Hypothesis B (Preparation Friction):** If session replays show long idle times or exit surveys cite "Can't find docs":
    *   *Experiment:* Add a "Prepare your documents" checklist before the upload step, or allow users to save progress and email themselves a reminder link.
*   **Hypothesis C (UI Complexity):** If drop-off occurs before `file_selector_triggered`:
    *   *Experiment:* Simplify the interface to a single drag-and-drop zone with progressive disclosure of requirements.

## Success Metrics
*   **Primary:** Upload step completion rate (target: +15% relative lift to drive overall +10% pre-approval lift).
*   **Guardrail:** Support ticket volume related to uploads (should decrease).
*   **Secondary:** Average time-to-complete for the upload step.

## Deliverable Timeline
*   **Nov 1:** Data instrumentation complete.
*   **Nov 8:** Diagnostic report and hypothesis presentation.
*   **Nov 15:** First A/B test launched.
