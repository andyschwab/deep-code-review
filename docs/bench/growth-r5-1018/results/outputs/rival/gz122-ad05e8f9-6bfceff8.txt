# NewsNile Social Feed Tracking Plan

**Objective:** Determine if the social feed increases engagement (session time) without cannibalizing core retention (push CTR) or creating low-value noise.

**Implementation Deadline:** September 28th
**Launch Date:** October 5th
**Decision Date:** Early November

## 1. Core Social Events (Priority: Critical)
Track these to measure adoption and distinguish "community" from "noise."

| Event Name | Properties | Why It Matters |
| :--- | :--- | :--- |
| `social_feed_viewed` | `entry_point` (tab, deep_link), `session_id` | Measures baseline adoption. |
| `article_comment_submitted` | `article_id`, `comment_length`, `is_reply` (bool) | **Community Signal.** High volume of replies indicates discussion, not just noise. |
| `article_shared` | `article_id`, `share_destination` (whatsapp, facebook, copy_link) | Validates viral potential. |
| `social_interaction_click` | `interaction_type` (like, reply, share), `article_id` | Measures passive vs. active engagement. |
| `scroll_depth_social` | `percentage` (25, 50, 75, 100), `feed_type` | Distinguishes scrolling "noise" from reading intent. |

## 2. Guardrail & Cannibalization Metrics (Priority: High)
Track these to ensure the new feature doesn't hurt existing revenue/retention drivers.

| Event Name | Properties | Why It Matters |
| :--- | :--- | :--- |
| `push_notification_clicked` | `campaign_id`, `destination` (article, social_feed) | **Cannibalization Check.** Monitor if the global 8% CTR drops post-launch. |
| `article_read_started` | `source` (push, social_feed, home_list), `article_id` | Isolates if social feed drives reads or replaces push-driven reads. |
| `session_ended` | `duration`, `primary_action` (read, comment, scroll) | Validates the 20% session time hypothesis. |

## 3. User Context Properties (Attach to All Events)
Ensure every event includes these user-level properties to segment analysis:
*   `user_segment`: `heavy_reader` (reads ≥3 articles/day) vs. `casual`.
*   `app_version`: To filter pre/post-launch data cleanly.
*   `days_since_install`: To control for new user behavior spikes.

## Isolation Strategy: How to Measure Impact
To isolate the social feed's impact from regular content updates for the November board decision:

1.  **Cohort Analysis (Time-Based):** Compare users who installed/activated *before* Oct 5 (Control) vs. *after* Oct 5 (Treatment). Do not compare day-over-day globally, as news cycles vary.
2.  **Source Attribution:** Tag every `article_read_started` with its `source`. If `source=social_feed` increases but `source=push` decreases proportionally, you have cannibalization. If total reads increase, you have growth.
3.  **Quality Ratio:** Calculate `(Comments + Shares) / Scroll Depth`. A high scroll depth with near-zero interactions indicates "noise." A balanced ratio indicates "community."
4.  **Heavy Reader Segmentation:** Specifically monitor the 40% of users who currently read ≥3 articles. If their push CTR drops significantly while their session time rises only marginally, the feature may be degrading core utility for your best users.

## Recommended Go/No-Go Criteria for Board
*   **GO:** Session time +15% AND Push CTR remains >7.2% (max 10% drop) AND Comment/Share ratio > 2%.
*   **NO-GO:** Push CTR drops >20% OR Session time increases <5% (indicating noise without retention).

Ensure the Alexandria team implements these events with strict naming conventions (lowercase, underscores) before the September 28th freeze. Validate data flow in GA4 DebugView immediately upon staging deployment.

*Note: Ensure no PII (user names, comment text) is sent in event properties to comply with privacy standards.*
*Recommendation: Set up a specific "Social Feed" conversion event in GA4 immediately upon launch to monitor daily trends.*
