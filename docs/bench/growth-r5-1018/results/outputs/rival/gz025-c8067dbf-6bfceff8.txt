# Post-Merger Tracking Audit & Consolidation Plan

**Objective:** Reduce event volume by 30% and storage costs while ensuring 100% compliance with UK healthcare regulations (UK GDPR, Data Protection Act 2018, NHS Data Security Standards).

### Phase 1: Legal & Compliance Baseline (Days 1–5)
*Goal: Define the "Must-Keep" list before touching technical infrastructure.*
1.  **Engage Legal/Compliance:** Convene a workshop with the Chief Compliance Officer to explicitly list data points required for the 7-year retention mandate. Focus on clinical safety logs, patient consent records, and audit trails for data access.
2.  **Map Regulations to Events:** Create a mapping document linking specific regulatory requirements to current event names. Any event not mapped to a legal requirement, active business decision, or clinical safety need is flagged as "Candidate for Archive."
3.  **Define Retention Tiers:** Establish three categories:
    *   **Tier 1 (Legal/Safety):** Retain raw data for 7+ years.
    *   **Tier 2 (Operational):** Retain aggregated data for 2 years; raw data for 90 days.
    *   **Tier 3 (Obsolete):** Safe to delete or archive immediately.

### Phase 2: Technical Inventory & Usage Analysis (Days 6–15)
*Goal: Identify what is actually firing and who is using it.*
1.  **Export Full Schema:** Extract all 400+ event names from both legacy systems (HealthRecord UK and MediData) including properties, triggers, and volume data from the last 12 months.
2.  **Usage Frequency Audit:** Query event logs to identify:
    *   **Zero-Low Volume:** Events with <10 occurrences in the last 90 days.
    *   **Duplicate Definitions:** Compare "patient login" variants across systems to identify conflicting schemas.
3.  **Stakeholder Survey:** Distribute a usage survey to Clinical, Product, and Analytics teams. Ask: "Which of these 50 high-volume events do you actively use in dashboards or reports?" Set a hard deadline for response; lack of response indicates low value.

### Phase 3: Consolidation & Standardization (Days 16–25)
*Goal: Merge duplicates and define the new single source of truth.*
1.  **Resolve Conflicts:** For conflicting core actions (e.g., "patient login"), select the most robust definition (usually the one capturing the most context) and deprecate the others.
2.  **Draft New Naming Convention:** Adopt a consistent `object_action` format (e.g., `patient_login_success`, `record_view_clinical`).
3.  **Create the "Golden Schema":** Document the final list of ~160 approved events. Explicitly mark deprecated events and their migration path (e.g., "Map `old_login` to `patient_login_success`").

### Phase 4: Implementation & Validation (Days 26–30)
*Goal: Execute the cleanup without data loss.*
1.  **Archive Obsolete Data:** Move Tier 3 data to cold storage or delete per legal approval.
2.  **Deploy Tracking Plan:** Update Google Tag Manager/analytics tools with the new Golden Schema.
3.  **Parallel Run:** Run old and new tracking simultaneously for 7 days to validate data integrity.
4.  **Final Sign-off:** Present the reduced schema, cost savings projection, and compliance certification to the IT Director and CCO.

### Deliverable for December 1 Presentation
Prepare a single executive summary containing:
*   The "Golden Schema" list of approved events.
*   A risk matrix showing how each retained event satisfies specific UK regulatory clauses.
*   Projected storage cost reduction (targeting 30%).
*   Timeline for full migration completion.

*Note: Do not delete any event logs until written confirmation is received from Legal regarding the 7-year retention scope. Prioritize clinical safety audit trails above all cost-saving measures.*
