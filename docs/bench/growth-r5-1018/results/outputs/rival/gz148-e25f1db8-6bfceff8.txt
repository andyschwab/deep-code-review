### Investigation Plan: Balancing Checkout Speed and Revenue

To determine if the UI update sacrificed revenue for speed, you must isolate *where* users bypass value-add opportunities. Do not rely on aggregate completion rates alone. Implement the following specific metrics and analysis framework immediately.

#### 1. Core Funnel Metrics to Measure
Break the new 4-step flow into micro-conversions. Compare pre-launch (Jan 1–19) vs. post-launch (Jan 20–Present) data for:

*   **Add-On Interaction Rate:** Percentage of users who click *any* add-on suggestion (e.g., "Frequently bought together," "Premium fruits").
    *   *Hypothesis:* This has likely plummeted. If users skip this entirely, the placement is now invisible or too fleeting.
*   **Coupon Application Rate:** Percentage of sessions where a coupon code is entered or a promo is clicked.
    *   *Context:* A drop here suggests users are no longer pausing to seek savings, implying a "rush" mentality.
*   **Cart Review Dwell Time:** Average time (in seconds) spent on the "Order Summary" step before clicking "Place Order."
    *   *Threshold:* If this drops below 3–5 seconds, users are blindly confirming without reviewing contents or offers.
*   **Scroll Depth on Summary Page:** Percentage of users who scroll to the bottom of the summary page (where add-ons are likely now positioned).
    *   *Action:* If <60% scroll to the add-on section, the new 4-click flow has pushed value items below the fold effectively hiding them.

#### 2. Behavioral Segments to Analyze
Do not analyze all users together. Segment the post-launch data by:

*   **Device Type:** Mobile users are more prone to "fat finger" rushing. If AOV dropped significantly more on mobile than desktop, the new UI may be too aggressive for small screens.
*   **User Tenure:** Compare "First-time users" vs. "Repeat customers." Repeat users know what they want; if *their* AOV dropped, the UI is actively blocking upsells rather than just streamlining new user friction.
*   **Basket Size:** Segment by initial cart value (e.g., <₹400 vs. >₹800). High-value baskets should have higher add-on attachment; if this correlation has broken, the suggestion logic is failing.

#### 3. How to Read the Data for Decision Making
Use this matrix to recommend action to the Operations Head:

| Scenario | Diagnosis | Recommendation |
| :--- | :--- | :--- |
| **High Completion (+), Low Dwell Time, Low Add-On Clicks** | Users are rushing; UI hides upsells. | **Tweak:** Re-introduce a mandatory "pause" or modal for add-ons before the final click. Do not revert. |
| **High Completion (+), Stable Dwell Time, Low Add-On Clicks** | Users see the page but ignore offers. | **Tweak:** Change add-on creative/copy. The placement is visible but unappealing. |
| **High Completion (+), Low Scroll Depth** | Add-ons are physically hidden below the fold. | **Tweak:** Move add-ons higher in the flow or use a sticky bottom sheet. |
| **High Completion (+), AOV Drop concentrated in Repeat Users** | Loyalty behavior disrupted. | **Tweak:** Create a "Express Re-order" path for loyalists, keep standard flow for others. |

#### 4. Immediate Next Steps
1.  **Calculate the Revenue Net:** Multiply the increase in volume (from 35% to 48% completion) by the new AOV (₹520). Compare this total revenue against the pre-launch total. If total revenue is *higher* despite lower AOV, the trade-off is successful, and you only need to optimize add-on placement, not revert.
2.  **Heatmap Verification:** If possible, overlay heatmaps on the new "Summary" step to confirm if users are physically seeing the add-on section or skipping it due to banner blindness.
3.  **A/B Test a "Friction" Variant:** Create a variant that adds *one* click back specifically for viewing add-ons. Test if this recovers AOV without significantly hurting the new 48% completion rate.

**Note:** Prioritize the "Revenue Net" calculation first; if total revenue is up, the goal shifts from "fixing a problem" to "optimizing margin." Ensure all date ranges exclude January 20 itself to avoid deployment-day anomalies.
