# Diagnostic Analysis Plan: Data Science Basics Track (Module 3)

**Objective:** Isolate the specific friction point causing the 76% attrition between enrollment (5,000) and final project submission (1,200) in Module 3.

**Primary Hypothesis:** Learners drop off due to local environment setup complexity before attempting the coding exercise.

## 1. Critical Events to Analyze

Query your analytics platform (e.g., Mixpanel, Amplitude, or custom logs) for the following events, filtered by `course_id: data-science-basics` and `module_id: 03`.

### A. Content Consumption (Video Engagement)
*   **Event:** `video_started`, `video_completed`, `video_paused`
*   **Key Properties:** `video_title`, `timestamp`, `percent_watched`
*   **Diagnostic Goal:** Determine if users skip the "Environment Setup" tutorial entirely or pause repeatedly at specific technical steps.
*   **Success Signal:** High completion rate on setup videos correlates with higher exercise attempts.

### B. Exercise Interaction (The Bottleneck)
*   **Event:** `exercise_viewed`, `code_editor_opened`, `code_submission_attempted`
*   **Key Properties:** `attempt_number`, `time_since_module_start`
*   **Diagnostic Goal:** Distinguish between users who never open the editor vs. those who try and fail.
*   **Success Signal:** If `exercise_viewed` is high but `code_editor_opened` is low, the barrier is psychological or instructional. If `code_editor_opened` is high but `code_submission_attempted` is low, the barrier is technical.

### C. Technical Failure & Errors
*   **Event:** `automated_test_failed`, `sandbox_error_logged`, `environment_setup_failed`
*   **Key Properties:** `error_code`, `error_message`, `os_type`, `browser`
*   **Diagnostic Goal:** Quantify the frequency of specific setup errors (e.g., "Python not found," "Dependency conflict").
*   **Success Signal:** A spike in `environment_setup_failed` immediately after `code_editor_opened` confirms the hypothesis.

### D. Support & Search Behavior
*   **Event:** `forum_search_executed`, `help_article_viewed`, `support_ticket_created`
*   **Key Properties:** `search_query`, `article_title`, `ticket_category`
*   **Diagnostic Goal:** Identify qualitative friction points via search terms (e.g., "install pandas error," "localhost not working").
*   **Success Signal:** High volume of searches containing "setup," "install," or "error" within 24 hours of starting Module 3.

## 2. Funnel Construction

Build a conversion funnel to visualize the drop-off:

1.  **Module 3 Started** (Baseline)
2.  **Setup Video Completed** (Did they watch the guide?)
3.  **Code Editor Opened** (Did they try to start?)
4.  **First Code Submission Attempted** (Did they run the code?)
5.  **Automated Tests Passed** (Did they succeed?)
6.  **Module 3 Completed**

**Analysis Logic:**
*   **Drop-off between Steps 1 & 2:** Instructional design issue (video is boring/confusing).
*   **Drop-off between Steps 2 & 3:** Setup complexity barrier (users watch but are afraid/unable to configure).
*   **Drop-off between Steps 3 & 4:** Technical environment failure (users try but encounter errors).
*   **Drop-off between Steps 4 & 5:** Exercise difficulty (users run code but fail logic tests).

## 3. Segmentation Requirements

Slice all data by:
*   **Device/OS:** Windows vs. Mac vs. Linux (Setup issues often vary by OS).
*   **Technical Background:** Self-reported skill level during signup (if available).
*   **Time of Day:** Correlate drop-offs with support availability.

## 4. Recommended Immediate Actions

1.  **Instrument Missing Events:** If `environment_setup_failed` or `code_editor_opened` are not currently tracked, deploy these immediately via your engineering lead.
2.  **Error Log Aggregation:** Create a dashboard grouping `sandbox_error_logged` by `error_message` to identify the top 3 blocking issues.
3.  **Qualitative Review:** Sample 20 `forum_search_executed` events with queries containing "error" to read exact user phrasing.

**Deliverable Timeline:** Complete data extraction and funnel visualization within 48 hours to inform the next content sprint.

*Note: Ensure all event timestamps align with the March 1st launch date to exclude legacy cohort data. Do not include users who enrolled but never accessed Module 3 in this specific friction analysis.*
