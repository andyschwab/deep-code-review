# CloudBridge Developer Week Launch: Proposed Conversion Funnel

**Prepared for:** Elena Rodriguez, Growth Lead
**Event:** Developer Week (Oct 10–12) | **Target:** 5,000 Registered Developers

## 1. The Conversion Funnel Structure

To identify drop-off points between identity verification and project creation, we propose a five-stage linear funnel. Each stage represents a critical milestone for successful onboarding.

| Stage | Name | Definition (Trigger) | Key Metric |
| :--- | :--- | :--- | :|
| **1** | **Event Registration** | User completes sign-up for Developer Week. | `event_registered` |
| **2** | **Keynote Engagement** | User watches ≥10 mins of the keynote stream. | `keynote_watched` |
| **3** | **API Sign-Up Initiated** | User clicks "Get API Key" from blog or stream. | `signup_started` |
| **4** | **Identity Verified** | User successfully passes ID verification check. | `identity_verified` |
| **5** | **Project Created** | User creates their first project environment. | `project_created` |

**Primary Conversion Goal:** `event_registered` → `project_created`
**Critical Drop-off Analysis:** Compare conversion rates between Stage 3→4 (Verification) and Stage 4→5 (Project Creation) to isolate the friction point.

## 2. Hypothesis Tracking: Keynote Impact

To validate the assumption that keynote viewers are 3x more likely to convert, we must tag the entry source and engagement status on every downstream event.

*   **Segment A (Keynote Viewers):** Users who triggered `keynote_watched`.
*   **Segment B (Blog Only):** Users who triggered `signup_started` with `source=blog` and did *not* trigger `keynote_watched`.

**Success Criteria:**
`(Conv Rate Segment A) / (Conv Rate Segment B) ≥ 3.0`

## 3. Essential Event Properties

To enable real-time segmentation and debugging during the event, the following properties must be attached to every event:

*   **User Context:** `user_id`, `registration_date`, `developer_type` (e.g., student, enterprise).
*   **Attribution:** `entry_source` (keynote_link, blog_post, email), `utm_campaign` (dev-week-2023).
*   **Technical Context:** `browser`, `os`, `error_code` (specifically for Stage 4 failures).
*   **Timing:** `session_duration`, `time_to_verify` (seconds between Stage 3 and 4).

## 4. Real-Time Reporting Dashboard

For the executive steering committee, the dashboard should display:

1.  **Funnel Visualization:** A live bar chart showing counts for Stages 1–5, updated every 15 minutes.
2.  **Drop-off Heatmap:** Percentage loss between each adjacent stage, highlighting the largest friction point in red.
3.  **Cohort Comparison:** Side-by-side conversion rates for "Keynote Viewers" vs. "Blog Readers."
4.  **Velocity Metric:** Average time elapsed from Registration (Stage 1) to Project Creation (Stage 5).

## 5. Immediate Implementation Steps

1.  **Instrumentation:** Deploy tracking tags for the five specific events listed above before October 10th.
2.  **Validation:** Run end-to-end tests on the `identity_verified` trigger to ensure false negatives (failed verifications) are logged with specific `error_code` properties.
3.  **Dashboard Setup:** Configure the real-time view to filter by `utm_campaign=dev-week-2023` to exclude non-event traffic.

This structure isolates the specific friction point (Verification vs. Project Creation) and provides the data necessary to validate the keynote engagement hypothesis immediately upon launch.

*Note: Ensure "Identity Verified" events fire only upon successful completion to avoid inflating Stage 4 numbers with attempted but failed verifications.*
*Recommendation: Add a "Support Contacted" event post-Stage 4 to capture users who drop off after verification due to confusion rather than technical failure.*
