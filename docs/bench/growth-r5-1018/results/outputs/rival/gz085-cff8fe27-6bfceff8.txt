# SalesFlow Proposal Customization Dashboard Plan

## Recommended Tracking Strategy
Track **both** granular interactions and final outcomes. Tracking only the save action hides *where* reps struggle; tracking every click creates noise. Use an "Intent-Action-Outcome" model:

### 1. Critical Events to Track (Real-Time)
| Event Name | Properties | Why It Matters |
|------------|------------|----------------|
| `pricing_editor_opened` | proposal_id, rep_id, template_type | Measures adoption of the new module |
| `pricing_line_item_added` | item_type, position | Shows active customization vs. minor tweaks |
| `pricing_line_item_deleted` | item_type | Indicates uncertainty or correction |
| `pricing_discount_applied` | discount_percent, approval_status | High-friction moment; often requires manager input |
| `editor_session_abandoned` | time_spent, last_action, step_reached | **Key coaching signal**: Identifies exactly where reps quit |
| `proposal_saved` | customization_level (none/light/heavy), time_to_complete | Correlates effort with your 20% velocity hypothesis |
| `proposal_sent` | time_from_save, customization_level | Final outcome for velocity calculation |

### 2. Dashboard Metrics for Weekly Reviews
Display these four panels for Regional Directors:

**Panel A: Adoption & Friction**
- % of proposals using custom pricing (Target: >40% by May)
- Average abandonment rate by step (e.g., "30% drop off at discount application")
- Top 3 exit points in the editor

**Panel B: Velocity Correlation**
- Avg. days to close: Customized vs. Default (Validate the 20% assumption)
- Avg. time spent in editor per deal size tier

**Panel C: Rep Performance Matrix**
- X-axis: Customization frequency
- Y-axis: Deal velocity
- *Quadrant Insight*: Identify reps who customize often but move slowly (need training) vs. those who don't customize but move fast (maybe don't need it).

**Panel D: Intervention Queue**
- List of deals where `editor_session_abandoned` occurred in the last 48 hours
- Action: Director clicks to view session replay or contact rep

### 3. Implementation Logic
- **Do not track** every mouse movement or keystroke.
- **Do track** state changes (add/remove/edit) and timestamp deltas between them.
- **Define "Abandonment"**: No activity for >5 minutes after opening the editor, without a `proposal_saved` event.
- **Define "Customization Level"**:
  - *None*: 0 line item changes
  - *Light*: 1-2 changes
  - *Heavy*: 3+ changes or discount applied

### 4. Coaching Workflow
1. **Monday Morning**: Director reviews "Intervention Queue" for stalled deals from last week.
2. **Weekly Review**: Analyze "Rep Performance Matrix."
   - *High Customization / Low Velocity*: Coach on efficiency or pricing confidence.
   - *Low Customization / Low Velocity*: Coach on value articulation using the tool.
3. **Hypothesis Validation**: After 30 days, compare close rates. If customized deals aren't closing 20% faster, the issue may be *how* they are customizing, not *if*.

This approach gives you the granular "where" for coaching without drowning managers in click-stream data.

*Note: Ensure PII (client names) is masked in the real-time view if accessed by non-account owners. Validate that your definition of "deal closed" in the CRM aligns with the timestamp used for velocity calculations.*
