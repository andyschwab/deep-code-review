### Diagnostic Data Plan (Sprint 1)

To distinguish between technical friction and content confusion, implement the following event tracking immediately on your web portal. Do not wait for support tickets; passive data is too slow for a November 2nd deadline.

**1. Granular Funnel Events**
Break the "Legal Review" step into micro-events to pinpoint the exact stall point:
*   `legal_section_viewed`: Triggered when the user scrolls to the terms.
*   `plugin_prompt_displayed`: Fired only if the browser detects a missing plugin or the signature canvas fails to load.
*   `signature_attempt_started`: User clicks/touches the signature box.
*   `signature_attempt_failed`: User triggers an error state or closes the modal without saving.
*   `form_abandonment`: Triggered on page unload, capturing `time_on_step` and `last_interaction`.

**2. Technical Context Properties**
Attach these properties to every event above to validate your plugin hypothesis without relying on support tickets:
*   `browser_name` & `browser_version` (e.g., "Safari 16.0")
*   `device_type` (Desktop/Mobile/Tablet)
*   `os_name` (Windows/macOS/iOS)
*   `plugin_status`: (Boolean: true if detected, false if missing)
*   `error_code`: Specific JS error message if the signature field fails to initialize.

**3. Behavioral Metrics**
*   **Rage Clicks:** Count rapid clicks on the signature area (indicates unresponsiveness).
*   **Copy/Paste Events:** Detect if users are trying to copy terms elsewhere (indicates confusion or desire to review offline).

### Experiment Structure: "Friction vs. Clarity" Test

Run an A/B test starting immediately to isolate the variable. Given your volume (~70 clients/month), run this for 3 weeks to gather sufficient data before Cian's presentation.

**Hypothesis:** Because users abandon at the signature step, we believe removing the browser-plugin dependency (switching to a native HTML5 canvas or click-to-sign) will increase completion rates from 64% to >85% by eliminating technical barriers.

**Variants:**
*   **Control (A):** Current workflow with plugin requirement.
*   **Variant B (Technical Fix):** Replace plugin with a native, mobile-friendly click-to-sign or simple typed-name field that requires no installation. Keep legal terms identical.
*   **Variant C (Clarity Fix - Optional if traffic allows):** Keep the plugin but add a progressive disclosure summary ("Key Terms: Liability, Duration, Cost") above the signature field to reduce cognitive load.

**Metrics:**
*   **Primary:** `contract_completed` rate (Visitors who reach the "Success" page).
*   **Secondary:** Average time spent on "Legal Review" step.
*   **Guardrail:** Support ticket volume related to "signature issues."

**Success Criteria:**
Statistically significant increase in completion rate (p < 0.05). If Variant B wins, the issue was technical. If both variants fail to improve significantly against the control, the issue is likely legal term confusion, requiring a content audit rather than a UI fix.

**Implementation Note:** Ensure your analytics tool captures the `plugin_status` property on the Control group to quantify exactly how many users lack the required software.

**Timeline:** Deploy tracking by end of week; launch test early next week to secure 3 weeks of data before November 2nd.
