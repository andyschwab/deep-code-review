# Errata (recorded 2026-10-17, after review; PREREGISTERED-CHOICE.md is left unedited because its hash is frozen in SHA256-choice.txt)

1. The tune table in PREREGISTERED-CHOICE.md does not match the committed results files. From `results4-idea-critic-PERUN_*-tune.json`: v0 0.55 [0.35, 0.75], cA 0.60 [0.50, 0.75], cB 0.55 [0.40, 0.70], cC 0.50 [0.30, 0.70]. The preregistered rule (highest tune win rate) still selects cA, but by one scenario over v0 and cB.
2. The claim that every tune judge record is complete is false. Tune scenarios 01, 02 and 03 lost every order for all three judges in all four arms (12 records, 36 votes, `judge4/idea-critic/PERUN_*/0[1-3].json`) to network errors logged in `ledger.jsonl`, so each counts as a forced tie. The tune selector therefore rests on 7 scenarios. The held-out records are all complete, so the held-out result is unaffected.
3. The cA h10 held-out record was re-judged because one order was missing after the driver's retry. The ledger shows no request error on its first-pass calls and a second GLM-5.2 call, which fits judge output that could not be parsed twice rather than a failed request. The deleted original is not preserved. The criterion applied was "a held-out record with a missing order is re-judged once"; v0 h19 also has a retried GLM-5.2 call, but its retry parsed, so it had no missing order and was not re-run. Effect on cA is at most 0.0125, and cA is reverted.
