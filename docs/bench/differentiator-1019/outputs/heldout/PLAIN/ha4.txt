To call the `optimize_tier_prices` endpoint in the OpenTariff REST API, you must send a `POST` request to the specific resource URL. This endpoint typically analyzes current usage patterns and suggests optimal pricing tiers to minimize costs.

### Authentication
OpenTariff uses standard Bearer Token authentication. You must include an `Authorization` header containing a valid JWT (JSON Web Token) obtained from the `/auth/login` or `/auth/token` endpoint. Without this header, the API will return a `401 Unauthorized` error.

### Request Example
Below is a `curl` example demonstrating how to structure the request. Replace `<YOUR_API_TOKEN>` with your actual token and `<ACCOUNT_ID>` with your specific account identifier.

```bash
curl -X POST "https://api.opentariff.io/v1/accounts/<ACCOUNT_ID>/optimize_tier_prices" \
  -H "Authorization: Bearer <YOUR_API_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "analysis_period": "last_90_days",
    "include_forecasting": true
  }'
```

**Key Request Components:**
*   **Method**: `POST`
*   **URL**: `/v1/accounts/{account_id}/optimize_tier_prices`
*   **Headers**:
    *   `Authorization`: Required. Format is `Bearer <token>`.
    *   `Content-Type`: Required. Must be `application/json`.
*   **Body**: Optional JSON payload allowing you to specify the time range for analysis or enable predictive forecasting.

### Response Fields
Upon a successful request (`200 OK`), the API returns a JSON object containing the optimization results. The primary fields in the response include:

1.  **`current_cost`**: (Float) The total cost incurred under the existing pricing tier during the analyzed period.
2.  **`projected_cost`**: (Float) The estimated cost if the recommended tier changes are applied.
3.  **`savings_amount`**: (Float) The absolute monetary difference between current and projected costs.
4.  **`savings_percentage`**: (Float) The percentage reduction in cost.
5.  **`recommendations`**: (Array) A list of specific actions. Each object in this array typically contains:
    *   `service_id`: The identifier of the service to modify.
    *   `current_tier`: The name of the existing pricing tier.
    *   `recommended_tier`: The suggested new pricing tier.
    *   `break_even_months`: The estimated time required for the savings to offset any migration fees.
6.  **`confidence_score`**: (Float) A value between 0.0 and 1.0 indicating the statistical confidence of the projection based on historical data stability.
7.  **`generated_at`**: (ISO 8601 Timestamp) The exact time the optimization report was created.

If the analysis cannot be performed due to insufficient data, the API may return a `422 Unprocessable Entity` with an error message detailing the missing information. Always ensure your account has at least one billing cycle of historical data before calling this endpoint.
