### Endpoint Documentation: `GET /api/v1/willingness-to-pay`

**Service:** Orchardpay
**Method:** GET
**Description:** Retrieves the calculated willingness-to-pay (WTP) score for a specific customer or transaction context. This metric helps merchants optimize pricing strategies by estimating the maximum price a customer is likely to accept based on historical behavior and market data.

#### Query Parameters

The following parameters must be included in the query string of the request URL:

| Parameter | Type | Required | Description |
| :--- | :--- | :--- | : |
| `customer_id` | String | Yes | The unique identifier assigned to the customer within the Orchardpay system. |
| `product_id` | String | Yes | The SKU or unique identifier of the product being evaluated. |
| `currency` | String | No | The three-letter ISO 4217 currency code (e.g., `USD`, `EUR`). Defaults to `USD` if omitted. |
| `include_breakdown` | Boolean | No | If set to `true`, returns a detailed breakdown of the factors influencing the score. Defaults to `false`. |

#### Example Request

```http
GET /api/v1/willingness-to-pay?customer_id=cust_8923&product_id=prod_551&currency=USD&include_breakdown=true HTTP/1.1
Host: api.orchardpay.com
Authorization: Bearer <your_api_key>
Accept: application/json
```

#### Response Field Descriptions

*   **`request_id`**: A unique UUID for tracing this specific API call in logs.
*   **`willingness_to_pay.score`**: A normalized score between 0 and 100 indicating the likelihood of conversion at the estimated max price.
*   **`willingness_to_pay.estimated_max_price`**: The calculated maximum price point the customer is predicted to accept.
*   **`willingness_to_pay.confidence_level`**: Indicates the reliability of the prediction (`low`, `medium`, `high`).
*   **`breakdown`**: Only present if `include_breakdown=true`. Provides insight into the specific data points driving the algorithm's decision.

This endpoint enables dynamic pricing engines to adjust offers in real-time, maximizing revenue while maintaining conversion rates. Ensure proper authentication via the `Authorization` header using your assigned Bearer token.
