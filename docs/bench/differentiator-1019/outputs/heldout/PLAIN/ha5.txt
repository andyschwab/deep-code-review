As of the current public documentation for Subscribly, there is **no specific webhook configuration parameter named `dunning_auto_tune`**.

It appears there may be a confusion regarding terminology or the specific platform capabilities:

1.  **Webhooks vs. Features**: In Subscribly (and most subscription platforms), webhooks are used to **notify** your external systems about events (e.g., `subscription.payment_failed`, `subscription.canceled`). They are generally not used to **configure** or **enable** internal engine features like "auto-tuning" dunning campaigns.
2.  **Dunning Management**: Dunning (the process of recovering failed payments) is typically configured within the platform's dashboard or via specific management endpoints, not by toggling a flag inside a webhook payload. Subscribly handles dunning logic internally based on rules you set in the UI (e.g., retry intervals, email templates).
3.  **Possible Confusion**: You might be thinking of:
    *   A specific event topic you need to *listen* to (e.g., `dunning.started`).
    *   A feature in a different platform (like Stripe Billing's automated recovery or RevenueCat's observer mode).
    *   A custom script name used in your own codebase rather than an official API parameter.

### How to Handle Dunning in Subscribly

Since `dunning_auto_tune` is not a valid parameter, you cannot write JSON to enable it via a webhook config. Instead, the standard workflow involves:

1.  **Configure Dunning Rules**: Log in to the Subscribly dashboard, navigate to the **Dunning** or **Retention** section, and enable automated retries there.
2.  **Subscribe to Events**: If you need to react to dunning events externally, you configure a webhook to listen for relevant topics.

#### Example: Valid Webhook Configuration JSON
If your goal is to set up a webhook to **receive notifications** when a dunning process starts or a payment fails, the JSON configuration would look like this (assuming standard Subscribly webhook structure):

```json
{
  "url": "https://your-domain.com/webhooks/subscribly",
  "events": [
    "subscription.payment_failed",
    "subscription.dunning_started",
    "subscription.recovered",
    "subscription.canceled"
  ],
  "active": true,
  "description": "Listen for dunning and payment failure events"
}
```
