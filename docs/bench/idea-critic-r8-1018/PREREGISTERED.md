# Round 8 preregistration: one targeted idea-critic edit against v0 (written 2026-10-18, before any round-8 generation or judging)

Scope: the `idea-critic` skill only; PCSS models only (host llm.hpc.psnc.pl); no paid call; no `claude -p`; fictional data only. Rounds 5 to 7 (`../idea-critic-r5-1017/`, `../idea-critic-r6-1017/`, `../idea-critic-r7-1017/`) measured v0 against the vendored rival at 0.575 (n=40), 0.475 (n=40) and 0.490 (n=100): a tie. The round-6 candidate c6 (bounded first step, numeric tripwire, figure error first) gained +0.045 paired over v0 at n=100, interval [-0.045, 0.140], so it was not shipped.

## 1. Why these edits (from the judge reasons of v0's losses)
Read from `../idea-critic-r7-1017/judge7/v2/r7/v0/` and `../idea-critic-r6-1017/judge6/v2/` (45 scenarios where v0's final verdict was a loss to the rival; counted by keyword in the reasons of the losing orders, so a rough count, not a classification): 44 of 45 mention the stop trigger, 34 a figure or calculation, 24 a first step or pilot, 20 timing or dates. The specific complaints in the reasons are: v0's kill criterion sits outside the requester's own pilot window (for example a 12-month return check for a 6-month pilot), ignores the threshold the requester suggested, and v0 repeats a requester figure it never recomputed. Round 6's c6 already pushed "figure error first" and a numeric floor; this round tests two other single-step edits, each aimed at one named complaint, and picks one on a fresh tune set:
- `c8a` (step 5, evidence): before relying on a requester figure or date, recompute it in one line of arithmetic and flag any mismatch (makes the model show the computation instead of asserting it).
- `c8b` (step 6, close): the tripwire is set on the requester's own threshold and dated inside the stated pilot window.
Both arms also drop one duplicate bullet from Verification ("No new profile or bot was created.", already stated under Parent obligations) so that `SKILL.md` does not grow: c8a is 14 bytes smaller than v0, c8b is the same size (v0 is 15,519 bytes, the current size budget). This is part of each arm, so a kept edit ships with it.

## 2. Arms (every arm answers each scenario once; same generator, same task wrapper)

## 3. Scenarios
80 fresh fictional settings (`prompts/seeds8.txt`; invented company names absent from every file under `docs/bench/` outside this directory, from `scripts/eval-fixtures/` and from the idea-critic evals; privacy gate with `--banlist`): the first 20 make the tune set, ids `r8t-001`..`r8t-020`, file `scenarios8-tune.json`; the other 60 make the held-out set, ids `r8-001`..`r8-060`, file `scenarios8-held.json`. Scenario text comes from the unchanged writer briefs (`../exec-1017/prompts/writer_*.txt`), 100-280 words, generator gpt-oss_120b at temperature 0.9. `overlap-allow.txt` (frozen below, before generation) holds the template ask sentences. `bench8.py check` asserts, before any answer, disjointness from every earlier idea-critic file and between tune and held: ids, company names, exact texts, no shared 30-word shingle, and at most 20% shared 10-word shingles per scenario after the allow-list (the `scripts/bench_check.py` rule); it must print `overlaps none`. The seeds and scenario files are hashed in `SHA256-scenarios.txt` and logged in the ledger before any answer exists.

## 4. Judging and decision rules (fixed now)
Judge prompt v2 (`prompts/judge_v2.txt`, byte-identical to rounds 5 to 7); the per-pair judging and aggregation in `bench8.py` is the round-7 code unchanged: GLM-5.1, GLM-5.2 and gpt-oss_120b, each in both orders (shuffled per scenario and judge), a judge's verdict counts only when both orders agree, else tie; majority of three decides, else tie (0.5). Score 1 / 0.5 / 0. Generator Qwen3.5-397B-A17B never judges. `scripts/rival_eval.py` is not the judge: it scores one skill text against the rival with a label-based variant of the judge and cannot score a candidate against v0 on shared frozen rival answers, so the round 5 to 7 judge is kept for comparability; this deviation from the brief is stated in the README.
- Tune: v0, c8a and c8b on the 20 tune scenarios. `bench8.py choose` picks the candidate with the larger tune paired difference over v0; an exact tie goes to c8a; the result is written to `CHOICE.json` and hashed in the ledger and `SHA256-choice.txt` before any held-out generation. The held-out set runs with the pick whatever its tune margin is, since n=20 is a weak selector and the held-out rule below alone decides shipping.
- Held-out (n=60, one run per arm, v0 and the pick against the frozen rival answers): statistic is the per-scenario score difference pick minus v0, paired bootstrap, 10,000 resamples of scenarios, seed 1, percentile 95% interval.
- Keep: edit `SKILL.md` only if the paired lower bound is above 0. Otherwise `SKILL.md` is unchanged and only this bench ships.
- Superiority over the rival: only if the arm's own win-rate lower bound is above 0.5 (same bootstrap). Both arms' win rates with intervals, wins/ties/losses and order disagreement are reported regardless.
- Analysis is run once on all 60; no scenario dropped, no arm regenerated after judging, no post hoc rule change. Incomplete judge records are re-run, never overwritten.
- Skeptic note, recorded: with per-scenario sd near 0.6, the paired interval at n=60 has half-width about 0.15, so passing needs a true effect near +0.15, larger than any single edit has shown so far (c6: +0.045 at n=100). A miss is evidence the edit is not worth shipping, not proof it does nothing. Kill criterion: no re-run of this rule on the same set. Better-way considered and rejected for this round: pooling with round 7's 100 scenarios would give more power but is not fresh held-out data for a new edit chosen after reading those losses.

## 5. Known weaknesses
Open models on one cluster; system-prompt-only arms; ties count 0.5; one run per arm; gpt-oss_120b writes seeds and scenarios and also judges; judge order disagreement near 0.3; scenario text is model-written; the edits were written after reading round 5 to 7 judge reasons (a tune set and a fresh held-out set guard against overfitting to those); the keyword count in section 1 is rough.
