**Delivery Plan: Unified Core Validator Consolidation**

**Objective:** Merge three validation libraries (Billing, Logistics, Identity) into one shared core with backward compatibility, phased rollout, and zero downtime for ongoing features.

**Constraints & Risks:**
- Build cost: $45/run, 22 mins; minimize re-runs.
- Integration tests flake on Tuesdays; avoid scheduling critical gates then.
- Production deploy requires written approval from Jane Smith and John Doe (currently on partial leave); secure approval early or delegate via documented standing grant.
- Silent drift in business rules exists; must audit and align before merging.

---

### **Lanes (Work Decomposition)**

**Lane 1: Audit & Spec (Product Analyst + Conductor)**
- **Work:** Inventory all validation rules across the three folders. Identify drift, conflicting error messages, and edge cases. Produce a unified spec with acceptance criteria and a "drift report."
- **Parallel?** Yes, starts immediately.
- **Output:** Unified spec, drift report, migration checklist.

**Lane 2: Core Implementation (Builder)**
- **Work:** Create the new unified library in a dedicated worktree. Implement all rules from the spec. Ensure backward-compatible APIs (aliases/deprecations). Add comprehensive unit tests.
- **Dependency:** Requires Lane 1's spec (G3).
- **Parallel?** No, waits for Lane 1.
- **Output:** New library code, unit tests, deprecation warnings.

**Lane 3: Phased Migration Scripts (Builder)**
- **Work:** Write scripts to migrate each service (Billing, Logistics, Identity) one by one to the new library. Ensure each script is reversible.
- **Dependency:** Requires Lane 2's library API to be stable.
- **Parallel?** No, waits for Lane 2.
- **Output:** Three migration scripts, rollback scripts per service.

**Lane 4: Independent Verification (QA)**
- **Work:** Run functional, regression, and integration tests on the exact SHA of Lane 2 + Lane 3 changes. Verify backward compatibility by running old test suites against the new library.
- **Dependency:** Requires Lane 2 and Lane 3 complete.
- **Parallel?** No, waits for implementation.
- **Output:** Test receipts, performance metrics, flake analysis (avoid Tuesdays).

**Lane 5: Security & Compliance Review (Security)**
- **Work:** Review the unified library for privacy, data handling, and supply-chain risks. Ensure no logic gaps from the merge.
- **Dependency:** Requires Lane 2 complete.
- **Parallel?** Can run alongside Lane 4.
- **Output:** Security verdict, compliance checklist.

---

### **Gates & Checks**

- **G0/G1 (Intake/Spec):** Lane 1 output reviewed by Conductor. Drift report validated against team leads' input (async).
- **G2 (Plan):** Work graph approved; budget set per lane (max 2 build runs per lane candidate).
- **G3 (Design):** Unified API contract signed off by Conductor (acting for architects if standing grant exists; otherwise park for Jane/John).
- **G4 (Implement):** Code committed in isolated worktrees. Unit tests green locally before any Nebula build.
- **G5 (Verify):** 
  - Run on exact SHA from Lane 2+3.
  - Skip integration suite if Tuesday; retry Wed AM.
  - Local stack up + unit + targeted integration (non-flaky subset) must pass.
  - Cost gate: Max 2 Nebula runs per candidate; fail closed if budget exceeded.
- **G6 (Review):** 
  - QA (Lane 4) and Security (Lane 5) verdicts independent of Builder.
  - Deep code review on unified library diff.
  - Blocker/Critical findings halt; High requires architect acceptance.
- **G7 (Integrate):** Merge to integration branch. One aggregate build on final SHA. Re-run affected tests.
- **G8 (Release):** 
  - **Human Gate:** Written approval from Jane Smith and John Doe required for production deploy. If unavailable, park G8; do not auto-deploy.
  - Phased rollout: Deploy to one service at a time (Billing → Logistics → Identity) with rollback ready.
- **G9 (Prod Verify):** Monitor each service post-deploy for 24h. Rollback immediately on regression.
- **G10 (Learn):** Retrospective on drift causes; add regression tests for any escaped gaps.

---

### **Review & Independence**

- **Builder (Lane 2/3)** never reviews their own code.
- **QA (Lane 4)** and **Security (Lane 5)** are independent roles, reviewing the exact SHA, not the narrative.
- **Conductor** rolls up evidence but does not approve merges or deploys.

---

### **Landing Strategy**

- **Merge Train:** Use serialized merge for integration branch to avoid collision. One integration owner.
- **Human Decisions:** 
  - G3 API contract (if no standing grant).
  - G8 Production deploy (Jane + John approval mandatory).
  - Tuesday flake retries (manual auth).
- **Rollback:** Per-service rollback scripts ready. If regression detected in G9, revert that service only; platform remains up.
- **Adoption Guide:** Delivered with G7; includes deprecation timeline, migration commands, and contact for issues.

**Total Estimated Builds:** 6–8 (2 per candidate SHA across lanes), costing ~$270–$360. Avoid Tuesday integration runs. Secure architect approval early to prevent G8 blockage.
