**Delivery Plan: Winter Frost Banner Copy Update**

**Constraints & Decisions**
*   **Deadline:** Live before 8 AM tomorrow.
*   **Risk:** Production deploy is irreversible without resetting analytics; staging data lags 4 hours.
*   **Shortcut Rejected:** "Direct push" is invalid; the main branch is protected. We must use the PR train.
*   **Flake Handling:** The accessibility checker will likely fail on the dynamic date. We will not retry it silently; we will cite the log and request the specific manual override from the shift lead immediately upon failure.
*   **Scope:** This is a content change, but it affects the user-facing surface. We will run the build and unit checks, but skip the full 22-minute regression suite as authorized for copy-only changes under 50 lines.

**Lanes & Serialization**

1.  **Lane A: Implementation (Builder)**
    *   **Work:** Update the hero banner text (discount % and end date) in the content source files.
    *   **Parallelism:** Can start immediately.
    *   **Output:** A commit tagged `docs-only` on a new branch `feat/winter-frost-copy`.
    *   **Check:** Local build verification (fast) to ensure syntax is valid before pushing.

2.  **Lane B: Verification (QA)**
    *   **Trigger:** Starts only after Lane A pushes and the static generation pipeline begins.
    *   **Work:**
        *   Monitor the build log for the $45 compute run.
        *   Once staged, verify the copy matches the legal approval exactly.
        *   **Critical:** Since staging data lags 4 hours, visual formatting check must be done on the *build preview URL* generated by the pipeline, not the persistent staging environment.
        *   Handle the accessibility flake: If the dynamic date triggers a false positive, capture the error log and flag it for the shift lead's manual override immediately. Do not wait for auto-retry.

3.  **Lane C: Release Coordination (Conductor)**
    *   **Work:** Prepare the merge train entry. Coordinate the timing to ensure the 22-minute build completes before the 8 AM deadline.
    *   **Serialization:** Must wait for Lane B's "Green" signal before requesting merge.

**Gates & Checks**

*   **G4 (Implement):** Builder commits change. Tag must be `docs-only` to bypass senior engineer approval.
*   **G5 (Verify):**
    *   **Location:** Build preview URL (exact revision).
    *   **Check:** Build success (exit 0). Accessibility check (manual override if flaky). Visual confirmation of copy.
    *   **Condition:** If the build fails, abort and fix. If the accessibility check flakes, proceed only after shift lead override.
*   **G6 (Review):**
    *   **Reviewer:** Growth Team Lead (independent of the Builder).
    *   **Scope:** Verify copy accuracy against the legal sign-off and confirm the `docs-only` tag is appropriate.
    *   **Revision:** Exact SHA of the PR head.

**Landing & Rollback**

*   **Merge Strategy:** Merge into `main` via the merge train. The protected branch rule requires a passing status check (which includes the manual accessibility override).
*   **Human Decision Required:**
    1.  **Shift Lead:** Must manually override the accessibility flake if it occurs.
    2.  **Owner/Requester:** Must confirm visibility on the preview URL before the merge is finalized to ensure formatting is correct (since staging is stale).
    3.  **Merge Approval:** The Growth Team Lead must approve the PR.
*   **Deployment:** Automatic upon merge to `main` (triggering the 22-minute pipeline).
*   **Rollback Plan:**
    *   **Action:** Revert the merge commit immediately.
    *   **Consequence:** This triggers a new build. Note that a full snapshot rollback resets analytics counters; therefore, a code revert is preferred over a snapshot restore unless the site is broken.
    *   **Timing:** Must be executed before the 8 AM email blast if the copy is incorrect.
