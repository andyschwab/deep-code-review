# Delivery Plan: Fraud Detection Model v4.2 Upgrade

## Lanes & Parallelism

**Lane A: Model Validation (Trust & Safety)**
*   **Work:** Execute the v4.2 artifact against the holdout dataset in the staging environment.
*   **Parallelism:** Runs independently of Lane B. Must complete before Lane C.

**Lane B: Rollback & Infrastructure Prep (Security Officer)**
*   **Work:** Verify the cluster restore script functionality in a dry-run mode. Prepare the `global-rules.yaml` edit window outside business hours.
*   **Parallelism:** Runs parallel to Lane A.

**Lane C: Deployment Execution (Lead Data Scientist + On-Call Security Officer)**
*   **Work:** Update the model pointer in the central registry. Monitor the automated accuracy gate.
*   **Dependency:** Requires successful completion of Lane A (Score > 98.5%) and Lane B (Rollback verified).

## Gates & Checks

**Gate 1: Precision Threshold (Automated)**
*   **Location:** Staging CI Pipeline.
*   **Trigger:** Lane A completion.
*   **Criteria:** Precision score must be strictly > 98.5% on the holdout dataset.
*   **Action:** If score ≤ 98.5%, the pipeline aborts immediately. No human override permitted.
*   **Flake Mitigation:** If the check fails due to network latency (>200ms) rather than model performance, a manual re-trigger is authorized once per deployment attempt.

**Gate 2: Dual Approval (Human)**
*   **Location:** Production Deployment Console.
*   **Trigger:** Gate 1 passed + Rollback verified.
*   **Approvers:** Lead Data Scientist AND On-Call Security Officer.
*   **Constraint:** Execution must occur outside business hours to access `global-rules.yaml`.

**Gate 3: Irreversibility Acknowledgement**
*   **Location:** Pre-deployment checklist.
*   **Criteria:** Explicit confirmation that the cluster restore script is the *only* rollback mechanism, as the registry update is irreversible.

## Review Process

**Independent Technical Review**
*   **Reviewer:** Senior ML Engineer (not involved in Lane A or C).
*   **Scope:** Review the holdout dataset results from Lane A and the logic of the accuracy gate script.
*   **Timing:** Before Gate 2 (Dual Approval).
*   **Deliverable:** Signed validation that the test results are statistically significant and not a product of the known network flake.

**Operational Review**
*   **Reviewer:** On-Call Security Officer.
*   **Scope:** Verification of the rollback script (Lane B).
*   **Timing:** Before Gate 2.

## Landing & Merge Strategy

**Activation**
*   The switch is activated only after the automated gate confirms the precision score in the staging environment.
*   The production pointer update is performed manually by the dual approvers during the designated off-hours window.

**Human Decision Points**
1.  **Flake Determination:** Deciding whether a failed accuracy gate is a genuine model failure or a network latency artifact requiring a re-trigger.
2.  **Go/No-Go:** The final dual approval to touch the production registry.

**Rollback Protocol**
*   **Trigger:** Any post-deployment anomaly or false-positive report.
*   **Action:** Immediate execution of the full cluster restore script.
*   **Constraint:** Since the registry change is irreversible, a "rollback" is technically a restoration of the previous cluster state. This process must be tested in Lane B.

**Post-Landing**
*   Monitor false-positive rates for 1 hour post-deployment.
*   If stable, close the ticket. If unstable, initiate Rollback Protocol immediately.
