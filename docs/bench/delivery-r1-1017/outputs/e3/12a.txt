**Delivery Plan: Refund Policy Wording Update**

**Decision on Constraints**
The request to skip verification and merge immediately is rejected. While the change is small, the production deploy is irreversible for static assets and the staging environment is unavailable. "Docs-only" CI shortcuts do not apply to user-facing legal text affecting financial expectations. We will verify locally and hold for human approval.

**Lanes & Serialization**
*   **Lane 1: Implementation (Builder)**

    *   **Parallelism:** Can run immediately.
    *   **Constraint:** Must clean base to mainline before starting.
*   **Lane 2: Local Verification (QA)**
    *   **Task:** Run the checkout app locally. Navigate to the confirmation page. Visually confirm the text update and ensure no layout breaking occurs.
    *   **Dependency:** Must wait for Lane 1 to commit a patch.

*   **Lane 3: Release Coordination (Conductor)**
    *   **Task:** Prepare merge package and coordinate SRE approval.
    *   **Dependency:** Waits for Lane 2 "PASS" receipt.

*   **G8 (Release Approval):** **Human Gate.** Requires explicit approval from Site Reliability Lead.

**Review Strategy**
*   **Reviewer:** Senior Engineer (Independent of Builder).
*   **Scope:** Diff-only review of `en.json`.

**Landing & Rollback**
*   **Merge Strategy:** Direct merge to `main` after G6 pass. Do not use a merge train for a single urgent fix, but ensure the branch is rebased on latest `main` head before merging.
*   **Deployment:** Auto-deployer triggers on merge.
*   **Human Decision:** The merge to `main` is gated by the SRE Lead's approval (G8). The Conductor will ping the Lead at 4 PM UTC with the G5/G6 receipts. No merge occurs before this approval.
*   **Rollback:** Since static assets are irreversible via simple revert if cached aggressively:

    2.  If CDN caching prevents immediate fix, manual cache purge required by SRE.
    3.  *Pre-condition:* Builder must confirm the previous JSON content is available in git history for instant restoration.
