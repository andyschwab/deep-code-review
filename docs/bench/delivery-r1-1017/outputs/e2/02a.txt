### Delivery Plan: Seasonal Trend Filter (G0–G10)

**G0 Intake & G1 Spec**
*   **Product Analyst:** Draft spec defining "Seasonal View" behavior: toggling overlays last year's revenue data on the current graph. Explicitly exclude changes to the frozen visualization library (v2.4). Define acceptance: overlay renders correctly on low-res screens; state persists across refresh.
*   **Conductor:** Set scope boundaries. Flag the flaky screenshot check as a known risk to be bypassed or manually verified, not a hard block.
*   **Human Gate:** Product Lead approves spec; Accessibility Champion signs off on interaction requirements before implementation starts.

**G2 Plan & Lanes**
*   **Lane A (Data & Logic):** *Builder* implements the data transformation to fetch/map last year's dates. Isolated worktree.
*   **Lane B (UI Component):** *Builder* adds the toggle switch and chart overlay logic within the dashboard module. Isolated worktree.
*   **Lane C (Persistence):** *Builder* implements local storage logic to save toggle state.
*   **Serialization:** Lanes A, B, and C run in parallel but must merge into a single integration branch sequentially to avoid conflict on the chart component file. Lane A merges first (data contract), then B (UI), then C (state).

**G3 Design**
*   **Architect:** Confirm no changes to the frozen viz library; ensure the overlay uses existing safe APIs.
*   **Security:** Verify local storage usage does not expose PII.

**G4 Implement**
*   Builders commit patches to their respective worktrees. Unit tests included for data mapping and state serialization. No full CI runs yet; run lightweight lint/type checks locally.

**G5 Verify (Exact Revision)**
*   **QA (Independent):**
    1.  Spin up staging with the integrated SHA.
    2.  **Manual Browser Verification:** Record a video session demonstrating the toggle on a low-resolution viewport, verifying the overlay and persistence after refresh. This satisfies the "real browser" requirement and bypasses the flaky CI screenshot check.
    3.  Confirm no regression in core chart rendering.
*   **Accessibility Champion:** Verify toggle keyboard navigation and screen reader announcements.

**G6 Review**
*   **Frontend Guild Lead:** Code review of all lanes (independent of Builders).
*   **Product Lead & Accessibility Champion:** Formal approval of the video evidence and accessible interaction.
*   **Security:** Final sign-off on data handling.

**G7 Integrate**
*   **Conductor:** Merge approved lanes into the integration branch. Run one full CI suite ($45 cost) only at this final SHA to validate the complete build.
*   **Gate Condition:** CI must pass excluding the known flaky screenshot check (manually overridden based on QA video evidence).

**G8 Release (Human Gated)**
*   **Deployment:** Automated push to Staging is immediate upon G7 success.
*   **Production Push:** Requires manual sign-off from the VP of Engineering during business hours.
*   **Rollback Plan:** If production issues arise: 1) Flip feature flag off (instant); 2) Revert commit; 3) Data repair (none expected as change is read-only/display).

**G9 Production Verify**
*   Monitor error logs and support tickets post-deploy. Confirm the three urgent enterprise clients can access the feature.

**G10 Learn**
*   Retrospective: Document the decision to bypass the flaky screenshot check via video evidence to refine future CI rules for animation-heavy components.

**Cost & Constraints**
*   **CI Cost:** Minimized by running full suite only once at G7.
*   **Timeline:** Parallel implementation (A/B/C) reduces build time; VP availability dictates final production release.
*   **Risk:** Frozen library constraint strictly enforced; no upgrades attempted.
