**Delivery Plan: Winter Frost Banner Copy Update**

**Scope & Constraints**
This is a high-velocity, low-risk content update with a hard deadline (08:00 tomorrow). While labeled "docs-only," the change affects a live user-facing surface (Domain P) and triggers a costly, slow pipeline. We will treat this as a single-lane delivery with accelerated verification, bypassing the full regression suite but enforcing the accessibility gate manually to mitigate the known flake.

**Lane Strategy (Single Lane)**
*   **Executor:** Builder (Growth Team Member).
*   **Worktree:** Isolated branch `feat/winter-frost-copy-2024` off the current production SHA.
*   **Task:** Update hero banner text (discount % and end date) in the content layer.
*   **Parallelism:** None required; single atomic change.

**Gates & Checks**

*   **G0/G1 (Intake/Spec):** Confirmed. Legal sign-off exists. Acceptance criteria: New text visible on staging; formatting verified by requester.
*   **G2 (Plan):** Budget set to $45 (one pipeline run). Time-box: 45 minutes total.
*   **G3 (Design):** N/A (Copy only).
*   **G4 (Implement):**
    *   Builder commits change with tag `docs-only`.
    *   **Exact Revision:** Commit SHA must be recorded before triggering pipeline.
*   **G5 (Verify) – Critical Path:**
    *   **Trigger:** Static generation pipeline (22 min).
    *   **Accessibility Gate:** The automated checker will likely flake on the dynamic date.
        *   *Action:* Builder monitors the run. If the a11y check fails due to the date string, the Shift Lead must manually override immediately. Do not wait for a re-run.
    *   **Staging Verification:** Once the pipeline completes, the Builder confirms the staging URL is updated.
        *   *Constraint Note:* Staging data lags by 4 hours. The Builder must verify *text content* only, ignoring data-driven personalization that may appear stale.
    *   **Requester Check:** Builder notifies requester immediately upon staging success for final formatting approval.
*   **G6 (Review):**
    *   **Reviewer:** Shift Lead (independent of Builder).
    *   **Scope:** Diff review (copy accuracy) + Confirmation of a11y override authorization.
    *   **Timing:** Can occur in parallel with the pipeline run (reviewing the diff) but must formally sign off before G8.
*   **G7 (Integrate):** Merge to `main` via PR. The `docs-only` tag bypasses senior engineer approval, but the Shift Lead's G6 sign-off is mandatory to clear the a11y exception.

**Landing & Release (G8/G9)**

*   **Human Decision (G8):**
    *   **Approver:** Shift Lead or Growth Owner.
    *   **Trigger:** Requester confirms formatting on staging.
    *   **Action:** Approve merge to `main`. This triggers the production deploy.
    *   **Warning:** Production deploy is irreversible without a full snapshot rollback (which resets analytics). Ensure copy is 100% accurate before this click.
*   **Production Verify (G9):**
    *   Once deployed, Builder verifies live URL.
    *   **Rollback Plan:** If critical error found post-deploy, execute immediate snapshot rollback. Acknowledge loss of the hour's analytics data as the cost of failure.

**Risk Mitigation**
*   **Pipeline Failure:** If the $45 build fails, do not retry immediately. Inspect logs. If it's the known a11y flake, prepare the manual override and retry once.
*   **Timing:** With a 22-minute build and 08:00 deadline, the PR must be opened and the pipeline triggered no later than 06:30 to allow buffer for the manual a11y override and requester review.
*   **Staging Lag:** Explicitly communicate to the requester that staging visuals involving dynamic user data will look 4 hours old; they are only approving the static banner copy.
