**What Flips It, and The Trigger**
The controlling input is **control of the private key**. If your system technically allows you to sign a transaction without the user's contemporaneous authorization (even if triggered by a "death" event), regulators view this as custody.
*   **Trigger:** The moment a user dies and your system executes a transfer using your key, you have transmitted value.
*   **Rule of Thumb:** If you can move the funds without the user physically present to type a password, you are a money transmitter.
*   **This Week's Step:** If your current code allows your server to co-sign a transaction based on an automated oracle (death certificate API), **stop** that workflow immediately and consult a fintech attorney to draft a "purely informational" will-execution service where the beneficiary, not you, initiates the transfer using keys stored via secret-sharing (Shamir's Secret Sharing) where you never hold a complete or functional key pair.
