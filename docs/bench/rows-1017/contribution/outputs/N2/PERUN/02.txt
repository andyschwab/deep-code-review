**Title:** [Design Proposal] Optional asset compression skip for faster local development loops

**Body:**

Hi BuildFast maintainers,

I fully respect the project's guideline regarding design discussions prior to feature PRs. In the spirit of adhering to that process efficiently, I'm submitting a concrete design proposal below for a feature that has significantly improved our team's inner-loop development time. We believe this could benefit the wider community facing similar latency issues during iterative development.

**The Problem**
During local development, full asset compression adds unnecessary latency to the build process when the final optimized bundle is not required. For large projects, this slows down the edit-reload cycle, impacting developer productivity.

**Proposed Solution**
Introduce a new CLI flag, e.g., `--no-compress` or `--dev-mode`, which bypasses the asset compression step while retaining other build functionalities (bundling, transpiling).

*   **Default Behavior:** Unchanged. Compression remains default to ensure production builds are optimized.
*   **New Flag:** When enabled, the build pipeline skips the compression phase.
*   **Scope:** This is strictly for local development workflows; CI/CD and production deployment scripts would continue to use the default compressed builds.

**Benefits**
*   **Reduced Build Times:** Early internal testing suggests a 40-60% reduction in local build times for medium-to-large projects.
*   **Improved DX:** Faster feedback loops allow developers to iterate more rapidly.
*   **Zero Production Risk:** Since the default behavior is untouched, there is no risk of accidentally deploying uncompressed assets unless explicitly configured.

**Implementation Sketch**
The change involves a conditional check in the build pipeline's configuration loader. We have a working prototype in our fork that demonstrates the feasibility with minimal code intrusion.

**Next Steps**
We are eager to contribute this back to the core project. Could we get a quick sanity check on this design direction? If this aligns with the project's roadmap, we are happy to refine the implementation details, add necessary tests, and submit a formal PR.

We understand you are busy, but given the immediate impact on developer workflow, we'd appreciate any early feedback you could share by the end of this week.

Thank you for maintaining such a robust tool.
