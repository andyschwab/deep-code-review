You do **not** need to open an issue first. For trivial fixes like broken links or typos, opening a separate issue is often considered unnecessary noise. The standard practice is to include the explanation directly in your Pull Request (PR) description.

Here is your step-by-step plan to ensure your contribution is accepted without process errors:

### Step 1: Fork and Clone
1.  Go to the ProjectZebra repository on GitHub.
2.  Click the **Fork** button (top right) to create your own copy.
3.  Clone your fork to your local machine:
    `git clone https://github.com/YOUR_USERNAME/ProjectZebra.git`
4.  Navigate into the folder: `cd ProjectZebra`

### Step 2: Create a Branch
Never work on the `main` branch. Create a specific branch for this fix:
`git checkout -b fix-readme-governance-link`

### Step 3: Make the Change
Open `README.md` in your text editor, find the old URL, and replace it with the new one you verified. Save the file.

### Step 4: Commit with the Correct Message
Since there is no ticket number, you must adapt the project's format. Most projects accepting contributions without tickets prefer a descriptive subject line.

**Exact commit message string to use:**
```text
docs: update broken governance link in README

The previous link to the governance document was returning a 404 error.
This updates the URL to the new location verified on [Date].
```
*Note: Replace `[Date]` with today's date. If the project strictly requires a ticket ID (e.g., `PROJ-123`) and refuses commits without one, you would need to open an issue first to generate that ID, but this is rare for documentation fixes.*

Run the commit:
`git add README.md`
`git commit -m "docs: update broken governance link in README" -m "The previous link to the governance document was returning a 404 error. This updates the URL to the new location verified on $(date +%Y-%m-%d)."`

### Step 5: Push and Open Pull Request
1.  Push your branch to your fork:
    `git push origin fix-readme-governance-link`
2.  Go to the **original** ProjectZebra repository on GitHub.
3.  You will see a yellow banner suggesting you open a Pull Request for your recently pushed branch. Click **Compare & pull request**.
4.  **Title:** `docs: Update broken governance link in README`
5.  **Description:** Briefly explain: "Hi, I noticed the governance link in the README was broken (404). I have updated it to the current location. Thanks for maintaining this project!"
6.  Submit the PR.

### Why this works
*   **Scope:** It isolates a single, non-controversial change.
*   **Convention:** Using `docs:` at the start of the message follows standard conventions (Conventional Commits) which usually satisfies automated linters.
*   **Efficiency:** It respects the maintainers' time by avoiding a redundant issue ticket for a self-explanatory fix.

If the automated checks fail specifically due to a missing ticket number, the bot will comment on your PR. At that point, you can simply reply asking if you should open a retroactive issue, but 99% of the time, this direct approach is preferred for link fixes.
