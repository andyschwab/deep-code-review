### Draft Pull Request Description

**Title:** Fix null-pointer dereference when loading malformed PNG files

**Description:**
This PR addresses a null-pointer dereference crash occurring during the parsing of malformed PNG files. The issue arises when the parser encounters a specific corruption pattern in the image header, leading to a null pointer being returned and subsequently dereferenced without validation.

**The Fix:**
A single-line guard clause has been added to verify the pointer validity before dereferencing. This prevents the crash and allows the library to gracefully handle the error condition by returning an appropriate error code.

**Reproducer & Test Case:**
Per the contribution guidelines, a synthetic test case is required. Since the original corrupt file cannot be shared due to privacy policies, I propose generating a minimal synthetic PNG that triggers this specific state.

The crash is triggered by a PNG file where the `IHDR` chunk is present, but the subsequent data chunk expected by the parser is truncated or malformed in a way that causes the internal loader to return `NULL` while still proceeding to the dereference step.

**Proposed Test Artifact:**
A small script or binary blob can be generated to create a file with the following hex structure:
1. Valid PNG Signature (`89 50 4E 47 0D 0A 1A 0A`)
2. Valid `IHDR` chunk.
3. A malformed/truncated `IDAT` chunk that specifically causes the parser's internal allocation to fail (returning `NULL`) while the control flow incorrectly continues to the access point.

*Action Requested:* Could a maintainer confirm the exact internal state transition that leads to the `NULL` return in the current codebase? With that confirmation, I can provide a minimal hex-string generator in the test suite that deterministically reproduces the crash condition without relying on external binary assets.
