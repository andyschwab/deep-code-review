### Strategy to Split Logic Fix from Formatting Noise

You must separate the atomic logic fix from the formatting changes before resubmitting. Since you have already pushed the mixed branch, you will need to rewrite history on a local copy and force-push a clean branch. Do not attempt to edit the existing mixed branch; create a new one.

**Step 1: Preserve the Current State**
Create a backup branch pointing to your current messy work. This ensures you do not lose the formatting changes if something goes wrong during the rewrite.
```bash
git checkout main
git pull
git checkout -b backup-mixed-pr <your-current-branch-name>
```

**Step 2: Create a Clean Branch for the Logic Fix**
Create a new branch from `main` specifically for the bug fix.
```bash
git checkout -b fix/aggregated-metrics-bug
```

**Step 3: Extract Only the Logic Changes**
Use interactive staging to select *only* the specific lines in the three files that constitute the logic fix. Do not stage whitespace or formatting changes.
```bash
git add -p
```
*   When prompted for each hunk, type `s` (split) if the hunk mixes logic and formatting.
*   Type `y` (yes) only for the specific lines fixing the aggregation logic.
*   Type `n` (no) for all formatting-only changes.
*   Once only the logic changes are staged, commit them:
    ```bash
    git commit -m "fix: correct aggregated metrics calculation in DataStream"
    ```

**Step 4: Isolate the Formatting Changes (Optional but Recommended)**
If you still want to propose the formatting cleanup, do it in a separate, subsequent PR. Create another branch from `main`:
```bash
git checkout -b chore/format-codebase
git add -p
# Select only the formatting changes (reject any remaining logic changes if any exist)
git commit -m "chore: apply consistent formatting across codebase"
```

**Step 5: Update Your Remote Branches**
You now have two clean branches locally. Push the logic fix to your fork. Since this is a new branch name, a standard push works.
```bash
git push origin fix/aggregated-metrics-bug
```
If you choose to submit the formatting later:
```bash
git push origin chore/format-codebase
```

**Step 6: Communicate with Stakeholders**
1.  **Notify your manager:** Explain that the original link contained non-atomic changes violating project standards. Provide the new link to `fix/aggregated-metrics-bug` as the correct proof of the logic fix.
2.  **Close the old PR:** If you opened a PR from the mixed branch, close it immediately with a note explaining you are resubmitting a clean, atomic fix.
3.  **Submit the new PR:** Open a new PR from `fix/aggregated-metrics-bug`. This now touches only the three relevant files, adhering to Ravi's requirements.

**Critical Warning:** Do not force-push (`git push --force`) to the branch your manager is currently looking at unless you explicitly coordinate it, as this rewrites history and can break their view. Creating a new branch name (as outlined above) is safer and clearer.

Note: Ensure your local working directory is clean before starting these steps to avoid accidental commits.
If the logic fix is tightly entangled with formatting such that `git add -p` cannot separate them, you may need to manually copy the fixed code blocks into a fresh checkout of the three files.
