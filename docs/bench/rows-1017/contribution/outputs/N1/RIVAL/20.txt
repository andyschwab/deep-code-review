### Search Strategy & Queries for AeroMap Duplicate Check

**1. Issue Tracker Search (GitHub/GitLab)**
Run these queries in the project's "Issues" tab to find existing reports or pending fixes. Use quotes for exact phrases and `is:` filters to narrow scope.

*   **Broad Crash Search:** `"vector tile" crash` OR `"missing geometry"`
*   **Specific Attribute Search:** `"geometry attributes" null` OR `"null geometry" rendering`
*   **Status-Specific Search:** `is:open is:issue "vector tile" crash` (Checks active bugs)
*   **Recently Closed Search:** `is:closed closed:2024-01-01..* "vector tile"` (Adjust date range to last 3–6 months to catch recent fixes)

**2. Commit History Search**
Check if the fix was already merged but not yet released or documented. Run these locally in your cloned repository:

*   **Search Commit Messages:**
    ```bash
    git log --oneline --all --grep="vector tile" --grep="null geometry" --grep="missing geometry" -i
    ```
    *(The `-i` flag makes the search case-insensitive.)*

*   **Search Code Diff (Most Critical):**
    This searches the actual code changes in history for patterns resembling your guard clause.
    ```bash
    git log -p --all -S "geometry" -- "*vector*" | grep -C 5 "null"
    ```
    Or specifically for the rendering engine file path (adjust path as needed):
    ```bash
    git log -p --all -S "null" -- "src/rendering/vector_tiles.rs"
    ```

**3. Pull Request Search**
Sometimes fixes are merged via PRs where the issue wasn't clearly tagged.

*   **Query:** `is:pr is:merged "vector tile" crash`
*   **Query:** `is:pr is:merged "guard clause" geometry`

**Execution Strategy**
1.  **Start with Closed Issues (Last 90 Days):** If a duplicate exists, it is likely recently closed. If you find one, read the closing commit hash.
2.  **Verify the Commit:** Take the hash from the closed issue/PR and run `git show <hash>` to confirm the fix matches your logic. If their fix handles the null check differently or incompletely, your contribution might still be valuable as a follow-up.
3.  **Check "Stale" Open Issues:** If an open issue exists but has no activity for months, your PR can reference it as a "revival" with a concrete fix, which is highly valued.
4.  **Keyword Variation:** If "vector tile" yields nothing, try the specific file format (e.g., "MVT", "PBF", "GeoJSON") combined with "crash" or "panic".

If these searches return no relevant results, your fix is likely novel. Proceed with writing tests and formatting, ensuring you reference any related (but unresolved) issues you found during this search in your final PR description.

*Note: If you find a merged fix that only partially addresses the problem, frame your PR as a "hardening" of that previous fix rather than a new bug fix.*
