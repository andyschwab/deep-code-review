### Legal & Git Compliance Checklist for RiverData PR

**Phase A: Legal Prerequisites (Do Before Opening PR)**
1.  **Locate the CLA:** Find the Contributor Licence Agreement link in the repository's `CONTRIBUTING.md`, `README.md`, or the project's website. Do not guess; use the official link.
2.  **Sign the CLA:** Complete the signing process immediately. Most projects use an automated bot (like CLA Assistant) that checks your GitHub username against a signed list.
    *   *Note:* You generally **must** sign before opening the PR. If you open the PR first, the bot will block all checks until you sign, delaying the review. Some strict projects may close unsigned PRs automatically.
3.  **Verify Status:** Ensure you have received a confirmation email or see a "CLA Signed" badge on your GitHub profile/project page before proceeding to git operations.

**Phase B: Fixing Existing Commits (Adding `Signed-off-by`)**
Since your commits lack the required trailer, you must rewrite your local branch history. **Do not** simply add a new commit saying "added sign-offs"; maintainers often reject this as clutter.

4.  **Configure Git Identity:** Ensure your local git config matches the identity used to sign the CLA.
    ```bash
    git config user.name "Your Name"
    git config user.email "your.email@example.com"
    ```
5.  **Start Interactive Rebase:** Begin an interactive rebase from the upstream main branch (replace `upstream/main` with the actual target branch).
    ```bash
    git fetch upstream
    git rebase -i upstream/main
    ```
6.  **Mark Commits for Editing:** In the editor that opens, change the word `pick` to `edit` (or `e`) for **every** commit in your list that lacks the sign-off. Save and close the file.
7.  **Amend Each Commit:** Git will stop at the first marked commit. Run the following to automatically append the `Signed-off-by` trailer using your configured identity:
    ```bash
    git commit --amend --signoff --no-edit
    ```
    *   *Crucial:* The `--no-edit` flag preserves your original commit message text, only appending the trailer.
8.  **Continue Rebase:** Once amended, continue to the next commit:
    ```bash
    git rebase --continue
    ```
    Repeat steps 7 and 8 until the rebase finishes. If conflicts arise, resolve them, `git add` the files, and run `git rebase --continue` again (you do not need to `--signoff` again during conflict resolution unless you create a *new* commit).

**Phase C: Pushing Changes**
9.  **Force Push Safely:** Since you rewritten history, you must force push to your fork. Use `--force-with-lease` to ensure you don't overwrite work if you pushed to the fork from another machine in the meantime.
    ```bash
    git push origin <your-branch-name> --force-with-lease
    ```
10. **Open the Pull Request:** Now that your local history is clean, signed, and matches your signed CLA status, open the PR on GitHub. The automated checks should now pass immediately.

**Note:** Never use `git push --force` without the `--lease` flag on shared branches. If the project uses a "squash and merge" strategy, the individual commit trailers matter less for the final history, but many maintainers still require them for the review trail.
