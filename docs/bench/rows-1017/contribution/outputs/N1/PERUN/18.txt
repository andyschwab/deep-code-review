### Contribution Compliance Checklist

**Phase 1: Legal Prerequisites (Do Before PR)**
1.  **Locate the CLA:** Find the Contributor Licence Agreement link in the upstream repository's `CONTRIBUTING.md`, `README.md`, or the organization's legal documentation page.
2.  **Sign the CLA:** Complete the digital signature process immediately. Most projects use an automated bot (e.g., CLA Assistant) that checks your GitHub username against a signed list.
    *   *Note:* You generally **must** sign before opening the Pull Request. If you open the PR first, the automated gate will likely block the merge until the signature is recorded, and some maintainers will not review code from unsigned contributors.
3.  **Verify Status:** Ensure your GitHub account is linked to the email address you used for the signature if the project uses a third-party verification service.

**Phase 2: Git History Correction (Fixing Missing Sign-offs)**
*Warning: These steps rewrite commit history. Since you have already pushed to your fork, you will need to force-push after amending.*

**Option A: If all commits lack the sign-off (Easiest)**
1.  Navigate to your local clone of the fork.
2.  Run the following command to append the `Signed-off-by` trailer to every commit in your current branch automatically:
    ```bash
    git rebase --exec 'git commit --amend --no-edit --signoff' -i <commit-hash-before-your-first-change>
    ```
    *(Replace `<commit-hash...>` with the hash of the last commit from the original upstream main branch, or use `HEAD~N` where N is the number of your commits.)*
3.  If the rebase stops due to conflicts, resolve them, then run `git rebase --continue`. The sign-off will be added automatically upon continuation.

**Option B: If only specific commits lack the sign-off**
1.  Start an interactive rebase:
    ```bash
    git rebase -i <commit-hash-before-your-first-change>
    ```
2.  In the editor, change `pick` to `edit` (or `e`) for every commit missing the sign-off. Save and close.
3.  Git will stop at the first marked commit. Run:
    ```bash
    git commit --amend --signoff --no-edit
    git rebase --continue
    ```
4.  Repeat the amend/continue step for each subsequent commit until the rebase finishes.

**Phase 3: Synchronization and Submission**
1.  **Force Push:** Because you rewrote history, you must update your remote fork:
    ```bash
    git push --force-with-lease origin <your-branch-name>
    ```
2.  **Open the Pull Request:** Navigate to the upstream repository and create the PR from your forked branch.
3.  **Verification:** Check the PR conversation tab.
    *   Look for a green checkmark or comment from the CLA bot confirming your signature.
    *   Look for a DCO (Developer Certificate of Origin) check confirming the `Signed-off-by` trailers are present.

**Critical Reminders:**
*   **Do not** create new "fixup" commits just to add sign-offs; maintainers prefer a clean history where every commit is legally compliant.
*   If the upstream repository uses a strict "squash and merge" policy, the individual commit sign-offs matter less than the final commit message, but adding them now ensures your DCO checks pass immediately and shows professionalism.
