Here is a checklist to verify your changes locally and ensure your front-matter is correct:

1.  **Locate the Source File**: Find the specific markdown file in the repository that corresponds to the documentation page you edited.
2.  **Inspect Existing Front-Matter**: Look at the top of the file for a block enclosed in `---`. Copy the exact format of the `author` and `last-reviewed` tags from a neighboring, recently updated file to ensure consistency.
3.  **Update the Author Tag**: Set `author` to your name or GitHub username exactly as you want it to appear. Do not leave this blank.
4.  **Update the Last-Reviewed Date**: Set `last-reviewed` to today's date. Check other files to confirm the required format (e.g., `YYYY-MM-DD` or `Month Day, Year`) and match it precisely.
5.  **Verify YAML Syntax**: Ensure there are no extra spaces before the tags, that colons are followed by a single space, and that the closing `---` is on its own line. Invalid YAML will cause the build to fail.
6.  **Install Dependencies**: Run the project's installation command (usually `npm install`, `yarn`, or `pip install -r requirements.txt`) to ensure you have the static site generator tools.
7.  **Run the Local Build**: Execute the specific build or preview command listed in the project's `README.md` or `CONTRIBUTING.md` (commonly `npm run build`, `npm run dev`, `hugo server`, or `mkdocs serve`).
8.  **Check for Errors**: Watch the terminal output. If the build fails, read the error message; it often points directly to the line number in the front-matter causing the issue.
9.  **Verify Content**: If the build succeeds, open the local preview URL in your browser. Confirm that your typo fix and code example render correctly and that the page metadata displays as expected.
10. **Final Review**: Double-check that you have not accidentally modified any other files, especially configuration files or other documentation pages.

**Note**: If the build fails due to front-matter, compare your header character-for-character with a working file; invisible characters or date format mismatches are common culprits. Always refer to the project's `CONTRIBUTING.md` for the exact build commands, as they vary by technology.
