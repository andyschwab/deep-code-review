**Immediate Harm Inventory**
Before proceeding, you must formally record the following specific risks for this feature:
*   **Unsafe Automation of Irreversible Actions:** The system executes financial transfers and binding purchase orders without a human gate. A single hallucination or logic error results in immediate financial loss that is difficult or impossible to reverse.
*   **Hallucination Surfaced as Fact:** The agent might invent a supplier, fabricate an invoice amount, or misread inventory levels, presenting these errors as authoritative facts to the payment gateway.
*   **Over-reliance:** By removing human approval, the design forces users to trust the output past its reliability. If the model fails, there is no override mechanism to stop the transaction before it settles.
*   **Bias/Unfair Outcomes:** If the training data contains historical biases against certain vendors, the agent could systematically delay payments to specific groups or favor others, causing tangible economic damage to small partners.

**Required Controls Before Launch**
You cannot ship this feature in its current state. The "floor" for any AI system performing high-stakes, irreversible actions is a **human-in-the-loop gate**. Full autonomous execution of payments and binding orders is the failure mode this safety discipline exists to prevent.

To manage residual risk, you must implement the following immediately:
1.  **Insert a Human Gate:** Change the workflow so the agent *drafts* payments and reorder requests but requires explicit human confirmation before execution. No money moves and no stock is ordered without this second signature.
2.  **Define Confidence Tiers:** Do not show raw model confidence scores (e.g., "92% sure") to users, as this implies a precision the system likely does not have. Instead, use defined coarse tiers such as "Verified Source," "Corroborated," or "Unverified," accompanied by clear definitions of what those terms mean.
3.  **Run Output Evaluations:** You must build a test suite specifically for these harms. This includes adversarial prompts designed to trick the agent into paying fake invoices or ordering excess stock. You need a known-bad positive control (a test case that *should* fail) and a known-good negative control. Only after running these tests can you report a residual risk level, and even then, it is a measurement of current performance, not a guarantee of future safety.
