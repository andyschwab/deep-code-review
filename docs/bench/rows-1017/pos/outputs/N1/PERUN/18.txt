**Do not deploy this system in its current state.** Automatically issuing formal disciplinary notices without human review, especially using noisy data that misses break times, creates an unacceptable risk of harming workers through false accusations. This is a high-stakes, irreversible action that requires a human-in-the-loop gate by default. Full automation of disciplinary actions is the failure mode this review exists to prevent.

Before any testing begins, you must redesign the workflow: the AI can flag potential low performance, but a human manager must review and confirm every warning before it is sent. No amount of testing can justify removing this safeguard given your admitted data quality issues.

### Harm Inventory
Your system currently exposes workers to these specific harms:
*   **Bias/Unfair Outcomes:** Noisy data missing break times will systematically penalize workers who take legitimate breaks, potentially disadvantaging specific groups or individuals with different working patterns.
*   **Hallucination as Fact:** The system will present incorrect efficiency scores as objective truth, leading to formal warnings based on fabricated poor performance.
*   **Unsafe Automation:** Issuing disciplinary notices is a high-stakes action affecting livelihoods and morale. Automating this without human oversight is dangerous.
*   **Over-reliance:** Managers may trust the automated score over their own observations or worker explanations if the system presents results with false precision.
*   **Missing Disclosure:** Workers may not know an AI made the initial determination or that the data feeding it is known to be flawed.

### Measurement Strategy (Pre-Deployment)
You cannot certify the system as "fair" or "accurate" before deployment. Instead, you must measure residual risk and report it transparently. Since you cannot run tests here, you must build the following evaluation plan:

1.  **Adversarial Probe Sets:** Create test inputs simulating known scenarios:
    *   *Positive Control:* Workers with recorded breaks missing from the data stream. The system must **not** flag these as low performance if the logic is corrected, or must flag them as "Data Unverified" if not.
    *   *Negative Control:* Workers with consistently high scan rates despite data gaps.
    *   *Edge Cases:* Shift changes, equipment downtime, and varied break durations.
2.  **Subgroup Analysis:** Slice results by shift, warehouse zone, and tenure to check for systematic disadvantages. Do not rely on aggregate accuracy; a system can be 95% accurate overall but 100% wrong for night-shift workers.
3.  **Define Success Thresholds:** Your team must set owner-defined thresholds. For irreversible actions like warnings, propose zero tolerance for false positives caused by data gaps. If the system generates even one false warning due to missing break data, the launch must stop.
4.  **Injection and Leakage Checks:** Test if user-supplied data or external factors can manipulate scores, and ensure no worker's data leaks into another's profile.

**Reporting Rule:** If you cannot measure a metric (e.g., bias rate for a specific subgroup due to small sample size), label it **UNVERIFIED**. Do not invent a "99% accurate" claim.

### Managing Residual Risk
*   **Human-in-the-Loop (Mandatory):** Implement a hard gate where no warning is issued without explicit manager confirmation. The AI provides a draft; the human decides.
*   **Uncertainty Tiers:** Do not show managers a precise score like "87% efficiency." Instead, use defined coarse tiers:
    *   *Confirmed:* Data complete, consistent with peer average.
    *   *Corroborated:* Data mostly complete, supported by other metrics.
    *   *Unverified:* Data gaps detected (e.g., missing break times). **Action:** Block automatic warning generation.
*   **Transparency Artifact:** Create a **Model Card** and **Data Card** before deployment. These must state:
    *   Intended use: Drafting performance insights only, not final discipline.
    *   Limitations: Explicitly state that break times are currently missing from data and cause false lows.
    *   Owner: Name the specific person responsible for this output.
    *   Performance: Report measured results by subgroup, marking unmeasured areas as UNVERIFIED.

### Governance and Legal Routing
*   **Ownership:** Assign a specific owner to re-review this system whenever the data pipeline, model, or warehouse process changes.
*   **Legal Duty:** Whether automated disciplinary decisions violate labor laws or require specific AI disclosures under regulations like the EU AI Act is a legal determination. Route this immediately to counsel. Do not assume compliance; let legal name the regime and requirements.
