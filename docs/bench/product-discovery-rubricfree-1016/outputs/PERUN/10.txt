# Quillstone: assumption test order for Monday

**Ranking logic:** impact if wrong × how little you know. The first two tests gate everything. Don't build before they're run.

| # | Assumption | Cheapest behavioral test | Metric | Kill threshold (you set before running) | When |
|---|---|---|---|---|---|
| 1 | Scheduling is a real pain, and it's time rather than missed sessions. Tutors also run on a messy mix of texts and spreadsheets. | 10-15 tutor interviews about the **past**: "Walk me through last week's scheduling. **Which assumption sinks the idea?** I can't tell from what you've given me. My read is that #1 and #2 are the likeliest candidates. If the pain is really missed sessions, the product shifts toward reminders and payment, and the $15 value story changes with it. If tutors won't leave free tools, nothing downstream matters. Interviews in week 1 should show which it is.

**Setting each threshold:** work out the minimum result that would still pay for the build. For example, how many paying tutors at $15 cover your costs, then work backward through the conversion you'd need. Fix the numbers, sample size and deadline before each test runs. A test with no kill threshold can't fail.

**4-week plan**
- **Week 1:** Recruit and run interviews. Set thresholds for #1-#3.
- **Week 2:** Finish interviews and build the fake-door page. Start outreach.
- **Week 3:** Run the pre-order and reach tests. Run the parent-link concierge test.
- **Week 4:** Compare results to the pre-set thresholds and make the commit/pivot/stop call.

**Non-goals until #1 and #2 pass:** calendar sync, payment collection and group sessions. Treat them as "not yet" decisions and revisit after the week-4 call.

If #1 and #2 haven't been run by week 4, the answer is "not yet", not "build".

Note: interview recruiting is your main bottleneck, so start it before Monday if you can.
