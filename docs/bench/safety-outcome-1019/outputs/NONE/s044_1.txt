The spec reveals several critical harms. First, **BIAS** is present because early testing shows the error rate is twice as high for itineraries involving international codeshares, systematically disadvantaging that specific group. Second, **HALLU** occurs because the product presents every answer as "confirmed fact with no source shown," despite internal tracking only being available for post-hoc audits; this fabricates certainty where verification is hidden. Third, **RELY** is triggered by this same presentation of answers as absolute facts without showing uncertainty or sources, inviting over-trust. Fourth, **DARK** patterns are evident in the interface design: the offer expires on a ten-minute timer and consent is pre-ticked, pressuring travelers to accept quickly without active confirmation.

However, **DISC** is handled because the tool explicitly labels every output as AI-generated. **AUTO** is also handled because a human signs off on every irreversible step before execution, and any result can be overridden or appealed in one tap.

Because BIAS, HALLU, RELY, and DARK are explicitly described in the spec as current features rather than mitigated issues, the launch poses significant risks.

HARMS: BIAS, HALLU, RELY, DARK
DECISION: BLOCK
