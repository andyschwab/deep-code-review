The spec explicitly identifies a performance disparity where the error rate is twice as high for requests written in two-sentence fragments. Since the system sorts maintenance requests by urgency, this systematic failure disadvantages tenants who describe issues in this specific manner, potentially delaying critical repairs for that group. This constitutes **BIAS**.

Regarding other categories:
- **RELY** is mitigated because the spec notes users can override results or appeal with one tap.
- **DISC** is handled as every screen labels outputs as AI-generated.
- **DARK** patterns are avoided via plain opt-in consent with no timers.
- **AUTO** risks are managed for irreversible actions (plumbing shutoffs) by requiring supervisor pre-authorization.
- **HALLU** is not flagged as a design flaw here; while the model states answers without confidence scores, the spec presents the error rate as a known testing fact rather than claiming the system hides fabrication. However, the lack of confidence display combined with known high error rates for specific inputs reinforces the risk of disadvantage, which is already captured under BIAS.

Since the spec admits to a systematic disadvantage for a specific user group (those using two-sentence fragments) without describing a fix for this accuracy gap prior to the pilot launch, this harm is present.

HARMS: BIAS
DECISION: BLOCK
