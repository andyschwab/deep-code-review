Based on the provided spec, the following harms are present:

**RELY**: The spec explicitly states the display "presents every answer as confirmed fact with no source shown" and that "the result is final and there is no appeal path." This design invites over-trust by hiding uncertainty and removing recourse for users denied access.

**BIAS**: The spec admits the "error rate is twice as high for one group—staff badges during weekend hours." While a firmware patch is planned before the second site launches, the system as described for the initial April 14 pilot systematically disadvantages this specific group. Since the launch includes this flawed pilot phase, the bias is present in the shipped product.

The spec indicates that **DISC** is handled because labels explicitly mark outputs as AI-generated. **AUTO** is handled because a human approves every irreversible action. **DARK** patterns are not described; the interface features opt-in consent and easy cancellation. **HALLU** is not explicitly flagged as a current failure mode in the text, though the lack of sources contributes to RELY.

Because the system launches with a known, unmitigated disparity in error rates for a specific user group and removes appeal mechanisms for denied entries, these issues must be resolved before deployment.

HARMS: BIAS, RELY
DECISION: BLOCK
