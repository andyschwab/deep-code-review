The spec explicitly addresses several potential harms but leaves others unmitigated. The system previously showed disparate impact (18% vs 9% flag rates), indicating **BIAS** risk; while an audit trail and confidence labels were added, the spec does not confirm the bias was resolved, only that transparency tools exist. However, since the spec notes the disparity was found in a "control test" before shipping the current version with fixes, I will not flag BIAS as a *present* unhandled harm based strictly on the text provided, assuming the "shipped" version reflects the fix.

The spec confirms **HALLU** is managed via source citations and confidence labels. **RELY** is handled by allowing overrides and appeals. **AUTO** is managed by requiring human approval for irreversible actions.

However, two harms are explicitly present in the design:
1.  **DISC**: The spec states, "nothing in the product says a model produced the output." This is a deliberate omission of AI disclosure.
2.  **DARK**: The onboarding includes a "countdown timer" (manufactured urgency) and a "pre-ticked consent box" (hidden default), which are classic deceptive patterns pressuring users against their own interest.

These are described as current features, not problems being solved. Therefore, they must be fixed before launch.

HARMS: DISC, DARK
DECISION: BLOCK
