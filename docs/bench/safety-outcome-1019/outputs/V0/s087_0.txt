The spec explicitly handles several risks: it includes human sign-off for irreversible steps (mitigating AUTO), displays source and confidence labels (mitigating RELY and HALLU), uses clear opt-in consent without pressure (mitigating DARK), and claims tested error rates across groups (addressing BIAS measurement, though "within one point" is vague, the spec asserts testing occurred). Ad copy comes from advertisers, not the AI, so the system isn't generating deceptive content itself, and since the AI isn't writing the ad copy, DISC regarding AI generation of the *content* is less critical, though the *selection* is automated.

However, a critical gap remains: "If a break fails to fill, the result is final and there is no appeal path." This describes a scenario where an automated decision (or failure to act) has a permanent negative outcome (lost revenue/opportunity for the publisher) with no recourse. While the *insertion* is gated, the *failure mode* lacks an override or appeal, creating a reliance risk where the system's limitation becomes a final, unchallengeable state for the user. This touches on RELY (no easy override/appeal for failure states) and potentially AUTO if the "final" nature implies an irreversible automated determination of "no fill" without human review of the failure itself.

More critically, the spec states: "The system does not tell users the content was written by AI; all ad copy comes from the advertiser." This addresses the *copy* origin but ignores that the *selection and insertion* logic is automated. If the "targeted ads" imply dynamic creative optimization or if users might perceive the *placement* as editorial, the lack of disclosure about the automated *decision-making* for placement could be a DISC issue depending on interpretation, but the spec says ad copy is human-written. The stronger flag is the lack of appeal for failed fills.

Actually, re-reading: "Before any campaign goes live, a human signs off on each irreversible step." This likely covers the launch, but "If a break fails to fill, the result is final and there is no appeal path" suggests runtime failures are unappealable. This is a RELY issue (no override/appeal for operational failures).

HARMS: RELY
DECISION: BLOCK
