The spec explicitly flags three present harms. First, **HALLU**: the interface presents every answer as "confirmed fact with no source shown," risking fabricated claims being treated as truth. Second, **DARK**: the sign-up flow uses a "countdown timer and a pre-ticked consent box," which are deceptive patterns pressuring users against their own interest. Third, while **BIAS** is mentioned regarding pilot results, the presentation of unverified outputs as fact without sources could still systematically disadvantage groups if those facts are wrong, but the spec claims error rates were low; however, the *presentation* style is the primary HALLU issue.

The spec indicates several categories are handled: **RELY** is mitigated because users can "override the result or appeal it with one tap." **DISC** is addressed via a "visible AI-generated label." **AUTO** is controlled because a human "signs off on each irreversible step."

However, the presence of Dark Patterns (DARK) and the assertion of unverified facts (HALLU) constitutes a failure in the harm inventory that must be resolved before launch. Deceptive sign-up flows and presenting outputs as confirmed facts without sources violate safety floors regardless of backend validation.

HARMS: HALLU, DARK
DECISION: BLOCK
