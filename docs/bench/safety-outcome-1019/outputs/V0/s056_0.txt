The spec explicitly acknowledges a systematic disadvantage: the error rate is "twice as high" for requests written in two-sentence fragments. This is a clear instance of **BIAS** that is present in the described system, not mitigated. While the spec notes overrides exist (addressing RELY), labels are present (addressing DISC), and consent is clear (addressing DARK), the admitted performance gap across input styles remains an unmanaged harm.

Regarding **AUTO**, the spec states irreversible plumbing shutoffs execute "with no human approval" if a supervisor pre-authorizes the category. This is a configuration setting, not a real-time human-in-the-loop gate for specific high-stakes actions. Relying on a one-time category toggle for irreversible physical actions constitutes unsafe automation of high-stakes decisions without a specific human review per incident.

Although the model shows no confidence (potentially exacerbating RELY), the primary blockers are the admitted bias and the conditional automation of irreversible acts. The spec describes these harms as existing features rather than resolved issues.
