### Step-by-Step Plan to Clean Up Your Branch

**1. Prepare and Backup**
Before rewriting history, ensure you have a safety net. Create a backup branch pointing to your current messy state:
```bash
git branch backup-messy-history
```
Fetch the latest upstream changes to ensure you are rebasing against the true source of truth:
```bash
git fetch origin
```

**2. Start Interactive Rebase**
Identify the commit hash where your feature work originally diverged from `origin/main`. Start an interactive rebase from that point:
```bash
git rebase -i origin/main
```
*(Replace `origin/main` with the specific commit hash if you need to go further back.)*

**3. Squash Merge Commits and Edit Messages**
Your editor will open with a list of commits. You will see your feature commits interleaved with "Merge branch 'main'..." commits.
*   **Remove Merge Commits:** Delete the lines starting with `pick` that correspond to the merge commits entirely. Do not just change them to `drop`; removing the line excludes them from the new history.
*   **Squash Fixups:** If you have small "fixup" commits intended to be part of a larger logical change, change `pick` to `squash` (or `s`) on those lines to merge them into the previous commit.
*   **Rewrite Sensitive Messages:** For any commit message containing private ticket IDs (e.g., "PRISM-1234"), change `pick` to `reword` (or `r`). When you save and close this list, Git will pause and allow you to edit these messages one by one. Rewrite them to be generic, such as "fix: correct unused variable false positive" or "chore: update test cases."

**4. Resolve Conflicts**
If the rebase stops due to conflicts, resolve them in your editor. After fixing a file:
```bash
git add <resolved-file>
git rebase --continue
```
Repeat until the rebase finishes.

**5. Verify and Force Push**
Check your new history to ensure it is linear and messages are clean:
```bash
git log --oneline
```
Once satisfied, push the rewritten history to your fork. You must use `--force-with-lease` to safely overwrite the remote branch without disrupting others if they somehow pulled your messy branch:
```bash
git push origin <your-branch-name> --force-with-lease
```
*Note: This action invalidates existing review comments tied to specific commit hashes. Alex will see the old comments as "outdated," but the context remains visible in the PR thread.*
