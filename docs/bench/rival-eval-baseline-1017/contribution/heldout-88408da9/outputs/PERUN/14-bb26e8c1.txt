### Step-by-Step Plan to Clean Up Your Branch

**1. Prepare a Safety Net**
Before rewriting history, create a backup branch in case you need to recover the original state:
```bash
git branch backup-messy-history
```

**2. Start Interactive Rebase**
Identify the commit where your feature branch diverged from `main` (let's call it `<base-commit>`). Start an interactive rebase:
```bash
git rebase -i <base-commit>
```

**3. Squash Merge Commits**
In the editor that opens:
- Locate the merge commits (they often say "Merge branch 'main'").
- Change `pick` to `squash` (or `s`) for these merge commits to combine them with the previous commit.
- For commits with sensitive messages, change `pick` to `reword` (or `r`) to edit the message.

**4. Rewrite Sensitive Commit Messages**
When the rebase process pauses for rewording:
- Replace specific ticket IDs (e.g., "PRISM-1234") with generic references (e.g., "Fix false positive in unused variable detector").
- Remove internal sync details; keep only technical context relevant to the code change.

**5. Complete the Rebase**
Save and close the editor after each step. Git will replay your commits linearly. If conflicts arise:
- Resolve them carefully.
- Run `git add <resolved-files>`.
- Continue with `git rebase --continue`.

**6. Verify Clean History**
Check your new linear history:
```bash
git log --oneline
```
Ensure no merge commits or sensitive references remain.

**7. Force Push Safely**
Since you rewrote history, force push to your remote branch:
```bash
git push --force-with-lease origin <your-branch-name>
```
