*   **Days 3–5: Incremental Migration (Strangler Pattern).**
    *   Do not rewrite the whole module at once. Wrap the new logic in a feature flag.
    *   Route 1% of live traffic (or shadow traffic) to the new code path while the old path remains the source of truth.
    *   Compare outputs of old vs. new systems for every transaction. Discrepancies trigger an immediate alert.
*   **Days 6–7: Validation & Ramp.**
    *   If shadow traffic shows 100% parity, increase routing to 10%, then 50%.
    *   Perform the database migration on a cloned production environment one final time under load.
    *   **Your Oversight Required:** Review the parity reports and sign off on the 50% ramp.
*   **Day 8: Final Decision Gate.**
    *   **Go:** If error rates are zero and parity is confirmed at 50% traffic. Proceed to 100% cutover plan.
    *   **No-Go:** If any data mismatch or unhandled exception occurs. Revert flags to 0% and delay the release. The code freeze becomes a hard stop.
*   **Day 9: Contingency Prep.**
    *   If "Go": Prepare the final merge request and communication plan for the cutover.
    *   If "No-Go": Document the specific blockers and draft the delay announcement.
