For ZenFlow's March 15 beta, reject "track everything." Instrument only events that answer specific questions about value delivery and retention. With 5,000 downloads, your North Star is **Weekly Active Users Completing a Core Session**, not total downloads or screen views. Screen views are vanity; they rise regardless of value. Focus on the AARRR funnel bottom-up: if users don't retain the core action, acquisition data is useless.

**Critical Events (Instrument Before Launch)**
These events answer the only questions that matter for an MVP: Do users find value? Do they return?

1.  `session_started`
    *   **Question:** Did the user attempt the core value proposition?
    *   **Properties:** `session_type` (meditation/sleep), `duration_target`, `entry_point`.
    *   **Why:** Defines activation. Without this, you cannot measure if the app works.

2.  `session_completed`
    *   **Question:** Did the user receive full value? (Your "Aha!" moment).
    *   **Properties:** `session_id`, `actual_duration`, `completion_rate` (0-100%).
    *   **Why:** Completion correlates strongly with retention in content apps. This is your primary activation metric.

3.  `paywall_viewed`
    *   **Question:** Did the user reach the monetization gate?
    *   **Properties:** `trigger_context` (trial_expiry_warning/content_lock), `days_since_install`.
    *   **Why:** Measures funnel leakage before conversion.

4.  `subscription_started` (Trial)
    *   **Question:** Did the user commit to the trial?
    *   **Properties:** `plan_type`, `trial_duration_days`.
    *   **Why:** Your primary conversion event.

5.  `user_identified`
    *   **Question:** Can we track this user across sessions?
    *   **Properties:** `pseudonymous_user_id` (stable, non-PII).
    *   **Why:** Essential for retention cohorts. *Note: Do not use raw PII here; route identity mapping to privacy compliance protocols.*

**Deferred Events (Do Not Instrument Yet)**
Save engineering bandwidth and reduce noise. Add these only if specific hypotheses fail later.

*   `audio_paused` / `audio_resumed`: Unless you suspect a technical bug causing drop-offs, this is noise. Total completion matters more than intermediate pauses.
*   `settings_changed`: Irrelevant for early retention.
*   `screen_view`: Generic views are vanity. Only track views if they represent a distinct funnel step (e.g., `paywall_viewed` above).

**Implementation Rules for Engineering**
*   **Stable Identity:** Every event must carry a `pseudonymous_user_id` that persists across reinstalls/sessions to enable cohort analysis.
*   **Timestamps:** Use server-side receipt time where possible to avoid clock-skew in retention calculations.
*   **No Benchmarks:** Do not hardcode "good" thresholds (e.g., "40% completion is good"). Compare Week 2 retention to Week 1 baseline only.
