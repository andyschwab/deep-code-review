# ZenFlow Beta Tracking Plan (Priority: Pre-Launch)

**Goal:** Validate trial-to-paid conversion and Day-7 retention without data noise.
**Principle:** Track only actions that inform a specific immediate decision. Discard "screen views" unless they represent a unique funnel step.

### Tier 1: Critical (Must Ship March 15)
*These events are non-negotiable for calculating conversion rates, retention, and revenue. Without these, you cannot measure success.*

| Event Name | Trigger | Key Properties | Decision Informed |
| :--- | :--- | :--- | : |
| `app_installed` | First open after download | `install_source`, `device_os`, `waitlist_member` (bool) | Validates acquisition channel quality. |
| `onboarding_completed` | Final step of signup flow | `duration_seconds`, `steps_skipped` | Identifies friction in account creation. |
| `paywall_viewed` | User lands on subscription screen | `context` (trial_end, manual_upgrade), `plan_displayed` | Measures paywall exposure rate. |
| `trial_started` | Successful entry into free trial | `plan_type`, `trial_duration_days` | **Primary Conversion Metric.** |
| `content_started` | Audio/Meditation begins playing | `content_id`, `content_type` (session/story), `duration_total` | Validates content engagement. |
| `content_completed` | Audio finishes naturally | `content_id`, `percent_listened` (should be 100) | **Key Retention Signal.** Differentiates true usage from churn. |
| `subscription_converted` | Payment successful post-trial | `plan_type`, `revenue`, `currency` | **Primary Revenue Metric.** |
| `subscription_cancelled` | User cancels trial or sub | `cancel_reason` (if captured), `days_remaining` | Identifies churn drivers. |

### Tier 2: High Value (Implement if time permits)
*These help optimize the user experience but are not required for top-line reporting in week one.*

| Event Name | Trigger | Key Properties | Decision Informed |
| :--- | :--- | :--- | :--- |
| `search_performed` | User searches library | `query_text`, `results_count` | Identifies content gaps. |
| `favorite_added` | User bookmarks content | `content_id`, `content_type` | Signals high intent/loyalty. |
| `settings_updated` | User changes playback/settings | `setting_name`, `new_value` | Validates feature utility. |

### Explicitly Excluded (Do Not Track Yet)
*These create noise and storage costs without informing immediate beta decisions.*
*   **Screen Views:** Do not track generic screen views (e.g., `home_viewed`, `library_viewed`). Rely on `app_installed` and specific action events to infer flow.
*   **Playback Controls:** Do not track `pause`, `resume`, `skip_forward`, or `volume_change`. These are functional interactions, not conversion signals. Aggregate these later via session logs if needed for product tuning, not marketing analytics.
*   **App Background/Foreground:** Unless you have a specific hypothesis about background usage affecting retention, skip this for now to save volume.

### Implementation Notes for Engineering
1.  **Naming Convention:** Use `snake_case` (e.g., `trial_started`). Ensure consistency across iOS and Android.
2.  **User Identity:** Ensure `user_id` is generated at `app_installed` and persisted to link anonymous usage to the account upon `trial_started`.
3.  **Data Types:** Ensure `revenue` is sent as an integer (cents) to avoid floating-point errors.
4.  **Validation:** Test that `content_completed` only fires when the audio reaches 95%+ completion, not when the user manually exits.

**Note:** This plan focuses on the "North Star" metrics (Trial Start, Content Completion, Conversion). Intermediate interaction data can be added once you have 1,000+ active users and specific UX hypotheses to test.
