### Implementation Plan: Currency Formatting Extraction

**Phase 1: Specification & Baseline (G0–G1)**
1.  **Freeze & Baseline:** Pin the current commit SHA. Run `npm run test:full` to establish a green baseline.
2.  **Define Scope:** Explicitly separate "core formatting logic" (including the EUR 3-decimal rule) from "checkout-specific flow logic." The new package will contain *only* the core logic.
3.  **Data Sampling:** Extract the specific set of 1,000 transactions requested by Priya. Run the current function against them and save the output as `baseline_output.json`. This is the immutable truth for verification.

**Phase 2: Package Extraction (G2–G3)**
4.  **Scaffold Package:** Create the new standalone package structure (e.g., `packages/currency-formatter`).
5.  **Migrate Core Logic:** Move the formatting functions and the specific EUR rounding logic into the new package.
6.  **Isolate Checkout Logic:** Identify the checkout-specific code currently mixed in. Refactor the twelve callers to implement this logic locally or via a new checkout-specific helper, ensuring the new package remains pure.
7.  **Unit Tests:** Port existing unit tests to the new package. Add specific regression tests for the EUR 3-decimal edge cases.

**Phase 3: Migration (G4)**
8.  **Update Imports:** Systematically update all twelve modules to import from the new package location.
9.  **Refactor Callers:** Apply the isolated checkout logic identified in Step 6 to the relevant modules.
10. **Complex Test Repair:** Update the complex checkout module tests. Do not simplify them; adapt them to the new import structure while ensuring they still validate the original business requirements.

**Phase 4: Verification (G5–G6)**
11. **Automated Regression:** Run `npm run test:full`. The build fails if any test (including the complex checkout ones) does not pass.
12. **Data Integrity Check:** Run the new package against the 1,000 sampled transactions. Generate `new_output.json`.
13. **Diff Report:** Compute the diff between `baseline_output.json` and `new_output.json`.
    *   **Success Criteria:** Zero differences. Any deviation in financial values is a critical failure.
14. **Generate Report:** Compile the "Before-and-After" report for Priya, explicitly stating: "0 discrepancies found across 1,000 samples; EUR 3-decimal rounding verified."

**Phase 5: Integration & Release (G7–G8)**
15. **Code Review:** Submit the changes for independent review, attaching the verification report and the green test suite results.
16. **Merge & Deploy:** Upon approval, merge to the integration branch and deploy.
17. **Post-Deploy Sanity:** Run a smoke test on the live finance and checkout services using a subset of the sample data to confirm runtime behavior.

**Deliverables:**
*   New standalone `currency-formatter` package.
*   Updated source code for all twelve modules.
*   Green `npm run test:full` suite.
*   Verification Report for Priya (PDF/Markdown) with the 1,000-transaction diff analysis.

**Notes:**
*   Do not proceed to Phase 3 until the baseline data (Step 3) is secured; this is the only way to prove financial accuracy.
*   If the complex checkout tests fail during migration, fix the test implementation, not the business logic, to match the baseline behavior.
