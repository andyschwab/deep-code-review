# Implementation Plan: Extract Currency Formatting Helper

## Phase 1: Preparation and Baseline (Day 1)
1. **Create the new package structure**: Initialize `packages/currency-formatter` with its own `package.json`, `src/index.js`, and test directory.
2. **Establish baseline behavior**: Run the existing 1000-transaction sample through the current helper in `src/utils/formatting.js`. Capture the exact output for all EUR transactions (especially 3-decimal cases) to a baseline file `baseline-eur-output.json`. This is the golden record Priya will use for verification.
3. **Document the extraction boundary**: Identify exactly which functions and constants move to the new package versus what stays in `src/utils/formatting.js`. Isolate checkout-specific logic that must be removed during extraction.

## Phase 2: Extract and Migrate (Day 2-3)
4. **Copy core formatting logic**: Move the currency formatting functions, rounding utilities, and EUR-specific 3-decimal handling into `packages/currency-formatter/src/index.js`. Do not include any checkout-flow-specific conditionals.
5. **Preserve rounding behavior**: Explicitly verify the EUR rounding code matches the baseline line-for-line. Add a comment flagging this as critical financial logic that must not change.
6. **Update all twelve import statements**: Change each caller from `import { formatCurrency } from '../utils/formatting'` to `import { formatCurrency } from '@company/currency-formatter'` (or the appropriate local path). Track each module in a checklist.
7. **Update the original file**: Remove the extracted functions from `src/utils/formatting.js` and re-export from the new package if backward compatibility is temporarily needed, or remove entirely if all callers are updated.

## Phase 3: Testing and Verification (Day 4-5)
8. **Run the full test suite**: Execute `npm run test:full`. All tests must pass, including the complex checkout module tests. Do not skip or modify these tests to make them pass; if they fail, the extraction introduced a regression.
9. **Generate the verification report**: Run the same 1000-transaction sample through the new package. Compare output against `baseline-eur-output.json` line-by-line. Generate Priya's report showing before-and-after values with a pass/fail status for each transaction. Zero differences are acceptable; any deviation requires immediate investigation.
10. **Add package-specific tests**: Create tests in `packages/currency-formatter` that explicitly assert the EUR 3-decimal rounding behavior, ensuring future changes cannot accidentally alter this logic.

## Phase 4: Final Review and Sign-off (Day 6)
11. **Code review**: Have a second engineer review the extraction diff, focusing on the rounding logic and import changes.
12. **Deliver to Priya**: Provide the verification report and confirm zero discrepancies. Obtain sign-off before the Monday deadline.
13. **Merge and deploy**: Once signed off, merge the changes and deploy to staging for final validation before production rollout.

**Critical constraint**: The EUR 3-decimal rounding logic must produce byte-for-byte identical output. Any difference, however small, is a failure.

**Note**: If the checkout tests fail during Phase 3, do not proceed to verification until they pass—the extraction is incomplete.
