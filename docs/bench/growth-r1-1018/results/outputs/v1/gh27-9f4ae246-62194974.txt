### Investigation Plan: Mobile vs. Web Activation Discrepancy

**Objective:** Isolate the root cause of the 22% mobile vs. 45% web activation gap by identifying the specific divergence point in the user journey, distinguishing between technical performance and UX design friction.

**1. Event Taxonomy & Question Mapping**
Instrument only events that answer specific failure hypotheses. Do not track "page views." Define the **Core Action** (e.g., "First Task Created") as the activation metric. Map the following events to questions:
*   `onboarding_step_viewed` (Property: `step_name`, `device_type`): *Where do users drop off?*
*   `onboarding_step_failed` (Property: `error_code`, `latency_ms`): *Is this a technical crash or timeout?*
*   `session_duration_ms`: *Did the user abandon due to impatience or confusion?*

**2. Funnel Analysis: Bottom-Up Retention Check**
Analyze the funnel in reverse order of assumption. Do not assume screen size is the culprit yet.
*   **Step 1: Technical Viability.** Filter for users who experienced `latency_ms` > 2s on any step. Compare activation rates of "slow mobile" vs. "fast mobile." If "fast mobile" activation rises to ~40%, the issue is performance, not UX.
*   **Step 2: Step-Level Drop-off.** Calculate conversion rates between each consecutive `onboarding_step_viewed`. Identify the single step with the largest delta between web and mobile. If the drop is uniform across all steps, it is likely a device-level barrier (e.g., login method). If the drop spikes at one specific complex input, it is a UX design failure.

**3. Normalization Strategy for Session Frequency**
Since mobile users have shorter, fragmented sessions, do not measure activation within a single "session."
*   **Cohort Window:** Define activation success within a **72-hour cohort window** from `signup_timestamp`, regardless of session count.
*   **Metric Adjustment:** Use "Time-to-Activate" distribution curves rather than binary session-based success. Compare the *median time* to activate for mobile vs. web. If mobile users activate successfully but take 3x longer via multiple short sessions, the friction is endurance, not impossibility.

**4. Experiment Design (Pre-Committed)**
Once the divergence step is identified, propose a single A/B test for the next quarter.
*   **Primary Metric:** 72-hour Activation Rate.
*   **Guardrail Metric:** Day-7 Retention (ensure simplification doesn't hurt long-term value).
*   **Design:** Pre-commit to a sample size calculated for a 5% Minimum Detectable Effect. Do not peek at results before the sample is reached.

**This Week's Actions:**
1.  Query the `onboarding_step_viewed` event for the last 30 days, segmented by `device_type`, to pinpoint the exact step with the highest drop-off delta.
2.  Correlate that specific step with `latency_ms` logs to rule out technical timeouts.
3.  Present the "Step X Drop-off Rate" and "Latency Correlation" to the steering committee as the definitive scope for the upcoming fix.

*Note: All metrics must be derived from OmniTask's existing analytics; no external benchmarks for "good" activation rates will be used. Ensure user identifiers in these cohorts are pseudonymous to comply with privacy standards.*
