# CodeLeap Signup Funnel Friction Analysis Plan

## Executive Summary
To address the 65% drop-off post-skills assessment (introduced March 12), we must isolate whether friction stems from **length** (time/effort) or **content** (difficulty/anxiety). The following micro-conversions and analysis structure will validate the root cause using existing logs to inform the April 1st cohort strategy.

## 1. Essential Micro-Conversions to Extract
Query existing server logs and database timestamps for these specific events between March 12 and present:

| Micro-Conversion | Data Point to Extract | Diagnostic Value |
| :--- | :--- | :--- |
| **Assessment Start** | `timestamp_start` | Establishes entry volume. |
| **Question View** | `question_id`, `view_timestamp` | Identifies exact drop-off questions. |
| **Question Interaction** | `input_type` (text/select), `attempts_per_question` | Distinguishes between "thinking time" and "struggle." |
| **Assessment Complete** | `timestamp_end`, `total_score` | Measures completion rate vs. performance. |
| **Post-Assessment Exit** | `exit_location` (immediate close vs. curriculum view) | Determines if rejection is of the *test* or the *fit*. |

## 2. Analysis Structure

### A. The "Length vs. Difficulty" Matrix
Segment users who abandoned into four quadrants based on **Time Spent** (duration between start and last event) and **Progress Depth** (last question ID viewed).

*   **High Time + Low Progress:** Users stuck on early questions.
    *   *Diagnosis:* **Content Difficulty.** The questions are too hard or confusing immediately.
    *   *Signal:* High variance in `attempts_per_question` for Q1–Q3.
*   **Low Time + Low Progress:** Users quitting immediately upon seeing the format.
    *   *Diagnosis:* **Expectation Mismatch/Intimidation.** The UI looks too rigorous before they start.
*   **High Time + High Progress:** Users quitting near the end.
    *   *Diagnosis:* **Fatigue.** The assessment is too long.
    *   *Signal:* Drop-off spikes at specific intervals (e.g., after Q10).
*   **Low Time + High Progress:** Users rushing and quitting.
    *   *Diagnosis:* **Low Intent.** Likely not a product issue.

### B. The "Score Correlation" Check
Correlate `total_score` of completers against their `time_to_complete`.
*   If completers with low scores take significantly longer than high scorers, the content is likely too difficult for the target audience, validating the "rigorous" assumption.
*   If drop-off occurs uniformly regardless of question difficulty ratings, length is the primary driver.

### C. Cohort Comparison (Pre/Post March 12)
Compare the `time_on_page` for the signup step *before* March 12 (no assessment) vs. *after*.
*   If total funnel time increased by >3 minutes but conversion dropped >50%, length is the culprit.
*   If time increased slightly but conversion plummeted, the *nature* of the questions is the barrier.

## 3. Strategic Recommendation Framework

Based on the data above, present one of these two paths to the executive team:

**Path A: Simplify the Assessment (If Data Shows Length/Fatigue)**
*   *Trigger:* Drop-off correlates with question count (>10 questions) or time (>5 mins).
*   *Action:* Reduce questions to 5 core competency checks. Remove open-text fields in favor of multiple-choice to reduce cognitive load.
*   *Goal:* Reduce friction to get users to the curriculum value prop faster.

**Path B: Add Motivational Copy/Context (If Data Shows Difficulty/Anxiety)**
*   *Trigger:* Drop-off spikes at specific "hard" questions or users spend high time on early questions then quit.
*   *Action:* Insert micro-copy before the assessment: *"This isn't an exam. There are no wrong answers. We use this to personalize your learning path."* Add a progress bar if missing.
*   *Goal:* Reframe the assessment from a "gate" to a "service."
