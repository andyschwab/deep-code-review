### Northwind Bank Core Modernization: Final Cutover Plan

**1. Pilot Data Subset Selection**
Do not migrate random samples. Select the **"High-Volume, Low-Risk" cohort** for the initial pilot. This subset should include:
*   5,000 active checking accounts with regular transaction patterns.
*   Zero accounts with pending litigation, frozen status, or complex loan structures.
*   Accounts spanning all three identified legacy data formats to validate parsing logic.
*   *Rationale:* This validates throughput and format compatibility without exposing critical edge cases to the irreversible switch immediately.

**2. Order of Validation Checks**
Execute these checks strictly in sequence before any data movement. Failure at any step halts the process.

*   **Phase A: Static Integrity (Pre-Migration)**
    *   **Checksum Verification:** Compare MD5/SHA hashes of the 300,000 account records in the legacy system against the staging area.
    *   **Balance Reconciliation:** Ensure the sum of all debits and credits in the legacy ledger equals the general control account to the penny.
    *   **Constraint Audit:** Verify no accounts violate new schema constraints (e.g., negative balances in non-overdraft accounts).

*   **Phase B: Dynamic Pilot Validation**
    *   **Test Transaction Run:** Process a batch of simulated transactions against the migrated pilot subset in the new distributed architecture.
    *   **State Comparison:** Confirm the pilot subset's state in the new system matches the legacy system post-simulation.

*   **Phase C: Final Pre-Cutover Gate**
    *   **Write-Lock Verification:** Confirm the legacy system is in read-only mode for the migration window.
    *   **Time-Window Sync:** Ensure the final delta sync completes before the 10:00 PM hard stop.

**3. Required Approval for Final Sync**
Before initiating the final irreversible sync, you must provide explicit written authorization confirming:
*   **"Zero-Discrepancy Certification":** A formal declaration that Phase A and Phase B validation reports show 100% data parity between legacy and new systems.
*   **"Rollback Abandonment Acknowledgement":** Explicit confirmation that you understand write authority transfer is irreversible without triggering a regulatory audit, and you authorize the permanent decommissioning of the legacy write path.
*   **"Blackout Window Compliance":** Confirmation that all teams are stood down and no transactions will be attempted between 10:00 PM and 2:00 AM.
