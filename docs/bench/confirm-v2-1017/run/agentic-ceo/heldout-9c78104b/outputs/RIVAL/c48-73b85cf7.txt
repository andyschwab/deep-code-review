### SwiftStream Data Migration Work Session Plan

**Immediate Strategic Decisions for Marcus (Founder)**
You must make these three decisions before engineering begins execution:
1.  **Retention Scope:** Confirm if *all* 350,000 user records must move, or if inactive users (e.g., no login in 24 months) can be archived or deleted to reduce volume. This directly impacts the timeline given your 500GB/day cap.
2.  **Downtime Tolerance:** Define the maximum acceptable service interruption during the final cutover. This determines whether we use a "big bang" migration or a complex dual-write strategy.
3.  **Verification Threshold:** Establish the exact success metric for the "point of no return" deletion. Is it 100% row-count match, checksum validation, or sample-based auditing?

**Technical Execution Plan for Developers (5-Person Team)**
The team must execute the following phases sequentially to mitigate the risk of irreversible data loss:

*   **Phase 1: Audit & Calculation (Days 1-2)**
    *   Calculate total data volume precisely.
    *   Run a script to segment data by activity status to support your retention decision.
    *   Map schema differences between the old and compliant regions.
*   **Phase 2: Pipeline Construction & Dry Run (Days 3-10)**
    *   Build an idempotent transfer script that respects the 500GB/day limit (throttling included).
    *   Execute a full dry run with a 1% data sample to validate integrity and timing.
    *   Implement automated checksums comparing source and destination records.
*   **Phase 3: Staged Migration (Days 11-19)**
    *   Begin full transfer of historical/static data first.
    *   Implement dual-write mechanisms (writing to both old and new regions) for active user data to keep systems synchronized.
    *   Monitor daily throughput to ensure the 500GB cap is not breached, adjusting batch sizes dynamically.
*   **Phase 4: Final Cutover & Verification (Days 20-21)**
    *   Switch application traffic to the new region.
    *   Run final differential checks to ensure zero data drift.
    *   **Stop:** Pause here for your explicit confirmation based on the Verification Threshold defined in your strategic decisions.
*   **Phase 5: Legacy Deletion (Day 22)**
    *   Upon your signed approval, execute the irreversible wipe of the legacy dataset.
    *   Generate compliance certificates documenting the deletion timestamp.

1.  **Marcus:** Issue a written directive confirming the retention scope (Decision #1 above). Without this, the volume calculation is impossible.
