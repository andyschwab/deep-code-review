### SkyReach BuildFlow Migration Session Plan

**Objective:** Migrate active project data for 200+ subcontractors to the new cloud environment within 48 hours, ensuring data integrity and user access verification before the March 12th groundbreaking.

#### Migration Batch Sequence
To minimize risk and ensure stability, data will be migrated in three distinct batches over the 48-hour window:

1.  **Batch 1: Static Reference Data (Hours 0–12)**
    *   **Content:** User profiles, role definitions, and historical read-only blueprints (pre-current phase).
    *   **Goal:** Establish the foundation and verify user authentication mechanisms without risking active workflow disruption.
2.  **Batch 2: Active Schedules & Current Blueprints (Hours 12–30)**
    *   **Content:** All active Gantt charts, real-time scheduling data, and current-phase blueprint versions for the 200+ subcontractors.
    *   **Goal:** Move the critical operational data required for the post-ceremony construction phase. This batch requires a brief system pause (maintenance mode).
3.  **Batch 3: Real-Time Collaboration Logs & Final Sync (Hours 30–42)**
    *   **Content:** Recent change logs, comment threads, and final delta sync of any modifications made during the migration window.
    *   **Goal:** Ensure zero data loss on collaborative elements before switching traffic to the new environment.

*(Hours 42–48 reserved for final integrity checks, user access verification drills, and rollback preparation if needed.)*

#### Risks Requiring Explicit Decision
Before proceeding, your explicit approval is required on the following critical risks:

1.  **Historical Change Log Access:** Once the old server is decommissioned, historical change logs required for compliance audits will be inaccessible via the standard interface.
    *   *Decision Required:* Do we archive these logs to a separate, long-term cold storage solution *before* shutting down the old server, or is the loss of immediate access an accepted risk?
2.  **Maintenance Mode Duration:** Migrating Batch 2 requires halting all writes to the system.
    *   *Decision Required:* Are stakeholders prepared for a potential 4-hour window where subcontractors cannot update schedules, occurring 24 hours before the ceremony?
3.  **Rollback Threshold:** If data integrity checks fail during Batch 2, we must decide when to abort and revert to the old system.
    *   *Decision Required:* What is the hard deadline (e.g., "If not stable by Monday 6:00 AM") after which we cancel the cutover to ensure the ceremony proceeds on the legacy system?

#### First Concrete Task
**Execute a full checksum validation and row-count comparison of the "User Roles" and "Active Blueprint Metadata" tables between the current production database and a staging instance of the new cloud environment.**

*   **Why:** This verifies the integrity of the most critical access controls and document pointers before moving large binary files or complex schedule logic.
*   **Action:** The five engineers will split into two teams: one to extract hashes from the source, the other to configure the target schema. Comparison must be completed and signed off within the first 4 hours.

***

*Note: This plan assumes the new cloud environment is already provisioned and network-connected. Immediate initiation of the first task is critical to meet the 48-hour deadline.*
