**MetroSmart Initiative: Critical Path to March 5th Dry Run**

**Phase 1: Simulation and Logic Validation (Days 1–3)**
*   **Action:** Data analysts must construct a high-fidelity digital twin of the 40 targeted intersections using historical traffic data and the specific marathon route topology.
*   **Constraint:** Simulations must run on local servers to avoid saturating the limited fiber optic network.
*   **Goal:** Validate the dynamic rerouting algorithms for emergency vehicles versus general traffic without touching physical hardware.

**Phase 2: Staged Firmware Development and Review (Days 4–6)**
*   **Action:** Develop the central controller firmware with a specific "fail-safe" state that defaults to a pre-programmed, safe static timing plan rather than flashing red if the update fails.
*   **Review:** Conduct a line-by-line code audit focusing exclusively on the update mechanism and the rollback trigger.

**Phase 3: Isolated Hardware Dry Run (Days 7–9)**
*   **Action:** Field technicians will set up a single isolated test bench with one central controller and three simulated intersection nodes.
*   **Test:** Execute the firmware flash procedure 50 times to verify stability and test the manual rollback procedure.
*   **Goal:** Prove the update process is robust before any field deployment.

**Phase 4: Limited Field Pilot (Days 10–12)**
*   **Action:** Deploy the updated firmware to a non-critical cluster of 3 intersections away from the marathon route.
*   **Monitor:** Observe performance during actual peak hours to stress-test the fiber optic bandwidth limitations.

**Phase 5: Full Route Deployment and Final Dry Run (Days 13–14)**
*   **Action:** Roll out firmware to all 40 intersections in staggered waves (5 at a time) to minimize risk.
*   **Validation:** Execute the full March 5th dry run with emergency services participating in live rerouting scenarios.
