### Northwind Capital Emergency Refactor Session Plan

**Immediate First Task:**
Conduct a 30-minute "Freeze and Baseline" session. Lock the current codebase to prevent new commits, spin up a production-mirror environment, and run the existing load test suite to capture the exact latency baseline at 50k transactions/minute. Do not write a single line of new code until this baseline is recorded and agreed upon by the lead architect.

**Session Structure & Workflow:**

1.  **Planning Phase (Hours 0–2):**
    *   **Objective:** Define the "Point of No Return" criteria and rollback strategy.
    *   **Action:** Map the specific order logic functions causing latency. Create a step-by-step migration path that allows parallel running of old and new logic if possible, or defines a hard cut-over window.
    *   **Output:** A signed-off technical specification document detailing the refactor scope, risk mitigation, and exact rollback triggers.

2.  **Coding Phase (Hours 2–8):**
    *   **Objective:** Execute the core logic rewrite in isolated branches.
    *   **Action:** Senior engineers pair-program the critical path components. Junior developers handle unit test updates and peripheral tooling.
    *   **Constraint:** Code is merged only after passing local stress tests exceeding 60k transactions/minute (20% buffer).

3.  **Review & Validation Phase (Hours 8–12):**
    *   **Objective:** Verify stability under peak load.
    *   **Action:** Deploy to the staging environment. Run continuous soak tests and spike tests. Perform a "game day" simulation of a failed deployment to practice the rollback procedure.
    *   **Output:** Go/No-Go decision based on performance metrics matching the success criteria defined in Phase 1.

**Decision Authority Matrix:**

*   **Requires Product Lead (Your) Approval:**
    *   Final Go/No-Go decision for production deployment.
    *   Authorization to trigger the rollback procedure if latency exceeds the baseline by >5% during staging.
    *   Approval of the communication plan for stakeholders if the deadline is threatened.
    *   Definition of the acceptable latency threshold (e.g., must be under X milliseconds).

*   **Delegated to Senior Engineers:**
    *   Selection of specific algorithms or data structures for the rewrite.
    *   Resolution of merge conflicts and code review approvals.
    *   Configuration of the load testing environment and parameters.
    *   Determination of specific unit test coverage requirements.
    *   Execution of the deployment scripts once Go-ahead is given.

**Critical Success Factor:**
The success of this session relies on strict adherence to the baseline established in the first task. Without knowing exactly where you stand today, you cannot measure improvement or guarantee safety. Every subsequent decision must reference that initial data point.

*Note: Ensure all team members are aware that no non-essential meetings are to occur during the 12-hour window. Communication should be limited to the war room channel.*
