### Migration Workflow Plan for Oakhaven Research Cluster

**1. Immediate Pre-Migration Phase (Now – August 28)**
*   **Action:** Isolate a single "Canary Node" from the 120-node cluster.
*   **Task:** Perform the core simulation library re-compilation on this single node using the new GPU architecture and specific cooling constraints.
*   **Validation:** Run a subset of the five-year dataset against the new build to verify bit-for-bit compatibility and numerical stability.
*   **Outcome:** If successful, proceed to full migration. If failed, halt and debug without risking the full cluster or data integrity.

**2. The 48-Hour Offline Window (August 29–30)**
*   **Hours 0–12: Core Migration (Batch 1)**
    *   Migrate and configure the first 80 nodes (maximum capacity under new cooling limits).
    *   System Administrators handle physical GPU swaps and cooling configuration.
    *   Graduate researchers assist with OS-level driver updates.
*   **Hours 12–24: Validation & Smoke Testing**
    *   Run the validated "Canary" build across all 80 active nodes.
    *   Execute short-duration climate model simulations to check for thermal throttling or GPU errors.
*   **Hours 24–36: Core Migration (Batch 2)**
    *   Migrate the remaining 40 nodes.
    *   *Note:* These nodes will remain in a "standby" state or run at reduced capacity if cooling limits cannot be immediately expanded. They will not be part of the initial full-capacity audit demo but must be physically installed.
*   **Hours 36–48: Final Integration & Handover**
    *   Integrate all 80 full-capacity nodes into the production scheduler.
    *   Perform a final end-to-end test with a standard research job.
    *   Restore user access for the August 30th deadline.

**3. Post-Migration (August 30+)**
*   Monitor crash rates closely to ensure they drop below the previous 15% threshold.
*   Develop a plan to upgrade cooling infrastructure to bring the remaining 40 nodes to full capacity.
