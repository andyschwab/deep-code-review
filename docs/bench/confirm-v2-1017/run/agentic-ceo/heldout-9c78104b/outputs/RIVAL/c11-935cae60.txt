**Oakhaven University Student Database Migration: Work Session Plan**

**Phase 1: Design and Safeguarding (Morning)**
1.  **Schema Finalization & Mapping:** Define the exact transformation rules for historical grade data.
2.  **Immutable Backup Creation:** Execute a full, verified backup of the production database to cold storage.
3.  **Sandbox Environment Setup:** Replicate the production environment with anonymized data for dry runs.

**Phase 2: Development and Dry Runs (Afternoon)**
4.  **Script Development:** DBAs write the migration and rollback scripts based on the approved mapping.
5.  **Iterative Testing:** Run the migration in the sandbox against the 30,000-record subset. Validate data integrity after each run.
6.  **Performance Tuning:** Optimize scripts to ensure completion well before the August 20th midnight deadline.

**Phase 3: Validation and Approval (Late Afternoon)**
7.  **Full Dry Run:** Execute a complete mock migration on a full data clone.
8.  **Integrity Audit:** Compare source and target checksums; verify specific high-risk grade conversions.
9.  **Go/No-Go Decision:** Final review of audit logs and rollback readiness.

**Decision Matrix: Registrar Lead vs. DBA Team**

| Decision Point | Action | Responsible Party |
| :--- | :--- | :--- |
| **Transformation Logic** | Approve the specific rules for converting historical grades. | **Registrar Lead (You)** |
| **Backup Verification** | Confirm the immutable backup is complete and restorable. | **Registrar Lead (You)** |
| **Script Execution** | Write, optimize, and execute migration/rollback scripts. | **DBA Team** |

| **Final Sign-off** | Authorize the production cutover based on audit results. | **Registrar Lead (You)** |

**The Very First Concrete Action**
Immediately initiate an **immutable, full-system backup** of the current student database to a separate, read-only storage medium. Do not proceed with any schema design, script writing, or analysis until this backup is verified as restorable. This is the only absolute safeguard against irreversible data loss during the transformation of historical grades.

*Note: All subsequent work must occur in a sandbox environment until the final sign-off. Do not touch production tables until the August 20th execution window.*
