**Decision:** Proceed with a "Safety-First Audit" phase immediately; do not begin data transfer until the allergy field mapping is validated by a clinical expert and a frozen legacy snapshot is secured. *   **Throughput Required:** 2,000,000 records / 83 days = ~24,100 records/day.
*   **Team Capacity:** 8 staff total. If 2 are dedicated to audit/prep and 6 to migration logic, daily target per person is ~4,000 records (feasible only with automation, not manual entry).
*   **Risk Buffer:** 0 days allocated for re-work if allergy mapping fails post-migration.

**Decisions Made:**
1.  **Who Audits Data Quality First:** A **Senior Veterinarian (Clinical Lead)**, not a data analyst. Only a clinician can verify that "Penicillin allergy" in the legacy system maps correctly to the new schema's "Contraindications" field. Data analysts lack the medical context to spot life-threatening mapping errors.
2.  **Policy Choices You Must Make Now:**
    *   **Conflict Resolution:** When legacy records conflict (e.g., two different birth dates), default to the **most recent clinical encounter** unless flagged by the Clinical Lead.
    *   **Missing Data:** If an allergy field is null in the legacy system, the new system must flag the record as **"Unverified – Manual Review Required"** before any insurance claim can be processed against it. Do not auto-fill with "None."
    *   **Cut-off Date:** No new non-emergency data entry in the legacy system after **October 15**. All changes after this date must be paper-based and entered post-migration.
3.  **First Actionable Step to Secure Legacy Database:**
    *   **Action:** Issue a command to the IT lead to perform a **full, read-only binary backup** of the legacy database immediately and store it on offline, immutable storage.
    *   **Constraint:** Revoke all "write" permissions for the migration team on the legacy system; they may only extract reads. This prevents accidental corruption during the mapping analysis.
