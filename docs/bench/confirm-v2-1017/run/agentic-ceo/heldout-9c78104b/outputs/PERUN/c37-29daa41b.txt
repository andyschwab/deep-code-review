**Decision:** Proceed with a **Phased Validation Migration** rather than a single "big bang" move. The one-time encryption key rotation is the single point of failure; it must be isolated, tested on a non-production subset, and executed only after data integrity is verified on the new platform. Do not attempt to migrate all 12,000 scans in one night; the risk of interruption causing total data loss is unacceptable.

**Figures:** 12,000 scans / 4 specialists = 3,000 scans per person. If the window is limited to night hours (assume 8 hours), that is 375 scans/hour/person. If the legacy system throughput is unknown, the full migration cannot be guaranteed in one session. The plan below assumes a pilot batch of 100 scans tonight to validate the pipeline before scaling.

**Sequence of Operations:**

1.  **Pilot Batch Selection (Tonight):** Select 100 diverse, non-critical artifact scans.
2.  **Environment Hardening:** Verify the secure server room network isolation and power stability (UPS check).
3.  **Dry Run (No Key Rotation):** Transfer the 100 scans to the new platform in current format to test bandwidth and storage write speeds.
4.  **Encryption Test:** Perform the encryption key rotation *only* on the pilot batch. Verify decryptability on the display walls.
5.  **Full Migration Batching:** If the pilot succeeds, divide the remaining 11,900 scans into nightly batches sized to fit the available night window with a 20% time buffer.
6.  **Verification Loop:** After each nightly batch, verify a random sample on the display walls before clearing the legacy source.
7.  **Final Cutover:** Execute the final key rotation on the complete dataset only after the last batch is verified.
