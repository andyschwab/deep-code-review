**Decision: Conduct a full-tabletop exercise first.**

Do not run simulations or deploy to a single district yet. Simulations rely on historical data that may not reflect the specific chaos of a hurricane, and a live district test carries unacceptable risk given the "one-way switch" constraint; if the algorithm fails during a real call in the pilot district, you cannot roll back, violating your safety floor. A tabletop exercise is the only option that stress-tests the human-machine handoff, the "no rollback" decision tree, and the coordinator workflow without endangering lives.

**Workflow Plan (Target: Ready by June 1)**

**Phase 1: Validation & Stress Testing (Weeks 1-2)**
*   **Action:** Run a full-tabletop exercise using hypothetical "worst-case" hurricane scenarios (e.g., simultaneous calls exceeding fleet capacity, comms outages).
*   **Goal:** Verify that dispatch coordinators understand the new logic and that the algorithm's suggestions align with human judgment under pressure.
*   **Owner:** Dispatch Coordinators lead the scenario; Developers observe to tune logic based on coordinator feedback.

**Phase 2: Shadow Mode Deployment (Weeks 3-5)**
*   **Action:** Deploy the algorithm in "shadow mode" across the entire region. It calculates routes but does not dispatch units; humans dispatch using the old system.
*   **Goal:** Compare algorithmic routes against actual human decisions and measured response times in real-time without risk.
*   **Owner:** Developers manage the shadow infrastructure; Coordinators log discrepancies between suggested and actual routes.

**Phase 3: The Gate & Switch (Week 6)**
*   **Action:** Review shadow mode data. If the algorithm shows a clear path to the 40% improvement without critical safety failures, flip the switch.
*   **Goal:** Final activation before June 1.
*   **Owner:** Chief of Staff authorizes the flip based on the data package.

**Risk Evaluation Matrix**

**Risks You Must Evaluate Personally (Chief of Staff):**
1.  **The "No Rollback" Threshold:** Define the exact metric failure rate that stops the switch. If shadow mode shows even one instance where the algorithm would have stranded a caller, you must halt.
2.  **Liability & Ethics:** Accept responsibility for the algorithmic decisions once live. Ensure legal counsel has reviewed the "black box" decision liability.
3.  **Human Override Protocol:** Verify the clear, immediate mechanism for a coordinator to ignore the algorithm if intuition or unmodeled factors (e.g., a bridge out not in the system) dictate otherwise.

**Tasks the Technical Team Handles Autonomously:**
1.  **Scenario Construction:** Build the hypothetical data sets for the tabletop exercise.
2.  **Shadow Infrastructure:** Deploy the code to run parallel to the legacy system without intercepting dispatch commands.
3.  **Data Reconciliation:** Write scripts to compare shadow routes vs. actual routes and generate the performance report for your final gate review.
4.  **Latency Monitoring:** Ensure the new algorithm meets the speed requirements under load during shadow mode.
