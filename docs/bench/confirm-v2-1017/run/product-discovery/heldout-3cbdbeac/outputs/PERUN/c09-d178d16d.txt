# Decision Brief: Dark Mode Beta Launch Assessment

**Status:** UNVERIFIED / DO NOT LAUNCH YET
**Recommendation:** Delay beta launch. Execute a targeted diagnostic test to isolate the root cause of navigation errors before proceeding.

### Current Evidence Summary
*   **Desirability (High):** 60% of 15 agencies rate dark mode as "critical." This indicates strong market pull and potential satisfaction gains.
*   **Usability (Critical Failure):** Prototype testing shows a 20% increase in navigation errors in dark themes.
*   **The Conflict:** High stated preference vs. degraded actual performance.

### Risk Analysis
Your working assumption—that visual preference outweighs temporary efficiency drops—is currently **untested and risky**. A 20% increase in navigation errors is not merely an "adaptation period" friction; it suggests a fundamental breakdown in interface legibility or interaction logic.

If launched as-is:
1.  **Support Volume:** Expect a spike in tickets related to "broken" navigation, not just "getting used to" the look.
2.  **Credibility Loss:** Design agencies (your core users) will perceive the tool as unprofessional if basic navigation fails, regardless of color preference.
3.  **False Signal:** You will be unable to distinguish if future churn is due to the feature itself or the poor implementation of contrast/switching.

### The Missing Variable: Root Cause
We do not know if the errors stem from:
*   **A:** Poor contrast ratios in the current palette (fixable via design tokens).
*   **B:** Fundamental flaws in the theme-switching mechanism (architectural issue).
*   **C:** Lack of user mental model for the specific dark layout (training issue).

Launching without distinguishing these variables turns the beta into a expensive, chaotic debugging session rather than a validation of value.

### Required Action: The Cheapest Disconfirming Test
Before committing to a full beta, run a **48-hour targeted usability sprint** with the following parameters:

*   **Objective:** Isolate whether contrast or switching logic causes the 20% error rate.
*   **Method:** Take the 3 users who committed the most navigation errors in the last session.
    *   *Test A:* Present a static high-contrast dark mockup (no switching). Ask them to navigate.
    *   *Test B:* Ask them to toggle themes repeatedly on a simple screen.
*   **Metric:** Error rate per task.
*   **Kill Threshold:** If errors remain >10% in Test A (static high contrast), the issue is likely structural (C), requiring a redesign, not a palette tweak. If errors drop to <5%, the issue is contrast (A), which can be fixed before beta.

### Decision Rule
*   **IF** the diagnostic test identifies contrast as the sole culprit AND fixes reduce errors to <5%: **Proceed to Beta** with a "Known Issues" disclaimer.
*   **IF** errors persist or the cause is structural: **Delay Launch**. Fix the core interaction first. No amount of "critical" demand justifies shipping a broken navigation flow.

### Non-Goals for This Stage
*   **Perfect Aesthetic Polish:** Do not spend time refining shadows or hues until navigation errors are resolved.
*   **Full Feature Parity:** The beta does not need every module in dark mode; it only needs the core navigation loop to function flawlessly.

***

**Note:** Do not rely on the "60% critical" stat to override the usability failure; users often cannot articulate *why* a UI fails them, only that it feels wrong.
**Next Step:** Schedule the 48-hour diagnostic test with the engineering lead to prepare the specific contrast variants.
