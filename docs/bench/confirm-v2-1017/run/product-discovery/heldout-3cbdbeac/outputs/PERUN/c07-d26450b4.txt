# Executive Briefing: Invoice Data Entry Automation Proposal

**Decision Status:** UNVERIFIED. Do not approve the three-month build yet. The core assumption regarding scalability and uniformity of processes across the 200-person department is untested. Proceeding now risks building a custom tool for five outliers that fails for the remaining 195 users, creating immediate technical debt.

### 1. The Riskiest Assumption
**Assumption:** The workflow used by the five Toronto accountants is representative of the broader accounting department, and a single parser can handle the variance in invoice formats across all vendors used by Northwind Logistics.
**Risk:** If these five users handle a unique subset of vendors or use non-standard manual workarounds, the automation will have zero applicability to the other 195 staff. The "18 hours saved" figure may not scale; the maintenance burden, however, will apply immediately.

### 2. Required Validation Test (Before Development)
**Test:** Concierge Pilot & Variance Audit.
**Method:**
*   **Step A (Variance Check):** Randomly sample 50 invoices from the other 195 accountants. Compare their formats and data fields against the Toronto group's invoices.
*   **Step B (Concierge Test):** For one week, have an engineer manually process the Toronto team's invoices using the proposed logic (simulating the parser) without writing code. Measure the actual time taken and error rate when encountering edge cases.

**Kill Thresholds (Decide these numbers before starting):**
*   **Format Variance:** If more than **20%** of the sampled invoices from the wider department differ significantly in structure from the Toronto set, the "single parser" approach is invalid.
*   **Processing Time:** If the simulated manual process takes longer than **5 minutes** per invoice (due to exception handling), the projected ROI of "under two minutes" is false.
*   **Adoption Signal:** If fewer than **3** of the 5 Toronto users actively rely on the concierge service during the trial (vs. reverting to their old way), the pain point is not acute enough to justify a build.

### 4. Strategic Recommendation
**Immediate Action:** Reject the build request for now. Authorize a **one-week discovery sprint** to run the Variance Audit and Concierge Pilot defined above.
**Rationale:** A three-month build is a high-cost solution to a problem that may only exist for 2.5% of your staff. If the pilot confirms the workflow is universal, the ROI case becomes undeniable. If it reveals high variance, you avoid sinking three months of engineering capacity into a tool that requires constant custom tweaking for every new vendor, which is a common failure mode for internal parsers.

**Non-Goal for This Stage:** Building the actual parser, integrating with the legacy system, or creating a UI. These are only relevant once the "universal workflow" assumption is proven true.
