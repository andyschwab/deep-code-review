## Add connection pooling to reporting service

This PR replaces the old singleton connection class with a new pool manager to improve query performance and concurrency.

**Changes**
- Added `PoolManager` class; removed the legacy singleton.
- Default pool size: 50 connections (max 200).
- Connection timeout: 5s; idle timeout: 300s.
- Updated the health check endpoint to report pool status.
- Modified 12 files across the service.

**Results**
- Main dashboard query latency dropped from 1.2s to 0.3s.
- Load test passed: 5,000 concurrent requests with zero errors.

**Known limitation: Database failover**
The pool does not automatically refresh connections when the primary database fails over to the replica. I could not test this scenario because the staging environment lacks a failover trigger. It is unclear whether the pool will timeout and error out or eventually recover after DNS propagation.
