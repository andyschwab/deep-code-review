This PR replaces the dashboard's polling mechanism with Server-Sent Events (SSE) to reduce server load and improve client stability.

**Changes**
- Removed 450 lines of polling logic and interval timers.
- Added 280 lines for SSE event source handlers.
- Updated the mock server to support the new endpoints.
- Added a visual connection status indicator (yellow dot when disconnected).

**Impact**
- Server request volume dropped from 600 req/min to 12 req/min per client.
- Client memory usage remains stable at 15MB.

**Known Limitation: Reconnect Logic**
The current implementation handles initial connections successfully, but the reconnect behavior after a network dropout (e.g., 30 seconds offline) has not been tested. Our local network proxy is difficult to configure for simulating dropouts, so I could not verify if the browser auto-reconnects and resumes the stream correctly or if we need to implement a manual retry loop with a `Last-Event-ID` header to catch up on missed messages.

**Request for Review**
I am seeking your approval to merge this despite the untested reconnect scenario. The performance gains are significant, and the visual indicator provides immediate feedback to users if the connection drops. We can address the specific reconnect edge case in a follow-up ticket once we have a better way to simulate network failures, or proceed with monitoring it in the staging environment.

Please let me know if you are comfortable merging this now or if you require the reconnect logic to be fully validated first.
