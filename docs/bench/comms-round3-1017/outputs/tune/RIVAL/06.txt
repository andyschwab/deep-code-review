This PR implements lazy loading for eight feature modules (orders, promotions, settings, help, profile editor, notifications, rewards, and feedback), shifting initialization from app startup to first access. The change touches 41 files (+567 lines, -23 lines). All 218 unit tests and 54 integration tests pass.

On a Pixel 7 (8 GB RAM), the update delivers significant startup gains:
- Cold start: 3.2s (down from 5.8s)
- Warm start: 1.1s (down from 2.0s)
- Time to interactive: 3.8s (down from 6.4s)
- Startup memory: 87 MB (down from 134 MB)

However, testing is currently limited to high-RAM devices. We lack data on low-memory devices (down to our 2 GB support floor), where on-demand loading could introduce jank or crashes. I also haven't verified behavior when users access lazy modules while offline or with cached data.

Tom, please review whether these startup improvements justify shipping in the next release given the untested low-end device scenarios, or if we should hold for broader device testing first.
