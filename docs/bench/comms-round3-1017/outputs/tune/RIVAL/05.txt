**Upgrade order-events to message-broker client v3.1.0**

This PR replaces the legacy message-broker client (v2.4.1) with v3.1.0 across 23 files. The update refactors connection initialization, retry logic, and message serialization, resulting in a net reduction of 256 lines of code.

**Validation**
- Unit tests: 342/342 passed.
- Integration tests: 89/89 passed.
- Staging load test results:
  - Throughput increased from 12,400 to 18,700 messages/sec.
  - p99 latency improved from 45ms to 31ms.
  - Memory usage dropped from 2.1 GB to 1.4 GB per instance.

**Known Gaps & Risks**
The staging broker was not restarted during testing, so the new reconnection logic under failure conditions remains unverified. Specifically:
1. **Recovery Time:** We need to confirm the new client meets our <30s recovery SLA after a broker restart.
2. **Dead-Letter Queue (DLQ):** The v3 documentation notes changes to DLQ behavior that have not yet been validated against our expectations.
