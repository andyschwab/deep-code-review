**PR Review: Circuit Breaker for Inventory API**

This PR adds a failure-based circuit breaker to the downstream inventory API to address the 15% error rate seen during peak hours. The implementation opens the circuit after 5 consecutive failures, holds it open for 30 seconds, and serves a cached response (up to 5 minutes old) during that window. Test coverage includes 4 new tests, bringing the total suite to 180 passing tests.

Two gaps need your decision before merging:

1.  **Slow responses:** The current logic trips only on explicit failures. It does not handle cases where the API responds slowly without erroring. We have not implemented or tested a timeout-based trip. Do you want to add timeout handling in this PR, or is mitigating hard failures sufficient for now?
2.  **Cache staleness:** The fallback returns data cached up to 5 minutes ago. We need to confirm if this staleness is acceptable for downstream consumers during an outage.

If you agree that handling hard failures is the priority and 5-minute stale data is safe, I'll merge this as-is and open a follow-up ticket for timeout logic. Otherwise, I can hold for the timeout implementation.
