**PR: Swap message-broker client in order-events service**

This PR replaces the old message-broker client with the new one across the producer, consumer, config, and two test files (+250, -180 lines). The change improves throughput from 5,000 to 8,000 messages/second on the producer side, with similar gains on the consumer. All 150 existing tests pass, plus 6 new tests covering the new client's API.

Two reconnection scenarios remain untested:
1.  **Broker restart:** We rely on the new client's automatic reconnection, but haven't verified it works with our specific config.
2.  **Extended outage:** The current config sets a 30-second reconnect timeout, so we haven't tested behavior when the broker is down for more than 60 seconds.

Taylor, please review the reconnection code to decide if we need explicit tests for the broker-restart case or if the library's default behavior is sufficient given our timeout settings.
