**PR Summary: Session-Store Caching Layer**

This PR introduces an in-memory cache to the session-store service to improve read performance. The changes span four files: the new cache implementation, a configuration file, updates to the service main file, and a new test file. The net change is +200 lines and -30 lines.

**Performance Impact**
Read latency has dropped from 120ms to 30ms, a 75% improvement. Write path latency remains unchanged at 100ms.

**Testing Status**
The full test suite passes, including five new tests covering standard cache hit and miss scenarios.

**Open Questions for Review**
Sam, please focus your review on two areas:

1.  **Eviction Race Condition:** We have not yet tested the scenario where two requests simultaneously attempt to evict and repopulate the same key. The current implementation uses a mutex to handle this, but we need your assessment on whether the locking strategy is sufficient or if a specific concurrency test is required.
2.  **Cache Capacity:** The cache size is currently configured for 10,000 entries. We are unsure if this threshold will hold during peak traffic. We plan to monitor this metric post-deployment, but please let us know if you recommend a different baseline based on historical load data.

The PR is ready for your review.
