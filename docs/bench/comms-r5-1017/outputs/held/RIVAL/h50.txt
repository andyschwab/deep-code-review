**PR: Add read replica path for reporting dashboard**

This change routes the dashboard's heavy queries to a new read replica, reducing main query latency from 800ms to 150ms (an 81% improvement). The update touches four files: database config, a new query router, the dashboard service, and a test file (+140, -25 lines). All 110 tests pass, including two new cases verifying the read/write split.

Two items need your input before we merge:

1.  **Replica-lag alerting:** We implemented a basic alert if lag exceeds 5 seconds, but we haven't determined if this threshold fits the dashboard's tolerance. Please advise on the appropriate limit and whether we need more sophisticated lag detection.
2.  **Failover behavior:** The query router is designed to fall back to the primary if the replica goes down, but we haven't tested this scenario yet. Let us know if you want this validated in the current PR or tracked as a follow-up task.

The branch is ready for your review.
