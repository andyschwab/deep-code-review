**Fix flaky retry logic in payments webhook**

This PR corrects aggressive retry behavior in the payments webhook handler that previously caused duplicate charge attempts. The fix implements exponential backoff with jitter, scaling from 1 second to 5 minutes across five attempts.

Changes include updates to the webhook handler and a corresponding test file (+80 lines, -40 lines). The suite now includes 45 passing tests, with three new cases specifically covering retry timing and duplicate prevention.

**Open questions for review:**
1.  **Out-of-order event delivery:** The current fix does not handle scenarios where a later event arrives before an earlier one. We observed this once in staging but never in production, and it remains unclear if the payment provider guarantees order. Please advise whether to address this in a follow-up ticket or expand the scope of this PR.
2.  **High-load behavior:** While the backoff intervals seem reasonable, we have not yet validated system behavior under high load.

Alex, please review the implementation and let us know how you would like to proceed regarding the out-of-order event edge case.
