## Caching layer for session-store

This PR adds a cache manager to the session-store service to reduce read latency. The change modifies five files and introduces a new caching layer that sits between the request handler and the underlying store.

**Performance impact**
Average read latency dropped from 120ms to 30ms in local benchmarks. The improvement comes from serving frequent session reads directly from memory instead of hitting the database on every request.

**Implementation details**
The new cache manager handles storage and retrieval of session data. It integrates with the existing service logic without changing the public API. Session writes still go directly to the primary store to ensure durability, while reads check the cache first.

**Known gaps**
We have not yet tested the cache-eviction race condition under high concurrency. There are also a few edge cases around cache invalidation that need further review. These items are tracked for follow-up and do not block the initial merge, but they should be addressed before full rollout.
