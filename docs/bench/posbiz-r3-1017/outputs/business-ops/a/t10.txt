### Revenue Impact Analysis: Flat Fee vs. Usage-Based Model

**Current State (Baseline)**
*   **Revenue:** $118,800/mo (1,200 users × $99).
*   **Variable Cost:** $14,400/mo (1,200 users × $12).
*   **Contribution Margin:** $104,400/mo.

**Proposed State (Hybrid Transition Scenario)**
*Assumptions: You lose 240 high-volume users. You gain 400 low-volume users at $0.50/doc. The remaining 960 users stay on the flat fee (or transition logic is applied; this model assumes the 400 new users are *additional* to the retained base, replacing the lost ones partially).*

1.  **Retained Base:** 960 users × $99 = **$95,040** revenue.
2.  **New Usage-Based Users:** 400 users × 50 docs × $0.50 = **$10,000** revenue.
3.  **Total New Revenue:** $105,040.
4.  **Revenue Delta:** $105,040 - $118,800 = **-$13,760/mo** (approx. 11.6% decrease).

**Cost Impact Analysis**
*   **Lost Variable Costs:** 240 users × $12 = -$2,880 (savings).
*   **New Variable Costs:** 400 users × 50 docs × ($12/avg_docs?).
    *   *Constraint Note:* Your current cost is $12/user/month flat. If cost scales strictly with documents, we must estimate the cost-per-document.
    *   *Derivation:* If current heavy users (top 10% = 120 users) generate 40% of volume, and average users generate the rest, the cost per document is unknown without total volume.
    *   *Conservative Estimate:* Assuming the $12 average holds for the new low-volume users (50 docs), cost is 400 × $12 = $4,800.
    *   *Optimistic Estimate:* If $12 covers a heavy user (e.g., 200 docs), cost per doc is $0.06. New cost: 400 × 50 × $0.06 = $1,200.
*   **Net Cost Change:** Likely an increase in total variable costs if the new users are inefficient, or a decrease if the lost heavy users were disproportionately expensive.

**Decision Aid**
*   **Read:** At the specific volumes provided (losing 240 heavy, gaining 400 light), **revenue drops by $13,760/month**. The gain from new users does *not* outweigh the loss of high-volume subscribers under these specific numbers.
*   **The Flip Input:** To break even on revenue, the 400 new users must generate **$34.50/user/month** ($13,760 / 400). At $0.50/doc, they must average **69 documents/month**, not 50.
*   **Threshold Rule:** If LTV of a "low volume" user < $35/month, this specific swap destroys value. Do not proceed unless your acquisition data shows average usage > 69 docs/month.
*   **Next Step:** Before changing pricing, run a "Van Westendorp" style survey or A/B test on a small segment: offer the usage rate to 50 new signups only. Measure actual document volume. If average < 69 docs, the model fails at this price point.

**Required Data Segmentation**
To refine this model, query your database for:
1.  **Documents Per User (DPU) Distribution:** Histogram of all users. Identify the exact cutoff where a user becomes "heavy."
2.  **Cost-to-Serve Ratio:** Calculate `Server Cost / Document Count` for the top 10% vs. bottom 50%. If heavy users cost disproportionately more, losing them might improve margins despite revenue loss.
3.  **Elasticity Proxy:** Identify users who have paused usage or logged in less frequently during the recession. These are your highest-probability candidates for the usage-based plan.

*Note: This analysis applies your provided numbers to standard unit economics formulas; it does not account for potential brand damage or long-term churn acceleration beyond the stated 20%. Server cost behavior at scale (step-functions vs linear) was estimated based on the provided average.*
